Claude Memory 2026 — カテゴライズされたエントリ、アプリから API まで

中級
What you'll learn
  • 2026 年 7 月に何が変わったか正確に見る — アプリでカテゴライズされたエントリが日次サマリを置き換え、新しいベータヘッダが API を再配線
  • 設定で個別エントリを表示、編集、削除する方法を学ぶ — すべてを消去せずに
  • agent-memory-2026-07-22 ヘッダが memory_store エンドポイントにもたらす 4 つの動作変更と、古いカーソルが機能しなくなる理由を理解する
  • memory_store.* Webhook と Dreams に会う — 誰も文書化しない部分
  • Claude に何を覚えて(何を忘れて)ほしいかを教える 5 つの実用パターンを適用する

1 年間、「Claude のメモリ」はモデルが毎日書き直す 1 つの進化する段落を意味しました — 略歴には良いが、構造のあるものには悪い。2026 年 6 月から 7 月の間、Anthropic はそれをエントリベースのモデルに置き換えました: Claude がリアルタイムで読み書きする多数の小さくカテゴライズされたノート。同じアイデアがアプリと Managed Agents メモリ API を動かします。このページはそれらを接続し、両方の面を 1 つのメンタルモデルから理解できるようにします。

最終検証: 2026-07-24。

agent-memory-2026-07-22 ベータヘッダ、memory_store Webhook イベント、Dreams モデルサポートはすべて過去 4 週間で変更されました。出荷前にプラットフォームリリースノートで現在のベータステータスと価格を確認してください。

次の情報源で確認してください: 公式情報源.

両側を統一するメンタルモデル​

両側は今や同じように動きます: 名前付き場所の多数の小さいエントリ、それぞれ独立して書き換え可能。古いモデル(ユーザーあたり 1 つのブロブを全体書き換え)はアプリで消え、API 面には存在したことがありません。「パスのエントリ、プレフィックスでリスト、一度に 1 つずつ編集」 を内在化すれば、両面は別機能に感じなくなります。

用語
Enter キーまたはスペースキーでカードを裏返します。左右の矢印キーでカードを移動できます。用語を表示しました。

パート 1 — アプリで: カテゴライズされたエントリ​

実際に何が変わったか、そしていつ​

Guided walkthrough1 of 3
  1. 新しい Settings › Reflect の面が、時間を費やしたトピック、最もアクティブな日、ピーク時間、そして Claude との作業方法についての観察を表示し始める。Web + Claude Desktop の Free、Pro、Max でベータ。メモリ有効が必要。
  2. メモリは 1 つの回転する日次サマリではなく、Claude が会話中に読み更新する個別のカテゴライズされたエントリのセットになる。Claude Apps リリースノートで発表。
  3. サードパーティ報道は Free、Pro、Max、Team、Enterprise 全体で利用可能と位置付けているが、プランごとの表現は Anthropic のヘルプセンターとニュース投稿の間で変わる。重要な場合(コンプライアンス、監査)、あなたのプランのために製品内で検証。

形状変更が重要な理由​

古い日次サマリには単一の失敗モードがありました: 無関係なコンテキストが互いに漏れる。あなたの仕事プロジェクトに関する事実を修正すると、Claude はあなたの書き方に関する何かを上書きするかもしれない。小さくカテゴライズされたエントリは構造的にそれを修正 — 各編集は 1 つのレーンにスコープされる。

ほとんどのユーザーが見逃す 3 つの結果:

  • 取得は連想ではなく標的的になった。 Claude は残りのコンテキストを引きずらずに「あなたのコミュニケーション設定」を引き出せる。サマリを突破するために「X が好き、Y ではない」を必要としたプロンプトは、今や既存のエントリに直接当たる。
  • 外科的に刈り込める。 すべてを消して Claude にあなたが誰かを教え直すのではなく、設定で 1 つの間違ったエントリを削除する。1 つのミス修正の「全焼却」税が消えた。
  • カテゴリは目に見えないスキーマとして機能する。 Claude がエントリの属す場所を決めるとき(例:「コミュニケーションスタイル」対「現在のプロジェクト」)、その事実が将来の個人チャット、将来の仕事チャット、または両方で呼び出されるかどうかを暗黙的に選んでいる。前もって適切に名付けることが後のより良い呼び出しを後押しする。

自分のエントリを表示し管理する​

Guided walkthrough1 of 5
  1. カテゴリ(プロフェッショナルコンテキスト、コミュニケーション設定、進行中プロジェクト、そして類似のバケット)でグループ化されたエントリが見える。
  2. 各エントリには独自のコントロールがある。残りに触れずに間違った事実を修正 — 再設計の全理由。
  3. Claude に特定のものを覚える、忘れる、または更新するよう頼み(「Bun を使う、npm ではない、と覚えて」)、それはマッチするエントリをライブで更新する。
  4. インコグニトチャットはメモリ書き込みとチャット履歴から除外される。永続化したくないもの — 機密な下書き、一度限りの探索、要約されたくない認証情報 — に使う。
  5. Settings › Reflect が Claude があなたに何を話してきたかを表出させる。ざっと見てメモリドリフトを捕まえる — 気にしないトピックが表示され続けるなら、エントリを刈り込む。
Watch out
  • メモリはベストエフォートの呼び出しであって、権威ある保管ではありません。監査するもの(契約、認証情報、薬、法的事実)の真実の情報源として扱わないでください。ハード要件はプロンプトまたはプロジェクトの指示で再述してください。

実際に機能する 5 つのパターン​

1. 標準設定を一度、明示的に設定

Please remember these as standing preferences for our chats:
- Language: Italian for prose, English for code and error strings.
- Units: metric.
- Coding style: TypeScript strict, no default exports.
- Voice: direct, no filler, no closing "let me know if…".

Store each as its own entry in the right category.

2. 消去せずに単一の事実を修正

Update the memory entry that says I use Vercel for hosting — I moved everything to
Cloudflare Workers last month. Leave every other project fact alone.

3. 意図的に忘れる

Delete any memory entries about the "Project Nightingale" launch — that work is finished
and I don't want it surfacing in future chats.

4. Claude が何を知っていると思っているか監査

Before we start, list every memory entry you have about me, grouped by category.
Flag anything that looks outdated so I can decide whether to keep or delete it.

5. 探索的チャットをサンドボックス化

(Open the chat in Incognito.) Don't try to remember anything from this conversation —
I'm just exploring a sensitive draft I don't want stored.

パート 2 — API で: memory_stores と新しいベータヘッダ​

Managed Agents プラットフォームはメモリを memory stores として公開します — パスでアドレス指定され、path_prefix でリストされ、カーソルでページングされるメモリのコレクション。2026 年 7 月 2 日に Anthropic は agent-memory-2026-07-22 を出荷しました。これは素朴な移行を壊すのに十分な意味論を変えるベータヘッダ。2026 年 7 月 22 日に古い managed-agents-2026-04-01 ヘッダが同じリスト動作を採用 — なので「新しい」ルールは今 memory-store エンドポイントで唯一のルール。

知っておくべき 4 つの動作変更​

#何が変わったか古い動作agent-memory-2026-07-22 の下での新しい動作
1リスト順序order_by / order でクライアント制御安定した、サーバ定義の順序。 order_by と order は無視される — 必要ならクライアント側でソート
2depth パラメータ自由形式の整数0、1、または省略のみを受け入れる。他の任意の値は 400 を返す
3path_prefix マッチング部分文字列マッチ/ で終わる必要があり、全パスセグメントのみをマッチ
4ページネーションカーソル交換可能新しいヘッダなしで発行されたカーソルはそれと一緒に有効ではない。採用時はページ 1 から再開

さらに 2 つの落とし穴:

  • ヘッダ衝突。 memory-store エンドポイントでは、agent-memory-2026-07-22 が managed-agents-2026-04-01 を置き換える。両方を送ると 400 を返す。memory-store コールのみを移行し、他の managed-agents エンドポイントは元のヘッダのまま。
  • SDK はすでに切り替わっている。 Python 0.116.0、TypeScript 0.110.0、Go 1.56.0、Java 2.48.0、Ruby 1.55.0、PHP 0.36.0、C# 12.35.0、CLI 1.16.0 はすべて memory-store コールで自動的に agent-memory-2026-07-22 を送る。コードが明示的に betas を渡す場合、そこの managed-agents-2026-04-01 を置き換える — 両方を追加しない。

list-memories コールを最小限に移行​

Guided walkthrough1 of 6
  1. 少なくとも Python 0.116.0 / TS 0.110.0 / Go 1.56.0 / Java 2.48.0 / Ruby 1.55.0 / PHP 0.36.0 / C# 12.35.0(CLI 1.16.0)にアップグレード。memory-store コールのヘッダ切り替えは自動。
  2. order_by / order を削除 — サーバは無視する。コードが返されたリスト順序でソートするなら、ソートをクライアント側に移動。
  3. 0 か 1 以外の任意の depth を意図に最も合う値に置き換えるか、パラメータを省略。
  4. すべての path_prefix がスラッシュで終わるように。部分セグメントマッチに頼っていた部分文字列スタイルのプレフィックスを削除 — 今は静かにより少ない結果を返す。
  5. アップグレード後の最初のリクエストで、保存されたカーソルを再利用しない。ページ 1 から始め、新しい応答から次のカーソルを再導出。
  6. 手動で betas を渡すなら、memory-store コールの managed-agents-2026-04-01 を agent-memory-2026-07-22 に置き換える — 決して両方を送らない。

Webhook: ポーリングなしで memory-store ライフサイクルに反応​

2026 年 7 月 22 日にヘッダデフォルトと共に出荷: 3 つの memory_store.* Webhook イベントタイプが今やメモリストアのライフサイクルをカバーし、4 つの environment.* イベントがサンドボックス環境をカバー。これはほとんどのインテグレータが見逃す部分 — タイマーで GET /v1/memory_stores をポーリングする代わりに、エージェントランがメモリストアを作成、更新、または削除するのに反応できる。Managed Agents Webhook エンドポイントで購読し、イベントを自分の監査証跡やダッシュボードにルーティング。

Dreams: バックグラウンドでメモリを再編成​

2026 年 5 月 6 日のリリースノートで発表され、7 月 10 日に Claude Fable 5 と Sonnet 5 をサポートするよう拡張された Dreams は、既存のメモリストアと過去のセッショントランスクリプトを読み、再編成された出力メモリストアを生成するリサーチプレビュー: 重複がマージされ、古いエントリが置き換えられ、新しい洞察が表出。エンドポイントは dreaming-2026-04-21 ベータヘッダでゲートされ、アクセスはリクエスト制。アプリの月次リキャップの API 側アナログとして扱う — ストアが沈殿しないようにするスケジュールされた反射パス。

アプリ vs API — 1 つの表​

側面Claude.ai アプリManaged Agents API
ストレージ単位カテゴライズされたエントリパスのメモリ
グループ化カテゴリ(プロフェッショナルコンテキスト、コミュニケーション設定、進行中プロジェクト、…)パスセグメント(/projects/acme/…)
読み書きチャット中にライブセッション中のエージェントツールコール
人間編集可能はい、Settings › Memory でエントリごとはい、memory-store エンドポイント経由
消去エントリごと、またはすべてメモリごと、プレフィックスごと、またはストア削除
反射月次リキャップ(Settings › Reflect)Dreams(リサーチプレビュー)
分離インコグニトチャットエージェントごと、セッションごとのメモリストア選択
利用可能性Free、Pro、Max、Team、Enterprise(プランごとに検証)Managed Agents(公開ベータ)

これが AILmanac の残りのどこにいるか:

  • メモリとコンテキスト編集 — クライアント側メモリツール、異なる獣: ストレージを実装。
  • チャット横断メモリ — アプリメモリの初心者向け概要。
  • エージェントメモリアーキテクチャ — カテゴライズされたエントリが回転サマリより勝る理由を理解するエピソディック対セマンティックメモリの理論。
  • Managed Agents — ここで説明された memory-store 面をホストするハーネス。

いずれかを有効にする前のプライバシーチェックリスト​

Pro tip
  • Team と Enterprise: 管理者がエントリを検査できるか確認。アプリメモリをデータ分類「機密」ではなく「内部」として扱う。
  • Claude に API キー、トークン、認証情報をエントリに書かせない。メモリオンでチャットに貼り付けたなら、メッセージと結果のエントリを削除。
  • 法的、医療、財務の一時的なものにインコグニトを使う。そうしなければ、アプリが後で文言を要約するのを防ぐものはない。
  • 定期的に監査。「私についての各エントリをリスト」プロンプトを月次で実行し、当てはまらないものを削除。
  • API 側では、memory_stores を第一級データとして扱う。バックアップし、重要なランの前後で list-diff し、memory_store.* Webhook イベントを監査証跡にログ。
