Poolside Laguna:クラスを超える性能を発揮するオープンウェイトのコーディングモデル

中級

2026年7月2日、Poolside AI ——NVIDIA も参加するラウンドで約 20 億ドルを 120 億ドルのバリュエーションで調達した米国のファウンデーションモデル研究所——が、初の公開モデルである Laguna ファミリーをリリースしました。3 つの MoE コーディングモデルはすべて寛容な OpenMDW-1.1 ライセンスの下で公開され、単一のプレトレーニングコーパスを共有し、主にどれだけ大きなマシンに向けるかだけが異なります。2 週間後、彼らはこのファミリーに Laguna S 2.1 を追加しました。118B/8B アクティブの MoE でありながら、DeepSWE v1.1 で DeepSeek-V4-Pro-Max を打ち破り(40.4% 対 9.0%)、アクティブパラメータは 6 分の 1、さらに SWE-Bench Multilingual で 78.5% を記録——ローンチ時点でそのリーダーボードにおける最高公開スコアです。

このページは、このファミリーの実用的なフィールドガイドです。各サイズが実際に何を興味深いものにしているのか、多くのカバレッジが見逃した 2 つのトレーニングパイプラインの選択、クローズドフロンティアおよびオープンウェイトの競合に対する率直なベンチマークの姿、今日ローカルで実行する方法、そして Claude、GLM-5.2、Kimi K3 よりも Laguna を選ぶべき具体的なタスクを扱います。

What you'll learn
  • ファミリーを一目で把握する——3 サイズ、1 コーパス、1 ライセンス——そしてどのサイズがどのハードウェアに対応するのか
  • 8B のアクティブパラメータが 1.6T のトータルを打ち破れる理由を理解する:MoE ルーティング + コーディング特化のポストトレーニング
  • SWE-Bench Multilingual、Terminal-Bench 2.1、DeepSWE v1.1、SWE-Bench Pro の率直なベンチマーク像を読み解く
  • モデルの挙動を形作る 2 つのトレーニングパイプラインの初——FP8 での RL、マルチハーネストレーニング——を知る
  • OpenRouter で 3 行、あるいは MacBook や DGX Spark 上で GGUF/MLX を使ってローカルで Laguna を動かす
  • Claude Opus 5、GLM-5.2、Kimi K3、GPT-5.5 と比べて Laguna を選ぶべきタイミングを判断する

ファミリーの全体像​

3 つのモデル、1 つの共有プレトレーニング実行、3 つのハードウェアエンベロープ。これは意図的です:Poolside は 1 回プレトレーニングし、サイズごとにポストトレーニングしたため、ファミリー全体で個性が一貫しており、タスクの形状ではなく手元の箱に基づいてサイズを選びます。

モデル総パラメータアクティブパラメータコンテキストターゲットハードウェアライセンス
Laguna XS 2.133B (MoE)3B最大 256Kシングルラップトップ / MacBook GPUOpenMDW-1.1
Laguna S 2.1118B (MoE)8B最大 1Mシングル DGX Spark または FP8 の H200OpenMDW-1.1
Laguna M.1225B (MoE)23B256K+エンタープライズマルチ GPU ノードOpenMDW-1.1

この表から得られる 3 つの実用的な要点:

  • ファミリー全体で同じコーパス。 Laguna S 2.1 のポストトレーニングは XS 2.1 の上に新しいデータを追加していません——S 2.1 の発表がこれを明示しています。挙動の改善は新しい文書を与えることではなく、より大きなモデルクラスと異なるポストトレーニングレシピから来ています。つまり、ファインチューニングの知見はサイズ間できれいに転用できます。
  • 推論コストに関わるのはアクティブパラメータの列です。 8B アクティブでは、Laguna S 2.1 はトークンあたり 118B ではなく 8B デンスモデルの計算プロファイルを持ちます。それが「シングルアクセラレータで動く」と「ラックが必要」の違いです。
  • OpenMDW-1.1 は本物の寛容ライセンスであって、ソースアベイラブルライセンスではありません。 これは Linux Foundation によって公開されたもので、重みやデータを明確にカバーしない従来のオープンソースライセンスと、静かに商用利用を禁止するベンダーの「オープン」ライセンスとのギャップを埋めるためのものです。著作権、特許、データベース、営業秘密にわたって無制限かつロイヤリティフリーの権利を付与し、出力は明示的に非拘束です。
最終検証: 2026-08-03。

パラメータ数、コンテキストウィンドウ、ライセンスは Poolside 独自のローンチ資料と独立したカバレッジからのものです。次のセクションのベンチマークスコアは Poolside のローンチ投稿からのもので、MarkTechPost の分析と照合済みです。リーダーボードのランクはローンチ時点で引用されており、毎週動きます。引用する前に、Poolside のブログと Hugging Face のモデルカードで現在の数値を確認してください。

次の情報源で確認してください: 公式情報源.

ヘッドラインから明らかでない 3 つのこと​

1. FP8 での RL は本当のエンジニアリングブレークスルーであり、マーケティングではない​

LLM のポストトレーニングにおける強化学習は歴史的に BF16 で実行されてきました。なぜなら、FP8 精度での勾配ノイズが RL が提供する小さなシグナルを吹き飛ばすと想定されていたからです。Poolside は Laguna S 2.1 を FP8 で RL 学習された初のフロンティア規模のモデル であると公に主張しています。これが真実であれば——2026 年 8 月初旬時点で反例は現れていません——これは RL ステージのメモリフットプリントを半減させ、以前は高価すぎたタスクに与えられたクラスタが RL 計算を費やせるようにします。

ユーザーにとっての実用的な帰結:Poolside の RL ステージは選択的でした。彼らは 409k のトレーニング環境 (83k のターミナル、168k のソフトウェアエンジニアリング)を報告しており、ほとんどの挙動を合成データから SFT でブートストラップし、最も難しい問題に RL を予約しています。それはベンチマークのデルタに現れます——DeepSWE v1.1 での思考モードのブーストは 16.5% → 40.4% ——これは、RL がすべてのタスクにばら撒かれるのではなく、難しい推論に狭く費やされたときに期待される形です。

2. マルチハーネストレーニングが、サードパーティのエージェント内で崩れない理由​

コーディングモデルは通常、1 つのエージェントハーネス(ベンダー独自のスキャフォールド)内でトレーニングされ、その後、数十の他のもの(Cursor、Cline、Aider、Continue、Kilo など)にデプロイされます。トレーニングとデプロイのハーネス間のギャップこそが、「ベンチマークではうまくいったのに」という多くの失敗が生まれる場所です。Poolside は 83k のターミナル環境と 168k のソフトウェアエンジニアリング環境にわたる 複数のハーネスで Laguna をトレーニングしました。これが、モデルが初日から独自のスキャフォールド外で使用可能である理由として彼らがクレジットしているメカニズムです。

Laguna の報告された挙動におけるマルチハーネストレーニングの目に見えるシグナル:粘り強さ(失敗したツール呼び出し 1 回でアプローチを放棄しない)、検証優先(出荷前に自分の出力を再読する)、リソースフルネス(直接の道が塞がれたときに代替パスを見つける)。これらはエージェント的な挙動であり、次トークンの挙動ではありません——プレトレーニングデータを増やしても得られません。

同じ設計選択に直接対応する既知の制限は、驚かないように把握しておく価値があります:

  • サードパーティのハーネスにおける わずかなスキーマの違い に Poolside のネイティブなものと比べて苦しむ——ハーネスは 409k のトレーニング環境の何かに「十分近い」ように見える必要があります。
  • 配列内のネストされたツール呼び出しで不正にエスケープされた JSON を時々出力します。まれですが実在します。
  • 数学コンペティション問題で考えすぎる ——AIME スタイルのタスクで拡張思考が必要以上に長く実行されます。コーディングには問題ないが、数学には無駄です。

3. アクティブパラメータ比率がコストの全ストーリー​

目を引く数字は 1.6T 対 8B です:Laguna S 2.1 はトークンあたりのアクティブパラメータが 6 分の 1 でありながら、DeepSWE v1.1 で DeepSeek-V4-Pro-Max(1.6T トータル)を 31.4 ポイント上回っています。しかし、有用なフレーミングは推論コストです:

モデルトークンあたりのアクティブパラメータ概算のトークンあたり計算量参考 API 価格*
Laguna XS 2.13B~3B デンス相当無料枠 / $0.05 台
Laguna S 2.18B~8B デンス相当$0.10 入力 / $0.20 出力 per M(OpenRouter)
GLM-5.2~40B~40B デンス相当$1.20-1.40 入力 / $4.10-4.40 出力 per M

OpenRouter 上の S 2.1 と Claude Opus 5 のトークンあたり 150 倍のギャップ はヘッドライン用の公平な比較ではありませんが、有用な比率は S 2.1 対 他のオープンウェイトフロンティアモデル(GLM-5.2、Kimi K3)です:Laguna は出力トークンあたり約 12 倍安く、SWE-Bench Multilingual スコアは同じリーグにあります。それがモデルに任せることが経済的に妥当な仕事を変える価格エンベロープです。

ベンチマークの姿 —— 率直なバージョン​

S 2.1 のローンチ時点で報告されたスコアで、Poolside 独自の投稿とサードパーティのカバレッジの間で照合済み:

ベンチマークLaguna S 2.1何を測定するか備考
SWE-Bench Multilingual78.5%多くの言語にわたる実際の GitHub 修正タスクローンチ時点でトップの公開オープンウェイトスコア
Terminal-Bench 2.170.2%(思考) / 60.4%(非思考)長い shell ワークフロー約 10 ポイントの思考モードアップリフト
SWE-Bench Pro (Public)59.4%より困難な自律的なリポジトリレベルの修正フロンティアのクローズドモデルはまだ先行
DeepSWE v1.140.4%(思考) / 16.5%(非思考)困難な SWE ベンチマークアクティブパラメータが約 200 分の 1 にもかかわらず 9.0% の DeepSeek-V4-Pro-Max を打ち破る
SWE Atlas (Codebase QnA)46.2%大規模リポジトリを理解するDeepSWE の数値を先行
Toolathlon Verified49.7%マルチツールオーケストレーション中位

これらを読むための 3 つの解釈ルール:

  • SWE-Bench Multilingual と Terminal-Bench 2.1 は、エージェント的コーディングモデルにとって真剣に受け止めるべき数字です。 それらは実際に割り当てる仕事——「実際のリポジトリでこのバグを修正する」、「この shell ワークフローをグリーンにする」——にマッピングされます。Poolside はオープンウェイト側で両方をリードしています。
  • クローズドフロンティアは最難のベンチマークでまだ勝っています。 Claude Fable 5 と Kimi K3 は SWE-Bench Pro と一部の Toolathlon スライスでリードしています。Laguna のローンチを「Anthropic は打ち破られた」と読まないでください——「コーディングのオープンウェイトの天井が数ポイント上昇した」と読んでください。
  • 思考モードは無料ではないが、勝利のほとんどはそこにあります。 Terminal-Bench 60.4% → 70.2%、DeepSWE 16.5% → 40.4%。コストのために思考をオフにすると、モデルの大部分を放棄することになります。

Laguna を動かす​

Guided walkthrough1 of 4
  1. OpenRouter、Baseten Model Library、Vercel AI Gateway、Kilo/Cline/Hermes の統合はすべて初日からアクセスを提供しました。OpenRouter のローンチ時のリスト価格:$0.10 per M 入力、$0.20 per M 出力、評価用の無料 256K コンテキストティア付き。OpenAI 互換の chat completions エンドポイント —— ベース URL とモデル ID を交換するだけです。
  2. XS 2.1(33B/3B MoE)は GGUF と MLX の変換版があります。32〜64GB の MacBook では、llama.cpp または MLX の下で使用可能な速度で動作します。これは、コーディングアシスタントをラップトップから決して離したくない場合に使用するサイズです。
  3. 精度ごとのメモリフットプリント:BF16 ~236GB(2 台の Spark またはマルチ GPU ノードが必要)、FP8 ~118GB(シングル Spark または H200)、INT4 ~59GB(シングル Spark の 128GB 統合メモリに余裕を持って収まる)。vLLM、SGLang、Ollama すべてローンチ時にサポート。最新の NVIDIA パーツ向けに NVFP4 重みも公開。
  4. chat.poolside.ai はインタラクティブな評価のために認証なしでファミリーを提供します。エージェントに配線する前に、これを使って感覚を掴んでください。

OpenRouter 経由で Laguna S 2.1 を呼び出す(Python)

import os, openai

client = openai.OpenAI(
  base_url="https://openrouter.ai/api/v1",
  api_key=os.environ["OPENROUTER_API_KEY"],
)

resp = client.chat.completions.create(
  model="poolside/laguna-s-2.1",
  messages=[
      {"role": "system", "content": "You are a senior engineer. Reply with a unified diff, no prose."},
      {"role": "user", "content": "Fix the off-by-one in this function:\n\ndef last_n(xs, n): return xs[-n-1:]"},
  ],
)
print(resp.choices[0].message.content)

Laguna 対代替候補、いつ手を伸ばすか​

2026 年 8 月初旬時点のモデルランドスケープを考慮した実用的な判断マップ:

タスクベストピック理由
長期のリポジトリレベルのバグ修正、予算に敏感Laguna S 2.1トップのオープンウェイト SWE-Bench Multilingual、出力トークンあたり GLM-5.2 や Kimi K3 より約 12 倍安い
MacBook 上のエージェント的コーディング、オフライン必須Laguna XS 2.13B アクティブパラメータ + MLX ビルド、このサイズでこれに匹敵する SWE-Bench Multilingual に到達するものは他にない
