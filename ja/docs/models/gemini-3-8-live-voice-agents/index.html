Gemini 3.8 Live と Live Extended Thinking:Google の新しい音声モデルのビルダー向けフィールドガイド(2026年9月)

中級

2026年9月15日、Google は 2 つの speech-to-speech モデルをリリースしました:Gemini 3.8 Live(gemini-3.8-live)と Gemini 3.8 Live Extended Thinking(gemini-3.8-live-extended-thinking)です。どちらも本日から Gemini API と Google AI Studio で一般提供(GA)されています。Google のローンチ記事はほぼベンチマークとデモです。音声エージェントを構築するなら、重要な詳細は開発者向けドキュメントにあります:ツールはデフォルトで非同期に実行されるようになり、ある設定フィールドはエラーを返すようになり、ある機能はモデルが聞いている間ずっとオンで課金されます。このページはそれらの詳細を 1 か所にまとめたものです。

What you'll learn
  • マーケティング上の名前ではなく、実際の API の違いに基づいて 2 つのモデルを選び分ける
  • thinkingLevel、affective dialog、ブロッキングツールの罠にはまらずに gemini-3.1-flash-live-preview のエージェントを移行する
  • セッションの壁を前提に設計する:音声のみ 15 分、音声+映像 2 分、WebSocket 接続 1 本あたり約 10 分
  • 音声セッションの実際のコストと、コストが分数より速く増える理由を見積もる
  • API キーを漏らさずにブラウザクライアントを出荷する
最終検証: 2026-09-15。

本日リリース。モデル ID、GA ステータス、機能一覧は Gemini API changelog(2026年9月15日)より。価格は Gemini API の料金ページより。トークン制限と移行リストは gemini-3.8-live のモデルページより。Thinking、ツールスケジューリング、VAD の詳細は Live API の capabilities ガイドと tools ガイドより。セッション制限は session-management ガイドより。課金の注意点は Live API のベストプラクティスガイドより。ベンチマークとコンシューマー向け提供状況は Google のローンチ記事より。1 点の食い違い:ローンチ記事はモデルが会話中に 97 言語を検出して切り替えると述べていますが、Live API の概要ページは依然としてライブ翻訳が「70 以上の言語」をカバーすると述べています。どちらの数字を引用するにせよ、それがどの機能を指しているか先に確認してください。

次の情報源で確認してください: 公式情報源.

一文で言うと​

低レイテンシの音声エージェントのデフォルトには gemini-3.8-live を使います。発信者が難しい多段階の質問をし、短い遅延が許容できる場合には gemini-3.8-live-extended-thinking を使います。どちらも 音声入力 100 万トークンあたり $3.00(約 $0.005/分)、音声出力 100 万トークンあたり $12.00(約 $0.018/分)、テキストは $0.75 / $4.50 です。どちらも 131,072 トークンの入力ウィンドウと 65,536 トークンの出力上限を持ち、どちらも Gemini API に無料枠があります。

すべての音声出力には SynthID の透かしが入ります。あなたのプロダクトがモデルの音声を録音または再公開する場合、AI 音声検出器がそれを識別できます。

ほとんどの報道が見落としている 3 つのこと​

1. 「thinking」モデルは推論しながら話す​

Extended Thinking は考えている間に沈黙しません。Google はこれを「推論と発話を同時に行う」と説明しています。早い段階で口頭の合図(「確認しますね」)を出し、バックグラウンドで推論が続く間も進捗を語ります。これは、クライアントがモデルの完了をどう判断するかを変えます。このモデルでは turnComplete: true はセッションがアイドルであることを意味しません。バックグラウンド推論がまだ動いている可能性があります。通話を終了する、人間に引き継ぐ、次のスクリプト化されたステップを開始する前に、代わりに interaction_status(IN_PROGRESS と IDLE)を確認してください。

これは OpenAI が GPT-Live で導入したのと同じ「速く話す者、ゆっくり考える者」の分離です。違いは、Google が両方の役割を 1 つのモデルに入れているのに対し、GPT-Live は推論を別のフロンティアモデルに委譲している点です。

2. 3.1 Flash Live からのアップグレードはモデル名の文字列だけでなく挙動も変える​

gemini-3.1-flash-live-preview → gemini-3.8-live に関する Google の移行ノートには、コードの動作を変える 4 つの変更が含まれています:

  • thinkingLevel を削除する。 3.1 Flash Live のデフォルトは minimal でした。3.8 Live はこのフィールドを受け付けないため、3.1 からコピーした設定からは削除する必要があります。
  • ツール呼び出しはデフォルトで非同期になった。 3.1 Flash Live では「ツールのレスポンスを送るまでモデルは応答を開始しない」動作でした。3.8 Live では関数の実行中もモデルは話し続けます。レイテンシには良いことですが、先に完了しなければならないツール(本人確認、決済)には明示的に behavior: BLOCKING を設定する必要があります。Extended Thinking モデルにはブロッキングモードがないため、そうしたフローは自分のコード側にゲートが必要です。
  • プロアクティブ音声は常にオン。 モデルは自分に向けられていない発話には応答しないと判断できます。これはオフにできず、ベストプラクティスガイドは 聞いている間も入力トークンが課金されると述べています。
  • Affective dialog は廃止。 エージェントが発信者の口調に合わせるために enableAffectiveDialog に依存していたなら、削除して新しいデフォルトの挙動をテストしてください。

役に立つ変更が 2 つあります。send_client_content がセッション全体で機能するようになったため、通話中にテキストのコンテキスト(CRM データ、転送の記録)を注入できます。ターンカバレッジのデフォルトは TURN_INCLUDES_AUDIO_ACTIVITY_AND_ALL_VIDEO になりました。

3. 音声セッションのコストは長さより速く増える​

音声はおよそ 毎秒 25 トークン(1 分あたり約 1,500)で蓄積されます。分単価はここから来ています:1,500 × $3/1M ≈ $0.0045(入力)、1,500 × $12/1M = $0.018(出力)。罠は、各ターンが新しい音声だけでなく蓄積されたコンテキスト全体を再処理することです。ベストプラクティスガイドが直接そう述べています。その上に 2 つの小さなコストが積み重なります:文字起こしを有効にすると音声出力に加えてテキスト出力が課金され、プロアクティブ音声はモデルが聞いている間の入力トークンを課金します。

ざっくりした例示(Google の数字ではなく、こちらの計算):20 ターンの 10 分間の通話を考えます。コンテキストは 0 から約 15,000 トークンに成長するので、平均的なターンは約 7,500 トークンの入力を再読します。これは約 150,000 入力トークン(約 $0.45)で、新しい音声だけを数えた場合の約 $0.045 と比べて大きな差です。長い通話は合計だけでなく、分あたりのコストも高くなります。 15 分の壁を越えるためにいずれにせよ必要なコンテキストウィンドウ圧縮は、このコスト増も抑えます。

セッションの壁と、それを前提にした設計​

Guided walkthrough1 of 6
  1. 圧縮なしでは、音声のみのセッションは 15 分、音声+映像のセッションは 2 分で停止します。それとは別に、各 WebSocket 接続は約 10 分で切れます。2 分の映像制限は、ほとんどの画面共有デモに引っかかります。
  2. スライディングウィンドウとトークンのトリガー閾値を指定して ContextWindowCompressionConfig を設定します。これによりセッション長の制限がなくなり、ターンごとの入力コストが際限なく増えることも止まります。トリガーは意図的に選んでください:圧縮は最も古いターンを破棄するので、エージェントが必ず覚えておくべきこと(ポリシー、発信者の身元)はシステム指示に固定するか、send_client_content で再送してください。
  3. SessionResumptionConfig を設定し、各 SessionResumptionUpdate から最新のハンドルを保存します。ハンドルはセッション終了後 2 時間有効なので、切断された接続は新しい通話を始めるのではなく状態を引き継いで再開できます。
  4. サーバーは切断前に timeLeft フィールド付きの GoAway を送ります。その時間を使って現在の文を言い終え、再開ハンドルで再接続すれば、発信者は途切れを聞くことがありません。
  5. サーバーが割り込み(barge-in)を通知したら、クライアント側の再生バッファを即座にクリアしてください。さもないと、発信者はモデルがすでに放棄した文を最後まで話すのを聞くことになります。
  6. 入力は 16 kHz リトルエンディアンの raw 16 ビット PCM、出力は 24 kHz の 16 ビット PCM です。マイク入力(通常 44.1 または 48 kHz)を 16 kHz にリサンプリングし、20〜40 ms のチャンクで送ってください。大きなバッファは、どのモデルにも取り除けないレイテンシを加えます。

ブラウザとモバイルのクライアント:API キーは絶対に出荷しない​

Live セッションはクライアントが Google に直接接続するときに最もよく機能します。リアルタイム音声を自分のバックエンド経由でプロキシするとレイテンシが増えるからです。これを安全に行う方法が エフェメラルトークンです。サーバーが発行し、クライアントが 1 回使います。デフォルト:トークンは作成から 30 分で失効し、1 分以内に新しいセッションを開始するために使う必要があり、1 回の使用が許可されます。liveConnectConstraints で特定のモデル、レスポンスモダリティ、再開設定にロックできるので、盗まれたトークンを他の用途に使うことはできません。エフェメラルトークンは Live API でのみ、かつ v1beta でのみ機能します。

gemini-3.8-live 向けシステム指示の骨格(非同期ツール、常時オンのプロアクティブ音声)

You are Ava, a voice assistant for Northwind Travel. You are SPEAKING, not writing.
RESPOND IN ENGLISH. YOU MUST RESPOND UNMISTAKABLY IN ENGLISH.

Style:
- Short sentences, one idea each. Never read lists, markdown, or URLs aloud.
- If speech is clearly not addressed to you (TV, side conversation), stay silent.

Tools:
- lookup_booking: invoke ONLY after the caller has given BOTH booking reference AND last name.
- While a lookup is running, tell the caller you are checking. Do not guess the result.
- change_booking: before invoking, read back the exact change and wait for a clear spoken "yes".

Safety:
- Repeat back every number, date, and name before acting on it.
- If audio is unclear, say what you think you heard and ask.
- Anything involving refunds or payment details: offer a human agent instead.

この骨格は Live エージェントに関する Google 自身のガイダンスに従っています:出力言語を大文字で明示し、各ツールにいつ呼ぶべきかの正確な条件を与えます。2 つ目のルールは非同期ツールではより重要です。ツールの実行中もモデルは話しており、そうしないよう指示しなければ沈黙を推測で埋めてしまうからです。

Gemini 3.8 Live と代替案の比較​

  • Claude との比較。 Claude の音声機能はターンベースのままです:Claude アプリの音声モード、Claude Code のプッシュトゥトーク。よくあるハイブリッドは、Live モデルを会話のフロントエンドにし、重い推論やコーディングのために Claude をツールとして呼ぶ構成です。非同期関数呼び出しはこのパターンによく合います。ツールの実行中も通話を続けられるからです。
  • OpenAI との比較。 GPT-Live は音声ネイティブの全二重 ChatGPT プロダクトです。開発者向けには、OpenAI の提供物は Realtime API 上の gpt-realtime です(全体像は 全二重音声 AI を参照)。
  • 初期のコミュニティ報告(Hacker News のローンチスレッド、未検証)。 コメント投稿者はレイテンシ、音声品質、アクセントの処理、ライブ翻訳を称賛しました。一方で Extended Thinking の推論が一貫しない、エージェント的なフローでモデルが「追加の要件を勝手に作り出す」と述べる人もいました。これらは測定ではなく逸話ですが、35.1% の banking スコアと整合しています:信頼する前に、自分のタスクをエンドツーエンドでテストしてください。

Key takeaways
  • GA モデルが 2 つ、価格は 1 つ:gemini-3.8-live は低レイテンシのデフォルト;gemini-3.8-live-extended-thinking は話し続けながらバックグラウンドで推論する。
  • 3.1 Flash Live からの移行は挙動を変える:thinkingLevel を削除し、完了必須のツールを BLOCKING にし、常時オンのプロアクティブ音声(聞いている間も課金)を想定し、affective dialog を捨てる。
  • 制限は最初から計画に入れる:音声のみ 15 分、音声+映像 2 分、接続 1 本あたり約 10 分。圧縮、再開ハンドル、GoAway の処理は本番に必須。
  • すべてのターンがコンテキスト全体を再読するため、コストは通話の長さより速く増える。圧縮はセッション長の対策であると同時にコストの対策でもある。
  • 音声による銀行業務タスクでの Google の最高スコアでさえ 35.1%。お金やデータを動かすものには必ず口頭の確認ゲートを置く。
