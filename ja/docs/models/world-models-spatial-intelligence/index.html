ワールドモデル:今日、実際に作れるもの

中級

2026 年 9 月 28 日、AMD は World Labs を株式で約 82 億ドルで買収すると発表しました — Xilinx に次ぐ、同社史上 2 番目に大きな取引です。そして Fei-Fei Li が executive vice president 兼 chief scientist として Lisa Su の直属で参加します。その翌日には OpenAI の DevDay が トップページを占めました。この 2 つで、「ワールドモデル」は今週の言葉になりました。

この言葉には問題があります。それを共有する 2 つのプロダクトは、アーキテクチャ的に正反対 なのです。一方は世界をモデルの内側に保ち、あなたが動くたびにフレームをストリーミング します。インタラクティブで、エクスポートできず、セッションは秒単位で打ち切られます。 もう一方は、ダウンロードして所有し自分で無料でレンダリングできる 3D シーンを生成します。 永続的で、エンジンにすぐ載せられて、完全に不活性です。間違ったほうを選ぶのは好みの 間違いではなく、再アーキテクチャです。

このページは実務的な切り分けです。それぞれのファミリーが実際に何を出力するのか、検証済みの API とエクスポートの詳細、よくある思い込みに決着をつける唯一のベンチマーク、自分の GPU で 動かせるオープンウェイト、そしてどちらのファミリーもやってくれない 5 つのこと。

What you'll learn
  • ワールドモデルの 2 つのファミリーを見分け、何を永続させたいかで選ぶ
  • 本当の限界を知る:60 秒の壁、物理の免責事項、商用権を左右するエクスポートのティア
  • World API を正しく読む — 非同期オペレーション、WLT-Api-Key ヘッダー、そしてどの splat 形式が出てくるか
  • 動画モデルと 3D モデルのどちらを選ぶかで、雰囲気ではなく WorldScore の証拠を使う
  • オープンなワールドモデルを自分で動かし、なぜ inverse dynamics が 82 億ドルに値する部分なのかを理解する
最終検証: 2026-09-30。

取引条件は AMD 自身のニュースルームのリリースより:およそ 82 億ドル、全額株式、2026 年 9 月 28 日発表、規制当局の承認を条件に 2026 年末までにクローズ見込み — つまりまだ クローズしておらず、クローズ後にプロダクトのロードマップは動きうるということです。 Project Genie のアクセス条件、Marble のプランのティア、World API の価格はいずれも予告なく 変わる商用サーフェスです。Genie 3 の解像度とフレームレートの数値は Google の Project Genie の投稿ではなく第三者の報道から来ており、Google の投稿が述べているのは 60 秒の生成上限 だけです。WorldScore のリーダーボードの順位はチームが投稿するたびに動きます。ここにある 数値を引用する前に、リンク先の一次情報を読んでください。

反応する世界が必要なら — プレイヤーがキーを押す、ロボットのポリシーが行動を取って何が 起きるかを見る — フレーム生成器が必要です。永続する世界が必要なら — ゲームの中の アセット、レンダーパイプラインのセット、来月 5 人のユーザーが読み込んで同じものを見る シーン — 3D 生成器が必要です。この話題での「なぜ単に…できないのか」という混乱した質問の ほぼすべては、片方を手にしながらもう片方を求めている人によるものです。

フレーム生成器と、60 秒の壁​

Google の Project Genie は 2026 年 1 月 29 日に研究プレビューから半ば公開の プロダクトになりました。アクセスの形は狭く、それを前提に計画を立てる前に知っておく価値が あります:Google AI Ultra の加入者、米国のみ、18 歳以上、そして Google AI Ultra for Business では明示的に利用不可。Google 自身はこれを「実験的な研究プロトタイプ」と 呼んでいます。

最も多くを教えてくれる制限は Google 自身のもの:生成は 60 秒に制限される。 これは課金の 判断ではなく、状態の問題です。フレーム生成器では世界はどこにも保存されていません — それは モデルのコンテキストによって含意されているのです。すべてのフレームは、プロンプトと蓄積された フレームとあなたの行動から予測されます。したがって一貫性は、長いチャットを縛るのと同じもの、 つまりモデルがどれだけの履歴を保持して整合させられるかによって縛られます。壁から離れて また戻ったとき、その壁がまだそこにあるかどうかは記憶の問題であって、レンダリングの 問題ではありません。

Google が明記している注意書きが、正直なスペックシートの残りです。生成された世界は 「完全に実物そっくりに見えるとは限らず、プロンプトや画像、現実世界の物理に常に忠実に従うとは 限らない」、そしてキャラクターは「ときに制御しづらかったり、制御のレイテンシが高くなったり する」。

フレーム生成器をシミュレータとして使うつもりだったなら、この物理の一文を注意深く読んで ください。これは解くエンジンではなく、もっともらしさのエンジンです。フレーム 300 と フレーム 301 のあいだで運動量が保存されることを保証するものは何もありません。

誰も触れないフレーム予算​

一般に報じられている 24 fps でのインタラクティブ生成は、あなたの入力がサーバーに届くまでを 含めて、エンドツーエンドで1 フレームあたり約 41.7 ms です。この 1 つの数字が、この ファミリーのプロダクト上の判断のほとんどを説明します。なぜセッションが短いのか、なぜ アクセスが有料ティアに絞られているのか、なぜまだ公開 API がないのか、そしてなぜコスト曲線が アセットあたりではなく視聴者の秒あたりなのか。あなたが買っているのはファイルではありません。 誰かが見ているあいだじゅう 42 ミリ秒の締切を守り続けなければならない GPU を借りているのです。

3D 生成器と、実際に受け取るもの​

World Labs の Marble は、テキスト、画像、パノラマ、複数視点、あるいは動画クリップを、 移動可能な 3D シーンに変えます。重要なエンジニアリング上の事実は、その表現です。出力は メッシュではなく 3D Gaussian splat です。

splat は、色と視点依存のシェーディングを持つ、小さく向きのある半透明の粒が何百万個も 集まったものです。写真からの再構成が非常に美しく、コモディティ GPU で高速にレンダリング できます。そして表面も、辺も、面も持ちません — 次のセクションが見た目以上に重要なのは そのためです。

Marble 自身のエクスポートのドキュメントが言う、受け取れるもの:

エクスポート利用条件
Gaussian splat — SPZ と PLYStandard プラン
360 パノラマStandard プラン
コライダーメッシュStandard プラン
テクスチャ付きメッシュ(GLB)+ 商用権Pro プランのみ
そもそも何であれFree では不可 — 生成のみ

この表には落とし穴が 2 つ潜んでいます。第一に、コライダーメッシュは別のエクスポート です — splat に対しては直接レイキャストも衝突も物理も行えないので、これが必要になります。 プレイヤーが見るのは splat で、エンジンが判定にかけるのはコライダーメッシュです。splat だけ 出荷すれば、美しい世界に床がありません。第二に、商用権は Pro ティアに紐づいており、 エクスポートするという行為に紐づいてはいません。生成した世界をプロダクトに入れる前に プランを確認してください。

Marble のドキュメントはまた、低解像度のエクスポートが「より高解像度のファイルと知覚的に できるだけ似るよう最適化されている」とも述べています — 大きいほうを出荷するために支払う前に、 小さいティアをテストすべきだというヒントです。

SPZ:World Labs のものではない 10 倍​

いくつかの記事が取り違えている点:SPZ は Niantic の形式であり、Niantic Spatial が オープンソース化したもので、World Labs の発明ではありません — Marble は単にそれに エクスポートしているだけです。それでも使う価値はあります。SPZ は各球面調和係数を 8 ビットの 符号付き整数として格納し、さらに任意で量子化でき、知覚できる品質低下なしに同等の PLY より およそ 10 倍小さくなります。Niantic 自身のテストでは、ほとんどのシーンで約 5 ビットが スイートスポット、8 ビットで MSE は実質ゼロ、3 ビットで約 18 倍の圧縮とされています。 2026 年にリリースされた SPZ 4 は、圧縮を属性クラスごとに 1 本ずつ、6 本の並列 ZSTD ストリームに分割し、同じ約 10 倍のサイズ優位性のまま圧縮がおよそ 3〜5 倍高速、 エンドツーエンドの読み込みが 1.5〜2 倍高速になりました。

splat をウェブで配信するなら、これは「読み込めるシーン」と「読み込めないシーン」の差です。

API を、本当のところ​

World API は Marble の生成をあなた自身のコードに公開します。World Labs のドキュメント 索引と公式 Python クライアントから確認できる形:

  • 入力:テキスト、画像、パノラマ、マルチビュー入力、動画。
  • 出力:SPZ、PLY、SOGS、KSPLAT、SPLAT 形式の splat。
  • 認証:WLT-Api-Key ヘッダーで渡す API キー。Python クライアントは環境変数から WORLDLABS_API_KEY を読みます。
  • 実行モデル:非同期。生成を投入するとオペレーションが返り、完了するまで ポーリングします。クレジット残高のエンドポイント、メディアのアップロード/取得、 world の作成/取得/一覧/エクスポート/削除もあります。
  • クライアント:worldlabsai/worldlabs-api-python、Python 3.12+。CUDA GPU が必要 なのはローカルレンダリングのときだけで、API 利用には不要です。
  • 価格:従量課金。

テキストから world を生成し、ポーリングする

# github.com/worldlabsai/worldlabs-api-python  (Python 3.12+)
# export WORLDLABS_API_KEY=...

from worldlabs_api.client import WorldLabsClient
from worldlabs_api.models import WorldTextPrompt, WorldsGenerateRequest

client = WorldLabsClient(api_key="your-key-here")

request = WorldsGenerateRequest(
  display_name="Mystical Forest",
  world_prompt=WorldTextPrompt(text_prompt="A mystical forest"),
)

op = client.generate_world(request)      # returns an operation, not a world
done = client.poll_operation(op.operation_id)   # poll until done is true
world = done.response

初日からその非同期の境界を前提に統合を設計してください。world の生成はリクエストではなく ジョブです — バッチ推論や動画生成と同じ教訓です。ハンドラが world をインラインで待つなら、 書き直すことになります。

ゲームエンジンなしでレンダリングする​

World Labs は Spark も維持しています。THREE.js / WebGL2 向けの MIT ライセンスの 3D Gaussian splatting レンダラーで、生成された world をウェブページとして出荷できます。 .PLY、.SPZ、.SPLAT、.KSPLAT、.SOG を読み込み、THREE.js のパイプラインで splat を 通常のメッシュと融合し、WebGL2 を備えた約 98% のデバイスを対象にします。

Spark 2.0(2026 年 4 月 15 日)は、大きなシーンをブラウザで成立させるリリースです。 シーンのサイズに関係なくフレームあたり一定数の splat をレンダリングする LoD の splat ツリー、HTTP Range リクエストに対応してまず粗いプロキシがほぼ即座に現れ、 段階的に精細化されるストリーミング形式 .RAD、そして固定の GPU メモリプールに対する 仮想 splat ページングにより、GPU メモリより大きなシーンも — スマートフォンや Quest 3 でも — レンダリングできます。

生成した world をウェブに載せる

npm install @sparkjsdev/spark three
# docs and live examples: https://sparkjs.dev

いまコスト曲線に何が起きたかに注目してください。生成のあとは、CDN から静的ファイルを 配信し、ユーザーの GPU でレンダリングしています。world を配信するのは無料です。 これは 視聴者の秒ごとが推論であるフレーム生成器のモデルの、ちょうど裏返しです。

証拠:WorldScore​

「動画モデルを使えばいい」はこの領域で最もよくある近道であり、いまやそれに答える ベンチマークがあります。WorldScore(Stanford、arXiv:2504.00983)は、3D、4D、 text-to-video、image-to-video のモデルを横断する world 生成の統一ベンチマークです — 約 3,000 例、制御性・一貫性・知覚品質・動きの指標を備え、明示的な 3D 一貫性と カメラ制御の測定を含みます。

判断を変えるべき結果:WorldScore-Static では、専用の 3D シーン生成器が先行しています — WonderWorld が 72.69、LucidDreamer が 70.40 で、動画モデルより明確に上です。 幾何学的に一貫した世界の中をカメラで動きたいのが要件なら、個々のフレームの見栄えが良くても 動画モデルは間違った道具です。

注意点が 2 つ。リーダーボードは生きており、チームが投稿するたびに動きます。そして WorldScore-Static は名前のとおりのものを測っています — 静的な世界であり、静的な一貫性が 強いことは動特性について何も教えてくれません。

オープンウェイト:Cosmos 3 と、AMD が実際に買ったもの​

world モデルを持つのにベンダーの API は必要ありません。NVIDIA は物理 AI 向けのオープンな omnimodel である Cosmos 3 を、Hugging Face 上の重みとともに公開しました:

モデルサイズ動作環境
nvidia/Cosmos3-Edge4Bエッジデバイス、ロボット、ビジョンエージェント
nvidia/Cosmos3-Nano16B = 8B reasoner + 8B generatorワークステーション級、例: RTX PRO 6000
nvidia/Cosmos3-Super64B = 32B reasoner + 32B generatorHopper / Blackwell、大規模な合成データ

アーキテクチャ的には、テキスト、画像、動画、音声、そして行動を 1 つのモデルで扱う Mixture-of-Transformers であり、推論のための自己回帰サブシーケンスと生成のための拡散 サブシーケンスを組み合わせています。Hugging Face Diffusers に組み込まれているので、 入口は普通の Python です。

オープンなワールドモデルをローカルで動かす

pip install --upgrade diffusers transformers accelerate

# Cosmos3-Nano is 16B (8B reasoner + 8B generator); check the model
# card on Hugging Face for the licence and the exact torch version
# before you build on it.

import torch
from diffusers import Cosmos3OmniPipeline

pipe = Cosmos3OmniPipeline.from_pretrained(
  "nvidia/Cosmos3-Nano", torch_dtype=torch.bfloat16
)

さて、価格の理由を説明する部分です。Cosmos 3 のタスク表は動画の小技の一覧ではありません:

入力出力それが何か
テキスト / 画像 / 動画動画動画生成
テキスト / 動画テキスト視覚言語推論
行動 + 画像 + テキスト動画forward dynamics — 「これをしたら、何が起きる?」
テキスト + 動画行動inverse dynamics — 「どんな行動がこれを生んだ?」
画像 + テキスト動画と行動ポリシー生成

inverse dynamics が静かな主役です。これは映像をラベル付きの行動に変えます — つまり 普通の動画がロボットの学習データになり、生成された world がハードウェアなしでポリシーを 学習・評価する場になるということです。AMD 自身のリリースは World Labs を「インタラクティブな 3D 環境を生成・再構成・シミュレートする」モデルを作る企業と表現し、加えて「ロボット学習と シミュレーション」の技術にも言及し、推論・ロボティクス・シミュレーション・物理 AI が同社の 将来のシリコンロードマップに情報を与えるという枠組みでこの取引を語っています。

グラフィックスの物語ではなく計算の物語として読むと、学習環境のフライホイールへの 82 億ドルは、 text-to-3D ツールへの 82 億ドルとは別種の賭けです。

ワールドモデルがやってくれない 5 つの仕事​

Guided walkthrough1 of 5
  1. chain-of-thought も XML タグもツール利用のテクニックも、どれも持ち越せません。ワールドモデルを条件づけるのは、アシスタントに指示することよりカメラを演出することに近いのです。重要なのは入力画像、視点、記述された照明、そして行動の並びです。唯一転移する習慣は素材への規律 — きれいで構図の良い条件づけ画像は、凝った一段落に勝ります。
  2. Google は、生成された世界が現実世界の物理に従わない可能性があるとはっきり述べています。Cosmos 系の forward dynamics はもっともらしい次の観測を予測するのであって、それを解くこととは違います。ワールドモデルはシナリオを生成するために使い、それを裁定するのは本物の物理エンジンにさせてください。間違った答えが金銭や安全のコストになるなら、ループの中にソルバーが必要です。
  3. Gaussian splat には表面がありません。レイキャスト、キャラクターコントローラー、ナビメッシュ、物理はすべてジオメトリを必要とし、だからこそ Marble はコライダーメッシュを別途エクスポートし、高品質なテクスチャ付き GLB を Pro ティアに置いています。world あたり 2 つのアセット — 見えるものと、ぶつかるもの — を計画に入れ、実際に支払うティアでメッシュのエクスポートを予算化してください。
  4. ファイルが存在しません。世界はセッションの長さだけ存在して消え、同じプロンプトを再実行すれば別の世界になります。これは永続的な状態の上に成り立つワークフロー全体を排除します:レベルをレビューする、そこに修正を出荷する、2 人のユーザーが同じシーンを読み込む、シーンが変わっていないことをテストでアサートする。そのどれかが必要なら、エクスポート可能なジオメトリが必要です。
  5. エクスポートの表がライセンスです。Free は生成できてもエクスポートは一切できず、splat・パノラマ・コライダーは Standard、テクスチャ付きメッシュと商用権は Pro にあります。オープンウェイトの場合の同等の手順は、出荷したあとではなく前に Hugging Face のモデルカードのライセンスを読むことです。このリストの中で回避するのが最も安く、遅れて気づくと最も高くつく失敗です。

一度で選ぶ​

  • ゲームやプロダクトのアセット、複数ユーザー、明日も同じに見える必要がある → 3D 生成器。 ウェブなら SPZ、エンジンなら GLB でエクスポートし、コライダーを忘れずに。
  • インタラクティブな探索、ユーザー 1 人、目新しさが目的 → フレーム生成器。60 秒の セッションの内側で設計する。
  • ポリシーの学習または評価 → forward と inverse の dynamics を持つオープンウェイトを 自分の GPU で。安全に関わるものには本物のシミュレータを添えて。
  • 一貫したシーンの中を動くカメラ → 動画モデルではありません。WorldScore がそう言って います。
