DeepSeek-V4.1-Flash: DeepSWE で Opus 5 と並ぶ 1M コンテキストのオープンウェイト (2026年9月)

中級

2026年9月10日 04:00 UTC、DeepSeek は API を新モデルに切り替え、同日にウェイトを公開した: DeepSeek-V4.1-Flash、deepseek-flash として提供される。これは新しいアーキテクチャファミリーの最小メンバーだが、小さなモデルではない: 5,520 億パラメータ、100 万トークンのコンテキスト、ネイティブビジョン、そして 1 トークンあたり 890 バイト の KV キャッシュ。Google と Anthropic の両方が今や看板に掲げる長期ソフトウェアエンジニアリングベンチマーク DeepSWE v1.1 で、DeepSeek は 74.2 を報告しており、Claude Opus 5 を 0.2 ポイント上回る。Terminal-Bench 4.0 では Opus 5 の 51.8 に対して 31.2 を報告している。両方の数値は真実であり、その差こそが物語のすべてだ。

このページは Claude ユーザーのためのフィールドガイドである: 実際に何が変わったのか、すべての deepseek-v4-pro リクエストを静かに付け替えたルーティング変更、努力ダイヤルとそれが請求額に与える影響、ウェイトの実行方法、そして Claude が依然として正しい選択であるワークロード。

What you'll learn
  • V4.1-Flash のローンチ数値を正しく読む: DeepSWE では Opus 5 と同点、Terminal-Bench では大きく後れ、そしてその分裂が矛盾ではない理由
  • 新しい Causal Encoder-Decoder + CSA2 設計を理解し、890 バイトの KV キャッシュが何をもたらすか (そして DeepSeek がまだ特性評価していないと言っていること) を知る
  • 1–100 の reasoning_effort ダイヤルを意図的に使う — 25 対 100 は約 2.5 倍の出力トークンで DeepSWE 8 ポイントの差
  • 正直なコスト計算をする: ピーク $0.30 / $1.20、オフピークはその半分、オフピークのキャッシュヒットは 100 万あたり $0.003 — そしてどのレートを支払うかを決める UTC ピーク時間帯
  • 9月14日のルーティング変更を知る: deepseek-v4-pro は V4.1-Pro が出荷されるまで静かに V4.1-Flash を提供する
  • 提供パス (ホスト API、vLLM、SGLang、Docker Model Runner) と DeepSeek が推奨するサンプリングデフォルトを選ぶ
最終検証: 2026-09-15。

モデル ID、ルーティング日付、価格は DeepSeek の 9月10日の発表と API 価格ページ から。アーキテクチャ、ライセンス、推論努力の範囲、サンプリングデフォルトは Hugging Face モデルカード から。Claude Opus 5 および GPT-5.6 Sol とのベンチマーク比較は、9月10日に VentureBeat が報じた DeepSeek 自身のローンチ表であり、独立したハーネスが公開されるまではベンダー実施のものとして扱うこと。3.0/4.0 の Terminal-Bench の差も同じ表から。アーキテクチャに「まだ完全には特性評価していない堅牢性の境界」があるという DeepSeek の声明は、同じ報道からの引用である。

次の情報源で確認してください: 公式情報源.

一文で言うと​

V4.1-Flash は DeepSeek 初の 新アーキテクチャ (Compressed Sparse Attention 2 を備えた「Causal Encoder-Decoder」) 上のモデルで、MIT ライセンスで公開され、ネイティブビジョン、1M トークンウィンドウ、最大出力 384K、そして 1 から 100 まで連続的に制御可能な推論努力 を備える。V4 時代のすべての Flash エンドポイントを即座に置き換え、9月14日 からは V4.1-Pro が登場するまで、すべての deepseek-v4-pro 呼び出しにも Flash 価格で応答する。

Claude ユーザーが見逃してはならない 3 つのこと​

1. DeepSWE の同等性と Terminal-Bench の劣勢は同じ事実を二度見ているにすぎない​

DeepSeek のローンチ表のうち、エージェント開発チームにとって重要な列:

ベンチマークDeepSeek-V4.1-FlashClaude Opus 5GPT-5.6 Sol
DeepSWE v1.1 (解決率)74.274.073.0
Terminal-Bench 3.030.043.3—
Terminal-Bench 4.031.251.8—
CyberGym88.1——
AutomationBench54.8——

DeepSWE は、リポジトリを読み、パッチを計画し、それを適用するモデルに報いる: 長いコンテキスト、慎重な検索、少数の大きな編集。Terminal-Bench は、各判断が直前のツール結果に依存する、多数の短く適応的なシェルターンに報いる。V4.1-Flash は 1M トークンのコンテキストと安価なキャッシュを持つので、前者の形状に適している。プリフィル時に 8B、デコード時に 16B のアクティブパラメータ で動作しており、これは密な最先端モデルに比べて「ステップあたりの思考量」がはるかに少ないため、後者の形状では苦しむ。あなたの仕事がプルリクエストのように見えるなら、同等性の主張は信頼でき、評価する価値がある。あなたの仕事が対話型のターミナルセッションのように見えるなら、20 ポイントの Terminal-Bench の差が予算を組むべき数値だ。同じ分裂は一週間前の Google の Gemini 3.8 Flash のローンチでも、同じアーキテクチャ上の理由で現れている。

ベースモデルの行はより静かな物語を語る: MMLU-Pro 74.1 (V4-Flash 68.3、V4-Pro 73.5)、HumanEval 79.4 (V4-Flash 69.5)、GSM8K 93.0 (V4-Flash 90.8)。新しい「Flash」は先月の「Pro」よりも優れたベースであり、これが DeepSeek が Pro のトラフィックをそこへルーティングすることに抵抗がなかった理由だ。

2. 推論努力ダイヤルは本物のダイヤルであり、請求額に直結する​

Claude の effort (low/medium/high/max) とは異なり、V4.1-Flash は 1 から 100 の整数 を公開している。DeepSWE v1.1 における DeepSeek 自身のアブレーション: effort 25 は 66.0%、effort 100 は 74.2% をスコアし、最高設定は およそ 2.5 倍の出力トークン を出力する。また、60–80 の帯域は最大努力の精度の大部分を半分未満のトークン予算で提供する とも述べている。上のすべてのベンチマーク行は reasoning_effort=100 で実行された。つまり同等性の数値は高価な数値だ。まず 100 で再現し、次に自分の評価がまだ合格する最も安い設定まで下げていく。これは 推論モデルの比較 で Gemini の thinking_level と Claude の effort に対して推奨しているのと同じ規律である。

3. クライアント側の変更なしに 2 つのルーティング変更が起きた​

  • 9月10日 から、deepseek-v4-flash と deepseek-v4-flash-vision-exp は V4.1-Flash にルーティング され、Flash レートで課金される。V4-Flash-Vision-Exp ページの数値は、今やホストされたエンドポイントではなくオープンウェイトを記述するものになった。
  • 9月14日 04:00 UTC から、すべての deepseek-v4-pro リクエストも「V4.1-Pro がローンチするまで」Flash レートで V4.1-Flash にルーティング される。

deepseek-v4-pro に固定した評価があるなら、あなたの本番モデルは日曜日の朝に足元で変わった。スイートを再実行すること。利点は同じ呼び出しが今や Pro レートのおよそ 4 分の 1 のコストになることで、欠点はあなたがチューニングした Pro 固有の挙動が消えたことだ。これはまさに、プロバイダがモデル ID をエイリアスする際に モデル間でのプロンプトの移植 が警告する失敗モードである。

モデルカードの概要​

KV キャッシュの行がアーキテクチャ上の見出しだ。1 トークンあたり 890 バイトなら 1M トークンの会話でもキャッシュは 1 ギガバイト未満であり、これが DeepSeek が 72 時間のキャッシュ寿命を約束し、キャッシュヒットを 1 セントの数分の一で価格設定できる理由である。同じ問題に対する Anthropic の答えは Claude Fable 5.1 でのより安いキャッシュ読み取りレートで、DeepSeek の答えはキャッシュを物理的に小さくすることだ。どちらも同じ習慣へと導く: 安定したプレフィックスを先頭に置き、実行中に決して編集しないこと。プロンプトキャッシング を参照。

価格: ピーク時間の罠​

DeepSeek は 2 段階のレート表を維持している。ピーク時間は月曜から金曜の 01:00–04:00 および 06:00–10:00 UTC; それ以外はすべてオフピークで、ピークレートのちょうど 半額 である。

100 万トークンあたりピークオフピーク
入力、キャッシュヒット$0.006$0.003
入力、キャッシュミス$0.30$0.15
出力$1.20$0.60

ここから 2 つのことが導かれる。第一に、「100 万あたり $0.003」という見出しは オフピークのキャッシュヒット 価格であり、6 つのセルのうち最も安いものだ; ピーク時間のコールドなエージェント実行は入力でその 100 倍を支払う。第二に、ピーク時間帯は UTC で定義されており、ヨーロッパの朝と米国の深夜の終わりをカバーしている。09:00 UTC にスケジュールされたバッチジョブは、同じジョブを 11:00 UTC に実行する場合の 2 倍を支払う。ずらせるならずらすこと。これらのセルを Anthropic、OpenAI、Google の定価と並べるフレームワークには プロバイダ横断の AI コスト を使い、現在の Claude の定価は モデルと価格 にある。

自分で実行する​

ほとんどの人にはホスト版が正しい: モデルは巨大で、API はこのページで最も安いものだ。データがネットワークの外に出せない場合、あるいはレート制限なしに努力ダイヤルと 1M ウィンドウを使いたい場合にセルフホストすること。

Guided walkthrough1 of 5
  1. BF16 の 552B パラメータは 1 テラバイトを超えるウェイトになる; F8_E4M3 と I8 の safetensors はそれを半分または 4 分の 1 にするが、それでもマルチ GPU ノードが必要だ。Kimi K3 や Colibrì クラスの MoE をまだ運用していないなら、ピーク $0.30 / $1.20 のホストエンドポイントが償却したハードウェア費用を上回る。Kimi K3 をローカルで実行する のハードウェア計算を参照。
  2. vLLM、SGLang、Docker Model Runner、Transformers の 4 つが挙げられている。カードには Jinja チャットテンプレートが同梱されておらず、カスタムのエンコーディング実装を使用しているため、プロンプト形式を手作りするのではなく、リポジトリの inference フォルダにあるリファレンスコード (または deepseek-recipe ツールキット) を使うこと。
  3. temperature 1.0、top_p 0.95 または 1.0、コンテキストウィンドウ 1M。これらはベンチマーク行が生成された設定だ。Claude 向けに調整した temperature 0.2 を盲目的に移植しないこと。
  4. まず自分の評価で DeepSeek の数値を再現する。次に 80、60、40 を試し、精度と出力トークンを記録する。ほとんどのチームはベンダー自身が指し示す 60–80 の帯域に落ち着くだろう。
  5. DeepSeek は新アーキテクチャにまだ完全には特性評価していない堅牢性の境界があると述べており、特に非常に長いコンテキストでのスパース検索がそれに当たる。実際に使うコンテキスト長で needle-in-haystack とマルチホップ検索のテストを実行すること。1M という数値は約束ではなく上限として扱うこと。

V4.1-Flash を選ぶべきとき、Claude に留まるべきとき​

Pro tip
  • V4.1-Flash を選ぶ: DeepSWE のように見えるリポジトリ規模のコーディングタスク (多く読み、少し編集する) で、effort 60–100 で実行でき、解決した issue あたりのコストがそれでも Claude を桁違いに下回る場合。
  • V4.1-Flash を選ぶ: 1M トークンウィンドウと数日間温かいキャッシュを必要とするあらゆるもの — 72 時間のグローバルキャッシュ寿命と 1 トークンあたり 890 バイトの KV により、『コードベース全体をコンテキストに保つ』ことが安価になる。
  • V4.1-Flash を選ぶ: MIT ライセンスが重要で、すでにマルチ GPU の MoE スタックを運用しているセルフホストまたはデータレジデンシーのワークロード。
  • Claude に留まる: 対話型ターミナルエージェントと、多数の短いターンからなるあらゆるループ。20 ポイントの Terminal-Bench 4.0 の差 (31.2 対 51.8) はノイズではなく、それはほとんどの実際の Claude Code セッションの形状だ。
  • Claude に留まる: Anthropic のツール使用ループ、プリフィルされたアシスタントターン、構造化出力の厳密性、あるいはファーストパーティ API の安全性と保持の保証を必要とする作業。DeepSeek API は OpenAI 形式であり、モデルには文書化された、特性評価されていない長文コンテキストの失敗モードがある。
  • 両方をクロスチェックする: コーディングエージェントなら、DeepSeek の effort=100 と Claude のデフォルト effort で自分の評価を実行し、次にそれぞれで合格する最も安い設定で実行する。ベンダーの表は最大努力で実行されたものであり、あなたの請求額はそうではない。

このリストの背後にある持続的なフレームワークは モデルの選び方。Anthropic 形式と OpenAI 形式の API 間でプロンプトを移動する際に何が変わるかは モデル間でのプロンプトの移植。これらの比較の基準となる Claude 側のリファレンスは Claude Fable 5.1 と Opus 5。

Key takeaways
  • V4.1-Flash はリポジトリ形状のモデルだ: DeepSWE では Opus 5 と同等、Terminal-Bench 4.0 では 20 ポイントの劣勢。多く読み、少し編集する作業に合わせること。
  • 1–100 の努力ダイヤルが価格のレバーだ。すべてのローンチ数値は 100 でのもの; DeepSeek 自身のガイダンスは、60–80 が半分未満のトークンで精度の大部分を維持するというものだ。
  • 価格セルは 1 つではなく 6 つ。$0.003 の見出しはオフピークのキャッシュヒット入力; ピーク時間のコールドなトークンはその 100 倍。ピークは平日の 01:00–04:00 および 06:00–10:00 UTC。
  • 2 つの静かなルーティング変更: 9月10日に V4-Flash エンドポイント、9月14日に deepseek-v4-pro。Pro に固定していたなら、モデルは変わった — 評価を再実行すること。
  • 890 バイトの KV キャッシュと 72 時間のキャッシュ寿命により、長寿命の 1M トークンコンテキストは安価になるが、DeepSeek 自身が長文コンテキストのスパース検索を特性評価されていないと指摘している。信頼する前にテストすること。
