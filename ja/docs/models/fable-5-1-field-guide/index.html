Claude Fable 5.1:何が変わり、どう移行するか

中級

2026 年 9 月 1 日、Anthropic は Claude Fable 5.1(claude-fable-5-1)と、その Glasswing 限定の双子である Claude Mythos 5.1(claude-mythos-5-1)を出荷しました。発表をざっと流し読みすると「Fable の改良版」と片付けて先に進みたくなるでしょう。やめてください。これは、単純なモデル ID の差し替えが本番環境で 400 を返しうる初めての Claude ポイントリリースです。強制 tool_choice は廃止され、thinking ブロックはそれを生成したモデルと会話に紐づけられ、会話履歴の編集は新規アカウントではエラーとして強制されます。また、価格表の中でいちばん安い行こそが興味深い初めてのリリースでもあります。キャッシュ読み取りが $1 から $0.25 / MTok に下がったのです。これが、定価 $10 / $50 を据え置いたまま、典型的なワークロードで約 25%、エージェント色の強いワークロードで最大 45% のコスト削減を Anthropic が主張できる理由です。

このページは移行のフィールドガイドです。何が変わったのか、何が壊れるのか、何が得られるのか、そして半日で実行できるチェックリストをまとめています。

What you'll learn
  • claude-fable-5 → claude-fable-5-1 の差し替えを 400 に変えてしまう 3 つの破壊的変更と、それぞれの修正方法を知る
  • 5 つの追加機能を使う:メッセージ単位の effort、ターン限定システムメッセージ、進捗更新、安くなったキャッシュ読み取り、コンテンツ来歴
  • コード変更なしで現れる 7 つの挙動変化(並列ツール呼び出しの減少、ナレーションの減少、密度の高い散文、ファイル全体の書き換え)を見分ける
  • Fable 5、Opus 5、GPT-5.6 Sol に対する発表時ベンチマークを、売り込みに乗せられずに読む
  • 自分のワークロードに対して Fable 5.1 か Opus 5 か Fable 5 かを決め、移行チェックリストを実行する
最終検証: 2026-09-14。

モデル ID、価格、破壊的変更、ベータヘッダー、挙動に関する注記は、Anthropic 公式の「What's new in Claude Fable 5.1」、モデル概要、移行ガイド、価格ページに基づき、いずれも 2026 年 9 月 14 日に確認しました。ベンチマーク数値は発表記事にある Anthropic 自身のものです。ここで挙げた 3 つのベータは形が変わる可能性があるため、出荷前にヘッダーを再確認してください。最新のモデル一覧は Current Models & Pricing を参照してください。

次の情報源で確認してください: 公式情報源.

1 段落で言うと​

Fable 5.1 は Fable 5 の後継で、Opus の上にある同じ Mythos クラスのティア、同じ 1M トークンのコンテキスト、同じ 128K の最大出力、同じ入力 $10 / 出力 $50、同じトークナイザー、同じ常時オンのアダプティブ thinking、同じインバンドの stop_reason: "refusal" 挙動、同じ 30 日間保持の要件(ZDR なし)です。Anthropic 自身のガイダンスも趣旨は変わっていません。ほとんどの作業は Opus 5 から始め、Fable 5.1 は「要求の厳しい推論や長期のエージェント作業、または Claude Opus 5 を高い effort で使っても評価が届かない場合」に手を伸ばす、というものです。新しいのは、3 つの破壊的変更、5 つの追加機能、75% 安くなったキャッシュ読み取り、そして評価スイートが教えてくれる前に知っておくべき一連の挙動変化です。

3 つの破壊的変更​

これらが、ID を単純に切り替えられない理由です。どれも静かな劣化ではなく 400 です。

1. 強制ツール使用はエラーを返す​

tool_choice: {"type": "any"} と {"type": "tool", "name": "..."} は、いまや 400 invalid_request_error を返します:

tool_choice: type "tool" and "any" are not supported for this model.

理由は示唆に富んでいます。thinking は常にオンであり、強制ツール呼び出しはそれをスキップしてしまうため、モデルはツール引数の中で思考を行うことになり、引数の品質が落ちるのです。このチェックは Messages API、Message Batches API、トークンカウントのエンドポイントに適用されます。auto(デフォルト)と none は変わりません。

修正は 2 行の変更です。tool_choice を auto のままにし、ツールに strict: true を設定してスキーマに additionalProperties: false を入れ、プロンプトでツールを使う場面を明示します。Anthropic の注記によれば、Fable 5.1 は「明示的なツール指示に確実に従う」とのことです。本当に欲しかったのがツール呼び出しではなくスキーマに準拠した JSON なら、代わりに構造化出力へ移行してください。

強制ツール呼び出し → strict ツール + 明示的な指示

# Before (Fable 5) — now a 400 on Fable 5.1
"tool_choice": {"type": "tool", "name": "record_summary"}

# After (Fable 5.1)
"tools": [{
"name": "record_summary",
"description": "Record the structured summary of the document.",
"strict": true,
"input_schema": {
  "type": "object",
  "properties": {"summary": {"type": "string"}},
  "required": ["summary"],
  "additionalProperties": false
}
}],
"tool_choice": {"type": "auto"},
"messages": [{"role": "user",
"content": "Summarize: The meeting moved to Thursday. Call the record_summary tool with your result."}]

2. thinking ブロックは一方向​

すべての thinking ブロックは、どのモデルが生成したかを記録するようになり、保持は一方向です。Fable 5.1 は Opus 5、Fable 5、Mythos 5、およびそれ以前のすべての Claude の thinking ブロックを読めますが、それらのどれも Fable 5.1 のものは読めません。 Fable 5.1 へ移る会話は推論を保持します。Fable 5.1 から離れる会話(ルーター、Opus 5 へのフォールバック、セッション途中のコスト削減のためのダウングレード)は、Fable 5.1 のターンの推論を失います。

API はこれを、対象モデルが読めないブロックをモデルに見せる前にドロップすることで処理します。ドロップされたブロックは課金されず、input_tokens にも数えられません。thinking-binding-controls-2026-08-01 ベータヘッダーがなければドロップはサイレントで、ヘッダーがあればトップレベルの input_transformations 配列で報告されます。モデル間でルーティングしているなら、ヘッダーを送ってその配列をログに残してください。サイレントな推論の喪失は、バグ報告で「ステップ 12 以降モデルが馬鹿になった」として現れる典型です。

3. 以前のターンを編集すると thinking ブロックが無効になる​

これは 2 度読むべき項目です。Fable 5.1 の thinking ブロックより前にある何か、つまり system プロンプト、tools 配列、または以前のメッセージのいずれかを変更すると、それ以降のすべての thinking ブロックが無効になります。チェックが強制される場合、次のリクエストは The block is bound to a different conversation というメッセージを持つ 400 で拒否されます。

本日時点の強制ルール:

  • 2026 年 8 月 31 日以降に作成されたアカウント: 強制。
  • それ以前のアカウント: API は不一致を記録しますが、thinking.block_binding.prefix_mismatch_behavior を自分で設定した場合のみ作用します。
  • Mythos 5.1 はこのチェックをまったく実行しません。
  • Claude Code、claude.ai、Managed Agents、Agent SDK はプレフィックスを維持してくれます。手組みの messages 配列だけがリスクにさらされます。

ブロックを無効にするものについての Anthropic 自身のリストは、言い換えれば、エージェントハーネスによくある習慣のリストです:

以降のすべての thinking ブロックを無効にする有効なまま保つ
後続のターンを残したまま、以前のターンを編集、並べ替え、削除する先頭の連続した thinking ブロックを古い順に削除する
リクエストごとのリマインダーやステータス行を以前のターンに注入し、次のリクエストで取り除くサーバー側のコンパクションやコンテキスト編集による履歴のトリミング
1 つの会話内でリクエスト間にトップレベルの system や tools を再構築するcache_control マーカーを移動する
後から異なるバイト列を返す画像やドキュメントの URL(チェックはバイト単位なので、同じファイルに対するローテーションする署名付き URL は問題ない)リクエスト間で effort を変更する

修正はすべて 1 つのルールに帰着します。会話を追記専用として扱うこと。 ターンごとのリマインダーはターン限定システムメッセージ(後述)になります。ツールと指示の変更は会話途中のシステムメッセージとツール変更になります。トリミングはサーバー側のコンパクションになります。エラーにせず続行するには、thinking-binding-controls-2026-08-01 ヘッダーを prefix_mismatch_behavior: "drop_block" とともに送ります。そうするとドロップは input_transformations に reason: "prefix_binding_mismatch" として報告されます。

Anthropic はこれを部分的に蒸留対策として位置づけています。発表記事では、新しい API アカウントは転写を保持したまま以前のコンテキストを手動で編集することができなくなり、公に文書化された蒸留手法が封じられたとしています。あなたにとっての実用的な利点は、同じ規律がプロンプトキャッシュを温かく保つことにもつながる点です。

5 つの追加機能​

メッセージ単位の effort(ベータ)​

会話の途中で effort を、プロンプトキャッシュを無効化せずに変更できるようになりました。難しいステップでは上げ、定型的なステップでは下げます。mid-conversation-output-config-2026-07-01 ベータヘッダーを送り、effort のみを指定するシステムメッセージを挿入すると、新しいレベルは次のユーザーターンから有効になります。Claude API と Google Cloud 上の Fable 5.1、Mythos 5.1、Opus 5 でサポートされています。

キャッシュを壊さずに要約ターンの effort を下げる

{
"model": "claude-fable-5-1",
"max_tokens": 4096,
"output_config": {"effort": "high"},
"messages": [
  {"role": "user", "content": "Plan a migration from SQLite to PostgreSQL in three short steps."},
  {"role": "assistant", "content": "1. Export the SQLite data. 2. Create the PostgreSQL schema. 3. Import the data and verify row counts."},
  {"role": "system", "content": [], "output_config": {"effort": "low"}},
  {"role": "user", "content": "Summarize the plan in one sentence."}
]
}
# header: anthropic-beta: mid-conversation-output-config-2026-07-01

これは Thinking & Effort と Effort チューニングの effort ガイダンスと組み合わせて使います。デフォルトは high で、「セッション全体で 1 つのレベル」はもはや唯一の選択肢ではなく、手抜きの選択肢になりました。

ターン限定システムメッセージ(ベータ)​

role: "system" メッセージに clear_at: "next_user_message" を設定すると、現在のターンに限ってシステムプロンプトの権限を持ち、後続の user メッセージが存在するようになるとレンダリングされなくなります。そのメッセージはそのまま送り返し続けるため、それより前の何も変わらず、キャッシュは一致し続け、後続の thinking ブロックは有効なままで、クリアされたメッセージは入力トークンを消費しません。ヘッダー:mid-conversation-system-clear-at-2026-08-21。

{
  "role": "system",
  "clear_at": "next_user_message",
  "content": "Results have landed in your inbox. Check it before running more code."
}

これは、破壊的変更 3 が罰するようになった「リマインダーを注入し、次のリクエストで削除する」パターンの公認の代替手段です。

ツール呼び出し間の進捗更新(ベータ)​

Fable 5.1 は Fable 5 と同様に、ツール呼び出しの間に短い進捗メモを書き、それぞれを呼び出し直前の独立した thinking ブロックとして出します。デフォルトの thinking.display: "omitted" では、それらは空で返ってくるため、長いエージェントターンはユーザーには無音に見えます。新機能:display: "updates"(ヘッダー thinking-display-updates-2026-08-18)は、推論は隠したまま進捗メモをテキストとして返します。テキストが空でない thinking ブロックはすべて、レンダリングできるステータス行になります。"summarized" も、要約された推論と混ざった形でそれらを返します。生の思考の連鎖は依然として返されません。

キャッシュ読み取りが $0.25 / MTok​

基本入力5 分キャッシュ書き込み1 時間キャッシュ書き込みキャッシュ読み取り出力
Fable 5$10$12.50$20$1.00$50
Fable 5.1$10$12.50$20$0.25$50

キャッシュ読み取りは Fable 5.1 と Mythos 5.1 では基本入力の 0.025 倍で、他のすべての Claude モデルでは 0.1 倍です。書き込みと 512 トークンの最小キャッシュ可能プロンプトは変わらず、バッチも引き続き 50% オフ($5 / $25)です。毎ターン大きなキャッシュ済みプレフィックスを再読み込みする長いエージェントループでは、ここが発表記事の「最大 45% 安い」の出所です。他モデルとの比較:3 日後に同じ定価 $10 / $50 で発表された OpenAI の GPT-6 Astra は、キャッシュ読み取りに $1.00 を課金しており、Fable 5.1 の 4 倍です。Astra フィールドガイドを参照してください。

コンテンツ来歴​

Fable 5.1 と Mythos 5.1 のすべてのテキストは、すべてのプラットフォームで Anthropic の統計的テキスト透かしを持ちます。Claude が生成するファイル(たとえばコード実行経由)は、Files API を通じて取得すると署名付きの C2PA Content Credentials を持ちます。Anthropic によれば、この透かしはトークンや隠し文字を追加せず、あなたやあなたの組織に関する情報を含まず、リクエストの変更も不要です。背景:Anthropic は 2026 年 7 月に AI 生成コンテンツの透明性に関する EU AI Act 行動規範に署名しており、検証を必要とする規制当局、ファクトチェッカー、研究者、企業向けの検出 API がプライベートプレビュー中です。

Fable 5 とまったく同じまま残るもの​

Fable 5 をすでに正しく配線しているなら、以下はすべてそのまま引き継がれます:

  • アダプティブ thinking は常にオン。budget_tokens 付きの thinking: {"type": "enabled"} も {"type": "disabled"} も、どちらも 400 を返す。thinking を省略するか {"type": "adaptive"} を送る。
  • thinking.display のデフォルトは "omitted"。生の思考の連鎖は返されない。
  • インターリーブ thinking は自動で、ベータヘッダー不要。
  • プリフィルは 400 を返す。デフォルト以外の temperature、top_p、top_k は 400 を返す。
  • 拒否は HTTP 200 で stop_reason: "refusal" と stop_details.category を伴って届く。出力の前に届いた拒否には課金されない。許可されたフォールバック先は Opus 5 と Opus 4.8 で、フォールバッククレジットが切り替えのプロンプトキャッシュコストを返金する。完全なパターンは拒否と安全性を参照。
  • 30 日間保持は必須。それを持たない組織やワークスペースからのリクエストは 400 を返す。両モデルとも Covered Models。
  • 知っておくべき相違点が 1 つ:Fable 5.1 も Mythos 5.1 も Priority Tier ではサポートされない。 Fable 5 はサポートされる。優先キャパシティを購入しているなら、当面 Fable 5 にとどまる理由になる。

Mythos 5.1:同じモデル、異なるセーフガード​

Anthropic は、Fable 5.1 と Mythos 5.1 はセーフガード構成が異なる同一の基盤モデルであり、スペックと価格を共有すると述べています。Mythos 5.1 は承認された Project Glasswing 参加者のみに提供され、現在は米国の組織に限定されており、防御的セキュリティ作業向けの Cyber Verification Program と、米国政府と共同で運営する Life Sciences Verification Program を通じて提供されます。セーフガード面ではすべての人にとって 2 つのことが変わりました。Fable 5.1 は防御目的でのソフトウェア脆弱性の特定が許可されるようになり(Anthropic はセッションあたりのサイバーセーフガード介入が約 60% 減少したと報告)、一方でペネトレーションテスト、エクスプロイト生成、バイナリ脆弱性スキャンといったデュアルユースのタスクは引き続き Opus モデルへリダイレクトされます。また、生物学のセーフガードは、無害な初歩的生物学や医療の質問に対して発動する頻度が約 85% 減りました。Mythos 5.1 はまた、thinking ブロックの会話バインディングチェックをスキップします。Glasswing へのアクセスが得られない場合の Anthropic の指示はシンプルです。Fable 5.1 を使ってください。

名称に注意してください。Fable 5 フィールドガイドでは Mythos 5 を「安全性分類器のない Fable 5」と説明しました。5.1 では Anthropic の表現は「異なるセーフガード構成」であり、Mythos 5.1 は依然として Anthropic 自身の Claude Security 製品を支えています。フィルターなしのデプロイではなく、構成の異なるデプロイとして扱ってください。

まとめ​

Key takeaways
  • Fable 5.1 が Fable 5 のドロップイン置き換えになるのは、tool_choice を強制せず、会話履歴を編集せず、thinking ブロックを古いモデルにルーティングしない場合だけ。ID を差し替える前に 3 つすべてを grep すること。
  • 会話を追記専用として扱う:ターンごとのリマインダーにはターン限定システムメッセージ、指示とツールの変更には会話途中のメッセージ、トリミングにはサーバー側コンパクション。thinking ブロックを有効に保ち、かつキャッシュを温かく保つ。
  • 価格の要点は $0.25 のキャッシュ読み取り。長いエージェントループは安くなるが、短いチャットは安くならない。$5 / $25 の Opus 5 が依然として Anthropic 自身の「まずここから」。
  • 並列ツール呼び出しの減少、ナレーションの減少、密度の高い散文、ファイル全体の書き換えを想定すること。それぞれ 1 行のプロンプト修正があり、thinking.display: "updates" で目に見える進捗が戻る。
  • Priority Tier と ZDR が、Fable 5 または Opus 5 にとどまる 2 つの契約上の理由。
