Muse Ember: エグゼキュータ層と、誰も価格を見なかった帯域

中級

2026年11月9日、Meta Superintelligence Labsは最小のモデルMuse Ember(muse-ember-1.0)をリリースしました。狙いは「エージェントが一日中繰り返す仕事、つまりツール呼び出し、コーディングのサブタスク、ルーティング、抽出、長い文書の解析」です。価格は入力100万トークンあたり$0.10、出力100万トークンあたり$0.50でした。

偶然の数字ではありません。Claude Haiku 5.5の料金表と1セント単位まで一致します。Metaのローンチ表がMuse Emberを比較している相手は、Haiku 5.5とGPT-6 Lunaだけです。

だから面白い問いは「安いか」ではありません。どちらも安いのです。面白いのは、どちらのローンチページも答えていない問いです。見出し価格が同じなら、実際に請求額が少なくなるのはどちらか。 答えは、プロンプトがどこまで長くなるかに完全に左右されます。両方のモデルがプロンプト長で課金され、その境界の位置が違うからです。

What you'll learn
  • Haiku 5.5とMuse Emberが一緒に作る3帯域の料金表を読み、EmberがHaikuの入力・出力のちょうど5分の1、キャッシュ読み取りの12分の1になる100K〜200Kの窓を見つける
  • エージェントループの予算を平均コンテキストではなくピークコンテキストで立てる。境界を越えたリクエストは再価格化されるため
  • Metaのベンチマーク表を正直に読む。8行で勝ち、1行で7.7ポイント負け、主要指標は引き分け
  • Metaの脚注1に埋もれたハーネスの非対称性を見抜く。Terminal-Bench行は3つのモデルではなく3つの異なるエージェントハーネスの比較である
  • Metaが公開していないものを知る。パラメータ数なし、モデルカードなし、推論エフォート段階なし、オープンウェイトなし
  • Emberをプランナーの下のエグゼキュータとしてスタックに入れるべきか判断する。これはMetaも独立した証拠も実際に裏づけている使い方である
最終検証: 2026-11-10。

価格とベンチマークのスコアは公開から1日で、ベンダー公表値です。>200Kの帯域($0.30 / $0.012 / $1.50)はMetaの記事の本文ではなく脚注2にあります。予算に使う前にMetaの最新のモデルページで確認してください。この帯域がリクエスト全体を再価格化するのか、境界を超えたトークンだけなのかはMetaが明記していません。このページは解決せず、未解決の問いとして示します。「Meta internal」と記された行は第三者による再現がありません。音声・動画入力はMetaの主張であり、独立した掲載情報では執筆時点でテキストと画像の入力・テキスト出力のみが記録されています。パラメータ数、アーキテクチャ、知識のカットオフ、キャッシュ書き込み価格、バッチ価格、レート制限は非公開です。

出典: Metaのローンチ記事(research.meta.ai/blog/muse-ember)と脚注1・2。Haiku 5.5の価格はAILmanacのHaiku 5.5ページに記載したAnthropicの料金表から。独立したベンチマークと冗長性の数値はOrcaRouterのMuse Ember分析が報じたArtificial Analysisのもの。

一段落でまとめると​

Muse Emberは、クローズドウェイトで推論対応の長コンテキスト・エグゼキュータモデルです。コンテキストウィンドウは100万トークン、出力上限は512K、200,000トークンまでのプロンプトで100万トークンあたり**$0.10 / キャッシュ$0.004 / $0.50**、それを超えると3つの料金すべてが3倍になります。Metaはこれを3モデルの階段の最下段に置いています(Muse Wonderが計画し、Muse Sparkがコードを書き、Muse Emberが量をこなす)。Meta自身の評価では、**Artificial Analysis Intelligence IndexでClaude Haiku 5.5と同点(36対36)で、タスクあたりのコストは約3分の1($0.136対$0.411)**です。Metaの10のベンチマーク行のうち8つで勝ち、コードを出荷する人にとって重要な1行で負けています。

第1部 — 3帯域の料金表​

ローンチ報道が見逃した点です。Haiku 5.5とMuse Emberは見出し価格が同じで、1Mコンテキストウィンドウも同じ、そしてどちらもプロンプトが長くなると高い料金表に切り替わります。しかしHaikuの境界は100,000トークンで5倍、Emberの境界は200,000トークンで3倍です。

並べると、見出し価格は主題ではなくなります。

プロンプト長Haiku 5.5 入力 / 出力 / キャッシュ読み取りMuse Ember 入力 / 出力 / キャッシュ読み取りEmberの優位
≤ 100Kトークン$0.10 / $0.50 / $0.01$0.10 / $0.50 / $0.004入力/出力は同じ、キャッシュ読み取りは2.5倍安い
100K – 200Kトークン$0.50 / $2.50 / $0.05$0.10 / $0.50 / $0.004入力/出力が5倍安い、キャッシュ読み取りが12.5倍安い
> 200Kトークン$0.50 / $2.50 / $0.05$0.30 / $1.50 / $0.012入力/出力が1.67倍安い、キャッシュ読み取りが4.17倍安い

数値はすべて100万トークンあたり。Haikuの帯域はAnthropicの料金表、EmberはMetaのローンチ記事の脚注2によるものです。

この表から3つのことが見えてきます。どちらのベンダーの発表からも見えないものです。

勝負は中間の帯域にある​

プロンプトが100,000〜200,000トークンの間では、Haiku 5.5はすでに再価格化され、Muse Emberはまだです。この窓では、同じ価格を掲げる2つのモデルが、入力・出力でちょうど5倍、キャッシュ読み取りで12.5倍違います。

珍しい窓ではありません。数個のファイル、テストログ、ビルド出力を読んだコーディングエージェントは、セッションの中盤にはここにいます。大量のサブエージェント作業をルーティングしていて、トランスクリプトが日常的に100K〜200Kトークンに収まるなら、この帯域は最大のコストレバーです。プロンプトの削減よりも、キャッシュ戦略よりも、エフォート調整よりも大きい。

200Kを超えると、差は想像よりずっと縮む​

両モデルが高い料金表に乗ると、Emberの優位は入力・出力で5倍から1.67倍に縮みます。ワークロードがすべて200Kトークン超にあるなら、第2帯域の計算が示唆するよりずっと近い存在です。価格ではなく、後述のFrontierCodeの結果、出力の冗長さ、レイテンシ、すでに使っているクラウドといった要因で決めるべきです。

キャッシュ読み取りは静かな勝ち筋​

Emberのキャッシュ入力料金**$0.004/Mは、比較全体で最も攻めた数字です。Metaはこれを自社の入力料金に対する96%割引と説明しています。100K以下のHaikuの$0.01に対しては2.5倍、100K超のHaikuの$0.05に対しては12.5倍**です。

エージェントループでは特に効きます。エージェントは毎ステップ、安定したプレフィックス(システムプロンプト、ツールスキーマ)を再送するからです。このプレフィックスはキャッシュされます。キャッシュされないのは、成長していくトランスクリプトで、毎ステップ新規入力として課金されます。つまり長いエージェント実行は、安いキャッシュ読み取りと、高くて伸び続ける末尾の組み合わせであり、キャッシュ読み取り料金は全実行の全ステップにわたって掛け算されます。

Watch out
  • Metaの脚注は「より長いプロンプトではMuse Emberは$0.30」としか言っていません。高い料金がリクエスト全体に適用されるのか、200,000を超えたトークンだけなのかは書かれていません。Haiku 5.5の文書化された挙動はリクエスト全体の再価格化です。Metaが別の説明をするまで、Emberでもリクエスト全体の再価格化で予算を組んでください。それが保守的な想定であり、隣の先例とも整合します。

第2部 — 予算は平均ではなくピークコンテキストで立てる​

リクエストを再価格化する境界には、平均が完全に隠してしまう帰結があります。重要な数字は、単一リクエストの最高水位だけです。

20ステップのエージェントループを考えます。各ステップは、システムプロンプト、ツールスキーマ、蓄積されたトランスクリプトを再送します。プレフィックスは安定していて$0.004/Mでキャッシュされます。トランスクリプトは毎ステップ伸び、新規入力として課金されます。

Guided walkthrough1 of 5
  1. 実行内のすべてのリクエストの入力トークン数をログに残し、最大値を保持します。平均90Kトークンの実行が、最終ステップでは210Kに達することは十分あります。プロンプト長の料金表では、その最終ステップは平均的なステップではなく高い料金で課金される可能性があります。
  2. 入力トークンが200,000(Ember)または100,000(Haiku)を超えるステップ番号が分かるようにループを計装します。そのステップと以降のステップが請求の高い部分です。それ以前はほぼ無料に近い。
  3. 1つのビルドログやテストダンプが、実行を境界の向こうへ押し出すことはよくあります。各ツール結果に固定の上限を設ければ、キャッシュが依存する安定したプレフィックスを書き換えずにトランスクリプトを縮められます。帯域のコストとキャッシュのコストを同時に節約できます。
  4. ピークが安定して境界を超えるなら、見出し価格が低くても境界が悪いモデルは、見出し価格が高くても境界のないモデルに負けることがあります。料金表の価格ではなく、実際のピークで比較をやり直してください。
  5. トークン単価はタスク単価ではありません。他モデルが20ステップで済むところに28ステップ必要なモデルは、トークン単価が半分でも高くつくことがあります。エグゼキュータ選びを決めるのはこの測定で、どちらのベンダーも公表していません。

実行ごとにピーク入力トークンを記録し、実際にどの帯域で課金されているかを知る

# Pseudocode for any agent loop, any provider.
# The number you need is the MAX, not the mean.

peak_input = 0
for step in run:
  resp = call_model(messages=transcript, tools=schemas)
  peak_input = max(peak_input, resp.usage.input_tokens)
  transcript.append(resp)

print("peak input tokens:", peak_input)
# Haiku 5.5  -> expensive card above 100_000
# Muse Ember -> expensive card above 200_000

読み方を変える4つの観察があります。

AutomationBenchの差こそ本当の見出しで、「コードが上手い」とは別の主張​

**37.8%対Haikuの13.9%**は2.7倍で、表の中で圧倒的に広い差です。AutomationBench-AAは、厳格なpass@1で業務ワークフローの完遂を採点します。この結果が裏づけるのは特定の主張です。Emberは複数ステップの手続き的な仕事をやり遂げるのが際立って得意だということで、エグゼキュータという位置づけの最強の証拠です。コード品質については何も語っていません。

真剣に受け止めるべきはFrontierCodeの行​

Ember 27.2%、Haiku 34.9%。7.7ポイントの負けで、Emberが負ける唯一の行です。FrontierCode 2.0-AAは実際のエンジニアリングタスクを採点します。Metaがこの行を省かずに載せたのは評価できます。

Emberが46対37で勝つCoding Agent Index-AAと並べると、一貫した姿が浮かびます。Emberはコーディングエージェントのループを回すのは得意で、レビューを通るコードを書くのは苦手です。エグゼキュータの典型的なプロファイルであり、本番のdiffを書くモデルとしては最悪のプロファイルです。

Terminal-Benchのほぼ同点は、3つのモデルではなく3つのハーネスの比較​

Metaの脚注1は、このページで最も重要な一文です。Terminal-Bench 4.0の行は、各モデルをそれぞれの最良の公開ハーネスで実行しています。

  • Muse Ember → mini-swe-agent
  • Claude Haiku 5.5 → Claude Code
  • GPT-6 Luna → Codex

3つの異なるエージェントの足場にまたがる40.9対39.2は、1.7ポイントのモデル差ではありません。ハーネスの選択だけでエージェント系スコアは数ポイント動きます。まさにAIベンチマークに騙されずに読む方法が扱う罠です。この行は勝ちではなく「おおむね同等」と扱ってください。

指数は引き分け、効率が勝ち​

Metaの表は、EmberとHaiku 5.5の両方をIntelligence Indexで最高の36と示しています。裏の散布図は少し見栄えが落ちます。Ember 35.8(タスクあたり$0.136)、Haiku 36.2(タスクあたり$0.411)。全体の階段は次のとおりです。

第4部 — 割引の一部を食う冗長さ​

独立した指数の実行にある1つの数字は、Metaの記事には出てきません。Intelligence Indexで、Emberは中央値9,710万に対し約1億1,500万の出力トークンを出しており、評価者は「やや冗長」と述べています。

中央値より約18%多い出力です。しかも出力トークンは入力トークンの5倍の価格のモデルです。冗長さは、安いエグゼキュータが優位を静かに返してしまう唯一の場所で、ステップ数と複利で効きます。冗長なモデルが長い中間推論をトランスクリプトに書くと、トランスクリプトも速く膨らみ、実行が200Kの境界により早く近づきます。

ただし反証も実在し、Metaではなくローンチパートナーから出ています。You.comは自社のコーディングテストでp95レイテンシ2.2秒と出力トークン36〜48%減を報告し、Cloudflareは比較したモデルより末尾で最大30%高速だったと報告しています。どちらもローンチ記事内のパートナーの引用です。方向性の参考にはなりますが、独立した測定ではありません。

What you'll learn
  • この2つの知見は実際に食い違っています。独立した指数の実行は中央値より多い冗長さを測り、ローンチパートナーは従来モデルより出力トークンが36〜48%少ないと測りました。両方とも真でありえます。冗長さはワークロード依存で、You.comは指数の中央値とは別のベースラインと比較していました。解決法は、節約額を見積もる前に、自分のワークロードで完了タスクあたりの出力トークンを測ることです。

第5部 — Metaが出さなかったもの​

欠落はスペックと同じくらい情報を持っていて、すべて同じ方向を指しています。

  • ウェイトなし。 Emberはプロプライエタリで、Metaが提供します。Metaのオープンウェイトのラインには入りません。
  • パラメータ数なし、アーキテクチャの説明なし、モデルカードなし。 「最小で最も効率的」が開示のすべてです。
  • 推論エフォートの段階なし。 推論対応とされるだけで設定が公開されておらず、コストと品質の段を自分で調整できません。
  • 知識のカットオフなし、レート制限なし、キャッシュ書き込み価格なし、バッチ価格なし。
  • 独立したスループット数値なし。 毎秒トークン数、最初のトークンまでの時間、タスクあたりの時間のいずれも第三者からは出ていません。
  • 対応モダリティには争いがある。 Metaはテキスト、画像、音声、動画のネイティブ理解を主張していますが、独立した掲載情報では執筆時点でテキストと画像の入力・テキスト出力のみです。音声や動画の入力が不可欠なら、その上に作る前に最新のモデルページで確認してください。

安全面では、Metaは、EmberがSuperintelligence Scaling Frameworkのもとで化学・生物、サイバーセキュリティ、制御喪失のリスクについて評価され、フレームワークの高リスク閾値を下回ったこと、そして小さいにもかかわらず同じ中核の安全訓練を受けたことを述べています。その中にはWebページ、文書、ツール出力に隠された指示への耐性のテストも含まれます。最後の項目は、信頼できないツール出力を読み続けるエグゼキュータにとって重要な点です。なぜそれをテストするのが正しく、内部評価を通っても保証にならないのかは、プロンプトインジェクションを参照してください。

第6部 — どこに収まるか​

Metaの位置づけは明確です。最難問にはMuse Wonder、コーディングとエージェントのワークフローにはMuse Spark、反復可能な大規模作業にはMuse Ember。 参考までに、Muse Spark 1.3は料金表$1.25/$4.25で、タスクあたり**$2.39のとき指数37です。つまりMeta自身のラインナップ内で、Emberは指数でSpark 1.3より1ポイント低く、タスクあたりコストは約17分の1**です。

提供形態は、Muse CodeとMeta Model APIで、Responses APIに対応します。Ember、Spark、WonderはGoogle CloudとOracle Cloudでも提供されます。ローンチパートナーのClineは、コーディングや文書分析のようなサブエージェント作業のために作られたものだと説明しています。

正直な結論は、価格とベンチマークの形のどちらも指すものです。Emberについてのすべてがエグゼキュータを示し、公開された何ものもプランナーを示していません。 判断にはフロンティアモデルを置き、量にはEmberを置きましょう。この2層構成を作るなら、仕組みはモデルルーティングのパターンで、量が実際にどこから来るのかはエージェントがトークンを燃やす理由で扱っています。
