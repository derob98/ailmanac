DeepSeek V4-Flash-Vision:初のネイティブビジョン・フロンティアオープンウェイト

中級

2026年8月31日 00:00 UTC、DeepSeek は Hugging Face に新しいリポジトリを静かにプッシュしました:deepseek-ai/DeepSeek-V4-Flash-Vision-Exp。同じモデルが API で公開されてから(8月21日)10日後、重みは今や MIT ライセンスで公開されています。これはネイティブビジョンを備えた初の V4 ファミリーモデルです。後付けアダプターを付けたテキストモデルではなく、共同学習されたマルチモーダル MoE であり、ビジョン側のエージェントスコアは ApexBench で 26.2 から 36.5 に跳ね上がった一方、テキストのみのエージェントスコアはまったく動いていません。いくつかのエージェントベンチマークでは Claude Opus 4.8 に匹敵、あるいはわずかに上回り、API の価格は入力100万トークンあたり $0.22 です。

このページは、ローンチに付いてこなかった実践的なフィールドガイドです:アーキテクチャ上何が変わったか、重要な数字、誰も警告してくれない一つの厳格な制限、動かし方、そして Claude が依然として正解である場面。

What you'll learn
  • ここでの「ネイティブビジョン」の意味を理解する ― V4-Flash バックボーンに、後から貼り付けたのではなく一緒に学習されたビジョンエンコーダー + アライナー
  • リリースが意図した通りにベンチマーク表を読む:テキストのみのエージェントは維持、ビジョンエージェントは大幅向上、どちらも Claude Opus 4.8 に肉薄
  • 画像あたり384トークンという厳格なアーキテクチャ上の上限と、それがプロンプトの書き方をどう変えるかを知る
  • 正直なコスト計算をする:100万トークンあたり $0.22 / $0.66 / $0.007(キャッシュ)と Claude Opus 4.8 の $15 / $75
  • 適切なサービング経路を選ぶ ― ほぼ全員にはホスト型 API、本格的なセルフホストには vLLM + DSpark

一文で言うと​

DeepSeek V4-Flash-Vision-Exp は3050億パラメータのスパース MoE マルチモーダルモデル(トークンあたり 13B アクティブ、1.048M トークンのコンテキスト)で、V4-Flash テキストバックボーンに共同学習されたビジョンを追加し、2026年8月31日に Hugging Face で MIT ライセンスのオープンとして公開され、Claude Opus 4.8 のトークン単価のおよそ40分の1でエージェント級のマルチモーダル性能を提供します。

リリースノートに書かれていない V4-Flash-Vision の4つのこと​

1. テキストエージェントを壊さずにビジョンが追加された ― それがすべて​

強力なテキストモデルにビジョンを後付けしたオープンラボはすべて、テキストベンチマークで代償を払ってきました。DeepSeek のリリース表はその見せ場です:Terminal Bench 2.1 でビジョンモデルは 83.9(テキストのみの V4-Flash-0731 は 82.7)、DeepSWE では 59.3(54.4 から上昇)、Toolathlon-Verified では 75.9(70.3 から上昇)。これらはどれもビジョンタスクではなく、純粋なコードとツール使用のエージェント評価です。ビジョン版はテキストエージェント作業でテキストのみのチェックポイントより優れており、劣ってはいません。

これが重要なのは、Chameleon 以来この分野が待ち望んでいた「実証」だからです:ビジョンヘッドが十分に遅い段階で入り、ルーターがテキストエキスパートの特化を続けられる限り、巨大 MoE をテキストとビジョンで共同学習しても、マルチモーダル追加によるテキスト退行は起きません。

2. ビジョンエンコーダーには画像あたり384トークンの厳格な予算がある​

これは最初のプロンプトを書く前に学ぶべき最も重要な一点です。V4-Flash-Vision-Exp のビジョンエンコーダーは画像あたり最大384トークンを割り当てます。そしてこの上限はアーキテクチャ上のもので、商業的なポリシーではありません。これ以上を解放する「高詳細」モードは存在しません。実際的な帰結:

  • 大きなスクリーンショットは細かい文字を失う。 2560×1440 のダッシュボード、画像化された密な CSV、長い PDF ページは、384トークンの視覚特徴で表現できる解像度でエンコードされます。つまり小さいフォントの文字は往復を生き延びません。
  • 拡大縮小ではなく、切り抜く。 チャートから数字を読み取る必要があるなら、ページ全体ではなく、関心領域に切り抜いたチャートを送ってください。
  • 1枚の巨大な画像より複数画像。 大きな文書は領域ごとのタイルに分割してください。各タイルがそれぞれ384トークンの予算を得ます。

Chartography が 64.3(Claude Opus 4.8 の 65.0 に匹敵)に達する理由であり、同時にフルページのスクリーンショットで12ポイントフォントの脚注をモデルがやはり見落とす理由でもあります。構築するすべてのビジョンエージェントワークフローは、この上限を前提にすべきです。

3. MoE ルーティングが異常にスパース ― トークンあたり256のうち6エキスパートが発火​

公開されているほとんどの MoE レシピは、32 または 64 のうち 8 エキスパートを活性化します。V4-Flash-Vision-Exp ははるかに広いエキスパートバンクを使います:256 のルーティングエキスパート + 1 の共有エキスパートで、トークンあたり発火するルーティングエキスパートは6つだけ、活性化率 2.3% です。モデルは 43層、隠れサイズ 4,096 で、ハイブリッドアテンションスタックは2つの仕組みを組み合わせています:

  • Compressed Sparse Attention(CSA) ― 長距離の読み取りのためのスパースパターン。
  • Heavily Compressed Attention(HCA) ― 深いコンテキストの末尾のための積極的に圧縮された形式。

その上に、Manifold-Constrained Hyper-Connections(mHC) が標準的な残差接続を制約付き多様体への射影で置き換えており、論文によれば43層スタックを通じた信号伝播を安定させます。これらが合わさって、二次的なアテンションコストなしに 1,048,576 トークンのコンテキストウィンドウを謳える理由になっています。

リリースパターン ― API が先、重みは10日後​

V4-Flash-Vision-Exp は 2026年8月21日に DeepSeek API でローンチし、オープンウェイトとして Hugging Face に着地したのは 8月31日でした。この10日間のギャップが DeepSeek の新しいデフォルトです。API と重みを同時に出荷してきた Z.ai(GLM)と比べると、DeepSeek は意図的に順序付けしています。

業界の読み:ラボは今や、巨大なオープン MoE が出荷されることで一致しています。残る問題はリリースサイクルのいつ重みが届くかです。本番計画にとってこれが意味するのは:

  • 初日からオンプレミスが必要なら、GLM ファミリーのリリースを注視する。
  • API から始めて1〜2週間後にセルフホストに切り替えられるなら、DeepSeek がそのパターン。

V4-Flash-Vision-Exp を動かす​

現実的な経路は3つあります。実際に重要な2つの制約で選んでください:重みを自分のインフラに置く必要があるか、そして VRAM(または RAM)にいくら払えるか。

Guided walkthrough1 of 3
  1. api.deepseek.com の OpenAI 互換エンドポイント。モデル ID は deepseek-v4-flash-vision-exp。価格は100万トークンあたり $0.22 / $0.66 / $0.007。データレジデンシーやエアギャップの制約がない限り、これが正解です。
  2. vLLM コンテナは day-0 サポートと deepseek_v4 ツールコールパーサーを同梱しています。GB300 × 4(または同等の B300 構成)のノードが1台必要です。DSpark 投機的デコーディングは --speculative-config で有効化します。DeepSeek が公開したスループット数値には FP8 KV キャッシュと block-size 256 の両方が必須です。
  3. unsloth/DeepSeek-V4-Flash-Vision-Exp-GGUF は2つの動的量子化を提供しています:155 GB の UD-Q4_K_XL と 162 GB の UD-Q8_K_XL。どちらも 24/48/80 GB の単一 GPU には収まりません。動くのは、192 GB 以上のシステム RAM とオフロードを備えた太いワークステーション、または CPU スピルオーバー付きの小さなマルチ GPU リグです。

ホスト型 API ― Python(OpenAI 互換)

import openai

client = openai.OpenAI(
  api_key="YOUR_DEEPSEEK_KEY",
  base_url="https://api.deepseek.com/v1",
)

response = client.chat.completions.create(
  model="deepseek-v4-flash-vision-exp",
  messages=[
      {
          "role": "user",
          "content": [
              {"type": "text", "text": "What does this chart claim, and what's the one thing it hides?"},
              {"type": "image_url", "image_url": {"url": "https://example.com/chart.png"}},
          ],
      }
  ],
)
print(response.choices[0].message.content)

セルフホスト ― GB300 × 4 上の vLLM と DSpark

docker run --gpus all -p 8000:8000 \
vllm/vllm-openai:deepseekv4-flash-vision \
deepseek-ai/DeepSeek-V4-Flash-Vision-Exp \
--kv-cache-dtype fp8 \
--block-size 256 \
--tensor-parallel-size 4 \
--tool-call-parser deepseek_v4 \
--speculative-config '{"method":"dspark","model":"deepseek-ai/DeepSeek-V4-Flash-Vision-Exp","num_speculative_tokens":3}'

V4-Flash-Vision を選ぶべきとき ― そして Claude に留まるべきとき​

V4-Flash-Vision を選ぶべきとき:

  • Opus 4.8 級のマルチモーダルエージェント品質が必要で、コストが要因になる場合。キャッシュ読み取り価格はクローズドなフロンティアのあらゆるものを圧倒します。
  • ワークロードが 1M トークンのコンテキストから恩恵を受ける場合(長文書 VQA、動画フレーム全体の分析、スクリーンショット付きの大規模リポジトリレビュー)。
  • コンプライアンス、エアギャップ作業、ファインチューニングのためにオープンウェイトが必要で、フロンティア級のハードウェアを持っている(または借りる)場合。
  • 画像のタイリングを制御できる、チャート中心またはダッシュボード解析のパイプラインを構築している場合。

Claude Opus 4.8(または Sonnet 5)に留まるべきとき:

  • 仕事がリポジトリ全体のコード変換や合成である場合 ― NL2Repo は差が本物である外れ値です(57.7 対 69.7)。
  • Claude 固有の機能が必要な場合:予算付きの拡張思考、スキル、Claude Code でのサブエージェントオーケストレーション、または Managed Agents のセッション予算制御。
  • プロンプトに極小の重要な文字を含む画像があり、タイリングできない場合 ― 384トークンの上限にぶつかって精度を失います。
  • 単一のベンダー / SLA / サポート窓口が欲しく、すでに Anthropic のツール群に投資している場合。

より広いモデル選択のフレームワークについては、モデルの選び方を参照してください。オープンウェイトの波全体の比較には、DeepSeek、Qwen とオープンウェイトの波が息の長い概観です。

最初に噛みつかれる落とし穴​

  1. 384トークンの上限を忘れる。 最初に構築する3つのビジョンエージェントは解像度を超過し、小さい文字で静かに精度を失います。計測を仕込んでください:画像ごとの寸法をログに残し、意図的にダウンスケール + タイリングする。
  2. --speculative-config を省くと DSpark は黙って落ちる。 フラグなしでは、vLLM はリリースが発表したスループットの1/3で平然とモデルをサービングします。本番では必ず投機設定を渡してください。
  3. GGUF はノートPC用モデルではない。 UD-Q4_K_XL は 155 GB です。より小さいマシンで「動いている」と示すコミュニティスレッドは、SSD スワップで秒間1トークン未満で動かしています ― 技術的には動作していても、使い物にはなりません。
  4. API と重みのバージョン整合は保証されない。 API モデルは黙って更新されることがあります。Hugging Face の重みは Vision-Exp に固定されています。API 上でベンチマークが月ごとに数ポイント動くなら、それが理由です。
  5. Exp は実験的という意味。 ビジョン版が本番の V4 リリースまで生き残る保証はありません。この特定のチェックポイントが1年後も存在するという前提で重要なパイプラインを構築しないでください。
