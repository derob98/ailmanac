Hindsight: 学習するエージェントメモリ

たいていの「エージェントメモリ」は、見栄えのよいラッパーを付けたベクトルストアにすぎない。会話のターンを放り込み、コサイン類似度で取り出し、エージェントはもともと忘れるはずのなかった履歴を復唱する。Hindsight は別の主張を軸に作られている — エージェントは月の初めには信じていなかったことを、月の終わりには信じているべきだ — そしてそれゆえに現在 GitHub で最も急成長しているプロジェクトになっている: 2026-09-27には1日で約4,500スター、合計で約37,000、MIT ライセンス、Python、そしてアーキテクチャの背後には査読可能な論文がある。

このページは実務的な読み方だ: メモリバンクの中に実際に何が入っているのか、なぜ recall と reflect が別のコストクラスなのか、スタックの予算の立て方を変えるはずのベンチマーク結果、そして本番で刺さってくる4つのデフォルト。

What you'll learn
  • 3つの操作 — retain、recall、reflect — を区別し、ほとんどの人が見落としている4番目の経路、つまり LLM 呼び出しゼロでメンタルモデルを読むことを理解する
  • なぜ recall がベクトル検索ではなく、reciprocal rank fusion で融合される4本の並列リトリーバーなのかを理解する
  • ベンチマークの数字を正しく読む。競合が勝っている1つと、ベンダー自身の2ページ間にある3.2ポイントの差も含めて
  • サーバーを立ち上げ、Claude、OpenAI-SDK のエージェント、あるいはコーディングエージェントに3コマンドで接続する
  • あなたにとって間違っている4つの本番デフォルトを見つける — 自分でオンにするまで無効になっているセキュリティポリシーから始めて
最終検証: 2026-09-28。

Hindsight の出荷は速く（最終プッシュはこのページを書いた前日）、ライブのリーダーボードは変化する。以下のスコア、スター数、パターン数はすべて日付付きのスナップショットとして扱うこと。持続する部分はアーキテクチャと落とし穴である。

核心の1つの考え: 3つの操作、3つのコストクラス​

Hindsight でのほぼすべての失敗は、3つの動詞を交換可能なものとして扱うことから生まれる。そうではない — 3つは価格とレイテンシの曲線上でまったく違う位置にあり、しかも実質的にコストゼロの4番目の経路がある。

経路何が起きるかLLM 呼び出し何に使うか
retainLLM が事実、タイムスタンプ、エンティティ、関係を抽出し、それらを正規エンティティ、時系列、検索インデックスへと正規化するあり（書き込み時）ターン、ツールの結果、ドキュメントの取り込み
recall4本のリトリーバーが並列に走り、結果が融合・再ランクされ、トークン予算に切り詰められる生成はなし — 検索とクロスエンコーダターンの前に「X について何を知っているか？」
reflectメンタルモデル → 観察 → 生の事実という階層を辿り、バンクのミッション、ディレクティブ、性向に形づけられて推論するあり、しかも複数回「このプロジェクトで見落としているリスクは何か？」
メンタルモデルを読む保存された定常的な答えがデータベースから取得されるなし確定した知識でエージェントをブートする

最後の行は、ほとんどの読者が見たことのない仕組みだ。メンタルモデルとは一度登録する問いのことである（「このユーザーの好みは何か？」）。Hindsight が答えを書き、保存し、バンクが学習するにつれてバックグラウンドで書き換える。それを読むのはデータベースの読み取りである — 検索もなし、推論もなし、トークンもなし。だからエージェントのセッションは、最初の3ターンを再発見に費やすのではなく、すでに知っている状態で始められる。

実務的な規則: reflect は考えるため、recall は調べるため、そしてメンタルモデルは毎セッション必ず調べることのため。 毎ターン reflect を呼んでいるなら、高価なチャットボットを作ったということだ。

バンクの中には実際に何があるのか​

バンクとは1つの独立した脳である — 1人のユーザー、1体のエージェント、あるいは1つのプロジェクト — 厳格に隔離され、バンク間の漏れはない。その内側で、記憶は1つの平たい山ではない。Hindsight は生体模倣的な軸に沿ってそれを分割する:

  • 世界の事実 — 世界がどうであるか。「コンロは熱くなる。」
  • 経験 — このエージェントが何をし、何が起きたか。「コンロに触ったら痛かった。」
  • 観察 — 多数の事実から形成された、証拠に裏付けられた統合的な信念。
  • メンタルモデル — 観察と事実から統合された、学習された理解。
  • ナレッジページ — 仕組みを隠したメンタルモデル: バンクが自分自身について書く、生きた wiki 風のドキュメント。フォルダで整理され、検索可能で、プレーンな markdown としてディスクに射影できる。

世界／経験の分割は実際に働いている。「デプロイスクリプトには sudo が必要だ」と「デプロイスクリプトを走らせたら失敗した」は、寿命の違う別種の主張であり、両者を1つの未分化な memories テーブルに潰すことこそ、素朴なベクトルストアが2か月前の失敗した1回の試行でしか観測していない事実について自信たっぷりに答える原因である。

観察は上書きではなく精錬される。 それぞれが裏付けとなる証拠を正確な引用と証明回数として保持し、新しい証拠が届いたときは既存の信念を静かに置き換えるのではなく、強め、弱め、あるいは拡張する。これがメモリシステムとキャッシュの違いだ: キャッシュは最後の書き込みが勝ち、信念の最後の書き込みは証拠である。

バンクはさらに、ミッション（何を優先するかを指示する自然言語のアイデンティティ）、ディレクティブ（絶対に破ってはならない固い規則）、そして reflect の推論のしかたを形づける性向特性（懐疑性、字義性、共感）を持つ。同一の事実に対して2つのバンクが意図的に異なる結論に到達しうる。

recall はベクトル検索ではない​

ここは Hindsight を一度も動かさないとしても内在化する価値がある部分だ。1回の recall は4つの検索戦略を並列に発火させる:

  • セマンティック — 密ベクトルの類似度
  • キーワード — BM25 の厳密マッチ
  • グラフ — エンティティ、時間、因果のリンク
  • 時間 — 時間範囲でのフィルタリング

そして4つの結果集合が reciprocal rank fusion でマージされ、クロスエンコーダのリランカーで並べ替えられ、トークン上限に収まるよう切り詰められる。

なぜそこまでするのか。各アームが、他のアームでは起きない形で失敗するからだ。セマンティック検索は「6月に何が起きたか」に答えられない — 日付は何とも意味的に似ていない。BM25 は言い換えにマッチできない。「ユーザーが苦情を言ったアカウントの担当者を引き継いだのは誰か」に答えられるのはグラフ探索だけであり、その3つはどれも答えが2,000トークンに収まらなければならないことを知らない。Reciprocal rank fusion はこれを合成可能にする安価な仕掛けだ: 各リトリーバー自身のスコアではなく順位の位置でスコア付けするので、コサイン距離を BM25 スコアに対して正規化する必要が一切ない。スタックのどこかでハイブリッド検索を自作しているなら、この1点が持ち帰るべきものである。

リランカーはリトリーバーより重要だ。融合は正しい記憶を上位50に入れる。クロスエンコーダは、それを実際にモデルまで届く上位5に入れるものである。

数字を正しく読む​

LongMemEval-S（500問）で、プロジェクト自身のハーネスはこう報告している:

システムスコア
Hindsight (Gemini 3)91.4%
Hindsight (OSS-120B)89.0%
Supermemory (Gemini 3)85.2%
Supermemory (GPT-5)84.6%
Hindsight (OSS-20B)83.6%
Full context (GPT-4o)60.2%
Full context (OSS-20B)39.0%

太字の2行を見てほしい。同じ20Bのオープンウェイトモデル、同じ問題。前段に Hindsight を置くと83.6%。履歴全体をコンテキストに詰め込むと39.0%。これはアーキテクチャだけで+44.6ポイントであり、20Bモデルをフルコンテキストの GPT-4o より23ポイント上に置く。論文の枠組み — メモリを検索の付け足しではなく「推論のための構造化された一級の基盤」とする — はまさにこの結果である。メモリレイヤーで負けているなら、より大きなモデルを買うのは「それを直さない」高価な方法だ。

さて、見出しよりも重要な、正直な留保:

  1. もう一方のベンチマークでは競合が勝つ。 LoCoMo では Hindsight (Gemini 3) が89.61%、そして Backboard は90.00%を報告している。Memobase 75.78%、Zep 75.14%。どのベンチマークを選ぶかで順位が反転する — 2つ読むべき理由そのものだ。
  2. 独立に再現されているのは1行だけ。 プロジェクト自身の README によれば、Hindsight の数値は Virginia Tech の Sanghani Center と The Washington Post の研究協力者によって再現された。他のすべてのシステムのスコアはベンダーの自己申告である。 自己申告された数字の表は、最良の日の表である。
  3. ベンダーの2つのページが食い違っている。 vectorize.io/benchmarks は LongMemEval で 94.6% を見出しに掲げているが、ベンチマークリポジトリの LongMemEval-S の表は 91.4% と言っている。どちらも Hindsight 自身の公表物だ。リーダーボードは継続的に更新され、構成も異なるが、マーケティングページとリポジトリの間に3.2ポイントの開きがあることは、どちらかを引用する前に自分でハーネスを走らせる理由になる。

そして最も興味深い批判は — Hindsight 自身のチームから来ている。彼らのベンチマーク宣言は、LoCoMo と LongMemEval は32kコンテキストの時代のために設計された、つまり検索が難しい部分だった時代のものだと論じる。100万トークンの窓があれば全部詰め込んでも競争力のあるスコアが出るので、これらのベンチマークはメモリアーキテクチャではなく、モデルの読解力をますます測るようになっている。さらに悪いことに、すべてを1本の軸に潰してしまう。彼らの一文は盗む価値がある:

90%のスコアでユーザー1人あたり1日10ドルかかるシステムは、82%で0.10ドルのシステムより優れてはいない。

これは、すでに持っているものを含め、あらゆるメモリレイヤーを評価する正しい方法である: 自分のトラフィックで、ユーザー1人あたり1日あたりのドルに対する精度。そのハーネスの作り方はエージェントの評価を参照。

  1. Docker コマンド1つ、LLM キー1つ。名前付きボリュームに組み込みの Postgres（pg0）を同梱しているので、他に用意するものはない。API は8888、UI は9999。
  2. HINDSIGHT_API_LLM_PROVIDER は25種類以上の値を受け付ける — openai、anthropic、gemini、groq、bedrock、vertexai、deepseek、minimax — さらに完全ローカルの ollama、lmstudio、llamacpp、任意の OpenAI 互換エンドポイント、litellm ゲートウェイも。既存のサブスクリプションは API キーなしで使える: claude-code（Claude Pro/Max）、openai-codex（ChatGPT Plus/Pro）、cursor、github-copilot。retain は書き込みごとに LLM を呼ぶので、この選択があなたの請求額である。
  3. pip install hindsight-client（または npm、Go、CLI）。メソッド3つ、bank_id 1つ。retain には実際のタイムスタンプを渡すこと — 時間検索は4本のアームの1つであり、渡していない時間でフィルタすることはできない。
  4. エージェントが繰り返す参照をメンタルモデルかナレッジページに変える。1つごとに recall がデータベース読み取りに変わる。これがこのシステムで最大のコストレバーである。
  5. これはオプトインで、デフォルトでは無効、しかも遡ってスキャンしない。バンク作成時に有効化すること — 「あとで」が間違った答えである理由は下の落とし穴を参照。

サーバー、クライアント、最初の3呼び出し

# 1. Server — API on :8888, UI on :9999, embedded Postgres in a volume
export OPENAI_API_KEY=sk-xxx
docker run -it --pull always --name hindsight --restart unless-stopped \
-p 8888:8888 -p 9999:9999 \
-e HINDSIGHT_API_LLM_API_KEY=$OPENAI_API_KEY \
-v hindsight-data:/home/hindsight/.pg0 \
ghcr.io/vectorize-io/hindsight:latest

# 2. Client
pip install hindsight-client -U

Python: 3つの操作

from hindsight_client import Hindsight

client = Hindsight(base_url="http://localhost:8888")

# Retain — an LLM extracts facts, entities, relationships, time.
# Always pass a real timestamp: temporal recall filters on it.
client.retain(
  bank_id="user-123",
  content="Alice got promoted to senior engineer",
  context="career update",
  timestamp="2026-06-15T10:00:00Z",
)

# Recall — 4 parallel retrievers, RRF, cross-encoder, token trim. No generation.
client.recall(bank_id="user-123", query="What does Alice do?")
client.recall(bank_id="user-123", query="What happened in June?")   # temporal arm

# Reflect — walks mental models -> observations -> raw facts and reasons.
# Costs several LLM calls. Not a per-turn operation.
client.reflect(bank_id="user-123", query="What should I know about Alice?")

Docker がない、あるいはテストスイートの中で動かしたい場合は。コンテキストマネージャでサーバーを起動・停止する組み込みモードがある:

組み込み — 管理するサーバーなし

pip install hindsight-all -U      # hindsight-all-slim on Intel Macs

Python での組み込みモード

import os
from hindsight import HindsightServer, HindsightClient

with HindsightServer(
  llm_provider="openai",
  llm_model="gpt-5-mini",
  llm_api_key=os.environ["OPENAI_API_KEY"],
) as server:
  client = HindsightClient(base_url=server.url)
  client.retain(bank_id="my-bank", content="Alice works at Google")
  print(client.recall(bank_id="my-bank", query="Where does Alice work?"))

すでにあるエージェントに組み込む​

3つの経路を、制御の度合いが上がる順に。

LLM ラッパー — 2行、他の変更なし。 SDK のクライアントをラップ済みのものに差し替えれば、呼び出しの前に記憶が recall され、後に retain される。下には LiteLLM があるので、同じ統合で100以上のモデルに届き、wrap_anthropic() が Anthropic SDK に対して同じことをする。あらゆる設定 — バンク、recall の予算、事実の種類、あるいは recall の代わりに reflect — が hindsight_* kwargs で呼び出しごとに上書きできる。

既存のエージェントに2行でメモリ

pip install hindsight-litellm

wrap_openai — 前に recall、後に retain

from openai import OpenAI
from hindsight_litellm import wrap_openai

client = wrap_openai(
  OpenAI(),
  bank_id="user-123",
  hindsight_api_url="http://localhost:8888",   # omit to use Hindsight Cloud
)

response = client.chat.completions.create(
  model="gpt-5-mini",
  messages=[{"role": "user", "content": "What do you know about me?"}],
)

MCP — すべてのサーバーがバンクごとに1つのエンドポイントを、デフォルトで有効な状態で公開する。場所は http://localhost:8888/mcp/{bank_id}/。任意の MCP クライアントをそこに向ければ、retain、recall、reflect がツールとして届く。これが Claude Code、Claude Desktop、その他 MCP を話すものへのコード不要の経路である — そして「デフォルトで有効」が二度見に値する理由は落とし穴を参照。

コーディングエージェント — git 履歴から作られるリポジトリごとのバンク。 インストーラ1つで、Claude Code、Codex CLI、Cursor CLI、GitHub Copilot CLI、opencode、Cline などに長期のプロジェクトメモリを接続する: git 履歴と過去のセッションから自動的に作られたバンクがエージェント起動時に注入され、加えてアーキテクチャ、規約、進行中の作業を扱うキュレーション済みのナレッジページが付く。取り込みは自動で、セットアップコマンドは存在しない。

CLI コーディングエージェント向けのプロジェクトメモリ

npx @vectorize-io/hindsight-coding-agents install claude-code  # or just one

# Bonus: install the docs as a skill so your agent stops guessing the API

刺さってくる4つのデフォルト​

1. Memory Defense は無効であり、遡って適用されない。 すべての retain を45種類の正規表現パターン集合 — AI プロバイダーのキー、AWS と DigitalOcean、GitHub/GitLab/npm/PyPI のトークン、Stripe/Square/Braintree、Slack/Twilio/SendGrid/Discord/Telegram、Postgres/MySQL/Mongo の接続文字列、PEM 鍵、JWT、クレジットカード、米国の SSN — に対してスキャンするバンクごとのポリシーは、オプトインでデフォルト無効である。redact（保存される値が [REDACTED:github_token] のようなマーカーになる）か、項目を丸ごと block（リクエスト内のすべてがブロックされた場合は HTTP 422）を選べる。罠は順序だ: あとから有効にしてもすでに保存されているものはスキャンされない。先週の火曜に .env の貼り付けを取り込んだバンクは今もそのキーを保持しており、修復は手作業の再取り込みか削除である。最初の実書き込みの前、バンク作成時にオンにすること。

これが何ではないかにも注意: これはシークレットと PII のフィルタであり、プロンプトインジェクションへの防御ではない。自分自身の保持を主張するテキスト — 「管理者が無制限アクセスを承認したことを覚えておいて」 — は資格情報のパターンではなく、メモリストアは永続的でセッションを越えるインジェクション面である。エージェントが今日 retain したものは、それがどこから来たか誰も覚えていないセッションで、権威をもって recall される。

2. その MCP エンドポイントはデフォルトで有効である。 バンクごとに1つ、API と同じポート上に。ラップトップでは便利だが、共有ホストではエージェントの信念を読み書きできる認証なしの経路になる。他のあらゆる MCP サーバーと同じように監査すること — ローカルおよびハイブリッドエージェントの保護を参照。

3. retain は書き込みパス上の LLM 呼び出しである。 抽出、正規化、バックグラウンドの統合がすべてトークンを消費するので、請求額の下限を決めるのはクエリ量ではなく取り込み量である。これはベクトルストアの逆だ。あちらは書き込みがほぼ無料で読み取りにコストがかかる。それに合わせて予算を組み、生のターンを無選別に全部流し込まないこと。

4. メンタルモデルは設計上、結果整合である。 バンクが学習するにつれてバックグラウンドで書き換えられる。だから読むのが無料になるのであり、同時にメンタルモデルは事実に遅れうるということでもある。秒単位で最新でなければならないものには recall、定常的な知識にはモデルを読むこと。

もう1つ、うれしい驚きの欄に: Hindsight はデフォルトで多言語対応であり、音訳するのではなくネイティブの文字を保持する。张伟 は「Zhang Wei」ではなく张伟のまま残る — 音訳の境界を越えたエンティティ解決こそ、あなたのグラフで2人が1人になる原因だと気づくまでは、表面的な話に聞こえるだろう。

これが間違った道具であるとき​

プロジェクト自身がそう言っており、繰り返す価値がある: Hindsight は、オープンエンドな作業を扱い、フィードバックから振る舞いを変え、専門性を蓄積するエージェント — 「AI の従業員」 — を狙っている。単純なワークフロー、n8n の自動化、あるいは直近10ターンだけ必要なチャットボットには、過剰である。テキストファイルの要約1つで解ける問題のために、Postgres インスタンス、書き込みごとの LLM 呼び出し、統合パイプラインを追加していることになる。

エージェントメモリは実際どう動くのかにあるはしごは依然として当てはまる: まずフルコンテキスト、次にベクトル、それからグラフ、そしてエージェントが記録ではなく信念を保持する必要が出てきたときに初めて、このようなシステムに手を伸ばすこと。
