バックグラウンドタスク、/loop、スケジュール実行

上級
最終検証: 2026-07-15。

バックグラウンドタスク、/loop、スケジュール実行の正確なコマンドと提供状況はリリースごとに変わります。公式ドキュメントで確認してください。

次の情報源で確認してください: 公式情報源.

すべてが素早い編集とは限りません。Claude Code は一つのプロンプトより長く続く作業を実行できます。バックグラウンドでの長いコマンド、繰り返しのループ、スケジュールされた実行です。

What you'll learn
  • 三つの仕組みを区別する: バックグラウンドタスク、/loop、スケジュールされたルーティン
  • セッションをブロックせずに長いコマンドを開始する。そして、それを密なループでポーリングするのが誤りである理由を知る
  • 一つの問いから適切なものを選ぶ: その作業はプロンプトより長く続くのか、セッションより長いのか、どちらでもないのか
  • スケジュール実行の指示を自己完結させる。各実行は新しく始まるから
  • 無人で動作するものにはガードレールを敷く

バックグラウンドタスク​

長時間実行されるコマンド（開発サーバー、テストウォッチャー、ビルド）を、セッションをブロックせずに開始します。Claude は作業を続け、タスクが出力を出したり終了したりすると通知を受け取ります。通常 & でバックグラウンドにするようなものすべてに使えますが、管理されているので、Claude があとで出力を読めます。

:::tip ビジーウェイトしない タスクをバックグラウンドで開始して先に進み、密なループでポーリングする代わりに、完了通知に呼び戻してもらいましょう。 :::

繰り返しのループ（/loop）​

/loop は、セッション内でプロンプトやコマンドを一定間隔で繰り返し実行します。たとえば「5 分ごとにデプロイの状況を確認して」のように。間隔を指定するか、Claude に自分のペースで進めさせます。CI の実行を見守ったり、ハーネスが通知してくれない外部ジョブをポーリングしたりするのに最適です。

セッション内で 5 分ごとにデプロイをポーリングする

/loop 5m check the deploy status and tell me the moment it goes green or fails

間隔を省略すると、Claude はあなたの時計ではなく自分のペースで進めます。

スケジュールされたクラウドエージェント​

時計に従って、継続的に行うべき作業、たとえば「毎朝新しい issue を要約する」「1 時間ごとにニュースを確認してドキュメントを更新する」には、スケジュールタスク / ルーティン（cron 形式）を使います。各実行は新しく始まるので、その指示は自己完結していなければなりません。

どれを選ぶか​

必要なこと使うもの
長いコマンドを実行しつつ作業を続けるバックグラウンドタスク
このセッション中、N 分ごとに何かをポーリングする/loop
スケジュールに従って、無期限に何かを行うスケジュールされたルーティン
Guided walkthrough1 of 4
  1. 一つのプロンプトより長いが、セッションよりは短い? バックグラウンドタスク。このセッション内で、プロンプトを繰り返す? /loop。セッション自体より長く、時計に従って、無期限に? スケジュールされたルーティン。
  2. 長いコマンドをバックグラウンドで開始して作業を続けます。タスクが出力を出したり終了したりすると Claude に通知されます。密なループでポーリングしないでください。
  3. スケジュールされた各実行は新しく始まるので、その指示に必要なコンテキストをすべて含めます。設定したセッションからは何も引き継がれません。
  4. スコープを厳密に絞った、元に戻せる作業だけに限り、厳格な権限と組み合わせます。ガードレールのない自律性は、この機能が陥りやすくしている失敗モードです。

:::warning 自律性にはガードレールが必要 スケジュールに従って無人で動作するものは、スコープを厳密に絞り、元に戻せるものにしてください。厳格な権限と組み合わせ、自律実行の堅牢化を読んでください。 :::

Check yourself

0/3
  1. 1毎朝、新しい issue の要約が欲しい。継続的に。どの仕組みが合いますか。
  2. 2スケジュールされたルーティンの指示が自己完結していなければならないのはなぜですか。
  3. 3長いテストウォッチャーをバックグラウンドで開始しました。次にやってはいけないことは何ですか。
Key takeaways
  • 三つの仕組み、一つの問い: その作業はプロンプトより長く続くのか（バックグラウンドタスク）、セッション内で繰り返すのか（/loop）、セッションそのものより長く続くのか（スケジュールされたルーティン）。
  • バックグラウンドタスクは & でバックグラウンドにしただけではなく管理されている。Claude があとで出力を読め、終了時に通知される。
  • ビジーウェイトしない。開始して先に進み、完了通知に呼び戻してもらう。
  • /loop は間隔を取るか、間隔を省けば自分のペースで進む。
  • スケジュールされた各実行は新しく始まるので、その指示は単体で成り立たなければならない。
  • 無人の自律性には、厳格な権限と元に戻せるスコープが必要。この組み合わせは任意ではない。
