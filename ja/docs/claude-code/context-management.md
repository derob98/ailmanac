## 大きな考え方

すべてのセッションには有限の[コンテキストウィンドウ](/docs/foundations/tokens-and-context)があります。ウィンドウが埋まるにつれて古い内容は圧縮され、Claude は「ぶれ」始めることがあります。コンテキストを意図的に管理することが、長いセッションを鋭く保つ鍵です。

## 二つの必須コマンド

ほぼすべての状況は2つのコマンドでカバーできます。コツは、意図に合ったコマンドを選ぶことです。

<Flashcards cards={[{front: "/clear", back: "会話を消去して新しく始めます。無関係なタスクに切り替えるときに使います。クリーンで集中したコンテキストを取り戻す最も安価な方法です。エイリアス: /reset と /new。"}, {front: "/compact", back: "ここまでの会話をコンパクトな形に要約します — 要点を残しつつ空き容量を確保します。同じタスクを続けたいが、ウィンドウが埋まりつつあるときに使います。任意でフォーカス指示を渡せます。"}]} />

判断は一つの質問で決まります: 新しいタスクか、同じタスクか?

```mermaid
flowchart TD
  A{New task or same task?} -->|New / unrelated| B[/clear]
  A -->|Same task, context full| C[/compact]
```

見落としやすい2つのポイント:

- **`/compact` は指示を受け取れます。** `/compact focus on the auth bug fix` とすると、自動処理が重要だと推測した内容ではなく、*あなたが*選んだ内容が残ります。ウィンドウに強制される前に、長い新しいタスクを始める手前で意図的に実行しましょう。
- **`/clear` は後戻りできない操作ではありません。** 名前を渡す(`/clear auth refactor`)と、消える側の会話が `/resume` ピッカーでそのラベルで表示されます。また、同じ Claude Code プロセス内であれば、巻き戻しメニューに `/resume <session-id> (previous session)` という項目が引き続き表示されます — [チェックポイントと巻き戻し](/docs/claude-code/checkpoints-and-rewind)を参照してください。

## 自動コンパクション — そのしきい値の動かし方

コンテキストが上限に近づくと、Claude Code は**自動コンパクション**を行い、作業が突然止まらないようにします。1M コンテキストウィンドウのモデルでは、デフォルトで約 967K トークンで発動します。それ以前のモデルは、そのコンテキストウィンドウの限界でコンパクションします。放置した会話を Claude Code がコンパクションすることもあります。

しきい値は自分で動かせます。`/autocompact 500k` なら早めにコンパクションされ、96% まで埋まってからではなく自分のタイミングで要約したいときに便利です。`/autocompact auto` でモデルに合わせて調整されたウィンドウに戻ります。

<PromptCard title="デフォルトより早くコンパクションする">{`/autocompact 500k`}</PromptCard>

<Steps items={[{title: "指定できる値", body: "生のトークン数(500000)、サフィックス付きの値(500k、1m)、モデルに合わせて調整されたウィンドウに戻す auto、セッション中の自動コンパクションを無効にする off。引数なしで /autocompact を実行すると現在のウィンドウが表示されます。"}, {title: "設定できる場所", body: "/autocompact コマンドは、ユーザー設定の modelSettings 内の現在のモデルの下に保存します。設定 JSON のトップレベルに autoCompactWindow を置くか、modelSettings 内のモデルごとに置くか、環境変数 CLAUDE_CODE_AUTO_COMPACT_WINDOW を使うこともできます。"}, {title: "優先順位(高い順)", body: "CLAUDE_CODE_AUTO_COMPACT_WINDOW、次に modelSettings 内のモデルごとの autoCompactWindow、次にトップレベルの autoCompactWindow、最後にモデルのデフォルトウィンドウ。管理設定のようにより優先度の高い設定スコープがウィンドウを指定している場合、/autocompact は値を保存しますが、セッションはそのスコープの値を使い続け — そのことを知らせてくれます。"}]} />

## コンパクションで残るもの

コンパクションが要約するのは*会話*です。セットアップがディスクから読み込むものはすべて別に扱われます — だからコンパクション後のセッションでもプロジェクトの規約を把握しているのです。

<Steps items={[{title: "ディスクから再注入されるもの", body: "システムプロンプトと出力スタイルは引き続き適用されます。プロジェクトルートの CLAUDE.md、スコープなしのルール、自動メモリ、プランモードで Claude が書いたプランが戻ります。スキルの説明は現在のスキルから再構築されます(Claude Code v2.1.304 以降)。セッションが git status のスナップショット付きで始まった場合、Claude Code は新しいものを読み込みます。"}, {title: "必要に応じて再読み込みされるもの", body: "paths: フロントマターを持つルールと、サブディレクトリ内のネストされた CLAUDE.md ファイルは要約されて消え、Claude が次に一致するファイルに触れたときにだけ再読み込みされます。コンパクションをまたいでルールを保持したい場合は、paths: フロントマターを外すか、プロジェクトルートの CLAUDE.md に移してください。"}, {title: "部分的に復元されるもの", body: "Claude Code は、Claude が読んだ・編集したファイルのうち最大5つを、更新が新しい順に再読み込みします — ただし 5,000 トークンを超えるファイルは、内容なしのパス参照('Referenced file')として戻ります。呼び出されたスキルの本文は、スキルごとに 5,000 トークン、合計 25,000 トークンを上限に再注入され、古いものから切り捨てられ、ファイルの先頭が保持されます。重要なことは SKILL.md の冒頭近くに書きましょう。"}, {title: "要約されて消えるもの", body: "会話そのもの。以前にフックが追加したコンテキストも含みます。'compact' ソースに一致する SessionStart フックは再実行され、その出力はコンパクション後のコンテキストに加わります — 戻ってこなければならないものにはこのフックを使います。"}, {title: "影響を受けないもの", body: "バックグラウンドコマンドとバックグラウンドのサブエージェントは動き続け、Claude Code はどれがまだ稼働中かを Claude に知らせるので、重複して起動することはありません。"}]} />

## 効果を保つテクニック

2つのコマンドに加えて、4つの習慣が最初からコンテキストを軽く保ちます。

<Steps items={[{title: "1セッション1タスク", body: "無関係な作業を午後いっぱい1つのコンテキストに積み上げないようにしましょう。"}, {title: "重い読み込みはサブエージェントに任せる", body: "大量の読み込みはサブエージェントに任せます — 消費するのはサブエージェント側のコンテキストで、結論だけが返ってきます。/docs/claude-code/subagents を参照してください。"}, {title: "貼り付けずに参照する", body: "大きなテキストを貼り付ける代わりに @path でファイルを指し示し、CLAUDE.md は簡潔に保ちましょう(/docs/claude-code/claude-md を参照)。"}, {title: "予算に目を配る", body: "/context を実行すると、カテゴリ別の内訳がリアルタイムで表示されます — 色付きのグリッドに加え、コンテキストを圧迫するツールやメモリの肥大化に対する最適化の提案、読み込まれた CLAUDE.md と自動メモリのファイルも確認できます。'all' を渡すと、フルスクリーンモードで項目ごとの一覧が展開されます。コンテキスト使用量を表示するステータスラインでも、同じ情報を受け身で得られます。/docs/claude-code/statusline を参照してください。"}]} />

<PromptCard title="コンテキストが実際にどこへ消えたかを見る">{`/context`}</PromptCard>

これらは最新のドキュメントに対応しています: [サブエージェント](/docs/claude-code/subagents)、[CLAUDE.md](/docs/claude-code/claude-md)、[ステータスライン](/docs/claude-code/statusline)。

:::tip[症状 → 対処]
Claude が以前の指示を忘れたり、同じことを繰り返したりし始めたら、ウィンドウが満杯の可能性があります。`/compact`(同じタスク)または `/clear`(新しいタスク)で、たいてい即座に解決します。`/context` を実行して確認しましょう — 会話が実際にウィンドウを超えている場合、出力にどれだけ超過しているかと、どのコマンドで空きを作れるかが表示されます。詳しくは[Claude はなぜそうしたのか?](/docs/contribute/troubleshooting)を参照してください。

一方、`Autocompact is thrashing` が出た場合は、コンパクションは機能しているものの、サイズの大きな何かがウィンドウを何度も埋め直しています — [Claude Code のトラブルシューティング](/docs/claude-code/troubleshooting)を参照してください。
:::
