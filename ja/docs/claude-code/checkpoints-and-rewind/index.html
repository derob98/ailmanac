チェックポイントと巻き戻し

中級
What you'll learn
  • チェックポイントが何を記録し、何を黙って記録しないのかを理解する
  • 巻き戻しメニューを2通りの方法で開き、毎回適切な復元アクションを選ぶ
  • 「restore」（状態を元に戻す）と「summarize」（コンテキストを圧縮する）を区別する
  • チェックポイントが Git を補完こそすれ、決して置き換えない理由を正確に知る
最終検証: 2026-10-20。

チェックポイントの挙動、巻き戻しメニューのアクション、スナップショットの上限や保持期間はリリースごとに変わります。公式ドキュメントで確認してください。

次の情報源で確認してください: 公式情報源.

基本の考え方​

大規模で野心的な変更を Claude に任せるとき、いちばん怖いのは「3回編集したところで失敗したらどうしよう？」という点です。チェックポイントはその答えです。Claude Code は編集のたびに事前のコードを自動でスナップショットするので、中途半端なリファクタリングを手作業でほどく代わりに、以前の状態へ巻き戻せます。

セッション全体のローカルな元に戻す機能と考えてください。「よし、大胆な方法を試そう」と、怖がらずに言えるセーフティネットです。

チェックポイントの作られ方​

チェックポイントは自分で作るものではなく、自動で作られます。

Guided walkthrough1 of 4
  1. ターンを開始する各プロンプトは、Claude のファイル編集ツールが動く前のコードの状態を記録します。コマンドも設定も儀式も不要です。
  2. Claude Code は、セッション内の直近100個のチェックポイント分のファイルスナップショットを保持します。それより古いものは破棄されるため、非常に長いセッションを最初まで巻き戻すことはできません。
  3. チェックポイントは会話と一緒に保存されるので、セッションを再開した後でも、実行中のセッションだけでなく /rewind を使えます。
  4. セッションのファイルスナップショットは、保持期間のクリーンアップで削除されます。デフォルトでは、そのセッションが最後にスナップショットを保存してから約30日後です。スナップショットが消えたチェックポイントに巻き戻そうとすると 'No files were restored' で失敗します。長く保持したい場合は cleanupPeriodDays を引き上げてください。

巻き戻しメニューを開く​

入り方は2通りあります。

Guided walkthrough1 of 2
  1. プロンプトでスラッシュコマンドを入力します。常に使えます。/checkpoint と /undo は同じコマンドのエイリアスなので、思い浮かんだ名前で構いません。
  2. プロンプト欄が空のとき、Esc の2回押しで巻き戻しメニューが開きます。テキストが入っている場合、2回押しはそのテキストを消去します（消去したテキストは入力履歴に保存されるので、↑ キーで呼び戻せます）。

巻き戻しメニューを開く

/rewind
Watch out
  • エイリアス名は、字面ほど文字どおりではありません。/checkpoint はその場でスナップショットを取るわけではなく（スナップショットは自動です）、/undo も直前の編集を単独で取り消すわけではありません。3つの名前はどれも同じメニューを開き、そこで時点とアクションを選びます。

メニューには、このセッションで送信したすべてのプロンプトが並びます。操作したい時点を選び、アクションを1つ選びます。

restore と summarize：重要な区別​

ここで混乱しやすくなります。メニューには2種類のアクションがあります。

  • Restore アクションは、ディスク上や会話の状態を変えます — 元に戻す操作です。
  • Summarize アクションは、ファイルには一切触れません — 会話を圧縮してコンテキストウィンドウの空きを増やします。
Watch out
  • Restore = 元に戻す（コード、会話、または両方を巻き戻す）。Summarize = コンテキストを圧縮する（ディスク上のファイルは変わらない）。
  • 編集で何かが壊れたら restore を使う。セッションが肥大化したがコードは問題ないなら summarize を使う。

restore アクション​

Guided walkthrough1 of 3
  1. ファイルとチャット履歴の両方を選択した時点まで戻します。その瞬間への、きれいな「時間の巻き戻し」です。
  2. チャットをそのメッセージまで巻き戻しつつ、現在のコードは保持します。残したい編集を失わずに質問をやり直したいときに便利です。
  3. ファイルの変更を元に戻しつつ、会話は保持します。編集は取り消し、それについての議論は残します。

2つのコードの restore オプションは、選択したチェックポイントに、元に戻せる追跡済みのファイル変更が実際にある場合にだけ表示されます。その時点以降にファイル編集が記録されていなければ、メニューには Restore conversation、2つの summarize オプション、Never mind（何も変更せずメッセージ一覧に戻る）だけが表示されます。

会話を復元した後（または "Summarize from here" を選んだ後）、選択したメッセージの元のプロンプトが入力欄に戻されるので、再送信や編集ができます。

summarize アクション​

どちらも会話の一部を AI が生成した要約に圧縮します — 選択したメッセージのどちら側を圧縮するかを選べる、対象を絞った /compact のようなものです。

Guided walkthrough1 of 2
  1. 選択したメッセージより前のメッセージはそのまま残ります。選択したメッセージとそれ以降が要約になります。脇道の議論を捨てつつ、初期のコンテキストを詳細のまま残したいときに使います。
  2. 選択したメッセージより前のメッセージが要約になり、選択したメッセージとそれ以降はそのまま残ります。会話の末尾にとどまります。序盤のセットアップのやり取りを圧縮しつつ、最近の作業を一字一句そのまま残したいときに使います。

どちらの場合も、元のメッセージはセッションの記録に残るため、Claude は詳細を参照でき、圧縮されたメッセージのあった場所には Summarized conversation のマーカーが表示されます。要約の焦点を指示するには、矢印キーで Summarize オプションを選択し、add context (optional) と表示された行に指示を入力して Enter を押します。数字キーでオプションを選ぶと、指示なしですぐに要約されます。

全体の流れは Context Management を参照してください。/rewind の summarize アクションが外科用メスなら、/compact は太い刷毛です。

What you'll learn
  • Summarize は同じセッションにとどまります。元のセッションをそのまま残して別のアプローチを試したい場合は、代わりに /branch または claude --continue --fork-session を使ってください。

/clear を越えて巻き戻す​

同じ Claude Code プロセス内で以前に /clear を実行した場合、巻き戻しメニューの先頭に /resume <session-id> (previous session) という項目が追加で表示されます。これを選ぶと、/clear の前にアクティブだった会話に戻れます。

最終検証: 2026-10-20。

この項目は、Claude Code を終了するか別のセッションを再開するまでの間だけ利用できます。消えた後は、/resume を実行して一覧から以前のセッションを選んでください。

次の情報源で確認してください: 公式情報源.

チェックポイントの限界 — 痛い目に遭うポイント​

チェックポイントは魔法のように思えますが、そうでなくなる瞬間があります。次の穴は重要です。

Guided walkthrough1 of 6
  1. Claude が実行するシェルコマンド — rm、mv、cp、コードジェネレーター、フォーマッター — が触れたファイルは追跡されません。チェックポイントの対象になるのは、Claude のファイル編集ツールによる直接の編集だけです。rm で削除されたファイルは、巻き戻しの観点では失われたままです。
  2. サブエージェントは同じファイルツールで編集しますが、通常、あなたのセッションはその編集を記録しません。例外は、フォアグラウンドのフォークされたスキル（background: false の context: fork）で、あなた自身のターン中に編集するため通常どおり巻き戻せます。それ以外のサブエージェント — デフォルトであるバックグラウンドのフォークされたスキルも含む — は、元に戻すのに Git が必要です。/docs/claude-code/subagents を参照してください。
  3. Claude Code の外で行った手動の編集や、並行する他のセッションによる編集は、通常は記録されません — 現在のセッションが編集したのと同じファイルに触れた場合を除きます。
  4. Claude の作業中にキューに入れ、実行中のターン内で届いたメッセージは、新しいターンを始めるのではなくそのターンに合流するため、自分専用のチェックポイントを持ちません — 巻き戻しメニューでは「No code restore」と表示されます。その後に起きたことを取り消すには、そのターンを開始したプロンプトまで巻き戻します。つまり、あなたのメッセージが届く前に行われた作業を含め、ターン全体が巻き戻されます。この印の付いたメッセージ自体を選んだ場合は、Restore conversation が選べ、ファイルはそのまま残ります。
  5. Restore は、追跡対象のうちシンボリックリンクまたはハードリンクであるパスをスキップし、'Restored the code, but skipped N files' と警告します。それらのファイルは現在の内容のままです。dotfile マネージャーのシンボリックリンクと pnpm のハードリンクのどちらもこれに該当します。復元の前に /debug を実行すると、スキップされるパスがデバッグログに明記されます。
  6. チェックポイントは素早いローカルの復旧手段です。コミットでもブランチでもなく、チームと共有することもできません。

チェックポイントと Git：両方使う​

解決する問題が違うので、組み合わせましょう。

チェックポイント (/rewind)Git
範囲1つのセッションプロジェクト全体の履歴
粒度ターンを開始するプロンプトごと、自動コミットごと、意図的
bash による変更を追跡する？いいえはい（ステージ/コミット後）
保持期間直近100個のチェックポイント、セッションの約30日後に整理永続
共有 / 共同作業不可可
イメージ「ローカルの元に戻す」「永続的な履歴」
Pro tip
  • 危険で大規模な実行の前に、動作する状態を Git でコミットしておく — それが永続的な最低ラインになる。
  • コミットの合間の素早いセッション内復旧には /rewind を使い、Git の履歴を汚さない。
  • Claude が破壊的な bash（rm/mv）、ジェネレーター、バックグラウンドのサブエージェントを実行する場合は Git に頼る — 巻き戻しではそれらのファイルは救えない。

使いどころ​

Guided walkthrough1 of 4
  1. 大胆な実装を試し、気に入らなければ分岐点までコードと会話を restore して別の方法を試します。
  2. 3プロンプト前の編集がバグを持ち込んだ？ 残骸をデバッグする代わりに、その直前までコードを restore します。
  3. バリエーションを試しつつ、動作確認済みの状態がいつでも /rewind 1回で戻れると分かっていられます。
  4. 冗長なデバッグの寄り道でコンテキストウィンドウが埋まった？ 途中から先を summarize し、最初の指示は詳細のまま残します。

Key takeaways
  • チェックポイントは、ターンを開始するプロンプトごとに取られる自動スナップショットで、セッションのローカルな元に戻す機能。直近100個を保持し、セッションの約30日後に整理される。
  • 巻き戻しメニューは /rewind（エイリアス: /checkpoint、/undo）か、空の入力欄での Esc 2回押しで開く。送信したすべてのプロンプトが並ぶ。
  • Restore アクションは状態（コード、会話、または両方）を元に戻し、summarize アクションはコンテキストを圧縮してファイルには触れない。
  • bash による変更、外部の変更、並行する変更、そしてサブエージェントの変更の大半は追跡されない — シンボリックリンクやハードリンクのパスも restore ではスキップされる。
  • チェックポイントは Git を補完するもので、置き換えるものではない。「ローカルの元に戻す」と「永続的で共有できる履歴」だと考えよう。

次へ​

  • Context Management — /compact、/clear、そして summarize が全体像にどう収まるか
  • プランモード — 編集が走る前に調査して計画を承認し、巻き戻しの回数を減らす
  • 権限（Permissions） — 大がかりなタスクを安全に実行するための、もう半分
