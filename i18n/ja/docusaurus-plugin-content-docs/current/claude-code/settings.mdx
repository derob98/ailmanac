5段階の優先順位(管理 → コマンドライン → プロジェクトローカル → 共有プロジェクト → ユーザー)と、「環境変数は階層ではない」というルールは、公式の[設定ファイルと優先順位](https://code.claude.com/docs/en/settings)のページに基づきます。キーごとの上書きは[設定リファレンス](https://code.claude.com/docs/en/settings-reference)に記載されています。
</VerifyNote>

`settings.json` は Claude Code の設定が置かれる場所です。[権限](/docs/claude-code/permissions)、[フック](/docs/claude-code/hooks)、環境変数、モデルのデフォルトなどが含まれます。**階層**を理解することが鍵です。

## 階層(優先順位の高い順)

同じキーが複数の場所で設定されている場合、Claude Code はそれを設定している最も高いレベルの値を使います。

<Steps items={[
  {title: "管理 / エンタープライズ", body: "managed-settings.json、MDM ポリシー、または claude.ai コンソールからのサーバー管理設定です。(いくつかのセキュリティ上敏感な例外を除き)あなたが設定するものは、これを上書きできません。"},
  {title: "コマンドライン", body: "claude --settings '<json-or-path>' で、1セッションだけに適用されます。管理を除くすべてのファイルより上にあり、どのファイルにも書き込まないため、覚えておきたくない実験に最適なツールです。"},
  {title: "プロジェクト(個人)", body: ".claude/settings.local.json で、git の管理対象外です。このリポジトリに対するあなたの上書き用です。マシン固有のパス、ここで使いたいモデル、自分だけが使いたいフックなど。"},
  {title: "プロジェクト(共有)", body: ".claude/settings.json で、リポジトリにコミットされます。チーム全体の規約で、新しいメンバーがクローンするだけで引き継ぐファイルです。"},
  {title: "ユーザー", body: "~/.claude/settings.json です。すべてのプロジェクトにまたがるあなたのデフォルト。優先順位は最も低いので、リポジトリは常にあなたの設定を上書きできます。"}
]} />

```mermaid
flowchart TB
  M[Managed / enterprise] -->|overrides| C[Command line --settings]
  C -->|overrides| L[Project local]
  L -->|overrides| P[Project shared]
  P -->|overrides| U[User]
```

:::note 環境変数は階層ではない
環境変数はこのスタックの外にあり、キーごとに解決されます。たとえば `ANTHROPIC_MODEL` はどのファイルの `model` キーよりも優先して適用され、`ANTHROPIC_DEFAULT_MODEL` はどのファイルも `model` を設定していないときにのみ適用されます。
:::

:::tip 共有ファイルはコミットし、ローカルファイルは無視する
チームの規約は `.claude/settings.json`(コミットする)に置きます。個人的な調整やマシン固有のパスは `.claude/settings.local.json`(git の管理対象外)に置きます。こうすれば、自分の好みを他の人に強制せずに、チームの一貫性を保てます。
:::

## よく設定するもの

- **`permissions`** — 許可/確認/拒否のルール。[権限](/docs/claude-code/permissions)を参照。
- **`hooks`** — ライフサイクルイベントで実行されるコマンド。[フック](/docs/claude-code/hooks)を参照。
- **`env`** — セッション用の環境変数。
- **モデル / 挙動のデフォルト** — たとえば好みのモデル。

## 安全に編集する

- 有効な JSON を保つこと(末尾のカンマがあると壊れます)。
- 広いルールよりも**狭い**権限ルールを選ぶこと。
- 秘密情報をコミットされるファイルに入れないこと。`env` の参照かシークレットマネージャーを使ってください。

<PromptCard title="どのファイルにも書き込まずに、1セッションだけ設定を試す">
{`claude --settings '{"permissions":{"allow":["Bash(git log *)"]}}'`}
</PromptCard>

そのままコピーして使える出発点となるファイルは、[フックと settings.json のレシピ](/docs/templates/hooks-settings)にあります。ファイルが不正な形式だったり、キーが期待どおりに働いていなかったりする場合は、`claude doctor` がセッションを開始せずに設定ファイルの検証エラーを出力します。それと `--safe-mode` については、[CLI のページ](/docs/claude-code/cli-flags)を参照してください。
