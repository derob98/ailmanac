**出力スタイル**は、システムプロンプトを直接変更することで、Claude Code の*伝え方* — 役割、トーン、冗長さ、推論を説明するかどうか — を変えます。変わるのは Claude がどう*応答するか*であって、何を*知っているか*ではありません。毎ターン同じ口調や形式を求めて何度も指示し直しているなら、使いどきです。

## 使う理由

- **ワークフローに合わせる。** 急いでいるときは簡潔にアクション優先で、学んでいるときは説明的に。
- **教えるモード。** 一部のスタイルは教育的な解説を加えます — コードベースや手法に慣れていく間にぴったりです。
- **一貫性。** 好みのスタイルを一度設定すれば、すべてのセッションがあなたの好きな読み味になります。

## 組み込みスタイル

Claude Code には 5 つが付属しています。

| スタイル | 何をするか | Default と比べた応答の長さ |
|---|---|---|
| **Default** | 標準のソフトウェアエンジニアリング用システムプロンプト — 効率的でアクション優先。 | — |
| **Proactive** | 日常的な判断では立ち止まらずに、ただちに実行し、妥当な仮定を置きます。auto モードより強い自律実行のガイダンスですが、ツールが動く前の権限プロンプトは引き続き表示されます。 | ほぼ同じ |
| **Concise** | 結果から始め、前置きや実況を省き、エンジニアリングの作業は Default と同じ徹底ぶりで行いながら、応答はデフォルトで短く保ちます。説明を求めれば、Claude は十分に答えます。エラー報告、セキュリティ警告、破壊的な操作の確認は、常に省略されません。**v2.1.237 以降**が必要です。 | 短い |
| **Explanatory** | ステップの間に教育的な「Insights」を加え、実装上の選択やコードベースのパターンを説明します。 | 長い |
| **Learning** | 協働的な、実践して学ぶスタイル: Insights を共有し、*さらに*小さな部分をあなた自身に書くよう求め、コードに `[TODO(human)]` マーカーを残します。 | 最も長い |

## 切り替え方

`/config` を実行し、**Output style** でスタイルを選びます。選択はプロジェクトレベルの `.claude/settings.local.json` に保存されます。メニューを使わずに設定するには、任意の設定ファイルの `outputStyle` フィールドを編集します。

<Steps items={[
  { title: "設定メニューを開く", body: "セッションで /config を実行し、Output style のオプションを探します。" },
  { title: "スタイルを選ぶ", body: "Default、Proactive、Concise、Explanatory、Learning のいずれかを選びます。選択はプロジェクトレベルの .claude/settings.local.json に保存されます。" },
  { title: "または直接設定する", body: "任意の設定ファイルの outputStyle フィールドを編集して、メニューを省略します(下の JSON を参照)。" },
  { title: "新しいセッションを始める", body: "スタイルはシステムプロンプトの一部で、セッション開始時に一度だけ読み込まれます — 反映させるには /clear を実行するか、新しいセッションを開きます。" }
]} />

```json
{
  "outputStyle": "Explanatory"
}
```

:::warning[変更には新しいセッションが必要]
出力スタイルはシステムプロンプトの一部で、Claude Code は**セッション開始時に一度だけ**それを読み込みます。変更は `/clear` か新しいセッションの後にのみ反映されます。(単独の `/output-style` コマンドは v2.1.91 で削除されました — `/config` か上の設定を使ってください。)
:::

## 出力スタイルが適用される場所と、されない場所

出力スタイルは**メイン**の会話のシステムプロンプトを変更します。これには特定の適用範囲があります。

- **サブエージェントは独自のシステムプロンプトを持つ**ので、出力スタイルを継承しません。Concise スタイルの中で Explainer エージェントを起動しても、*サブエージェント*は自身の指示を使い続けます。
- **`/fork` が唯一の例外です。** フォークされたサイドの会話は、親の完全なシステムプロンプトをコピーするので、スタイルを*保持します*。
- カスタムスタイルは、`keep-coding-instructions: true` を設定しない限り、**組み込みのコーディング指示を外します**。「純粋な執筆アシスタント」スタイルがエンジニアのように振る舞わなくなるのも、「図を先に」スタイルでコーディングを続けるのにこのフラグが必要なのも、そのためです。

## カスタムスタイルを作る

カスタムスタイルは Markdown ファイルです。フロントマターのあとに、システムプロンプトに追加する指示が続きます。3 つのレベルのいずれかに保存します。`name` を設定しない限り、ファイル名がスタイル名になります。

- **ユーザー** — `~/.claude/output-styles/`
- **プロジェクト** — `.claude/output-styles/`(作業ディレクトリとリポジトリのルートの間にある*すべての* `.claude/output-styles/` から読み込まれます。2 つのレベルが同じスタイル名を定義した場合は、**作業ディレクトリに最も近いものが優先されます** — パッケージがワークスペースのデフォルトを上書きするモノレポに最適)
- **管理ポリシー** — 管理設定ディレクトリ内の `.claude/output-styles/`

[プラグイン](/docs/claude-code/plugins-marketplaces)も、`output-styles/` ディレクトリでスタイルを同梱できます。

<PromptCard title="カスタムスタイルの例 — Diagrams first">{`---
name: Diagrams first
description: Lead every explanation with a diagram
keep-coding-instructions: true
---

When explaining code, architecture, or data flow, start with a Mermaid
diagram showing the structure, then explain in prose.`}</PromptCard>

<Callout type="tip" items={[
  "Claude の伝え方だけを変えて、通常どおりコーディングはさせたいときは、keep-coding-instructions: true を設定しましょう。",
  "Claude がソフトウェアエンジニアリングをまったくしないとき — たとえば純粋な執筆やデータ分析のアシスタント — は、これを省略(デフォルト)して、組み込みのコーディング指示を外します。"
]} />

### フロントマターのフィールド

| フィールド | 目的 | デフォルト |
|---|---|---|
| `name` | ファイル名から継承したくない場合のスタイル名。 | ファイル名 |
| `description` | `/config` のピッカーに表示されます。 | なし |
| `keep-coding-instructions` | Claude Code の組み込みのソフトウェアエンジニアリング指示を保持します。見せ方だけを変えるときは `true` に設定します。 | `false` |
| `force-for-plugin` | **プラグインのスタイル専用。** プラグインが有効になるたびに、このスタイルを自動的に適用し、ユーザーの `outputStyle` 設定を上書きします。複数の有効なプラグインがこれを設定した場合は、最初に読み込まれたものが優先されます。 | `false` |

<Callout type="warning" items={[
  "force-for-plugin は強力で、誤用しやすいものです — ユーザーが選んだスタイルを黙って上書きします。プラグインが Default ではどうしても動かない場合(たとえば「カスタマーサポート担当として振る舞う」のような完全な役割の変更)にのみ付け、プラグインの README に目立つように明記してください。"
]} />

## 出力スタイルと CLAUDE.md とその他のレバー

Claude Code の振る舞いをカスタマイズする機能はいくつもあります。出力スタイルはシステムプロンプトを直接変更し、*すべての*応答に適用されます。ほかのものは、指示を別の場所に追加するか、1 つのタスクに範囲を絞ります。

| レバー | 仕組み | 使いどき |
|---|---|---|
| **出力スタイル** | システムプロンプトを変更する | 毎ターン、異なる役割、トーン、デフォルトの応答形式がほしいとき |
| **[CLAUDE.md](/docs/claude-code/claude-md)** | システムプロンプトの後にユーザーメッセージを追加する | Claude に、プロジェクトの慣習とコードベースの文脈を常に知っていてほしいとき |
| **`--append-system-prompt`** | 何も取り除かずにシステムプロンプトに追記する | 単発の非対話的な実行に 1 回だけ追加したいとき |
| **[サブエージェント](/docs/claude-code/subagents)** | 独自のシステムプロンプト、モデル、ツールを持つヘルパーを動かす | 焦点を絞ったタスクのために、範囲が別になったヘルパーがほしいとき |
| **[スキル](/docs/claude-code/skills)** | 呼び出されたとき、または関連するときに、タスク固有の指示を読み込む | 再利用できるワークフローがあるとき |
| **[カスタム指示](/docs/claude-app/custom-instructions)** | Claude.ai のコンシューマー向けアプリでの親戚 | CLI ではなく、チャットアプリをカスタマイズするとき |

:::tip[適切なレバーを使う]
Claude に「終える前に必ずテストを実行する」ようにさせたい? それは**CLAUDE.md のガードレール**であって、スタイルではありません。「進めながら各ステップを説明する」ようにさせたい? それは**出力スタイル**です。1 回の `-p` 実行のために、単発のシステム指示を前置きしたい? それは **`--append-system-prompt`** です。振る舞いのルールは CLAUDE.md に、見せ方はスタイルに置きましょう。
:::
