## バックグラウンドタスク

長時間実行されるコマンド（開発サーバー、テストウォッチャー、ビルド）を、セッションを**ブロックせずに**開始します。Claude は作業を続け、タスクが出力を出したり終了したりすると通知を受け取ります。通常 `&` でバックグラウンドにするようなものすべてに使えますが、管理されているので、Claude があとで出力を読めます。

:::tip[ビジーウェイトしない]
タスクをバックグラウンドで開始して先に進み、密なループでポーリングする代わりに、完了通知に呼び戻してもらいましょう。
:::

## 繰り返しのループ（`/loop`）

`/loop` は、セッション内でプロンプトやコマンドを**一定間隔で繰り返し**実行します。たとえば「5 分ごとにデプロイの状況を確認して」のように。間隔を指定するか、Claude に自分のペースで進めさせます。CI の実行を見守ったり、ハーネスが通知してくれない外部ジョブをポーリングしたりするのに最適です。

<PromptCard title="セッション内で 5 分ごとにデプロイをポーリングする">
{`/loop 5m check the deploy status and tell me the moment it goes green or fails`}
</PromptCard>

間隔を省略すると、Claude はあなたの時計ではなく自分のペースで進めます。

## スケジュールされたクラウドエージェント

**時計に従って、継続的に**行うべき作業、たとえば「毎朝新しい issue を要約する」「1 時間ごとにニュースを確認してドキュメントを更新する」には、**スケジュールタスク / ルーティン**（cron 形式）を使います。各実行は新しく始まるので、その指示は**自己完結**していなければなりません。

```mermaid
flowchart LR
  A[Background task] -->|outlives one prompt, same session| A
  B[/loop/] -->|recurring within a session| B
  C[Scheduled routine] -->|cron, fresh run each time| C
```

## どれを選ぶか

| 必要なこと | 使うもの |
|---|---|
| 長いコマンドを実行しつつ作業を続ける | バックグラウンドタスク |
| このセッション中、N 分ごとに何かをポーリングする | `/loop` |
| スケジュールに従って、無期限に何かを行う | スケジュールされたルーティン |
