場所、読み込み順序、インポート構文は公式のメモリドキュメント（「How Claude remembers your project」）に基づいています。そこでは現在**2つ**の仕組みが説明されています：あなたが書く CLAUDE.md ファイルと、Claude 自身が書く**自動メモリ**です。インポートは最大4ホップの深さまで解決されます。具体的な内容はそちらで確認してください——こうした詳細は変わります。

[Claude Code](/docs/claude-code/what-is-claude-code) をより良くするために**一つだけ**やるなら、これをやってください。`CLAUDE.md` は Claude が毎回のセッション開始時に読むプレーンテキストファイル——あなたのプロジェクトの恒久的なブリーフィングです。

## なぜ最も効果の高い設定なのか

これがないと、毎回のセッションでプロジェクトを説明し直すことになります（「pnpm を使っている、テストは `__tests__` にある、`/generated` は触らないで…」）。これがあれば、Claude はすでに知っています。ここに良い指示を書けば、*今後すべての*やり取りを一度に改善できます。

## メモリの階層

Claude Code は複数の場所からメモリを読み込み、読み込み順——スコープの広いものから——にマージします。そのため、プロジェクトの指示はユーザーの指示の*後*にコンテキストへ入ります：

```mermaid
flowchart TD
  A["Managed policy<br/>/etc/claude-code/CLAUDE.md (org-wide, IT-managed)"] --> B["User instructions<br/>~/.claude/CLAUDE.md (all your projects)"]
  B --> C["Project instructions<br/>./CLAUDE.md or ./.claude/CLAUDE.md (committed)"]
  C --> D["Local instructions<br/>./CLAUDE.local.md (yours only — gitignore it)"]
```

- **管理ポリシー** — IT／DevOps チームが配布する組織全体の指示。パスは OS ごとに異なります：macOS では `/Library/Application Support/ClaudeCode/CLAUDE.md`、Linux と WSL では `/etc/claude-code/CLAUDE.md`、Windows では `C:\Program Files\ClaudeCode\CLAUDE.md`。
- **ユーザー指示**（`~/.claude/CLAUDE.md`）— すべてのプロジェクトに渡るあなた個人の好み。
- **プロジェクト指示**（`./CLAUDE.md` *または* `./.claude/CLAUDE.md`、コミット済み）— *この*リポジトリがどう動くか。チームと共有されます。リポジトリで [`AGENTS.md`](/docs/claude-code/agents-md) を使っている場合は、これらの代わりに、あるいはこれらと併せて読み込まれることがあります。
- **ローカル指示**（`./CLAUDE.local.md`）— サンドボックスの URL のような、あなただけのプロジェクト固有のメモ。`.gitignore` に追加してください。

作業ディレクトリより*上*のディレクトリ階層にあるファイルは起動時に読み込まれます。**サブディレクトリのファイルはオンデマンド**で、Claude がその領域の何かに触れたときに読み込まれます。

<Callout type="tip" items={["1つのファイルでは足りなくなった？指示を .claude/rules/*.md に分割しましょう——1トピックにつき1ファイルで、再帰的に発見されます。paths フロントマターのないルールは起動時に読み込まれ、優先度は .claude/CLAUDE.md と同じです。paths フロントマターを付けると、Claude が一致するファイルを扱うときだけそのルールが読み込まれ、コンテキストを節約できます。"]} />

## もう半分：自動メモリ

CLAUDE.md はメモリのうち*あなたが*書く半分です。Claude Code は**自動メモリ**も保持します——あなたの修正や好みから Claude 自身が書くメモで、リポジトリごとに保存され、あなたの CLAUDE.md ファイルと並んで毎回のセッションに読み込まれます。

| | CLAUDE.md ファイル | 自動メモリ |
| --- | --- | --- |
| **誰が書くか** | あなた | Claude |
| **何を保持するか** | 指示とルール | 学習とパターン |
| **スコープ** | プロジェクト、ユーザー、または組織 | リポジトリごと、ワークツリー間で共有 |

どちらも強制ではなく*コンテキスト*です：Claude はこれらを、必ず従わなければならない設定ではなく、重み付けできるガイダンスとして扱います。Claude の判断にかかわらずある動作を完全にブロックしたい場合は、代わりに [PreToolUse フック](/docs/claude-code/hooks)を使ってください。

<Callout type="warning" items={["自動メモリは最初の200行または25 KB までしか読み込まれません——膨れ上がった MEMORY.md は黙って切り捨てられます。起動時コストの詳しい内訳はコンテキスト予算の監査を参照してください。"]} />

## 何を入れるか

- プロジェクトが何であるかを、2 文で。
- 技術スタックと、**実行 / テスト / リント**の方法。
- Claude が推測できない規約（命名、構造、コミットスタイル）。
- **ガードレール**：「完了を宣言する前にテストを実行する」「`/vendor` は絶対に編集しない」「シークレットを決してコミットしない」。

## 何を入れないか

<Callout type="warning" items={["Claude は CLAUDE.md を文字通り従います——古い、曖昧、または願望的な指示はむしろ害になります。", "プロジェクトが今日実際にどう動くかを記述してください。短くて真実な方が、長くて理想的なものより優れています。", "巨大な貼り付けドキュメント（代わりに @imports を使う）、シークレット、実際には守らないルールは避けてください。", "プロジェクトの進化に合わせて正確さを保つよう、定期的に見直してください。"]} />

## インポート

ドキュメントを複製する代わりに既存のものを取り込みます——たとえばスタイルガイドを `@path/to/file` インポートで参照すれば、信頼できる情報源が一つになります。相対パスも絶対パスも使えます。相対パスは作業ディレクトリ**ではなく**、そのインポートを含むファイルを基準に解決されます。インポートされたファイルはさらに別のファイルをインポートできますが、深さは最大**4ホップ**までです。

痛い目に遭う前に知っておきたい構文の罠が2つあります：

- **スペースにはバックスラッシュが必要。** `@Design\ Docs/api-conventions.md` は動きます。バックスラッシュがないと、パスは最初のスペースで止まります。引用符で囲んでもファイルはまったくインポートされません。
- **バックティックで除外できる。** インポートの解析はコードスパンとフェンス付きブロックを飛ばすので、`` `@README` `` はそのままのテキストとして残り、単独の `@README` はファイルをインポートします。これが、読み込まずにパスを*言及する*方法です。

完全なリファレンスは[公式メモリドキュメント](https://code.claude.com/docs/en/memory)を参照してください。

<Callout type="tip" items={["信頼できる情報源を一つに：内容を CLAUDE.md に貼り付けるのではなく、@imports でファイルを参照しましょう。", "ドキュメントがすでに存在するなら、コピーせずリンクしましょう。コピーは古くなっていきます。"]} />
