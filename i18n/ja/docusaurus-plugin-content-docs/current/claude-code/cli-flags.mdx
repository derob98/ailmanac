以下のコマンド、フラグ、デフォルト値、バージョンの下限は、2026-10-07 に確認した公式の [CLI リファレンス](https://code.claude.com/docs/en/cli-reference)に基づいています。フラグはリリースごとに追加・変更されます。また、リファレンスには `claude --help` が**すべてのフラグを一覧表示するわけではない**と明記されています。つまり、`--help` に載っていないフラグが、お使いのビルドに存在しないとは限りません。ヘルプの文面ではなくリファレンスを確認し、`claude -v` でバージョンも確認してください。
</VerifyNote>

Claude Code のコマンドラインについて、多くの人は `claude`、`claude -c`、`claude -p` の 3 つを覚えたところで止まります。画面の前に座って使うだけなら、それで十分です。しかし Claude Code をスクリプト、CI ジョブ、バックグラウンドのキュー、あるいはチームメイトの手に委ねた途端、フラグは単なる便利機能ではなくなります。1 ドルで終わる実行と、1 時間ハングし続ける実行を分けるものになるのです。

このページはリファレンス表の写しではありません。この領域を**どの順番で学ぶか**、実際に結果を変えるフラグ、そして実害の出やすい 4 つの落とし穴をまとめています。

## まず問いから始める:これはどんな種類のセッションか

ほかの判断はすべて、この一点から決まります。Claude Code は実質的に異なる 6 種類のものを開始でき、それを選ぶフラグが最初に打つものになることがほとんどです。

| やりたいこと | フラグ | 得られるもの |
| --- | --- | --- |
| 画面を見ながら進める会話 | *(なし)* | このターミナルでのインタラクティブセッション |
| 1 回答えて終了 | `-p` / `--print` | 非インタラクティブ実行、出力は stdout |
| このターミナルより長く続く作業 | `--bg` / `--background` | バックグラウンドセッション。ID と管理方法を表示します |
| 試行用に隔離したブランチ | `-w` / `--worktree` | `<repo>/.claude/worktrees/<name>` 配下の git worktree |
| Anthropic のマシン上での作業 | `--cloud` | クラウドセッション、または既存のセッションにキューされるフォローアップ |
| スマートフォンからこのセッションを操作する | `--rc` / `--remote-control` | claude.ai や Claude アプリからも操作できるインタラクティブセッション |

このうち `--bg` と `-p` は組み合わせられません。片方はすぐに戻り、もう片方は答えを待つためです。バックグラウンドで動かしたいのが Claude セッションではなくシェルコマンドなら、`--bg` を `--exec` と組み合わせます。

<PromptCard title="テストスイートを Claude セッションではなくバックグラウンドジョブとして実行する">
{`claude --bg --exec 'pytest -x'`}
</PromptCard>

また `--bg` は開始前にそのディレクトリのワークスペース信頼(workspace trust)を確認します。そのため、信頼されていないリポジトリでのバックグラウンドセッションは、途中ではなく最初の段階で失敗します。

## 無人実行のための 5 つのフラグの契約

このページで最も価値の高い内容です。無人の `claude -p` 実行には、インタラクティブセッションにはない 3 つの失敗パターンがあります。誰も出さない承認を待って**ハングする**、想定よりはるかに長く**ループする**、スクリプトがデータを必要としているのに**文章を出力する**、の 3 つです。5 つのフラグでこの 3 つすべてを防げます。

  {title: "権限プロンプトに誰が答えるかを決める — --permission-prompts", body: "デフォルトは `host` で、プロンプトは Agent SDK のホスト、または `--permission-prompt-tool` に送られます。cron ジョブや CI ステップにはホストがいないため、`--permission-prompts none` を渡すと、Claude Code は待たずにそれらを拒否します。v2.1.259 以降が必要です。拒否が常態化せず稀になるよう、厳密に絞った `--allowedTools` のルールと組み合わせてください。"},
  {title: "ループに上限をつける — --max-turns", body: "デフォルトではターン数の上限はありません。`--max-turns 3` は、上限に達するとエラーで終了します。予算管理ではなく、暴走するエージェントループへの仕掛け線として使ってください。"},

## システムプロンプト系フラグと、その落とし穴

システムプロンプトを形作るフラグは 5 つあります。4 つはその文面を設定し、5 つ目は会話が開始時のテキストを保持し続けるかどうかを決めます。

| フラグ | 動作 |
| --- | --- |
| `--system-prompt` | デフォルトのプロンプト全体を、指定したテキストで置き換えます |
| `--system-prompt-file` | ファイルの内容で置き換えます |
| `--append-system-prompt` | デフォルトのプロンプトに、指定したテキストを追加します |
| `--append-system-prompt-file` | デフォルトのプロンプトに、ファイルの内容を追加します |
| `--system-prompt-snapshot` | `off` は毎回のリクエストでプロンプトを再構築し、`on`(デフォルト)は記録済みのものを再利用します |

*追加*にするか*置換*にするかは、アイデンティティをどうするかという選択です。追加は Claude Code のデフォルトのツールガイダンス、安全性に関する指示、コーディング規約を維持したまま、その上にあなたのルールを重ねます。実行ごとの指示、出力フォーマット、プロジェクトのコンテキストに適しています。置換はツールガイダンスを含めて**そのすべて**を捨てるため、そのサーフェスが本当にコーディングアシスタントではない場合、つまり誰も見ていないパイプライン内の非コーディングエージェントのような場合にのみ適切です。置換する場合、タスクがなお必要とするものはすべて自分で用意することになります。

両者は組み合わせられます。追加フラグと置換フラグを一緒に渡すと、デフォルトを置き換えたうえでテキストが追加されます。v2.1.283 以降では、フラグとそのファイル形式、たとえば `--append-system-prompt` *と* `--append-system-prompt-file` を同時に渡すこともでき、Claude Code は両方を使います。その際、入力した順序に関係なく、ファイルの内容が先に置かれます。

<Callout type="warning" title="落とし穴:再開した会話は、生まれた時のプロンプトを再利用する" items={["Claude Code はシステムプロンプトを会話の最初のリクエストで一度だけ構築し、セッションに記録します。","会話がコンパクトされるまで、以降のリクエストはすべて、--resume や --continue の後も含めて、その記録済みプロンプトを使います。","そのため、--append-system-prompt のテキストを編集して claude --continue を再実行しても、何も変わりません。フラグが壊れているのではなく、会話がまだ記録を使っているのです。","新しいテキストは、会話がコンパクトされたとき、または新しい会話で有効になります。","--continue の実行をまたいで文言を試行錯誤するには、--system-prompt-snapshot off を渡すと、リクエストごとにプロンプトが再構築されます。v2.1.257 以降が必要です。"]} />

安定した指示と実行ごとのコンテキストが混在する置換プロンプトでは、もう一つ知っておくと役立つ工夫があります。両者の間に `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` だけを含む行を置いてください。Claude Code は最初のそのような行で分割してその行を取り除くため、上側の部分はキャッシュされたままとなり、下側の部分だけが変わります。v2.1.275 以降が必要です。これが請求額にどう効くかは、[プロンプトキャッシュ](/docs/api/prompt-caching)で扱っています。

さらに、複数ユーザーでスクリプト化されたワークロードでは、`--exclude-dynamic-system-prompt-sections` が、自動メモリの場所のようなユーザーごとのコンテキストをシステムプロンプトから最初のユーザーメッセージへ移します。これにより、異なるマシン上の同じタスクが 1 つのキャッシュ済みプレフィックスを共有できます。デフォルトのプロンプトにのみ適用され、`--system-prompt` や `--system-prompt-file` を指定した場合は無視されます。

## 何かをオフにする 3 つのフラグ、そしてそれらは同じではない

これらは同じ意味で使われがちで、その後、症状が改善しないことに首をかしげることになります。3 つはそれぞれ異なる問題を解決します。

| | `--bare` | `--safe-mode` | `--restricted` |
| --- | --- | --- | --- |
| 解決する問題 | スクリプトからの呼び出しには起動が遅すぎる | 設定が壊れているが、どの部分か分からない | 評価用ハーネスが、この共有マシンに触れてはならない |
| CLAUDE.md、スキル、コマンド、サブエージェント、プラグイン、MCP、自動メモリ | 検出されない | 読み込まれない | マネージド設定と `--settings` のみ読み込まれる |
| 組み込みツール | Bash、ファイル読み取り、ファイル編集 | 通常どおり動作 | コマンド/コードを実行するツールと WebFetch は、`--tools` で個別に指定しない限り**削除される** |
| ファイルアクセス | 通常どおり | 通常どおり | 作業ディレクトリ内に限定 |
| `bypassPermissions` | 許可 | 許可 | **拒否** |
| マネージドポリシー | 適用される | 引き続き適用(ポリシーフックとステータスラインを含む) | 適用される |
| 副作用 | `CLAUDE_CODE_SIMPLE` を設定 | `CLAUDE_CODE_SAFE_MODE` を設定 | クラウドセッションの作成を拒否 |

この表は意図の段階的な違いとして読んでください。`--bare` は**速度**、`--safe-mode` は**診断**、`--restricted` は**封じ込め**のためのものです。一つ役立つ細かい点として、`--add-dir` で渡したディレクトリ内のスキルは `--bare` でも読み込まれます。これを使えば、ほかをすべて削ぎ落とした実行に、ちょうど一つの機能だけを残せます。

何かがおかしな挙動をしていて、Claude Code のせいか自分の設定のせいか分からないとき、最初に試すべきは `--safe-mode` です。これは、あるカスタマイズが自動モデルフォールバックを引き起こしているかどうかを切り分けたい場合にも当てはまります。`claude doctor` と組み合わせてください。これはセッションを開始せずに、読み取り専用のインストールおよび設定の診断を出力します。(セッション内の `/doctor` コマンドは別物で、修正を適用することもできます。)症状から入るデバッグの詳細は、[Claude Code のトラブルシューティング](/docs/claude-code/troubleshooting)にあります。`--restricted` には v2.1.248 以降が必要です。

## シェルからバックグラウンドセッションを操作する

`--bg` でセッションを開始すると、ターミナルはコントロールプレーンになります。ライフサイクル全体にコマンドがあり、そのどれもインタラクティブ UI を開く必要がありません。

## 間違えやすいフラグの組

<Callout type="warning" title="先回りして押さえておきたい 6 つの混同" items={["--tools は、どの組み込みツールが存在するかを制限します。--allowedTools は、どの呼び出しが権限プロンプトを省略するかを指定します。--disallowedTools は、呼び出しを拒否します。この 3 つは別々の役割であり、間違ったものを渡すことが「なぜまだ確認してくるのか」の最も多い原因です。","--tools は MCP ツールにはまったく影響しません。それらも取り除くには、--disallowedTools \"mcp__*\" を追加します。","--disallowedTools に素の名前を指定すると、そのツールは Claude のコンテキストから取り除かれます。Bash(rm *) のようにスコープを付けたルールでは、ツールは利用可能なまま、一致する呼び出しだけが拒否されます。","--dangerously-skip-permissions は bypassPermissions で起動します。--allow-dangerously-skip-permissions は、そのモードを Shift+Tab のサイクルに加えるだけなので、plan モードで開始して後から切り替えられます。実際に欲しかったのは、ほぼ間違いなく後者です。","--add-dir はファイルアクセスを与えますが、Claude Code はそれらのディレクトリからほとんどの .claude/ 設定を検出しません。ディレクトリを追加することは、その設定を採用することと同じではありません。","--desktop はプロンプトも、--verbose と --debug 系フラグ以外のフラグも受け付けません。セッションは Desktop アプリ自身が開始するためです。v2.1.285 以降が必要です。"]} />

ちょっとした使い勝手の工夫として、サブコマンドを打ち間違えると、Claude Code は最も近い候補を提案し、セッションを開始せずに終了します。`claude udpate` は、意図しない会話を開くのではなく `Did you mean claude update?` と表示します。
