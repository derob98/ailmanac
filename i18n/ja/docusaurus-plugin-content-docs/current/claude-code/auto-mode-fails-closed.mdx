このページのバージョン、日付、設定名はすべてAnthropic公式のClaude Codeチェンジログに基づいています。Claude Codeは週に数回リリースされます — v2.1.322（2026年11月10日）より新しいものがないか、チェンジログを再確認してください。
</VerifyNote>

[オートモード](/docs/claude-code/permissions)は、いまや多くの人が使うモードです。すべての操作で確認を求める代わりに、**安全分類器**が各操作を審査します。**v2.1.319**（2026年11月6日）で、Anthropicはその分類器に到達できないときの挙動を変更しました。この変更は誰の「新機能」リストにも載っていません。機能ではないからです。これまで黙って劣化していた状況を、明確な停止に変える強制の判断です。

Claude Codeを無人で動かしているなら — cron、CI、スケジュールタスク、セルフホストのランナー — 次のパイプライン実行の前に、続く2つの節を読んでください。

## 何が変わったか

オートモードのチェックは**サーバー側**で動きます。v2.1.319より前は、それに到達できないセッションは**組み込みのローカル分類器**にフォールバックして処理を続けていました。今はそうなりません。サーバーが確認できない呼び出しは、フォールバックなしで**確認を求められるか、拒否されます**。

| | v2.1.319より前 | v2.1.319以降 |
|---|---|---|
| サーバーチェックに到達できる | サーバー分類器が呼び出しを審査 | 変更なし |
| サーバーチェックに到達できない | 組み込みのローカル分類器にフォールバック | **確認を求める、または拒否** |
| 無人セッション（`-p`、cron、CI） | ローカル分類器で実行を継続 | **ターンが停止** |
| その場合の`claude -p`の終了コード | `0` | **`1`** |

最後の行が本番環境に影響するものです。終了コードの変更は*修正*として分類されています — 安全チェックが利用できないために操作が拒否されたとき、`claude -p`は`0`で終了していましたが、テキストおよびJSON出力は`1`で終了するようになりました。これは修正です：何もしないまま成功と報告するパイプラインは、あなたに嘘をついていました。ただし、実際に目にする症状は、アップデート後に緑だったジョブが赤に変わることで、本当の原因はエラーメッセージから一段離れたところにあります。

:::warning[3つの環境がこれを引き起こし、うち2つはまったく似ていない]
- **テレメトリ無効** — サーバーチェックは同じ経路を通ります。
- **フィーチャーフラグを取得していない** — 同様です。
- **LLMゲートウェイの背後** — ゲートウェイがチェックを破棄します。

**Bedrock、Vertex、Foundryは明示的に変更なしです。** そのため、Bedrockを使う組織は何も起きませんが、隣のゲートウェイ配下のチームは、同じバージョンですべての無人実行を失います。
:::

同じリリースで関連する修正が2つ入っており、どちらもこの失敗モードが隠れていたことを示しています：

- `/status`は、サーバー側のレビューが実際にはセッションに届いていないとき — たとえばそれを破棄するゲートウェイの背後で — **「Auto mode server: Enabled」**と表示していました。つまり、最初に頼る診断が、v2.1.319までは真実の逆を確認していたのです。
- ゲートウェイが安全チェックに`403`または`422`を返すと、オートモードは**毎ターン失敗**していました。（`apiKeyHelper`付きの`403`は変更なしです。）

## 挙動を静かに変えるその他5つの変更

**2026年10月7日から11月10日**の間に25のリリースが出ました（v2.1.293 → v2.1.322）。以下は、破壊的変更と名乗らないまま、既存の設定の動作を変えるものです。

### 1. Opus 4.8のファストモードは2026年11月30日に削除される

**2026年10月30日**付けで非推奨（v2.1.316で提供）。削除後は、Opus 4.8でのファストモードのリクエストは**エラーを返し、標準のOpus 4.8にフォールバックしません**。Opus 5.5に移行すれば高速化は維持されます。段階的な縮退がない固定日付は、このチェンジログの中でも最も珍しい種類の変更です — [モデルと料金](/docs/whats-new/models-and-pricing)を参照。

### 2. スキルの読み込みが、異なる2通りの方法で2度狭められた

- **v2.1.319：** Bashサンドボックスが有効な場合、開始フォルダーの*下*にある`.claude/skills`フォルダーのスキルは、そこでClaude Codeを起動するか、そこへ`/cd`したときにのみ読み込まれます。
- **v2.1.321**（11月9日）：`~/.claude/plugins`内の`.claude/skills`フォルダーは、Claudeがそこのファイルを扱っているときに**読み込まれなくなりました**。

[スキル](/docs/claude-code/skills)が黙って使えなくなったなら、まずここを確認してください — 症状は不在であり、エラーは出ません。

### 3. MCPツール呼び出しが自動でバックグラウンド化される

**v2.1.319**でターミナルのMCPタスクのサポートが追加されました：MCPサーバーがツール呼び出しをタスクとして実行する場合、Claude Codeはそれを**すぐに**バックグラウンドへ移し、完了したらClaudeに結果を伝えます。ツール呼び出しの中で待機させたい場合は`CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND`を設定します。

MCPタスクは**フィーチャーフラグの取得なし**でも動作するようになりました（Bedrock、Vertex、Foundry、LLMゲートウェイ、`DISABLE_TELEMETRY`）。`CLAUDE_CODE_DISABLE_MCP_TASKS=1`で完全に無効化できます。[MCPサーバー](/docs/claude-code/mcp)と[バックグラウンドタスク](/docs/claude-code/background-tasks)を参照。

### 4. 変更のないファイルを再読み込みすると、再び内容が返る

**v2.1.317**（11月3日）で、Readツールの`"file unchanged since your last Read"`スタブが削除されました。同じファイルを2回読むと、プレースホルダーではなくファイルが返ります。正確性の面では改善で — Claudeが古い前提で動くことがなくなります — 長いセッションが[コンテキスト予算](/docs/claude-code/context-budget-audit)を消費する速さには実際の変化があります。

### 5. `sed -i`は本物のBashコマンドになった

**v2.1.309**（10月22日）で、`sed -i`は疑似的なファイル編集プレビューではなく、標準のBashプロンプトが表示され、書かれたとおりに実行されるようになりました。他のBash編集と同様、**`/rewind`では復元されなくなりました**。ストリーム編集のインプレース変更を元に戻すのに`/rewind`に頼っていたなら、そのセーフティネットはなくなりました — [チェックポイントと巻き戻し](/docs/claude-code/checkpoints-and-rewind)を参照。

自動化するなら知っておきたい、より小さな6つ目：自己ペースの`/loop`は、ターン終了時にフォールバックの起床をスケジュールする代わりに**終了する**ようになりました（v2.1.319）。`CLAUDE_CODE_LOOP_KEEPALIVE=1`で以前の挙動に戻せます。
