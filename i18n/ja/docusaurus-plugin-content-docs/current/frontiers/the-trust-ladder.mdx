# 信頼のはしご

<Callout type="objectives" items={["自律性がオン/オフのスイッチではなく、一段ずつ登る「はしご」である理由","影響範囲(ブラストラディウス)と可逆性で整理した5つの段階(モデルの賢さではなく)","正しい段階を決めるための3つのルール:低めから始める、最悪ケースに合わせる、タスクごとに選ぶ","はしごが Claude Code のパーミッションモードにどう対応するか","CLAUDE.md の位置づけ ― 「頭の中にあるガードレール」をエージェントが実際に従えるものに変えるファイル"]} />

「AIにどこまで勝手に*やらせて*いいのか?」という問いは、ほぼすべてのエージェントに関する判断の根底にあります。Claude Code のパーミッション、自動承認の設定、スクリプトを無人で実行させるかどうか。多くの人はこれを単一のオン/オフスイッチとして答えがちです。すべてを見張るか、完全に放任するか。

AILmanac が代わりに使っている見方はこうです。

> **自律性はスイッチではなく、はしごである。一段ずつ登るものであり、立つべき段は「モデルをどれだけ信頼しているか」ではなく「ミスがどれだけ深刻か」で決まる。**

重要な洞察は、適切な自律性の量は、AIがどれだけ「賢い」かとはほとんど関係がないということです。問題は**影響範囲**(誤った行動がどれだけの損害をもたらすか)と**可逆性**(どれだけ簡単に元に戻せるか)です。優秀なモデルが不可逆的なことを監督なしに行う構成は、平凡なモデルが可逆的なことを行う構成よりも悪い設定です。

## 5つの段階

私たちが有用だと考えているモデルは、自律性の低い順に5つの明確な段階として捉えることです。

| 段階 | AIが行うこと | 適切な場面 | 安全にする要素 |
| --- | --- | --- | --- |
| **1. 提案のみ** | 何を*するつもりか*を伝えるだけで、行動は取らない | 高リスクまたは不可逆的な作業、まだ信頼していない領域、何が得意かをまだ学んでいる段階 | 実行者はあなた自身。あなたが手で行わない限り何も起きない。 |
| **2. レビュー用のドラフト** | 実際の成果物(コード、メール、クエリ)を作成するが、適用前に止まる | 出力が具体的で、自分で書くより目を通す方が速い場合 | 何かが効力を持つ前に、実際の人間が読む。流し読みではなく、本当に目を通すdiff。 |
| **3. 可逆的なものは実行** | 直接実行するが、低リスクで簡単に元に戻せる行動に限る | その行動にきれいな取り消し手段がある:バージョン管理下の編集、使い捨てブランチへの書き込み、1コマンドでロールバックできるもの | **可逆性こそがガードレール。** ミスのコストは「元に戻す」であって、「法務に説明する」ではない。 |
| **4. 実行してから報告** | 自律的に作業し、その後に何をしたかを正確に見せる | 反復的で範囲が明確なタスクで、*事前に*ゲートするより*事後に*レビューする方が安いもの | 完全で正直な監査証跡 ― ログ、diff、要約 ― を、あなたが実際に事後に読むこと。 |
| **5. ガードレール内での自律実行** | 厳格な制限の中で無人で動く | 何度も成功するのを見てきた、狭く十分に理解されたループ | **ガードレールが監督を担う。** AIが越えられない厳格な境界と、キルスイッチ。 |

## はしごの使い方

3つのルールで実践的になります。

## Claude Code への対応付け

Claude Code は、はしごが実際に機能する様子を見るのにうってつけの場所です。そのパーミッションシステムは本質的に、段階を選ぶためのダイヤルの集まりだからです。

- **段階1〜2**はデフォルトの慎重な姿勢:Claude が編集やコマンドを提案し、あなたが一つずつ承認します。すべてのdiffを着地前にレビューしている状態です。
- **段階3**は特定の可逆的なツール呼び出しを許可すること ― `git restore` で戻せる git リポジトリ内のファイル編集、使い捨てブランチでの実行など ― で、破壊的なものは引き続きゲートします。
- **段階4**は安全な行動のカテゴリを許可リストに入れ、それらについては Claude がプロンプトなしで進み、その後にトランスクリプトとdiffを読むことです。
- **段階5**は、狭く実証済みのループに対するより完全な自律性です。そしてこれは、本物のガードレール ― スコープを絞ったパーミッション、制約された作業ディレクトリ、停止できる手段 ― がある場合に*のみ*安全です。

安全に登ることを可能にする仕組みが、あなたの**[CLAUDE.md](/docs/claude-code/claude-md)**です。このファイルにガードレールを書き出します:常に許可されるもの、決して起きてはならないこと、立ち入り禁止のパス、止まって確認すべきタイミング。頭の中にしかないガードレールはエージェントを制約しませんが、CLAUDE.md に書かれたガードレールは制約します。どう表現すればよいか分からない場合は、[CLAUDE.md ジェネレーター](/docs/tools/claude-md-generator)が構造化された出発点を提供します。

正直なまとめ:**AIが有能そうだからという理由で自律性を与えてはいけません。行動が可逆的で、影響範囲が小さく、ガードレールが書き出されているからこそ与えるのです。** そして、証拠が集まるにつれて一段ずつ登ってください。
