1 年間、「Claude のメモリ」はモデルが毎日書き直す 1 つの進化する段落を意味しました — 略歴には良いが、構造のあるものには悪い。**2026 年 6 月から 7 月**の間、Anthropic はそれをエントリベースのモデルに置き換えました: Claude がリアルタイムで読み書きする多数の小さくカテゴライズされたノート。同じアイデアがアプリ*と* Managed Agents メモリ API を動かします。このページはそれらを接続し、両方の面を 1 つのメンタルモデルから理解できるようにします。

<VerifyNote lastVerified="2026-07-24" source="https://platform.claude.com/docs/en/release-notes/overview">
`agent-memory-2026-07-22` ベータヘッダ、memory_store Webhook イベント、Dreams モデルサポートはすべて過去 4 週間で変更されました。出荷前にプラットフォームリリースノートで現在のベータステータスと価格を確認してください。
</VerifyNote>

### 形状変更が重要な理由

古い日次サマリには単一の失敗モードがありました: 無関係なコンテキストが互いに漏れる。あなたの仕事プロジェクトに関する事実を修正すると、Claude はあなたの書き方に関する何かを上書きするかもしれない。小さくカテゴライズされたエントリは構造的にそれを修正 — 各編集は 1 つのレーンにスコープされる。

ほとんどのユーザーが見逃す 3 つの結果:

- **取得は連想ではなく標的的になった。** Claude は残りのコンテキストを引きずらずに「あなたのコミュニケーション設定」を引き出せる。サマリを突破するために「X が好き、Y ではない」を必要としたプロンプトは、今や既存のエントリに直接当たる。
- **外科的に刈り込める。** すべてを消して Claude にあなたが誰かを教え直すのではなく、設定で 1 つの間違ったエントリを削除する。1 つのミス修正の「全焼却」税が消えた。
- **カテゴリは目に見えないスキーマとして機能する。** Claude がエントリの*属す場所*を決めるとき(例:「コミュニケーションスタイル」対「現在のプロジェクト」)、その事実が将来の個人チャット、将来の仕事チャット、または両方で呼び出されるかどうかを暗黙的に選んでいる。前もって適切に名付けることが後のより良い呼び出しを後押しする。

## パート 2 — API で: memory_stores と新しいベータヘッダ

Managed Agents プラットフォームはメモリを **memory stores** として公開します — パスでアドレス指定され、`path_prefix` でリストされ、カーソルでページングされるメモリのコレクション。**2026 年 7 月 2 日**に Anthropic は `agent-memory-2026-07-22` を出荷しました。これは素朴な移行を壊すのに十分な意味論を変えるベータヘッダ。**2026 年 7 月 22 日**に古い `managed-agents-2026-04-01` ヘッダが同じリスト動作を採用 — なので「新しい」ルールは今 memory-store エンドポイントで*唯一*のルール。

### 知っておくべき 4 つの動作変更

| # | 何が変わったか | 古い動作 | `agent-memory-2026-07-22` の下での新しい動作 |
|---|---|---|---|
| 1 | リスト順序 | `order_by` / `order` でクライアント制御 | **安定した、サーバ定義の順序。** `order_by` と `order` は無視される — 必要ならクライアント側でソート |
| 2 | `depth` パラメータ | 自由形式の整数 | `0`、`1`、または省略のみを受け入れる。他の任意の値は **400** を返す |
| 3 | `path_prefix` マッチング | 部分文字列マッチ | `/` で終わる必要があり、**全パスセグメント**のみをマッチ |
| 4 | ページネーションカーソル | 交換可能 | 新しいヘッダなしで発行されたカーソルは**それと一緒に有効ではない**。採用時はページ 1 から再開 |

さらに 2 つの落とし穴:

- **ヘッダ衝突。** memory-store エンドポイントでは、`agent-memory-2026-07-22` が `managed-agents-2026-04-01` を置き換える。両方を送ると **400** を返す。memory-store コールのみを移行し、他の managed-agents エンドポイントは元のヘッダのまま。
- **SDK はすでに切り替わっている。** Python 0.116.0、TypeScript 0.110.0、Go 1.56.0、Java 2.48.0、Ruby 1.55.0、PHP 0.36.0、C# 12.35.0、CLI 1.16.0 はすべて memory-store コールで自動的に `agent-memory-2026-07-22` を送る。コードが明示的に `betas` を渡す場合、そこの `managed-agents-2026-04-01` を**置き換え**る — 両方を追加しない。

### Webhook: ポーリングなしで memory-store ライフサイクルに反応

**2026 年 7 月 22 日**にヘッダデフォルトと共に出荷: **3 つの `memory_store.*` Webhook イベントタイプ**が今やメモリストアのライフサイクルをカバーし、4 つの `environment.*` イベントがサンドボックス環境をカバー。これはほとんどのインテグレータが見逃す部分 — タイマーで `GET /v1/memory_stores` をポーリングする代わりに、エージェントランがメモリストアを作成、更新、または削除するのに反応できる。Managed Agents Webhook エンドポイントで購読し、イベントを自分の監査証跡やダッシュボードにルーティング。

### Dreams: バックグラウンドでメモリを再編成

2026 年 5 月 6 日のリリースノートで発表され、7 月 10 日に Claude Fable 5 と Sonnet 5 をサポートするよう拡張された **Dreams** は、既存のメモリストア*と*過去のセッショントランスクリプトを読み、**再編成された出力メモリストア**を生成するリサーチプレビュー: 重複がマージされ、古いエントリが置き換えられ、新しい洞察が表出。エンドポイントは `dreaming-2026-04-21` ベータヘッダでゲートされ、アクセスはリクエスト制。アプリの月次リキャップの API 側アナログとして扱う — ストアが沈殿しないようにするスケジュールされた反射パス。

## アプリ vs API — 1 つの表

| 側面 | Claude.ai アプリ | Managed Agents API |
|---|---|---|
| ストレージ単位 | カテゴライズされたエントリ | パスのメモリ |
| グループ化 | カテゴリ(プロフェッショナルコンテキスト、コミュニケーション設定、進行中プロジェクト、…) | パスセグメント(`/projects/acme/…`) |
| 読み書き | チャット中にライブ | セッション中のエージェントツールコール |
| 人間編集可能 | はい、Settings › Memory でエントリごと | はい、memory-store エンドポイント経由 |
| 消去 | エントリごと、またはすべて | メモリごと、プレフィックスごと、またはストア削除 |
| 反射 | 月次リキャップ(Settings › Reflect) | Dreams(リサーチプレビュー) |
| 分離 | インコグニトチャット | エージェントごと、セッションごとのメモリストア選択 |
| 利用可能性 | Free、Pro、Max、Team、Enterprise(プランごとに検証) | Managed Agents(公開ベータ) |

これが AILmanac の残りのどこにいるか:

- [メモリとコンテキスト編集](/docs/api/memory-and-context-editing) — *クライアント側*メモリツール、異なる獣: ストレージを実装。
- [チャット横断メモリ](/docs/claude-app/memory) — アプリメモリの初心者向け概要。
- [エージェントメモリアーキテクチャ](/docs/frontiers/agent-memory-architectures) — カテゴライズされたエントリが回転サマリより勝る理由を理解するエピソディック対セマンティックメモリの理論。
- [Managed Agents](/docs/api/managed-agents) — ここで説明された memory-store 面をホストするハーネス。
