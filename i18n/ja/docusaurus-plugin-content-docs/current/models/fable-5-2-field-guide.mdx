**2026年11月9日**、Anthropic は **Claude Fable 5.2**（`claude-fable-5-2`）と、認証制の姉妹モデル **Claude Mythos 5.2**（`claude-mythos-5-2`）をリリースしました。このリリースがこれまでのどの Claude フラッグシップとも構造的に違う点は一つです。**置き換え対象のモデルより安い**ことです。Fable 5.1 は入力100万トークンあたり $10、出力100万トークンあたり $50 でしたが、Fable 5.2 は **$8 と $40**（20%減）で、出力生成は最大30%高速になっています。

これは易しい側の話です。難しい側は、このリリースで最も影響の大きい変更が新機能では**なく**、動いている統合を最も壊しやすいという点です。thinking ブロックのプレフィックスチェックは、Fable 5.1 では 2026年8月31日以降に作成されたアカウントでのみエラーになっていましたが、**今回すべてのアカウントに適用されます**。会話履歴を編集するコードは、古いアカウントで2か月間エラーなく動いてきました。モデル ID を差し替えると 400 が返ります。

## 一段落でわかる要約

Fable 5.2 は [Fable 5.1](/docs/models/fable-5-1-field-guide) の後継で、Opus の上に位置する同じ Mythos クラスの階層、同じ100万トークンのコンテキスト、同じ最大出力128K、同じトークナイザー（Opus 4.7 で導入されたもの）、同じ常時オンの適応的 thinking、同じバンド内の `stop_reason: "refusal"` の挙動、同じ30日間の保持要件（ZDR なし）を備えています。Anthropic のガイダンスは変わりません。**まず現行の Opus、つまり Opus 5.5 から始め**、「Claude Opus モデルを高い effort で評価しても要件を満たさないとき」に Fable 5.2 を使います。新しいのは、20%の価格引き下げ、最大30%速い出力、トークン速度2.5倍・価格2倍のオプションの fast モード、4つの破壊的変更、そして既存のシステムプロンプトの複数の行を無意味または明確に高コストにするプロンプティング上の変化です。

## 4つの破壊的変更

いずれも静かな劣化ではなく 400 エラーです。この順で確認してください。最初のものは、何も悪いことをしていない人が引っかかる変更です。

### 1. プレフィックスチェックがすべてのアカウントに適用される

これは二度読むべき変更です。Fable 5.2 の thinking ブロックはそれぞれ、その前にあったすべての状態（`system` プロンプト、`tools` 配列、これまでの各メッセージ）を記録します。これらのいずれかが変わった後で thinking ブロックを送り返すと、API はリクエストを拒否します。

```text
The block is bound to a different conversation
```

**Fable 5.1** では、この 400 は **2026年8月31日以降**に作成されたアカウントでのみ発生しました。**Fable 5.2 では、アカウントの古さに関係なくすべてのアカウントで発生します。**（Mythos 5.1 は Claude API で既にこの挙動だったため、Mythos から移行する場合、この部分は変更ではありません。）

結果は具体的で厄介です。履歴を書き換えるハーネス（以前のターンにリマインダーを挿入する、古いメッセージを削る、セッション途中でシステムプロンプトを差し替える、何かを並べ替える）は、その日付より前に作成されたアカウントではエラーなく動いてきました。モデル ID を変えた途端に失敗し始め、その失敗は自分のコードの潜在バグではなく、新モデルの退行のように見えます。

:::danger[Fable 5.1 でエラーが出たことがなくても、これをテストする]
「今は動いている」は証拠になりません。`messages` 配列を自分のコードで組み立てている場合、Fable 5.1 でこのエラーが出なかったのは、アカウントが 2026年8月31日より前に作られたからにすぎない可能性があります。差し替えの後ではなく、前にテストを実行してください。
:::

次の条件が**すべて**成り立つなら、変更なしで安全です。`system` と `tools` が会話全体で同一である。コードが `messages` に**追記するだけ**である。各アシスタントターンが、API が返したとおり、すべてのブロックを元の順序のまま送り返されている。Claude Code、claude.ai、Claude Managed Agents、Claude Agent SDK がリクエストを組み立てる場合も安全で、その場合はモデル ID の変更が移行のすべてです。

編集を直す前に出荷しなければならない場合の暫定策は、`thinking-binding-controls-2026-08-01` ベータヘッダーを送り、`thinking.block_binding.prefix_mismatch_behavior` を `"drop_block"` に設定することです。リクエストは成功し、破棄された各ブロックがトップレベルの `input_transformations` 配列に列挙されます。これは設定ではなく暫定策として扱ってください。Anthropic 自身のテストでは、以前の thinking がターンごとに破棄されると、モデルは**最初から考え直し、より多くの出力トークンを使いました**。頼る前に、自分のタスクで計測してください。

恒久的な対処は追記専用の道具立てです。指示の変更には[会話途中のシステムメッセージ](/docs/api/mid-conversation-system-messages)、ターン単位のリマインダーにはターンスコープのシステムメッセージ、履歴を短くするにはコンパクション（要約の後に以前のターンを**一切残さない**もの）またはコンテキスト編集を使います。

### 2. Fable 5.2 の thinking ブロックは一方通行

Fable 5.2 と Mythos 5.2 は互いの thinking ブロックを読めます。また Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 5.1、Mythos 5.1、Opus 5、Fable 5、Mythos 5、およびそれ以前の Opus/Sonnet/Haiku モデルのブロックも読めます。**それ以外のモデルは、これらのブロックを読めません。**

つまり、会話を Fable 5.2 に*移す*と推論が保たれます。Fable 5.2 から*外へ*移すと、そこで走ったすべてのターンの推論が失われます。これには Opus 5.5、Fable 5.1、そして Fable 5.2 自身のフォールバック先である Opus 4.8 と Opus 5 の両方が含まれます。ルーター、コスト削減のためのダウングレード、サーバー側の拒否フォールバックを運用しているなら、これは理論上の話ではなく実際の挙動変更です。

失敗の仕方は静かです。API は読めないブロックをモデルに見せる前に破棄し、リクエストは成功し、破棄されたブロックは課金されません。`thinking-binding-controls-2026-08-01` ヘッダーを送って `input_transformations` を読んだときにだけ見えます。

モデルへの紐づけに加えて、もう一つの紐づけがあります。**Fable 5.2 の thinking ブロックは、それを生成したアカウント、またはそれにリンクされたアカウントでのみ機能します。** 別のアカウントからのリクエストは、ブロックが静かに破棄されたまま成功し、ベータヘッダーがあれば `reason: "organization_binding_mismatch"` として報告されます。環境間でトランスクリプトを移すときに影響します。

### 3. `computer_20251124` は Bedrock 以外では廃止

Fable 5.1 は computer use を2通りで受け付けていました。`computer_toolset_20260801` ツールセットと、`computer-use-2025-11-24` ベータヘッダーの背後にある古い `computer_20251124` ツールです。Fable 5.2 と Mythos 5.2 は**ツールセットのみ**をサポートします。`computer_20251124` を宣言すると、**Amazon Bedrock を除く**すべてのプラットフォームで 400 `invalid_request_error` が返ります。Bedrock では古いツールが従来どおり動きます。

複数のプラットフォームで運用している場合、この Bedrock の例外は覚えておく価値があります。同じリクエストボディが Bedrock では有効で、Claude API では無効になりえます。

### 4. Fable 5.2 の executor には Fable 5.2 または Mythos 5.2 の advisor が必要

ベータの [advisor ツール](/docs/api/tool-use)では、advisor は少なくとも executor と同等の能力が必要です。Fable 5.2 または Mythos 5.2 の executor は、advisor として `claude-fable-5-2` か `claude-mythos-5-2` **のみ**を受け付けます。それ以外の値は、Fable 5.1 や Mythos 5.1 を含めて 400 を返します。

順序に関する落とし穴があり、一度噛みついて1時間混乱させます。advisor の `model` を変えることは **`tools` の編集**なので、破壊的変更 #1 に引っかかります。advisor の変更は、既存の会話の途中ではなく**新しい会話**で行ってください。現在の executor を維持したまま advisor だけをアップグレードしたいなら、`claude-fable-5-2` に設定します。この値はどの executor モデルも受け付けます。

もう一点。助言を単に受け渡すのではなく、そのテキストをコードで読む場合、Fable 5.2 の advisor は助言を**暗号化して**返します。

## いま削除すべきプロンプトの行

飛ばされがちですが、飛ばすべきではないセクションです。Anthropic は、以前のモデル向けに書かれた指示のうち、Fable 5.2 で効かなくなったか、お金がかかるようになったものをいくつか文書化しています。

**「考えずに直接答えて」はもう効きません。** Fable 5.1 は通常、このような行に従いました。Anthropic のテストでは、`medium` 以上の effort では Fable 5.2 が考えるのを**止められず**、`high` 以上ではあいさつへの返信も含めてほぼすべての返信の前に考えます。解決策はより良い文ではなく、**そのターンの effort を下げる**ことです。行を削除して、ダイヤルを変えてください。

**プロンプトに書いたトークン予算がコストになっています。** タスクが使えるトークン数と残りをプロンプトでモデルに伝えるハーネスがあります。Anthropic の `high` と `xhigh` でのコーディングタスクのテストでは、**大きな予算を取り除くと、同等の性能でコストが下がりました**。（これは*プロンプト内のテキスト*についてで、テストの対象外だった API のベータ機能 task-budgets の話ではありません。）

**委任を促す常設の指示。** サブエージェントに仕事を回す行は、システムプロンプト、skill、エージェントファイルに蓄積します。Fable 5.2 は、プロンプトが促すハーネスでは積極的に委任し、Anthropic はサブエージェントがセッションのコストの大きな割合を占めうると述べています。移行前にそれらのファイルを読み、ハーネスがサブエージェントをデフォルトでどのモデルで動かすかを確認してください。

**厳格なスタイル制限は文章をぶつ切りにします。** Fable 5.2 はスタイル規則に忠実に従うため、「1文に指示は1つ、20語以内」のような規則は、害になるほど文字通りに守られます。

**Opus 5.5 ガイドの「その答えは完了として扱う」という行。** この2文は、`high` の effort でのフォローアップ質問に対する Fable 5.2 の thinking を実際に減らします。しかし Anthropic のテストでは、モデルが**以前の回答の誤りを指摘する可能性も大幅に下がりました**。ほとんどのアプリケーションでは割に合わないトレードです。モデルに自分の作業を見直し続けてほしい場面では入れないでください。

**蓄積された注意書き。** これは微妙で、5.2 が指示にどれだけ忠実に従うかに特有の問題です。慎重なルールは、コンテキストが引き継がれる場所（メモリファイル、ノート、指示ファイル、エージェント間メッセージ）に積み上がり、一部はモデル自身が書いたものです。Anthropic の数字では、以前のセッションからのメモが十数件あり、そのうち1件が「再試行しない」と書いていた場合、ツールがビジーだったときにモデルが再試行したのは約**10回中4回で、メモがなければほぼ毎回**でした。コンテキストにあるレビュアーエージェントの「最初のエラーで止める」だけで、Fable 5.2 は約3分の1の試行で再試行しなくなりました。同じ設定で **Fable 5.1 と Opus 5.5 はどちらも再試行しました**。

実際に効く対処は直感に反します。例外を認める別の行を足すのではなく、**例外をルール自体に書き込む**ことです。責任者が承認済みのステップに対して素の「決して〜しない」ルールがあると、モデルがそれを実行したのは約**10回中1回**でした。承認済みのステップにはゴーサインがあると述べる別の行を足してもほとんど変わらず、ルール自体を「まずゴーサインを取る」と書き直すと約**10回中9回**になりました。

## トークンに見合う2つのプロンプト追加

### タスクを最後までやり切る

Fable 5.2 は、作業が終わる前にターンを終えることがあります。残りの一覧で締める、続行を申し出る、タイムアウトのような通常の障害で止まる、といった形です。`low` と `medium` の effort で多く起こります。Anthropic はこのためのシステムプロンプトのテキストを公開しており、エージェント型コーディング製品のセッションを再生した `medium` の effort での測定効果は、**やり残しのある状態で終わるセッションが約半分に減る**一方、**出力トークンが約30%増える**というものでした。

This does not override the need for confirmation on risky or destructive actions.`}
</PromptCard>

これを自分用に調整するときに残す価値のある構造上の考え方は、**2種類の障害を分ける**ことです。通常の失敗（エラー、タイムアウト、ビジーなツール）は診断して乗り越えます。意図的な障害（触れないと印のついたファイル、意図的に与えられていないアクセス、安全上のガードレール）は手をつけず、報告します。Anthropic は、このテキストが許可を求める終わり方のほとんどをなくした一方、残りを列挙して止まる終わり方は**なくならなかった**とも述べています。

設計上考慮すべき帰結が一つあります。モデルが確認を求める頻度が減るため、**リスクのある操作や不可逆な操作には、自前の確認ステップを残してください。** プロンプトはゲートの代わりにはなりません。

### コードの所有者を伝える

これはリリース全体で最も印象的な測定効果で、しかも一文です。Fable 5.2 は、コードの所有者についてプロンプトが述べる内容に敏感に反応します。プロンプトが所有権について何も述べていない場合や、コードベースを他人のものとして書いた場合、モデルは**重複することになっても既存の構造に追加し**、**近くの問題を直さずに報告する**傾向がありました。

<PromptCard title="コードの所有権 — 一文で、効果は測定済み">
{`This codebase is yours: what it's for and how it's built are your call, and you'll keep building on it.`}
</PromptCard>

小さなコーディングタスクでの Anthropic の数字：この一文があると、モデルは約**半数**の試行で重複コードを統合し、なければ**10分の1未満**でした。この効果は、一文が長いシステムプロンプトの中にあっても保たれました。

では請求書です。これはトレードであり、ただの勝利ではありません。この一文があると、モデルは約**1.5倍の出力トークン**を使い、頼まれていない変更（多くは新しいテストとドキュメント）を複数行い、さらにバグ修正を除いて、**既存機能の挙動を6〜10回に1回変えました**。effort が高いほど頻度は上がりました。最後の要約は大きな変更には触れていても、小さな変更はしばしば抜けていました。

:::warning[要約ではなく diff をレビューする]
この最後の知見が運用上の要点です。モデル自身のまとめは、行ったことの完全な変更履歴ではありません。また、プロンプトの別の場所にあるスコープ制限はこの一文を**打ち消しません**。同じプロンプトの前の方に「ついでのリファクタリング、名前変更、整理はしない」とあっても、モデルは約3分の1の試行で重複コードを統合しました。ユーザーがコードを所有していて最小限の変更を望む場面では、この一文は入れないでください。
:::

## effort：high から始め、各レベルの用途を知る

Fable 5.2 は5つの effort レベルすべてをサポートし、Claude API のデフォルトは **`high`** です。Anthropic の整理では、**能力向上の大部分は `high` で既に得られており**、それ以上では向上にばらつきがあり、タスクに依存します。

| レベル | Anthropic が推奨する用途 |
|---|---|
| `low` | 手早いやり取り、仕様が明確なタスク、大量処理、高速なサブエージェント。ここでのスコアは、**より高い effort での Fable 5.1 に近い**水準でした。 |
| `medium` | 対話的なコーディング、チャット、日常的な知識労働。 |
| `high` | 難しいコーディング、リサーチ、エージェント的作業、無人の長時間実行。デフォルト。ターンは `medium` よりかなり長くかかります。 |
| `xhigh` | 最も難しい長時間のコーディングとエージェント作業で、*向上を計測できた場合*。社内のコーディングスコアをわずかに押し上げ、トークンを大幅に多く使いました。 |
| `max` | 上限の計測、または科学的発見や数学のような、時間とトークンが問題にならないオープンエンドな問題。 |

レベルを選ぶ際に覚えておく3つの挙動があります。モデルは**低い effort ほど早く止まりやすい**ので、`low`/`medium` のエージェント作業には上の「タスクを最後までやり切る」のテキストを組み合わせてください。`high` 以上では**ほぼすべての返信の前に考える**ので、プロンプトで thinking を消そうとせず、簡単なターンは低いレベルに回してください。そして **effort は返信の長さをほとんど変えません**。それはダイヤルではなくプロンプトの仕事です。

一つのワークフローでレベルを混在させることもできます。`medium` で計画し、無人の長い区間では effort を上げる、といった具合です。プロンプトキャッシュを*リセットせずに*会話の途中でレベルを変えるには、メッセージ単位の effort（ベータ、`mid-conversation-output-config-2026-07-01`）を使います。トップレベルの `effort` を新しく設定するとキャッシュが最初からになります。詳しくは [Effort Tuning](/docs/api/effort-tuning) と [Thinking & Effort](/docs/api/thinking-and-effort) を参照してください。

**3点目：最大の跳躍は最も狭い領域にあります。** RoboDojo Sim は2倍超（27.6% → 64.9%）、Remote Labor Index も2倍超（17.9% → 41.3%）です。印象的ですが、あなたのアプリケーションについて何かを予測する可能性が最も低い行でもあります。一般的な教訓と6つの質問のチェックリストは [AI ベンチマークに騙されずに読む方法](/docs/models/reading-ai-benchmarks) を参照してください。

Mythos 側では、Anthropic の表はセーフガードが効く場面でちょうど Fable 5.2 をわずかに上回ります。CyScenarioBench で **76.3%**、CVE Rediscovery で **89.6%**、24時間の de novo バインダー設計で **85.1%**、Terminal-Bench-Science 0.1 で **75.3%** です。

## Fable 5.2 と Mythos 5.2

Anthropic 自身の声明が最も明快な位置づけであり、言い換えるより引用する価値があります。「Claude Fable と Claude Mythos は同じ基盤モデルです。Fable には悪用を防ぐための強力なサイバーセキュリティおよび生物学のセーフガードがあり、それによってすべてのユーザーに提供できます。」

つまり Mythos 5.2 は大きなモデルではありません。サイバーと生物学のセーフガードを外した同じ重みで、**Cyber Verification Program** などのプログラムで検証された組織のみが利用できます。Anthropic は、Fable 5.2 のセーフガードは「Fable 5.1 と同等に堅牢でありながら、不要なブロックが少ない」とも述べています。5.1 で無害なセキュリティやライフサイエンスの作業が分類器に引っかかっていたなら、アクセス申請を考える前に、誤検知率は下がっているはずです。

実務上は、両者は互いの thinking ブロックを読めるので、会話を行き来させても推論は保たれます。拒否が正当な作業を妨げているなら、道は検証プログラムであり、プロンプトによる回避策ではありません。

## 拒否とフォールバック

Fable 5.2 はバンド内で拒否します。**HTTP 200** で `stop_reason: "refusal"` と、カテゴリを示す `stop_details` オブジェクトが返ります。カテゴリは5つです。

- `cyber`：マルウェアやエクスプロイトの開発を可能にしうる
- `bio`：危険な実験手法など、生物学的被害を可能にしうる
- `frontier_llm`：競合する AI モデルの開発を助けうる
- `reasoning_extraction`：モデルに内部の推論を応答テキストで再現するよう求める
- `general_harms`：その他の利用ポリシー領域

運用上の注意が2点あります。Fable 5.2 に許可されているサーバー側フォールバック先は **Opus 4.8 と Opus 5** で、破壊的変更 #2 のとおり、どちらも Fable 5.2 の thinking ブロックを読めないため、フォールバックすると会話の推論が失われます。また **`reasoning_extraction` には推奨フォールバックがない**ため、その拒否はそのまま確定します。対処は、応答テキストで推論を求めるのをやめ、代わりに `display: "summarized"` で thinking ブロックから読むことです。

## 出典間の矛盾：解決せず報告する

2026年11月10日時点で、Anthropic の2つの公式ページが Fable 5.1 の状態を異なる形で記述しています。[モデル概要](https://platform.claude.com/docs/en/models/overview)は `claude-fable-5-1` を **"Legacy models (still available)"** の下に載せています。[モデルの非推奨化](https://platform.claude.com/docs/en/about-claude/model-deprecations)のステータス表は **Active** とし、非推奨の発表はなく、廃止は早くても 2027年9月1日以降としています。

これらは対立というより両立しうるもので、その区別は有用です。Anthropic 自身のライフサイクルの用語では、**Legacy** は「今後は更新を受けず、将来非推奨になる可能性がある」という意味で、廃止日が割り当てられる **Deprecated** の一段手前です。概要ページのグルーピングは編集上のシグナルで、ステータス表は契約上のシグナルです。Anthropic は、公開済みのモデルを廃止する前に少なくとも **60日前の通知**を約束しており、そのカウントは通知が出た時点から始まります。

いずれにせよ、ぐずぐずする理由はありません。Fable 5.1 は今や後継モデルより**高い**のです。ライフサイクルの全体の追跡は [Deprecation & Migration Watch](/docs/whats-new/deprecations) を参照してください。

## よくある間違い

- **「Fable 5.1 で動く」を、履歴の扱いが正しい証拠として扱う。** アカウントが 2026年8月31日より前に作られたことしか証明していないかもしれません。この移行で最も噛みつかれやすいのがこれです。
- **`"drop_block"` を暫定策ではなく解決策として使う。** 400 を請求に変えるだけです。thinking が破棄されると、モデルは考え直します。
- **effort レベルを持ち越す。** モデルが違えば、同じ語でも thinking の量が違います。もう一度スイープしてください。
- **「直接答えて」の行をプロンプトに残す。** `medium` 以上ではもう効かず、それでもトークンを消費します。代わりに effort を下げてください。
- **ユーザーが所有するコードベースにコード所有権の一文を足す。** 重複の統合を約5倍にし、出力トークンを約1.5倍にし、既存機能の挙動を6〜10回に1回変えます。一部のリポジトリには正しく、ほとんどのクライアントワークには誤りです。
- **会話の途中で advisor の `model` を変える。** `tools` を編集するので、プレフィックスチェックに引っかかります。新しい会話でのみ行ってください。
- **モデルの最後の要約を完全な diff として読む。** Anthropic 自身のテストでは、小さな変更は要約から漏れます。
- **ローンチ時の表だけでアップグレードする。** 2行は Fable 5.2 に不利で、そのうち1行は半額未満の Opus 5.5 に負けています。
