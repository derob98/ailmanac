**WWDC 2026(2026年6月8日発表)** で Apple は Foundation Models の第3世代 —— **AFM 3** —— を出荷し、さらに **Foundation Models フレームワーク** を、Swift を一切書かない人にも意味のある方向へ拡張した。フレームワークは *第三者の LLM プロバイダ* を受け入れるようになり(Anthropic Claude と Google Gemini が Swift パッケージとして提供される)、*オンデバイス* の経路は玩具のような 3B モデルにとどまらず、**200 億パラメータのスパース MoE** が Apple Silicon 上で動作するようになった。ほとんどのエキスパートを NAND に保持し、プロンプトが必要とするぶんだけを RAM にスワップする方式だ。Claude アプリを作っていて「オンデバイス」を API ワークフローとは別世界だと扱ってきた人にとって、その隔たりは今年で埋まりつつある。このページでは、実際に出荷されたもの、目立たない仕組み、そしていま利用できる具体的な移行と互換性の選択肢を解きほぐす。

## 一文で言うと

**AFM 3** はオンデバイス LLM における Apple の2度目の本格的な挑戦だ。再構築された **3B の密モデル(Core)**、iPhone 上で動作する新しい **20B のスパース MoE(Core Advanced)**(大半のエキスパートをフラッシュストレージに保持)、Apple Silicon と Google Cloud 上の NVIDIA GPU で稼働する **Cloud** と **Cloud Pro** の対、そして Anthropic Claude と Google Gemini を同じ `LanguageModel` プロトコルの背後で交換可能なファーストクラスのプロバイダとして扱う **フレームワーク** から成る。開発者はオンデバイス呼び出しを無料で利用でき、App Store Small Business Program に参加している 200 万初回ダウンロード未満の開発者は Private Cloud Compute も無料で使える。

## AFM 3 について、あまり語られない 3 つのこと

誰もが「Apple はオンデバイスの 3B モデルを出した」という見出しを書いている。ここでは、多くの記事が飛ばす仕掛けを取り上げる。

### 1. 20B モデルが iPhone に収まるのは、大半が RAM ではなく NAND に住んでいるからだ

「200 億パラメータのモデルを iPhone に」という言葉を素直に読むと不可能だ。4-bit にしても 20B の重みは約 10 GB あり、iPhone が RAM に保持できる量をはるかに超える。WWDC 2026 の発表によれば、Apple の仕掛けは **AFM 3 Core Advanced モデルの全体をフラッシュメモリ(NAND)に格納** し、推論時には **入力に応じてルーティングされたエキスパートだけを DRAM にスワップ** することだ。アーキテクチャには常駐する *共有エキスパート* と、ルータがプロンプトごとに選ぶ *ルーティング対象のエキスパート* があり(20B 全体ではなく **一度に 1〜4B のパラメータ** を活性化する)、**Quantization Aware Training** と組み合わせることで、実用 RAM が約 8 GB のデバイスで 20B クラスのモデルを出荷できている。結果として iPhone 側のレイテンシは、行列積よりも NAND の読み出し帯域幅とルータの選択に支配されるようになる —— 3B の密モデルとは大きく異なる性能プロファイルだ。

### 2. 制約付きデコーディングはランタイムではなく Swift コンパイラに組み込まれている

フレームワークの `@Generable` マクロはよく「構造化出力」と説明されるが、それでは過小評価だ。`@Generable` は *コンパイル時* に動作し、Swift 型に対して JSON スキーマとパーサを生成する。フレームワークはそのスキーマを **制約付きデコーディング** に使う —— つまりオンデバイスモデルはトークンレベルで、あなたの Swift 構造体にパースし直せる出力しか生成できない。「JSON として妥当であることを祈って、駄目なら再試行」という手はない。`@Guide` アノテーション(`.anyOf(["PG", "PG-13", "R", "G"])`、範囲、説明など)を付ければ、それらもデコード時に強制される。Claude のツール使用ループの周りで JSON 修復のフォールバックを書いてきた人は、アプリのオンデバイス 3B 側からその再試行層を丸ごと落とせる。

### 3. フレームワークは任意の LLM —— Claude や Gemini を含めて —— を一つの Swift API の背後で受け入れる

WWDC 2026 のセッション **「Bring an LLM provider to the Foundation Models framework」** では 2 つの新しいプロトコルが出荷された:**`LanguageModel`**(能力とエグゼキュータ構成を宣言)と **`LanguageModelExecutor`**(実際の生成、KV キャッシュ、ストリーミングを扱う)。誰でもこれらに準拠した Swift パッケージを出荷できる —— Apple は launch time のプロバイダとして Anthropic Claude と Google Gemini を明示的に挙げた。結果として、アプリの側から見れば、同じ `LanguageModelSession`、同じ `@Generable` 型、同じツール呼び出しコントラクト、同じトランスクリプトモデルが、背後のモデルがオンデバイスの 3B であれ、Private Cloud Compute であれ、Anthropic API 上の Claude であれ、Google Cloud 上の Gemini であれ、Hugging Face からの MLX 重みファイルであれ、そのまま適用される。モデル選定は SDK の書き直しではなく Swift パッケージの依存関係になる。

## オンデバイス呼び出しの最小例

フレームワークの目玉機能は、オンデバイスの 3B から、ほとんど儀式なしに型付き・スキーマ検証済みの出力を得られることだ。

<PromptCard title="@Generable の構造化出力を用いたオンデバイス 3B 呼び出し(Swift)">
{`import FoundationModels

@Generable
struct TripIdea {
    @Guide(description: "Short, evocative title")
    let title: String

    @Guide(description: "One-paragraph pitch, 40–80 words")
    let summary: String

    @Guide(.range(1...14))
    let estimatedDays: Int

    @Guide(.anyOf(["easy", "moderate", "hard"]))
    let difficulty: String
}

let session = LanguageModelSession()   // defaults to on-device Core
let idea = try await session.respond(
    to: "Suggest a shoulder-season trip in Puglia for a family with a 6-year-old.",
    generating: TripIdea.self          // constrained decoding
)

print(idea.title, idea.difficulty, idea.estimatedDays)
`}
</PromptCard>

実行時、モデルはトークンレベルで、走行中のテキストが `TripIdea` としてパース可能であり続けるトークンだけを出力するよう強制される。JSON 文字列を目にすることはなく、`TripIdea` 値を受け取る。これはセッションがオンデバイスの 3B、PCC、あるいは Swift パッケージとして接続した第三者プロバイダのいずれと話していても同じ契約だ。

## Claude を同じ Swift セッションに持ち込む

WWDC 2026 の「Bring an LLM provider」セッションはこれを具体化した:`LanguageModel` と `LanguageModelExecutor` を実装し、git タグ付き Swift パッケージとして公開すれば、すでにオンデバイス 3B を使っていたアプリコードはイニシャライザを 1 つ変えるだけで自分のプロバイダを呼び出せる。

<PromptCard title="LanguageModel に準拠した第三者プロバイダのスケッチ">
{`import FoundationModels

public struct ClaudeSonnet5: LanguageModel {
    public let capabilities = LanguageModelCapabilities(capabilities: [
        .toolCalling, .guidedGeneration, .reasoning
    ])
    public var executorConfiguration: ClaudeExecutor.Configuration
}

public final class ClaudeExecutor: LanguageModelExecutor {
    public struct Configuration: Hashable {   // hashable = KV-cache key
        public var modelID: String
        public var tokenProvider: TokenProvider   // NOT a plain API key string
    }

    public required init(configuration: Configuration) throws { /* … */ }

    public func respond(
        to request: LanguageModelExecutorGenerationRequest,
        model: Model,
        streamingInto channel: LanguageModelExecutorGenerationChannel
    ) async throws {
        // 1. Map Foundation Models transcript → Anthropic /messages payload
        // 2. Stream deltas back via channel.send(.response(action: .appendText(...)))
        // 3. Surface tool calls / reasoning via the same transcript entry types
    }
}
`}
</PromptCard>

API が意図的に押しつけてくる、2 つの微妙な点がある。第一に、**`Configuration` はわざと `Hashable`** だ:フレームワークは構成をキーにエグゼキュータをキャッシュするため、*同じ構成 = 同じエグゼキュータ = ターンを跨いで保持される KV キャッシュ* となる。第二に、ガイダンスはイニシャライザ内での **素の API キー文字列** を明確に非推奨としている —— `TokenProvider` やサインインフローを使い、トークンをキーチェーンに保存し、クラウド呼び出しには App Attest を使って、改ざんされたビルドが外部からエンドポイントを叩くのを防ぐことを推奨している。
