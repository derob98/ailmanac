（`gpt-6.1-sol`）を出荷しました。うたい文句は **「5 分の 1 の価格で Astra に近い知能」**。
Hacker News のトップに直行しました。

Claude ユーザーにとって興味深い事実はうたい文句ではありません。GPT-6.1 Sol が
**Claude Sonnet 5.5 のレートカードとまったく同じ**位置（入力 $2 / 出力 $10 per MTok）に
着地し、しかもキャッシュ入力は Sonnet 5.5 の **半額**だという点です。2 つのモデル、同じ
見出し価格、異なる請求額、異なる仕事の形。このページでは、スペック、ほとんどの記事が
飛ばす価格のメカニズム、ベンチマーク表の正直な読み方、そして DevDay が開発者向けに
出荷した残りの内容を扱います。

### コンテキストウィンドウではない 2 つの上限

**1,050,000 はウィンドウです。922,000 が入力の上限です。** この差は、より大きな文書に使える
余裕ではありません — 推論と出力が必要とする部屋です。検索ステップを「1M コンテキスト」を
前提にサイズ設計すると、マーケティング上の数値より約 12% 早く上限に当たります。しかも当たるのは
最悪のタイミング、プロンプトを組み立てる費用をすでに払った後です。

**さらに 272K に価格の崖があります。** これを越えると入力とキャッシュ入力が倍になり、出力は
1.5 倍になります。これは GPT-6 Astra と同じ崖で、ロングコンテキスト作業の経済性を大きく
変えます:300K トークンのプロンプトは 272K のものより 10% 高いのではなく、入力側でほぼ 2 倍
かかります。境界の近くにいるなら、その下に収まるよう圧縮することは本気のエンジニアリング努力に
値します。Claude は 1M ウィンドウの価格付けが異なります — [プロバイダー間の AI
コスト](/docs/models/what-ai-costs-across-providers) と [プロバイダー間のプロンプト
キャッシュ](/docs/models/prompt-caching-across-providers) を参照してください。

## 罠:ツール呼び出しは両方の API にはない

モデルページは **Chat Completions（ツール呼び出しなし）** と **Responses API
（ツール呼び出しあり）** を挙げています。既存の統合を移植するなら、そこは 2 回読んでください。

あなたのコードが Chat Completions に POST しているなら — サードパーティのライブラリ、
ゲートウェイ、「OpenAI 互換」ラッパーの多くがデフォルトで使うエンドポイントです —
**このモデルで function calling は使えません。** 直し方はパラメータではなく、別の
エンドポイントと別のリクエスト形式です。

同じく非対応:Live、Realtime、Assistants、ファインチューニング、埋め込み、画像生成、動画、
音声合成と文字起こし、モデレーション、そしてレガシーの Completions。サポートされるツールの
リストは広い — ウェブ検索、ファイル検索、画像生成、コードインタープリタ、ホスト型シェル、
apply patch、skills、コンピュータ使用、MCP、ツール検索 — が、それは **Responses API** の
リストです。

## Claude と正しく比較する

見出しの数字は同じ、メカニズムは違います。

| | **GPT-6.1 Sol** | **Claude Sonnet 5.5** | **Claude Opus 5.5** |
|---|---|---|---|
| 入力 / 出力 per MTok | $2 / $10 | $2 / $10 | $4 / $20 |
| キャッシュ読み取り per MTok | **$0.10** | $0.20 | $0.20 |
| コンテキスト | 1.05M（入力 922K） | 1M | 1M |
| 最大出力 | 128K | 128K | 128K |
| ロングコンテキスト追加料金 | **あり、272K 超** | 公表された崖なし | 公表された崖なし |

見出しの同額よりも重要な帰結が 2 つあります。

**長いエージェントループでは、GPT-6.1 Sol のキャッシュ読み取りが安い行になります。** $0.10 対
$0.20 は 2 倍の差で、しかもエージェント的ループが毎ターン再び支払う項目です。プロンプトが
大きな安定した接頭部＋小さな差分なら — それはまさにエージェントの形です — 請求額が実際に
住んでいるのはそこです。

**272K を超えると方向が激しく反転します。** Anthropic は Claude 5.5 モデルに同等の崖を公表して
いないので、本当に 400K のコンテキストを必要とするワークロードはまったく異なる曲線で
価格付けされます。何かを比較する前に、自分が 272K のどちら側に住んでいるかを知ってください。

## ベンチマークを正直に読む

OpenAI の launch 時の数値を、launch 時点でまとめたもの。ベンダー実施であり、まだ誰も独立に
再現していません。

| ベンチマーク | GPT-6.1 Sol | GPT-6 Astra | Claude | タスクあたりコスト |
|---|---|---|---|---|
| **DeepSWE v1.1**（ソフトウェアエンジニアリング） | **75.2%**（high） | 74.8%（high） | Sonnet 5.5:71.0% | 約 $1.50 対 Astra 約 $7.70 |
| **OSWorld 2.0**（コンピュータ使用） | 71.4%（max） | **73.5%**（max） | Opus 5:60.3%（medium） | $1.30 対 Astra $9.30 |
| **GDP.pdf**（文書解析） | 32.0% | **32.2%** | Opus 5.5:28.8% | — |
| **AutomationBench 1.0.6**（業務ワークフロー） | 36.0% | — | **Sonnet 5.5:44.7%** | $0.30 対 Sonnet 約 $1.14 |
| 低 effort での事実誤り率 | **7.7%** | — | — | （GPT-6 Sol:11.4%） |

この表から受け取るべきことは 3 つです。

**1. 強い主張はコストの主張です。** DeepSWE で Astra に 0.4 ポイント勝つのはノイズです。
それをタスクあたり約 5 分の 1 のコストで行うのはノイズではありません。このリリースで興味深い
比較は、品質での Sol 対 Astra ではありません — 同じ品質に対する価格での Sol 対 Astra です。

**2. AutomationBench は OpenAI が前面に出さなかった行です。** Claude Sonnet 5.5 が
**44.7%**、GPT-6.1 Sol が **36.0%** — 業務ワークフロー自動化で 8.7 ポイント差、しかも
タスクあたりコストは約 4 倍。これはどちらかの圧勝ではなく、本物のトレードです:失敗した
ワークフローのコストが $0.84 を超えるなら、高いモデルが安いモデルです。リーダーボードでは
なく、自分の失敗コストで決めてください。

**3. 最良のコンピュータ使用の数値でも 71.4% です。** その能力のために設計された
ベンチマークで、おおよそ 10 タスクに 3 つが失敗します。[コンピュータ使用エージェントの
比較](/docs/models/computer-use-agents) にある確認ゲートの話はすべてそのまま当てはまります。

事実誤り率の数値は、最も静かで興味深い数字です:**低 effort で 7.7%**、GPT-6 Sol の
11.4% から低下しました。誤り率が特に*安い設定で*改善することが、ワークホースのモデルを
フォールバックではなくデフォルトとして使えるものにします。
