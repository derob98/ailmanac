## 一文で言うと

V4.1-Flash は DeepSeek 初の **新アーキテクチャ** (**Compressed Sparse Attention 2** を備えた「Causal Encoder-Decoder」) 上のモデルで、MIT ライセンスで公開され、**ネイティブビジョン**、**1M トークンウィンドウ**、**最大出力 384K**、そして **1 から 100 まで連続的に制御可能な推論努力** を備える。V4 時代のすべての Flash エンドポイントを即座に置き換え、**9月14日** からは V4.1-Pro が登場するまで、すべての `deepseek-v4-pro` 呼び出しにも Flash 価格で応答する。

## Claude ユーザーが見逃してはならない 3 つのこと

### 1. DeepSWE の同等性と Terminal-Bench の劣勢は同じ事実を二度見ているにすぎない

DeepSeek のローンチ表のうち、エージェント開発チームにとって重要な列:

| ベンチマーク | DeepSeek-V4.1-Flash | Claude Opus 5 | GPT-5.6 Sol |
| --- | --- | --- | --- |
| **DeepSWE v1.1** (解決率) | **74.2** | 74.0 | 73.0 |
| **Terminal-Bench 3.0** | 30.0 | **43.3** | — |
| **Terminal-Bench 4.0** | 31.2 | **51.8** | — |
| **CyberGym** | 88.1 | — | — |
| **AutomationBench** | 54.8 | — | — |

DeepSWE は、リポジトリを読み、パッチを計画し、それを適用するモデルに報いる: 長いコンテキスト、慎重な検索、少数の大きな編集。Terminal-Bench は、各判断が直前のツール結果に依存する、多数の短く適応的なシェルターンに報いる。V4.1-Flash は 1M トークンのコンテキストと安価なキャッシュを持つので、前者の形状に適している。**プリフィル時に 8B、デコード時に 16B のアクティブパラメータ** で動作しており、これは密な最先端モデルに比べて「ステップあたりの思考量」がはるかに少ないため、後者の形状では苦しむ。あなたの仕事がプルリクエストのように見えるなら、同等性の主張は信頼でき、評価する価値がある。あなたの仕事が対話型のターミナルセッションのように見えるなら、20 ポイントの Terminal-Bench の差が予算を組むべき数値だ。同じ分裂は一週間前の Google の [Gemini 3.8 Flash](/docs/models/gemini-3-8-flash) のローンチでも、同じアーキテクチャ上の理由で現れている。

ベースモデルの行はより静かな物語を語る: **MMLU-Pro 74.1** (V4-Flash 68.3、V4-Pro 73.5)、**HumanEval 79.4** (V4-Flash 69.5)、**GSM8K 93.0** (V4-Flash 90.8)。新しい「Flash」は先月の「Pro」よりも優れたベースであり、これが DeepSeek が Pro のトラフィックをそこへルーティングすることに抵抗がなかった理由だ。

### 2. 推論努力ダイヤルは本物のダイヤルであり、請求額に直結する

Claude の `effort` (`low`/`medium`/`high`/`max`) とは異なり、V4.1-Flash は **1 から 100 の整数** を公開している。DeepSWE v1.1 における DeepSeek 自身のアブレーション: **effort 25 は 66.0%、effort 100 は 74.2%** をスコアし、最高設定は **およそ 2.5 倍の出力トークン** を出力する。また、**60–80 の帯域は最大努力の精度の大部分を半分未満のトークン予算で提供する** とも述べている。上のすべてのベンチマーク行は `reasoning_effort=100` で実行された。つまり同等性の数値は高価な数値だ。まず 100 で再現し、次に自分の評価がまだ合格する最も安い設定まで下げていく。これは [推論モデルの比較](/docs/models/reasoning-models-compared) で Gemini の `thinking_level` と Claude の `effort` に対して推奨しているのと同じ規律である。

### 3. クライアント側の変更なしに 2 つのルーティング変更が起きた

- **9月10日** から、`deepseek-v4-flash` と `deepseek-v4-flash-vision-exp` は **V4.1-Flash にルーティング** され、Flash レートで課金される。[V4-Flash-Vision-Exp](/docs/models/deepseek-v4-flash-vision-open-multimodal) ページの数値は、今やホストされたエンドポイントではなくオープンウェイトを記述するものになった。
- **9月14日 04:00 UTC** から、すべての `deepseek-v4-pro` リクエストも「V4.1-Pro がローンチするまで」Flash レートで **V4.1-Flash にルーティング** される。

`deepseek-v4-pro` に固定した評価があるなら、あなたの本番モデルは日曜日の朝に足元で変わった。スイートを再実行すること。利点は同じ呼び出しが今や Pro レートのおよそ 4 分の 1 のコストになることで、欠点はあなたがチューニングした Pro 固有の挙動が消えたことだ。これはまさに、プロバイダがモデル ID をエイリアスする際に [モデル間でのプロンプトの移植](/docs/models/porting-prompts-across-models) が警告する失敗モードである。

## モデルカードの概要

| 仕様 | DeepSeek-V4.1-Flash |
| --- | --- |
| **API モデル ID** | `deepseek-flash` |
| **リリース** | 2026年9月10日 (API + オープンウェイトを同日公開) |
| **パラメータ** | 合計 552B; プリフィル時 8B、デコード時 16B アクティブ |
| **MoE レイアウト** | MoE 層ごとに 384 のルーテッドエキスパート + 1 の共有エキスパート; トークンあたり 6 のルーテッドエキスパートがアクティブ |
| **アーキテクチャ** | Causal Encoder-Decoder、Compressed Sparse Attention 2 (CSA2) |
| **KV キャッシュ** | 1 トークンあたり 890 バイト (FP4、E2M1): HBM では V4-Flash の約 1/4、SSD ストレージでは約 1/8; グローバル KV キャッシュの寿命は最低 72 時間 |
| **コンテキスト / 最大出力** | 1M トークン / 384K トークン |
| **ビジョン** | ネイティブ; ゼロから学習した DeepSeek-ViT、2D-RoPE、3×3 pixel-unshuffle ダウンサンプリング |
| **推論制御** | `reasoning_effort` 整数 1–100 |
| **ライセンス** | MIT |
| **ウェイト** | BF16、F32、F8_E4M3、I8 の Safetensors |
| **サービング** | vLLM、SGLang、Docker Model Runner、Transformers; `inference/` フォルダにリファレンス推論コード |
| **推奨サンプリング** | temperature 1.0、top_p 0.95 または 1.0、コンテキスト 1M |
| **API 同時実行数** | 2,500 |

KV キャッシュの行がアーキテクチャ上の見出しだ。1 トークンあたり 890 バイトなら 1M トークンの会話でもキャッシュは 1 ギガバイト未満であり、これが DeepSeek が 72 時間のキャッシュ寿命を約束し、キャッシュヒットを 1 セントの数分の一で価格設定できる理由である。同じ問題に対する Anthropic の答えは [Claude Fable 5.1](/docs/models/fable-5-1-field-guide) でのより安いキャッシュ読み取りレートで、DeepSeek の答えはキャッシュを物理的に小さくすることだ。どちらも同じ習慣へと導く: 安定したプレフィックスを先頭に置き、実行中に決して編集しないこと。[プロンプトキャッシング](/docs/api/prompt-caching) を参照。

## 価格: ピーク時間の罠

DeepSeek は 2 段階のレート表を維持している。**ピーク時間は月曜から金曜の 01:00–04:00 および 06:00–10:00 UTC**; それ以外はすべてオフピークで、ピークレートのちょうど **半額** である。

| 100 万トークンあたり | ピーク | オフピーク |
| --- | --- | --- |
| 入力、キャッシュヒット | $0.006 | $0.003 |
| 入力、キャッシュミス | $0.30 | $0.15 |
| 出力 | $1.20 | $0.60 |

ここから 2 つのことが導かれる。第一に、「100 万あたり $0.003」という見出しは *オフピークのキャッシュヒット* 価格であり、6 つのセルのうち最も安いものだ; ピーク時間のコールドなエージェント実行は入力でその 100 倍を支払う。第二に、ピーク時間帯は UTC で定義されており、ヨーロッパの朝と米国の深夜の終わりをカバーしている。09:00 UTC にスケジュールされたバッチジョブは、同じジョブを 11:00 UTC に実行する場合の 2 倍を支払う。ずらせるならずらすこと。これらのセルを Anthropic、OpenAI、Google の定価と並べるフレームワークには [プロバイダ横断の AI コスト](/docs/models/what-ai-costs-across-providers) を使い、現在の Claude の定価は [モデルと価格](/docs/whats-new/models-and-pricing) にある。
