**DeepSeek Harness**(コマンド名は `dsh`)は、DeepSeekが公開しているオープンソースのエージェントハーネスです。2026年8月13日にGitHubに登場し、本日時点でスターは242,626、フォークは29,081、ライセンスはMIT、実装言語はTypeScriptです。2026年10月1日に、DeepSeekが署名付きのデスクトップ版インストーラーを追加したことで、再びHacker Newsのトップページに載りました。

キャッチコピーはリポジトリの説明文にある*「Everything is a Plugin.」*の一文です。このフレーズは、これまでに公開されたほぼすべてのエージェントフレームワークのREADMEに載っていて、たいていは「プラグイン用のフォルダがあります」という意味にすぎません。ここではもっと強力で、風変わりな意味を持ちます。`docs/architecture.md` ではっきり述べられているとおり、モデルアダプター、ツールレジストリ、セッションログ、そして**エージェントループそのもの**がプラグインであり、「そのためそれぞれを設定によって置き換えられる」のです。フォークすることなく、YAMLファイルからエージェントループを削除して、自作のものに差し替えられます。

この設計には、優れた結果もあれば、高くつく結果もあります。このページでは、ランディングページを読むだけではわからない部分を扱います。

## 「すべてがプラグイン」は設計を支える主張である

`dsh` の下層にあるのは**Cordis**です。これはリポジトリ内(`vendor/`)に同梱されているプラグインフレームワークで、プロジェクトが引用しているarXiv論文*A Programming Paradigm for Spatiotemporal Composability*(arXiv:2608.25512、2026年8月26日投稿、北京大学とDeepSeek-AIの著者による)で解説されています。論文の二つの考え方は、ハーネスの実行時の挙動にそのまま対応しています。

- **時間的な合成可能性** — コンポーネントを取り除いたとき、その副作用を*完全に*元へ戻せること。ハーネスでは `ctx.effect()` がこれにあたります。プロンプトのセクション、ツールのスキーマ、モデルアダプター、プロバイダー、リスナーは、すべて元に戻せる効果としてインストールされます。そのため、プラグインをアンロードすると、登録内容が順序どおりに巻き戻され、孤立したものが残りません。
- **空間的な合成可能性** — 依存関係がリアクティブに解決されること。プラグインは `inject` で必要なサービスを宣言し、Cordisは、それらのサービスが揃うまでプラグインを起動しません。維持すべき起動シーケンスはなく、読み込み順は、宣言された要件から自然に決まります。

**サービス**は、共有コンテキスト上の安定したキーを占有します。この名前がアーキテクチャそのものです。

| サービスキー | 所有するもの |
|---|---|
| `ctx.llm` | LLMアダプターのレジストリ。モデルとの接合部 |
| `ctx.tools` | ツールレジストリと、スコープ付きの実行パイプライン |
| `ctx.agentLoop` | 既定のエージェントループドライバー |
| `ctx.agents` | 稼働中のエージェントのレジストリ |
| `ctx.sessions` | 追記専用の `SessionEvent` ログ |
| `ctx.systemPrompt` | システムプロンプトの組み立て |
| `ctx.fs` | ファイルシステムへのアクセス |
| `ctx.subprocess` | サブプロセスの実行 |
| `ctx.sandbox` | サブプロセスの閉じ込め |
| `ctx.subagents` | サブエージェントへの委任 |
| `ctx.ptcRuntime` | `run_code` のためのプログラム実行 |
| `ctx.credentials` | 認証情報との接合部 |

リポジトリはこれらを**ケイパビリティシーム**(capability seams)と呼び、それぞれを三つの役割に分けています。サービスを*宣言する*パッケージ、*実装する*パッケージ、*利用する*パッケージです。`ctx.sandbox` は `packages/sandbox/sandbox` が宣言し、`sandbox-local` と `sandbox-windows-acl` が実装し、`tool-bash` とPTCランタイムが利用します。実装を差し替えれば、利用側のコードを一切編集しなくても、すべての利用側が追従します。

プラグイン間の通信は型付きイベントで行われ、**宣言された五つのディスパッチモード**があります。このモードは、イベントの公開契約の一部です。

| モード | await するか | 順序 | 値を返すか |
|---|---|---|---|
| `emit` | しない | 登録順 | 返さない |
| `waterfall` | しない | 登録順 | 返す |
| `parallel` | する | 全部同時 | 返さない |
| `serial` | する | 登録順 | 返す |
| `bail` | しない | 登録順、最初のbailで停止 | 返す |

`waterfall` が特に興味深いのは、これが周囲をラップするミドルウェアだからです。リスナーは `(...args, next)` を受け取り、`next()` を呼べば、ラップされたかもしれない結果を連鎖の次へ渡し、`next()` を呼ばずに返れば、そこで処理を打ち切ります。「このツールを実行してよいか?」のような、判断が一つに決まるイベントでは、打ち切ることこそが設計意図です。判断を握るポリシーのリスナーは、委譲せずに返します。一方、注釈を付けるだけのリスナーは、必ず委譲しなければなりません。denyの判定を返すClaude Codeのフックを書いたことがあるなら、この形はすでにご存じでしょう。違いは、ここではそれがシェルの呼び出しではなく、ネイティブの拡張機構であることです。

エージェントループは**ターン**(ゼロ回以上のステップ)と**ステップ**(モデルへの1回のリクエストとそのツール呼び出し)で動き、公開されている拡張シーケンスは `agent/pre-step → agent/request → llm/stream → tools/* → step/end` です。これらがフックポイントです。ループにパッチを当てるのではなく、ループを購読して聴くのです。

## すでにClaude Codeを使っている人にとって重要な三つのこと

### 1. 既存のClaude Codeの `hooks.json` を実行できる

これは `dsh` について最も報じられていない事実です。`packages/hooks` には三つのパッケージが入っています。共通のエンジンである `hook-protocol`、**`hooks-claude-code`**、**`hooks-codex`** です。Claude Codeのブリッジを既存の `hooks.json` に向けると、セッションの開始、プロンプトの到着、ツールの実行、実行の停止の各タイミングで、フックが `dsh` の中で動きます。グループのREADMEは、できることを明記しています。**モデルに見えるメッセージ付き**でプロンプトやツール呼び出しをブロックする、会話にコンテキストを追加する、実行の継続を要求する、の三つです。

限界も同じくらい明記されており、移行を計画する前に確認すべき点です。*各統合は、元のツールが文書化しているコマンドフックのサブセットだけをサポートします。* つまり、`command` タイプのフックは移植できます。そのサブセットの外にあるClaude Codeの挙動に依存するものは移植できません。信頼しているフック層があるなら([Claude Codeのフック](/docs/claude-code/hooks)を参照)、これは書き直しではなく、「ガードレールを持ち込む」本当の道筋になります。

### 2. Claudeに接続できる。ただしサブスクリプションでは使えない

同梱のカタログに含まれるプロバイダー一覧には、`anthropic` と `openai` が名前で入っています。カタログにないもの(中継サーバー、社内ゲートウェイ、自前運用のサーバーなど)については、カスタムプロバイダーのフォームで、プロバイダーID、ベースURL、認証情報、そして**APIプロトコル**を入力します。選べるプロトコルは三つだけです。OpenAI Chat Completions、OpenAI Responses、Anthropic Messagesです。`cordis.patch.yml` では、それぞれ `openai-completions`、`openai-responses`、`anthropic-messages` として保存されます。

つまずきやすい点が二つあります。

- **一つのプロバイダーは一つのプロトコルしか話せません。** OpenAI形式とAnthropic形式の両方を提供するゲートウェイには、一つではなく*二つ*のプロバイダーエントリが必要です。
- **OAuthでのサインインには対応していません。** プロバイダーのガイドが、Codexを例に直接述べています。OAuthでサインインするプロバイダーは「まだここではサポートされていません」。つまり課金はAPIキーによる従量制であり、すでに支払っている席(シート)は使えません。既存のアシスタントのサブスクリプションで `dsh` を動かせると期待していたなら、従量課金のトークン代を見込んでください。計算方法は[プロバイダー別のAIコスト](/docs/models/what-ai-costs-across-providers)にあります。

モデル検出ボタンもあり、エンドポイントに、どのモデルを提供しているかを問い合わせます。便利ですが、心に留めておくべき注意点があります。**組み込み**のプロバイダーは、ベースURLがゲートウェイを指していても、常にインストール済みのカタログから応答されます。ゲートウェイが実際に何を提供しているかを見たければ、*カスタム*プロバイダーとして追加する必要があります。そうしないと、DeepSeekが同梱したリストを自分に読み返しているだけになります。

### 3. `run_code` はcodemodeであり、第一級のランタイムである

`packages/ptc-runtime` は、ツールレジストリがモデルに `run_code` として提示するものの裏にあるケイパビリティ群です。契約は次のとおりです。モデルは**一つのプログラム**を書き、そのプログラムがホストの提供する関数を通常の非同期呼び出しとして呼び出します。返ってくるのは、プログラムが出力した内容と戻り値だけです。途中のツール結果ではありません。20回の往復でもありません。

詳細は次のとおりです。

- TypeScriptバックエンドは、解決されたサンドボックスポリシーのもとで、各プログラムを**新しく管理されたNodeプロセス**で実行します。
- **各実行は、以前のプログラムの状態を持たずに始まります。** 頼れる暗黙のREPLセッションはありません。状態は、ファイルか戻り値で引き継いでください。
- 失敗は例外ではなく*結果*として返るため、呼び出し側は診断したり、モデルに渡したりできます。
- 実験的な**Pythonバックエンド**もあります。NodeホストとCPythonのサブプロセスの間でfd-3のワイヤープロトコルを使い、本当にCPythonが必要なときのために用意されています。

このパターンが初めてなら、なぜこれほどコンテキストを節約できるのかを最もわかりやすく解説しているのは、[Pi 1.0とcodemodeの技](/docs/models/pi-1-0-minimal-agent-harness)です。トランスクリプトに入らないツール結果は、トランスクリプトを膨らませようがありません。ここでも同じ理屈が当てはまります。違いは、`dsh` ではプログラムのランタイムが固定のサンドボックス選択ではなく、差し替え可能な接合部(`ctx.ptcRuntime`)になっていることです。

## サンドボックス:三つのモード、三つのカーネルプリミティブ、そして率直な但し書き

三つのモードは、Codexを設定したことがあるなら見覚えがあるでしょう。

| モード | サブプロセスがファイルに対してできること |
|---|---|
| `read-only` | 読み取りのみ |
| `workspace-write` | セッションのワークスペース配下にのみ書き込み可 |
| `danger-full-access` | 無制限 |

さらに興味深いのはバックエンドの表で、あなたのマシンで実際にポリシーを強制しているものが何かがわかります。

- **Linux** — bwrap、次点のフォールバックとしてLandlock。
- **macOS** — Seatbelt。
- **Windows** — 制限付きトークン。書き込み制限のバックエンドとして `sandbox-windows-acl` を使います。閉じ込められた子プロセスは、ワークスペースと専用の一時ディレクトリにしか書き込めません。

拒否された呼び出しは、**ユーザーが承認する一度限りのエスカレーション**を通じて再試行できます。つまりこのポリシーは、確認を挟んで先へ進む境界であり、越えられない壁ではありません。

そして但し書きです。これはパッケージのREADME自身が述べていることで、「サンドボックスされている」と言う人には、そのまま引用して伝えるべきです。**閉じ込めは「同じ世界の中」だけです。** ホストのカーネルとホストのファイルシステムを共有します。コンテナ、マイクロVM、リモート実行環境のような本物の隔離は、ここには一切登録されません。代わりに、ケイパビリティ全体を置き換えます。

`SAFETY.md` は、24万2千スターのリポジトリとしては珍しいほど率直で、初回の実行の後ではなく前に読む価値があります。そこには、ハーネスがモデルの生成したコードを実行し、サードパーティのプラグインを読み込み、ネットワークにアクセスし、プロセス、認証情報、ファイルに触れられること、サンドボックス、承認プロンプト、権限制御が、到達可能なものへの被害を防ぐという**固有の保証はない**こと、そしてこのソフトウェアは「安全または本番利用可能なものとして扱ってはならない」ことが書かれています。推奨事項は、地味ですが正しいものです。使い捨てのVMまたはコンテナを使う、プロジェクトの範囲内にあるものはバックアップを取る、リスクを受け入れる場合を除いて機微な認証情報を置かない、です。ローカルで実行するどのハーネスにも同じ考え方が当てはまります。[ローカルおよびハイブリッドエージェントの保護](/docs/models/securing-local-and-hybrid-agents)と[サンドボックスと認証情報のマスキング](/docs/claude-code/sandbox-credential-masking)を参照してください。

知っておく価値のある小さな**ガード**のグループもあります。`timeout-policy` と `repeat-tool-reminder` です。後者は、モデルが同じツールをループで呼び続けるという失敗モードへの注意喚起です。

## セッションログこそが製品である

`dsh` は、セッションをバージョン付きのJSONLファイル(`session.vN.jsonl[.zstd]`)として永続化し、バージョン間にはマイグレーションの連鎖があります。これは `ctx.sessionPersistence` という接合部を通して行われ、同梱の実装は `session-persistence-jsonl` です。コミットされるイベントには、`turn/start`、`step/start`、`user/message`、`assistant/message`、`tool/result`、`turn/end` があります。

その背後にある不変条件は、`dsh` を一度も使わない人でも真似する価値があります。**「モデルに見えたものは、ログに残る」**。モデルが見たすべての入力を、ログから再構成できなければなりません。ライブイベントはUIをリアルタイムで動かすために別に存在し、明示的に、真実の記録ではないとされています。

この一つのルールが、周辺のパッケージを成り立たせています。

- `session-query-sqlite` — JSONLをgrepする代わりに、SQLiteからセッションを照会できます。
- `dsh-session-projection` と `ctx.sessionProjections` — ゼロから再生するのではなく、セッションの状態を差分で畳み込みます。
- `llm-replay` と `token-meter`(「リプレイによるトークン計測」) — 記録されたセッションを再生してそのトークンコストを*計測*します。二つのプロンプトやモデルの変更を、雰囲気ではなく同一の入力で比較する方法です。
- `compaction-tool-result-pruner` — **モデルを使わない**ツール結果の刈り込みと説明されています。つまり、モデルに要約させる費用を払わずに、トランスクリプトを縮めます。Claude自身のやり方とは、[コンテキストのコンパクション](/docs/api/compaction)で比較できます。

エージェントの実行をデバッグしようとして、ログに記録されていたのがモデルが受け取ったバイト列ではなく*描画されたUI*だった、という経験があるなら、この不変条件が多くの機能より価値がある理由はすでにおわかりでしょう。

## ここでのMCPは、グローバルなレジストリではなく、サーバーごとのプラグインである

`dsh` は、stdioとStreamable HTTPの両方でMCPを話し、ネゴシエーション、ディスカバリー、検証、キャンセルには公式SDKを使います。設計上の選択は、一覧にする価値があるほど変わっています。

- **サーバーはオプトインで、サーバー一つにつきプラグインのエントリが一つです。** サーバーを見せたいCordisのスコープごとに、`@deepseek-ai/dsh-mcp-client` のエントリを一つずつ設定します。意図的に**共有の `ctx.mcp` サービスはありません**。クライアントは接続プラグインであり、ツールレジストリの*利用者*です。
- **サーバーを設定しなければ、MCPのコストもかかりません。** 設定済みのサーバーが一つも見えない呼び出し元には、ネイティブモードでもPTCモードでも、MCPのプロンプトテキストもMCPのツールも渡されません。「少しのセクション」ではなく、ゼロバイトです。これは思う以上に重要です。[MCPツールの本当のコスト](/docs/claude-code/mcp-token-cost)を参照してください。
- **公開されるツール名にはサーバー名が含まれる**ので、二つのサーバーに同名のツールがあっても区別されます。`serverName` は、登録スコープ内で一意でなければなりませんが、別々のエージェントスコープなら再利用できます。
- **サーバーの指示は、ログに残るシステムプロンプトに加わり**、クライアントの `maxInstructionBytes` で上限が決まります。冗長なサーバーがこっそりプロンプトを占有することはありません。ただし、これは悪意のあるサーバーがモデルに語りかけるチャネルでもあります。その攻撃面は[MCPツールポイズニングとラグプル](/docs/security/mcp-tool-poisoning-and-rug-pulls)で説明しています。
- **ツール一覧の更新に失敗しても、前の世代のツールが保持される**ので、セッションの途中でツールが消えることはありません。また、プロトコルのリビジョンを強制する製品設定はなく、ネゴシエーションはSDKがサポートするリビジョンに従います。

## 1時間を失う五つの落とし穴

1. **Cordisの設定オーバーライドは、エントリの設定全体を置き換えます。** プロバイダーのガイドが明記しています。既存のオーバーライドを編集するときは、他のフィールドと他のプロバイダーを自分で保持しなければなりません。一つのプロバイダーを不用意にパッチすると、残りを削除したことになります。`cordis.patch.yml` で起こせるミスのうち、最も高くつくものです。
2. **プロバイダーIDは変更できません。** リクエスト、保存済みセッション、モデルの既定値、認証情報への参照が、すべてこれをキーにしています。名前を変えるには、新しいプロバイダーを追加して古いものを削除します。表示名、ベースURL、プロトコル、認証情報、モデル一覧は編集できます。
3. **`--dump-config-schema` はプラグインのコードをインポートします。** 他のdumpフラグと違い、JSON Schemaを出力するために、合成されたツリーが宣言するプラグインのスキーマを読み込みます。そのため、信頼できないプラグインに向けて実行すると、そのインポート時のコードが実行されます。CLIリファレンスにも、この点に関する専用の安全上の注意書きがあります。`--help` のようにではなく、[サードパーティコードのレビュー](/docs/security/reviewing-third-party-code)と同じように扱ってください。
4. **プラグインのバージョン互換性は強制され、回避手段は明示的です。** インストール時とプロファイルの起動時に、宣言されたDSHのピア範囲が、`dsh --version` が示すランタイムのバージョンと照合されます。互換性のないプラグインには、確認済みの厳密なバージョン例外(`allow-version`、`revoke-version`)が必要です。良い衛生管理ですが、プラグインの読み込みを初めて拒否されると驚きます。
5. **すでにリクエストを送ったセッションは、自分のログに記録されたモデルを保持し続けます。** 既定のモデルを変更しても、稼働中のセッションが遡って切り替わることはありません。また、保存済みの既定値が削除されたプロバイダーを指していると、別のものを選ぶまで入力欄がブロックされます。どちらも正しい挙動ですが、午前1時にはバグに見えます。

## 位置づけ

ハーネスを研究するのではなく選ぶのであれば、率直な要約はこうです。`dsh` は、現在公開されているオープンなハーネスの中で、*アーキテクチャ*の面で最も興味深く、そして、いざというときに頼れる土台としては最も準備が整っていません。これは同プロジェクト自身の安全性ファイルが述べていることです。プラグインモデルは、競合のものより確かに強力です。`ctx.agentLoop` を差し替えられることは、ほとんどのハーネスでは、いくら払ってもできません。そしてフックのブリッジがあるため、導入は一か八かの賭けにはなりません。

一方で、`latest` タグはリリース候補、セキュリティ監査は未実施、互換性を損なう変更が予告されており、プロバイダーの仕組みはAPIキーを前提としています。分野全体の比較は、[コーディングエージェントCLIの比較](/docs/models/coding-agent-clis-compared)と[ローカルのコーディングエージェント](/docs/models/local-coding-agents)を参照してください。これを動かすモデルとして最も有力なものは、[DeepSeek-V4.1-Flash](/docs/models/deepseek-v4-1-flash-open-weight-1m)を参照してください。
