## ファミリーの全体像

3 つのモデル、1 つの共有プレトレーニング実行、3 つのハードウェアエンベロープ。これは意図的です:Poolside は 1 回プレトレーニングし、サイズごとにポストトレーニングしたため、ファミリー全体で個性が一貫しており、タスクの形状ではなく手元の箱に基づいてサイズを選びます。

| モデル | 総パラメータ | アクティブパラメータ | コンテキスト | ターゲットハードウェア | ライセンス |
|---|---|---|---|---|---|
| **Laguna XS 2.1** | 33B (MoE) | 3B | 最大 256K | シングルラップトップ / MacBook GPU | OpenMDW-1.1 |
| **Laguna S 2.1** | 118B (MoE) | 8B | 最大 1M | シングル DGX Spark または FP8 の H200 | OpenMDW-1.1 |
| **Laguna M.1** | 225B (MoE) | 23B | 256K+ | エンタープライズマルチ GPU ノード | OpenMDW-1.1 |

この表から得られる 3 つの実用的な要点:

- **ファミリー全体で同じコーパス。** Laguna S 2.1 のポストトレーニングは XS 2.1 の上に新しいデータを追加していません——S 2.1 の発表がこれを明示しています。挙動の改善は新しい文書を与えることではなく、より大きなモデルクラスと異なるポストトレーニングレシピから来ています。つまり、ファインチューニングの知見はサイズ間できれいに転用できます。
- **推論コストに関わるのはアクティブパラメータの列です。** 8B アクティブでは、Laguna S 2.1 はトークンあたり 118B ではなく 8B デンスモデルの計算プロファイルを持ちます。それが「シングルアクセラレータで動く」と「ラックが必要」の違いです。
- **OpenMDW-1.1 は本物の寛容ライセンスであって、ソースアベイラブルライセンスではありません。** これは Linux Foundation によって公開されたもので、重みやデータを明確にカバーしない従来のオープンソースライセンスと、静かに商用利用を禁止するベンダーの「オープン」ライセンスとのギャップを埋めるためのものです。著作権、特許、データベース、営業秘密にわたって無制限かつロイヤリティフリーの権利を付与し、出力は明示的に非拘束です。

## ヘッドラインから明らかでない 3 つのこと

### 1. FP8 での RL は本当のエンジニアリングブレークスルーであり、マーケティングではない

LLM のポストトレーニングにおける強化学習は歴史的に BF16 で実行されてきました。なぜなら、FP8 精度での勾配ノイズが RL が提供する小さなシグナルを吹き飛ばすと想定されていたからです。Poolside は Laguna S 2.1 を **FP8 で RL 学習された初のフロンティア規模のモデル** であると公に主張しています。これが真実であれば——2026 年 8 月初旬時点で反例は現れていません——これは RL ステージのメモリフットプリントを半減させ、以前は高価すぎたタスクに与えられたクラスタが RL 計算を費やせるようにします。

ユーザーにとっての実用的な帰結:**Poolside の RL ステージは選択的でした**。彼らは **409k のトレーニング環境** (83k のターミナル、168k のソフトウェアエンジニアリング)を報告しており、**ほとんどの挙動を合成データから SFT でブートストラップ**し、**最も難しい問題に RL を予約**しています。それはベンチマークのデルタに現れます——DeepSWE v1.1 での思考モードのブーストは **16.5% → 40.4%** ——これは、RL がすべてのタスクにばら撒かれるのではなく、難しい推論に狭く費やされたときに期待される形です。

### 2. マルチハーネストレーニングが、サードパーティのエージェント内で崩れない理由

コーディングモデルは通常、1 つのエージェントハーネス(ベンダー独自のスキャフォールド)内でトレーニングされ、その後、数十の他のもの(Cursor、Cline、Aider、Continue、Kilo など)にデプロイされます。トレーニングとデプロイのハーネス間のギャップこそが、「ベンチマークではうまくいったのに」という多くの失敗が生まれる場所です。Poolside は **83k のターミナル環境と 168k のソフトウェアエンジニアリング環境**にわたる **複数のハーネス**で Laguna をトレーニングしました。これが、モデルが初日から独自のスキャフォールド外で使用可能である理由として彼らがクレジットしているメカニズムです。

Laguna の報告された挙動におけるマルチハーネストレーニングの目に見えるシグナル:**粘り強さ**(失敗したツール呼び出し 1 回でアプローチを放棄しない)、**検証優先**(出荷前に自分の出力を再読する)、**リソースフルネス**(直接の道が塞がれたときに代替パスを見つける)。これらはエージェント的な挙動であり、次トークンの挙動ではありません——プレトレーニングデータを増やしても得られません。

同じ設計選択に直接対応する既知の制限は、驚かないように把握しておく価値があります:

- サードパーティのハーネスにおける **わずかなスキーマの違い** に Poolside のネイティブなものと比べて苦しむ——ハーネスは 409k のトレーニング環境の何かに「十分近い」ように見える必要があります。
- **配列内のネストされたツール呼び出しで不正にエスケープされた JSON** を時々出力します。まれですが実在します。
- **数学コンペティション問題で考えすぎる** ——AIME スタイルのタスクで拡張思考が必要以上に長く実行されます。コーディングには問題ないが、数学には無駄です。

### 3. アクティブパラメータ比率がコストの全ストーリー

目を引く数字は **1.6T 対 8B** です:Laguna S 2.1 はトークンあたりのアクティブパラメータが 6 分の 1 でありながら、DeepSWE v1.1 で DeepSeek-V4-Pro-Max(1.6T トータル)を 31.4 ポイント上回っています。しかし、有用なフレーミングは推論コストです:

| モデル | トークンあたりのアクティブパラメータ | 概算のトークンあたり計算量 | 参考 API 価格* |
|---|---|---|---|
| Laguna XS 2.1 | 3B | ~3B デンス相当 | 無料枠 / $0.05 台 |
| **Laguna S 2.1** | **8B** | **~8B デンス相当** | **$0.10 入力 / $0.20 出力 per M(OpenRouter)** |
| GLM-5.2 | ~40B | ~40B デンス相当 | $1.20-1.40 入力 / $4.10-4.40 出力 per M |
| Kimi K3 | ~32B | ~32B デンス相当 | GLM 帯と同様 |
| Claude Opus 5(フロンティア) | デンス、非公表 | フロンティア | $15 入力 / $75 出力 per M |

<small>*価格は OpenRouter および同等のアグリゲータから、2026 年 8 月初旬 —— 概算として扱ってください。</small>

**OpenRouter 上の S 2.1 と Claude Opus 5 のトークンあたり 150 倍のギャップ** はヘッドライン用の公平な比較ではありませんが、有用な比率は **S 2.1 対 他のオープンウェイトフロンティアモデル**(GLM-5.2、Kimi K3)です:Laguna は出力トークンあたり約 12 倍安く、SWE-Bench Multilingual スコアは同じリーグにあります。それがモデルに任せることが経済的に妥当な仕事を変える価格エンベロープです。

## ベンチマークの姿 —— 率直なバージョン

S 2.1 のローンチ時点で報告されたスコアで、Poolside 独自の投稿とサードパーティのカバレッジの間で照合済み:

| ベンチマーク | Laguna S 2.1 | 何を測定するか | 備考 |
|---|---|---|---|
| **SWE-Bench Multilingual** | **78.5%** | 多くの言語にわたる実際の GitHub 修正タスク | ローンチ時点でトップの公開オープンウェイトスコア |
| **Terminal-Bench 2.1** | **70.2%**(思考) / 60.4%(非思考) | 長い shell ワークフロー | 約 10 ポイントの思考モードアップリフト |
| **SWE-Bench Pro (Public)** | 59.4% | より困難な自律的なリポジトリレベルの修正 | フロンティアのクローズドモデルはまだ先行 |
| **DeepSWE v1.1** | **40.4%**(思考) / 16.5%(非思考) | 困難な SWE ベンチマーク | アクティブパラメータが約 200 分の 1 にもかかわらず 9.0% の DeepSeek-V4-Pro-Max を打ち破る |
| **SWE Atlas (Codebase QnA)** | 46.2% | 大規模リポジトリを理解する | DeepSWE の数値を先行 |
| **Toolathlon Verified** | 49.7% | マルチツールオーケストレーション | 中位 |

これらを読むための 3 つの解釈ルール:

- **SWE-Bench Multilingual と Terminal-Bench 2.1 は、エージェント的コーディングモデルにとって真剣に受け止めるべき数字です。** それらは実際に割り当てる仕事——「実際のリポジトリでこのバグを修正する」、「この shell ワークフローをグリーンにする」——にマッピングされます。Poolside はオープンウェイト側で両方をリードしています。
- **クローズドフロンティアは最難のベンチマークでまだ勝っています。** Claude Fable 5 と Kimi K3 は SWE-Bench Pro と一部の Toolathlon スライスでリードしています。Laguna のローンチを「Anthropic は打ち破られた」と読まないでください——「コーディングのオープンウェイトの天井が数ポイント上昇した」と読んでください。
- **思考モードは無料ではないが、勝利のほとんどはそこにあります。** Terminal-Bench 60.4% → 70.2%、DeepSWE 16.5% → 40.4%。コストのために思考をオフにすると、モデルの大部分を放棄することになります。

## Laguna 対代替候補、いつ手を伸ばすか

2026 年 8 月初旬時点のモデルランドスケープを考慮した実用的な判断マップ:

| タスク | ベストピック | 理由 |
|---|---|---|
| 長期のリポジトリレベルのバグ修正、予算に敏感 | **Laguna S 2.1** | トップのオープンウェイト SWE-Bench Multilingual、出力トークンあたり GLM-5.2 や Kimi K3 より約 12 倍安い |
| MacBook 上のエージェント的コーディング、オフライン必須 | **Laguna XS 2.1** | 3B アクティブパラメータ + MLX ビルド、このサイズでこれに匹敵する SWE-Bench Multilingual に到達するものは他にない |
| 最難のタスクにおける絶対的なフロンティア精度、コスト度外視 | **Claude Opus 5** または Fable 5 | クローズドフロンティアはまだ SWE-Bench Pro と最難スライスをリード |
| リポジトリ上の 100 万トークンコンテキスト、寛容ライセンスが必要 | **GLM-5.2** または **Laguna S 2.1** | 両方とも寛容ライセンスの下で 1M コンテキストを提供、GLM-5.2 は一般的な推論で強く、Laguna はエージェント的コーディングで強い |
| 厳密なツール呼び出しセマンティクスが必要なマルチツールオーケストレーション | **Claude** または **Kimi K3** | Laguna の中位の Toolathlon スコアと既知の JSON エスケープのエッジケースにより、ここでは弱いデフォルト |
| 規制環境、データが箱から出ない | **Laguna S 2.1 セルフホスト** | OpenMDW-1.1 は無制限の商用利用を付与、米国発の研究所、FP8 はシングルアクセラレータに収まる |

ワンライナー:**Laguna は、小さいアクティブパラメータ予算でフロンティアクラスのコーディング挙動が欲しく、ライセンスと出自が重要なときの現在のスイートスポットです。** これらの制約が拘束的なときに使用してください。そうでないときは Claude やクローズドフロンティアに手を伸ばしてください。
