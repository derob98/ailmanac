## 一文サマリー

MiMo-V2.6-Pro は **MIT ライセンスの 1.02T 総 / 42B アクティブ**なスパース MoE で、**1M トークンコンテキスト**と**テキスト・画像・動画・音声入力**を備え、短ホライズンのエージェンティックおよび自動化ベンチマークで Claude Opus 5 に並ぶか上回り、長ホライズンのターミナル作業では大きく劣り、自前で動かすのではなく借りる場合のトークン単価はおよそ 10 分の 1 です。

## 見出しからは自明ではない 4 つのこと

### 1. Terminal-Bench の勝ちと Terminal-Bench の負けは同じモデルの話

これは腹に落としておくべき点です。ローンチ報道は MiMo-V2.6-Pro が **Terminal Bench 2.1 で 89.9**、Claude Opus 5 の 89.1 をわずかに上回ったと広く伝えました。Xiaomi 自身のモデルカードは Terminal Bench 2.1 をまったく報告していません。報告しているのは **Terminal Bench 4.0** で、そこでは MiMo-V2.6-Pro が **34.9**、Opus 5 の **49.0** に対して 14.1 ポイントの劣勢です。

どちらの数字も本物です。Terminal Bench 2.1 は古く、ほぼ飽和したハーネスで、フロンティアモデルはどれも 90 付近に集まり、0.8 ポイントの差はノイズです。Terminal Bench 4.0 は現行版で、モデル間がまだ広がっています。どこかで「Terminal Bench で Claude を上回った」と読んだら、最初の問いは常に*どのバージョンか*です — エージェンティックスイートでは、バージョンの変化のほうがモデルの変化より大きな効果を持つのが普通だからです。

同じパターンは AILmanac の
[DeepSeek-V4.1-Flash](/docs/models/deepseek-v4-1-flash-open-weight-1m) と
[Gemini 3.8 Flash](/docs/models/gemini-3-8-flash) の記事にも現れています:DeepSWE では互角、Terminal-Bench 4.0 では 15〜20 ポイントの穴。これは安価ティアの典型的な形になりつつあります。

### 2. 世代間 33 ポイントのジャンプはハーネスの話であって知能の話ではない

モデルカード自身の表には前世代も載っています。MiMo-V2.5-Pro は DeepSWE v1.1 で **19.0**、Terminal Bench 4.0 で **1.5** でした。V2.6-Pro は 71.9 と 34.9 です。

モデルが 1 世代でターミナル作業が 23 倍うまくなることはありません。1.5 というスコアは、旧モデルがベンチマークのツールコールプロトコルを事実上こなせなかったことを意味します — 推論ではなくハーネスで失敗していたのです。*エージェンティック*ベンチマークにおける巨大な世代間差分は、まず「ツールコールを直した」と読み、それから初めて能力向上として読んでください。非エージェンティックなベンチマークの差分こそ誠実なものです:ProgramBench は 12.5 → 26.5、おおよそ倍増で、大きいが信じられる世代間ステップです。

### 3. 1M コンテキストは力技ではなくアテンション配置で買っている

MiMo-V2.6-Pro の LLM バックボーンは **70 層:スライディングウィンドウアテンション 60 層、グローバルアテンション 10 層** — 6:1 の比率です。スライディングウィンドウ層はローカルな KV ウィンドウしか保持しないため、1M トークン時点のトークンあたり KV フットプリントは、完全グローバルな 70 層スタックが必要とする量のごく一部で済みます。10 層のグローバル層が、情報を端から端まで伝えることを可能にしています。

MoE は **384 のルーテッドエキスパートのうちトークンあたり 8 個がアクティブ**で、1.02T のうち 42B がアクティブ — つまり**任意のトークンでモデルの約 4.1% が動く**計算です。Flash は同じ形で総計 309〜311B、アクティブ ~15B。だからこそ 1 兆パラメータのモデルをそもそもサービングできるのです:メモリでは 1T を、計算では 42B を支払います。

その上に、**1 パスあたり 7 トークンをドラフトする 5 層のマルチトークン予測投機デコーダ**が載っています。これはスループットの仕組みであり、次の点に関わってきます。

### 4. 「オムニモーダル」とは入力側のオムニモーダルであり、UltraSpeed は品質ではなくレイテンシを売っている

マーケティング的な言い回しがぼかしている 2 点:

**モダリティは入力側です。** カードはテキスト・画像・動画・音声をモダリティとして挙げ、681M パラメータの MiMo ViT ビジョンエンコーダ、308M の AudioTokenizer、127M の音声パッチエンコーダを備えます。Hugging Face 上の Pro のパイプラインタグはテキスト生成です。動画を与えて質問することはできますが、答えはテキストで返ります。音声や画像の*ジェネレータ*ではありません。メディアをまたぐ生成が欲しいなら、それは別のページです:
[generative media](/docs/models/generative-media-image-audio-video)。

**UltraSpeed は 10 倍の価格で同じモデルです。** `MiMo-V2.6-Pro-UltraSpeed` は、Pro と同等の品質で最大 20 倍の出力速度と説明され、Pro のトークン単価のおよそ 10 倍で掲載されています。Hugging Face 上にそれ専用の重みセットは存在しません — 投機デコーダと Xiaomi のインフラの上に構築されたサービングティアです。製品として完全に妥当ですが、実態どおりに値付けを考えてください:買っているのは対話型・リアルタイムワークロード向けの秒間トークン数であって、精度ではありません。バックグラウンドのバッチ処理なら、UltraSpeed は 10 倍の払い過ぎです。

押さえておく価値のある読み方が 3 つ:

- **Flash はほとんどの項目で Pro の数ポイント以内です。** DeepSWE で 67.9 対 71.9、AutomationBench で 52.3 対 53.1、そして CyberGym では Pro を*上回って*います。ホスティング価格が Pro のおよそ 3 分の 1、パラメータも 3 分の 1 であることを踏まえると、別の選択をする理由を実測していない限り Flash がデフォルトです。
- **CyberGym の競合列は空です。** Xiaomi は 94.0 と 95.1 を報告し、Claude や GPT との比較は公開していません。対抗馬のない数値は対抗馬のない数値として扱ってください — そのタスクで有能であることは分かりますが、首位であることは分かりません。
- **Pro が単独で勝っている行はちょうど 1 つ、AutomationBench だけです。** それ以外はほぼ互角か負けです。「フロンティアクラスのオープンウェイト」は妥当ですが、「Claude を上回る」は妥当ではありません。

集計面では、Artificial Analysis の Intelligence Index v4.3 が MiMo-V2.6-Pro をおよそ **46** に位置づけ、オープンウェイトモデルで首位、Grok 4.7 と同水準と報告しました。クローズドフロンティアは約 53 です。10 分の 1 の価格で 7 ポイントのインデックス差 — これが実際の売り文句です。

## レンタルと自前所有、それぞれのコスト

**レンタル**の場合、ローンチ時に OpenRouter と Xiaomi の掲載から報じられた 100 万トークンあたりの価格:

| モデル | 入力 | 出力 |
|---|---|---|
| MiMo-V2.6-Flash | $0.14 | $0.28 |
| MiMo-V2.6-Pro | $0.435 | $0.87 |
| MiMo-V2.6-Pro-UltraSpeed | $4.35 | $8.70 |

スケール感として、Claude Opus 5.5 は $4 / $20 で掲載されています([Opus 5.5 フィールドガイド](/docs/models/opus-5-5-field-guide)を参照)。Pro は入力でおよそ **9 倍、出力で 23 倍安い**計算です。UltraSpeed は入力で Opus 5.5 とほぼ同等、出力では半分以下 — これがあのティアについての誠実な考え方です。

**自前所有**はまったく別の話で、ローンチコマンドがそれを物語っています。モデルカードの Pro 向け SGLang サンプルは `--tp 16 --dp 2 ... --nnodes 2` を要求します:16 デバイスにわたるテンソル並列、2 つのデータ並列レプリカ、2 ノード。これはワークステーションではなくラックです。vLLM の経路は `--tensor-parallel-size 8` と軽めですが、それでも BF16 の 1.02T チェックポイントに 8 基のアクセラレータが必要です。

Flash は総計 ~309〜311B、アクティブ ~15B で、本格的なシングルノード機がどうにかサービングできる変種です。**MiMo-V2.6-Distill-Qwen-9B** チェックポイント — 9B の蒸留版で、Hugging Face には image-text-to-text として掲載 — が、ラップトップクラスの GPU に収まるものです。「有能なオープンモデルを自宅で動かす」が目標なら、Pro ではなくそこと
[Ollama でモデルをローカル実行する](/docs/models/run-models-locally-ollama)から始めてください。

所有についてもう 1 つ注意点があります。公開されているリポジトリは **RL 後のチェックポイント**(`-Pro-RL`、`-Flash-RL`)です。ベースチェックポイントはリリースされていません。サービング、量子化、適応はできますが、RL 前のベースから自前のポストトレーニングを始めることはできません。

## 手を伸ばすべき場面、そうでない場面

**適合する用途**

- 混在メディアに対する大量の分類・抽出・自動化。入力 100 万トークンあたり $0.14 という価格が、そもそも経済的に可能なことの範囲を変える領域。
- プライバシーや管轄権の理由で自前のハードウェアで動かさねばならず、かつ視覚や音声の理解が必要なもの — MIT ライセンスでこの組み合わせを提供するモデルはほとんどありません。
  [プライベートなローカル AI スタック](/docs/models/private-local-ai-stack)を参照。
- ツールがきちんと仕様化された、短く境界のあるエージェンティックタスク。AutomationBench と Toolathlon のスコアが、真に競争力があると示している領域です。

**適合しない用途**

- 長時間の自律的なコーディングセッション。Terminal Bench 4.0 の差は Opus 5 に対して 14 ポイント、GPT-5.6 Sol に対して 5 ポイントで、しかもベンダー自身の数値です。
- ポストトレーニングの出発点となるベースチェックポイントが必要な場合。出荷されたのは RL チェックポイントだけです。
- Pro の 1 台構成でのセルフホスト。Flash か 9B 蒸留版を見込むか、Pro を借りてください。

## Xiaomi が開示した、多くのラボが開示しないこと

異例に具体的なので記しておく価値があります:Xiaomi は RL トレーニング実行の形とコストを公開しました — おおよそ 6 日間の実行、**30 RL ステップ**、約 **75 万トラジェクトリ**、**1,568 プロンプト × ステップあたり 16 ロールアウト**、報告されたコストは **Pro が ~$2.62M、Flash が ~$850K**、RL 中は MoE ルータを凍結した非同期 GRPO を使用。

ここから読み取るべきことが 2 つ。第一に、強化学習中にルータを凍結するのは安定性のための選択です:エキスパート割り当てを固定しておくことで、ポリシー更新がどのエキスパートを発火させるかを静かに作り変えてしまうことを防ぎます。第二に、そしてより有用な点として、**フロンティアに隣接するポストトレーニング実行のコストは今や数百万ドル台**であって、数億ドルではありません。4 つのラボが同じ週に出荷した理由を説明するのは、この数字です。
