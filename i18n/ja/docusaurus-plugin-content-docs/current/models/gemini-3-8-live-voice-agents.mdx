## 一文で言うと

低レイテンシの音声エージェントのデフォルトには **`gemini-3.8-live`** を使います。発信者が難しい多段階の質問をし、短い遅延が許容できる場合には **`gemini-3.8-live-extended-thinking`** を使います。どちらも **音声入力 100 万トークンあたり $3.00(約 $0.005/分)**、**音声出力 100 万トークンあたり $12.00(約 $0.018/分)**、テキストは $0.75 / $4.50 です。どちらも **131,072 トークンの入力ウィンドウ**と **65,536 トークンの出力上限**を持ち、どちらも Gemini API に無料枠があります。

## 何がリリースされ、Google は何を主張しているか

| | `gemini-3.8-live` | `gemini-3.8-live-extended-thinking` |
|---|---|---|
| Google の位置づけ | 「ほとんどの低レイテンシ音声エージェント体験のデフォルト選択肢」 | 「ライブ音声のやり取り中にバックグラウンド推論をサポートする高推論の audio-to-audio モデル」 |
| Thinking | インターリーブ推論;**`thinkingLevel` は受け付けない** | `thinkingLevel` = `low` / `medium` / `high`(**`minimal` はなし**);要約には `includeThoughts: true` |
| 関数呼び出し | デフォルトで非同期(`NON_BLOCKING`);`BLOCKING` も引き続き利用可;スケジューリング `INTERRUPT` / `WHEN_IDLE` / `SILENT` | **非同期のみ**、ブロッキングモードなし、スケジューリング制御なし |
| コンシューマー向け提供面 | Search Live | Gemini Live アプリ;サブスクライバー向けに Docs、Gmail、Keep |
| 主要な数字(Google) | Artificial Analysis の Speech Agent Arena で 2 位 | 82.6 Speech-to-Speech Quality Index(1 位);68.6% τ-Voice;35.1% τ-Voice-banking;97.7% Big Bench Audio |

Google が公開を選んだ数字、**τ-Voice-banking の 35.1%** を見てください。最上位の音声モデルでさえ、現実的な銀行業務タスクを音声で完了できるのは約 3 分の 1 にすぎません。これをお金を扱う無人音声エージェントの上限とみなし、結果を伴うあらゆる操作に確認ゲートを置いてください([全二重音声 AI](/docs/models/full-duplex-voice-ai) と同じルールです)。

すべての音声出力には **SynthID** の透かしが入ります。あなたのプロダクトがモデルの音声を録音または再公開する場合、AI 音声検出器がそれを識別できます。

## ほとんどの報道が見落としている 3 つのこと

### 1. 「thinking」モデルは推論しながら話す

Extended Thinking は考えている間に沈黙しません。Google はこれを「推論と発話を同時に行う」と説明しています。早い段階で口頭の合図(「確認しますね」)を出し、バックグラウンドで推論が続く間も進捗を語ります。これは、クライアントがモデルの完了をどう判断するかを変えます。このモデルでは **`turnComplete: true` はセッションがアイドルであることを意味しません**。バックグラウンド推論がまだ動いている可能性があります。通話を終了する、人間に引き継ぐ、次のスクリプト化されたステップを開始する前に、代わりに `interaction_status`(`IN_PROGRESS` と `IDLE`)を確認してください。

これは OpenAI が GPT-Live で導入したのと同じ「速く話す者、ゆっくり考える者」の分離です。違いは、Google が両方の役割を 1 つのモデルに入れているのに対し、GPT-Live は推論を別のフロンティアモデルに委譲している点です。

### 2. 3.1 Flash Live からのアップグレードはモデル名の文字列だけでなく挙動も変える

`gemini-3.1-flash-live-preview` → `gemini-3.8-live` に関する Google の移行ノートには、コードの動作を変える 4 つの変更が含まれています:

- **`thinkingLevel` を削除する。** 3.1 Flash Live のデフォルトは `minimal` でした。3.8 Live はこのフィールドを受け付けないため、3.1 からコピーした設定からは削除する必要があります。
- **ツール呼び出しはデフォルトで非同期になった。** 3.1 Flash Live では「ツールのレスポンスを送るまでモデルは応答を開始しない」動作でした。3.8 Live では関数の実行中もモデルは話し続けます。レイテンシには良いことですが、先に完了しなければならないツール(本人確認、決済)には明示的に `behavior: BLOCKING` を設定する必要があります。Extended Thinking モデルにはブロッキングモードがないため、そうしたフローは自分のコード側にゲートが必要です。
- **プロアクティブ音声は常にオン。** モデルは自分に向けられていない発話には応答しないと判断できます。これはオフにできず、ベストプラクティスガイドは **聞いている間も入力トークンが課金される**と述べています。
- **Affective dialog は廃止。** エージェントが発信者の口調に合わせるために `enableAffectiveDialog` に依存していたなら、削除して新しいデフォルトの挙動をテストしてください。

役に立つ変更が 2 つあります。`send_client_content` がセッション全体で機能するようになったため、通話中にテキストのコンテキスト(CRM データ、転送の記録)を注入できます。ターンカバレッジのデフォルトは `TURN_INCLUDES_AUDIO_ACTIVITY_AND_ALL_VIDEO` になりました。

### 3. 音声セッションのコストは長さより速く増える

音声はおよそ **毎秒 25 トークン**(1 分あたり約 1,500)で蓄積されます。分単価はここから来ています:1,500 × $3/1M ≈ $0.0045(入力)、1,500 × $12/1M = $0.018(出力)。罠は、**各ターンが新しい音声だけでなく蓄積されたコンテキスト全体を再処理する**ことです。ベストプラクティスガイドが直接そう述べています。その上に 2 つの小さなコストが積み重なります:文字起こしを有効にすると音声出力に加えてテキスト出力が課金され、プロアクティブ音声はモデルが聞いている間の入力トークンを課金します。

ざっくりした例示(Google の数字ではなく、こちらの計算):20 ターンの 10 分間の通話を考えます。コンテキストは 0 から約 15,000 トークンに成長するので、平均的なターンは約 7,500 トークンの入力を再読します。これは約 150,000 入力トークン(約 $0.45)で、新しい音声だけを数えた場合の約 $0.045 と比べて大きな差です。**長い通話は合計だけでなく、分あたりのコストも高くなります。** 15 分の壁を越えるためにいずれにせよ必要なコンテキストウィンドウ圧縮は、このコスト増も抑えます。

## ブラウザとモバイルのクライアント:API キーは絶対に出荷しない

Live セッションはクライアントが Google に直接接続するときに最もよく機能します。リアルタイム音声を自分のバックエンド経由でプロキシするとレイテンシが増えるからです。これを安全に行う方法が **エフェメラルトークン**です。サーバーが発行し、クライアントが 1 回使います。デフォルト:トークンは作成から **30 分**で失効し、**1 分以内に新しいセッションを開始**するために使う必要があり、**1 回**の使用が許可されます。`liveConnectConstraints` で特定のモデル、レスポンスモダリティ、再開設定にロックできるので、盗まれたトークンを他の用途に使うことはできません。エフェメラルトークンは Live API でのみ、かつ `v1beta` でのみ機能します。

## Gemini 3.8 Live と代替案の比較

- **Claude との比較。** Claude の音声機能はターンベースのままです:[Claude アプリの音声モード](/docs/claude-app/voice-mode)、Claude Code のプッシュトゥトーク。よくあるハイブリッドは、Live モデルを会話のフロントエンドにし、重い推論やコーディングのために Claude をツールとして呼ぶ構成です。非同期関数呼び出しはこのパターンによく合います。ツールの実行中も通話を続けられるからです。
- **OpenAI との比較。** GPT-Live は音声ネイティブの全二重 ChatGPT プロダクトです。開発者向けには、OpenAI の提供物は Realtime API 上の gpt-realtime です(全体像は [全二重音声 AI](/docs/models/full-duplex-voice-ai) を参照)。
- **初期のコミュニティ報告(Hacker News のローンチスレッド、未検証)。** コメント投稿者はレイテンシ、音声品質、アクセントの処理、ライブ翻訳を称賛しました。一方で Extended Thinking の推論が一貫しない、エージェント的なフローでモデルが「追加の要件を勝手に作り出す」と述べる人もいました。これらは測定ではなく逸話ですが、35.1% の banking スコアと整合しています:信頼する前に、自分のタスクをエンドツーエンドでテストしてください。
