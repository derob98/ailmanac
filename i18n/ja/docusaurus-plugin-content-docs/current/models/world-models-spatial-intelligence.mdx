## 同じ名前を 2 つのものが共有している

|  | **フレーム生成器** | **3D 生成器** |
|---|---|---|
| 例 | Genie 3 / Project Genie、運転向けワールドモデル | Marble (World Labs) |
| 何を出力するか | あなたの行動を条件にした、1 フレームずつの動画ストリーム | シーン:Gaussian splat、パノラマ、任意でメッシュ |
| 世界はどこにあるか | モデルのローリングコンテキストの内側 | ダウンロードしたファイルの中 |
| インタラクティブ? | **はい** — それが存在意義 | いいえ。中を移動はできるが、反応はしない |
| エクスポート可能? | **いいえ**。エクスポートすべきジオメトリがない | はい — SPZ、PLY、GLB、コライダーメッシュ |
| コストの形 | インタラクションの秒あたり、視聴者あたり、永続的に | 生成時に一度きり。以後のレンダリングは自分のもの |
| 失敗の仕方 | ドリフトする、忘れる、セッションが尽きる | 静的で、何もシミュレートしない |

**反応する**世界が必要なら — プレイヤーがキーを押す、ロボットのポリシーが行動を取って何が
起きるかを見る — フレーム生成器が必要です。**永続する**世界が必要なら — ゲームの中の
アセット、レンダーパイプラインのセット、来月 5 人のユーザーが読み込んで同じものを見る
シーン — 3D 生成器が必要です。この話題での「なぜ単に…できないのか」という混乱した質問の
ほぼすべては、片方を手にしながらもう片方を求めている人によるものです。

## フレーム生成器と、60 秒の壁

Google の **Project Genie** は **2026 年 1 月 29 日**に研究プレビューから半ば公開の
プロダクトになりました。アクセスの形は狭く、それを前提に計画を立てる前に知っておく価値が
あります:**Google AI Ultra** の加入者、**米国のみ**、**18 歳以上**、そして Google AI Ultra
for Business では明示的に**利用不可**。Google 自身はこれを「実験的な研究プロトタイプ」と
呼んでいます。

最も多くを教えてくれる制限は Google 自身のもの:**生成は 60 秒に制限される。** これは課金の
判断ではなく、状態の問題です。フレーム生成器では世界はどこにも保存されていません — それは
モデルのコンテキストによって含意されているのです。すべてのフレームは、プロンプトと蓄積された
フレームとあなたの行動から予測されます。したがって一貫性は、長いチャットを縛るのと同じもの、
つまりモデルがどれだけの履歴を保持して整合させられるかによって縛られます。壁から離れて
また戻ったとき、その壁がまだそこにあるかどうかは*記憶*の問題であって、レンダリングの
問題ではありません。

Google が明記している注意書きが、正直なスペックシートの残りです。生成された世界は
「完全に実物そっくりに見えるとは限らず、プロンプトや画像、現実世界の物理に常に忠実に従うとは
限らない」、そしてキャラクターは「ときに制御しづらかったり、制御のレイテンシが高くなったり
する」。

フレーム生成器をシミュレータとして使うつもりだったなら、この物理の一文を注意深く読んで
ください。これは解くエンジンではなく、もっともらしさのエンジンです。フレーム 300 と
フレーム 301 のあいだで運動量が保存されることを保証するものは何もありません。

### 誰も触れないフレーム予算

一般に報じられている 24 fps でのインタラクティブ生成は、あなたの入力がサーバーに届くまでを
含めて、エンドツーエンドで**1 フレームあたり約 41.7 ms** です。この 1 つの数字が、この
ファミリーのプロダクト上の判断のほとんどを説明します。なぜセッションが短いのか、なぜ
アクセスが有料ティアに絞られているのか、なぜまだ公開 API がないのか、そしてなぜコスト曲線が
アセットあたりではなく*視聴者の秒あたり*なのか。あなたが買っているのはファイルではありません。
誰かが見ているあいだじゅう 42 ミリ秒の締切を守り続けなければならない GPU を借りているのです。

## 3D 生成器と、実際に受け取るもの

World Labs の **Marble** は、テキスト、画像、パノラマ、複数視点、あるいは動画クリップを、
移動可能な 3D シーンに変えます。重要なエンジニアリング上の事実は、その表現です。出力は
メッシュではなく **3D Gaussian splat** です。

splat は、色と視点依存のシェーディングを持つ、小さく向きのある半透明の粒が何百万個も
集まったものです。写真からの再構成が非常に美しく、コモディティ GPU で高速にレンダリング
できます。そして表面も、辺も、面も持ちません — 次のセクションが見た目以上に重要なのは
そのためです。

Marble 自身のエクスポートのドキュメントが言う、受け取れるもの:

| エクスポート | 利用条件 |
|---|---|
| Gaussian splat — **SPZ** と **PLY** | Standard プラン |
| 360 パノラマ | Standard プラン |
| **コライダーメッシュ** | Standard プラン |
| テクスチャ付きメッシュ(**GLB**)+ 商用権 | **Pro プランのみ** |
| そもそも何であれ | **Free では不可** — 生成のみ |

この表には落とし穴が 2 つ潜んでいます。第一に、**コライダーメッシュは別のエクスポート**
です — splat に対しては直接レイキャストも衝突も物理も行えないので、これが必要になります。
プレイヤーが見るのは splat で、エンジンが判定にかけるのはコライダーメッシュです。splat だけ
出荷すれば、美しい世界に床がありません。第二に、**商用権は Pro ティアに紐づいており**、
エクスポートするという行為に紐づいてはいません。生成した世界をプロダクトに入れる前に
プランを確認してください。

Marble のドキュメントはまた、低解像度のエクスポートが「より高解像度のファイルと知覚的に
できるだけ似るよう最適化されている」とも述べています — 大きいほうを出荷するために支払う前に、
小さいティアをテストすべきだというヒントです。

### SPZ:World Labs のものではない 10 倍

いくつかの記事が取り違えている点:**SPZ は Niantic の形式**であり、Niantic Spatial が
オープンソース化したもので、World Labs の発明ではありません — Marble は単にそれに
エクスポートしているだけです。それでも使う価値はあります。SPZ は各球面調和係数を 8 ビットの
符号付き整数として格納し、さらに任意で量子化でき、知覚できる品質低下なしに**同等の PLY より
およそ 10 倍小さく**なります。Niantic 自身のテストでは、ほとんどのシーンで**約 5 ビットが
スイートスポット**、8 ビットで MSE は実質ゼロ、3 ビットで約 18 倍の圧縮とされています。
2026 年にリリースされた **SPZ 4** は、圧縮を属性クラスごとに 1 本ずつ、6 本の並列 ZSTD
ストリームに分割し、同じ約 10 倍のサイズ優位性のまま**圧縮がおよそ 3〜5 倍高速**、
**エンドツーエンドの読み込みが 1.5〜2 倍高速**になりました。

splat をウェブで配信するなら、これは「読み込めるシーン」と「読み込めないシーン」の差です。

## API を、本当のところ

**World API** は Marble の生成をあなた自身のコードに公開します。World Labs のドキュメント
索引と公式 Python クライアントから確認できる形:

- **入力**:テキスト、画像、パノラマ、マルチビュー入力、動画。
- **出力**:**SPZ、PLY、SOGS、KSPLAT**、**SPLAT** 形式の splat。
- **認証**:**`WLT-Api-Key`** ヘッダーで渡す API キー。Python クライアントは環境変数から
  `WORLDLABS_API_KEY` を読みます。
- **実行モデル**:**非同期**。生成を投入するとオペレーションが返り、**完了するまで
  ポーリング**します。クレジット残高のエンドポイント、メディアのアップロード/取得、
  world の作成/取得/一覧/エクスポート/削除もあります。
- **クライアント**:`worldlabsai/worldlabs-api-python`、**Python 3.12+**。CUDA GPU が必要
  なのはローカルレンダリングのときだけで、API 利用には不要です。
- **価格**:従量課金。

<PromptCard title="テキストから world を生成し、ポーリングする">
{`# github.com/worldlabsai/worldlabs-api-python  (Python 3.12+)
# export WORLDLABS_API_KEY=...

from worldlabs_api.client import WorldLabsClient
from worldlabs_api.models import WorldTextPrompt, WorldsGenerateRequest

client = WorldLabsClient(api_key="your-key-here")

request = WorldsGenerateRequest(
    display_name="Mystical Forest",
    world_prompt=WorldTextPrompt(text_prompt="A mystical forest"),
)

op = client.generate_world(request)      # returns an operation, not a world
done = client.poll_operation(op.operation_id)   # poll until done is true
world = done.response`}
</PromptCard>

初日からその非同期の境界を前提に統合を設計してください。world の生成はリクエストではなく
ジョブです — バッチ推論や動画生成と同じ教訓です。ハンドラが world をインラインで待つなら、
書き直すことになります。

### ゲームエンジンなしでレンダリングする

World Labs は **Spark** も維持しています。**THREE.js / WebGL2** 向けの MIT ライセンスの
3D Gaussian splatting レンダラーで、生成された world をウェブページとして出荷できます。
`.PLY`、`.SPZ`、`.SPLAT`、`.KSPLAT`、`.SOG` を読み込み、THREE.js のパイプラインで splat を
通常のメッシュと融合し、WebGL2 を備えた約 98% のデバイスを対象にします。

**Spark 2.0**(2026 年 4 月 15 日)は、大きなシーンをブラウザで成立させるリリースです。
シーンのサイズに関係なくフレームあたり一定数の splat をレンダリングする LoD の
**splat ツリー**、HTTP Range リクエストに対応してまず粗いプロキシがほぼ即座に現れ、
段階的に精細化されるストリーミング形式 **`.RAD`**、そして固定の GPU メモリプールに対する
**仮想 splat ページング**により、GPU メモリより大きなシーンも — スマートフォンや Quest 3 でも —
レンダリングできます。

<PromptCard title="生成した world をウェブに載せる">
{`npm install @sparkjsdev/spark three
# docs and live examples: https://sparkjs.dev
# repo: https://github.com/sparkjsdev/spark
#
# Export from Marble as .spz (≈10x smaller than .ply), serve it as a
# static file, and load it into a THREE.js scene with Spark.
# For scenes over a few hundred MB, convert to .RAD so the viewer can
# range-request a coarse proxy first.`}
</PromptCard>

いまコスト曲線に何が起きたかに注目してください。生成のあとは、CDN から静的ファイルを
配信し、ユーザーの GPU でレンダリングしています。**world を配信するのは無料です。** これは
視聴者の秒ごとが推論であるフレーム生成器のモデルの、ちょうど裏返しです。

## 証拠:WorldScore

「動画モデルを使えばいい」はこの領域で最もよくある近道であり、いまやそれに答える
ベンチマークがあります。**WorldScore**(Stanford、`arXiv:2504.00983`)は、3D、4D、
text-to-video、image-to-video のモデルを横断する world 生成の統一ベンチマークです —
約 **3,000 例**、制御性・一貫性・知覚品質・動きの指標を備え、明示的な **3D 一貫性**と
カメラ制御の測定を含みます。

判断を変えるべき結果:**WorldScore-Static** では、専用の 3D シーン生成器が先行しています —
**WonderWorld が 72.69**、**LucidDreamer が 70.40** で、動画モデルより明確に上です。
幾何学的に一貫した世界の中をカメラで動きたいのが要件なら、個々のフレームの見栄えが良くても
動画モデルは間違った道具です。

注意点が 2 つ。リーダーボードは生きており、チームが投稿するたびに動きます。そして
WorldScore-Static は名前のとおりのものを測っています — *静的な*世界であり、静的な一貫性が
強いことは動特性について何も教えてくれません。

## オープンウェイト:Cosmos 3 と、AMD が実際に買ったもの

world モデルを持つのにベンダーの API は必要ありません。NVIDIA は物理 AI 向けのオープンな
**omnimodel** である **Cosmos 3** を、Hugging Face 上の重みとともに公開しました:

| モデル | サイズ | 動作環境 |
|---|---|---|
| `nvidia/Cosmos3-Edge` | **4B** | エッジデバイス、ロボット、ビジョンエージェント |
| `nvidia/Cosmos3-Nano` | **16B** = 8B reasoner + 8B generator | ワークステーション級、例: RTX PRO 6000 |
| `nvidia/Cosmos3-Super` | **64B** = 32B reasoner + 32B generator | Hopper / Blackwell、大規模な合成データ |

アーキテクチャ的には、テキスト、画像、動画、音声、そして**行動**を 1 つのモデルで扱う
**Mixture-of-Transformers** であり、推論のための自己回帰サブシーケンスと生成のための拡散
サブシーケンスを組み合わせています。Hugging Face Diffusers に組み込まれているので、
入口は普通の Python です。

<PromptCard title="オープンなワールドモデルをローカルで動かす">
{`pip install --upgrade diffusers transformers accelerate

# Cosmos3-Nano is 16B (8B reasoner + 8B generator); check the model
# card on Hugging Face for the licence and the exact torch version
# before you build on it.

import torch
from diffusers import Cosmos3OmniPipeline

pipe = Cosmos3OmniPipeline.from_pretrained(
    "nvidia/Cosmos3-Nano", torch_dtype=torch.bfloat16
)`}
</PromptCard>

さて、価格の理由を説明する部分です。Cosmos 3 のタスク表は動画の小技の一覧ではありません:

| 入力 | 出力 | それが何か |
|---|---|---|
| テキスト / 画像 / 動画 | 動画 | 動画生成 |
| テキスト / 動画 | テキスト | 視覚言語推論 |
| **行動** + 画像 + テキスト | 動画 | **forward dynamics** — 「これをしたら、何が起きる?」 |
| テキスト + **動画** | **行動** | **inverse dynamics** — 「どんな行動がこれを生んだ?」 |
| 画像 + テキスト | 動画**と行動** | **ポリシー生成** |

inverse dynamics が静かな主役です。これは映像を**ラベル付きの行動**に変えます — つまり
普通の動画がロボットの学習データになり、生成された world がハードウェアなしでポリシーを
学習・評価する場になるということです。AMD 自身のリリースは World Labs を「インタラクティブな
3D 環境を生成・再構成・シミュレートする」モデルを作る企業と表現し、*加えて*「ロボット学習と
シミュレーション」の技術にも言及し、推論・ロボティクス・シミュレーション・物理 AI が同社の
将来のシリコンロードマップに情報を与えるという枠組みでこの取引を語っています。

グラフィックスの物語ではなく計算の物語として読むと、学習環境のフライホイールへの 82 億ドルは、
text-to-3D ツールへの 82 億ドルとは別種の賭けです。

## 一度で選ぶ

- **ゲームやプロダクトのアセット、複数ユーザー、明日も同じに見える必要がある** → 3D 生成器。
  ウェブなら SPZ、エンジンなら GLB でエクスポートし、コライダーを忘れずに。
- **インタラクティブな探索、ユーザー 1 人、目新しさが目的** → フレーム生成器。60 秒の
  セッションの内側で設計する。
- **ポリシーの学習または評価** → forward と inverse の dynamics を持つオープンウェイトを
  自分の GPU で。安全に関わるものには本物のシミュレータを添えて。
- **一貫したシーンの中を動くカメラ** → 動画モデルではありません。WorldScore がそう言って
  います。
