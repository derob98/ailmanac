## この研究を一段落で

主にマドリードの [IMDEA Networks](https://networks.imdea.org/) に所属する9人の研究者が、
最も利用されている9つの会話型AIサービスを取り上げ、モバイルトラッキングの研究コミュニティが
アプリを調べるときと同じ手法で計測した。Webクライアントについては Chrome DevTools Protocol
経由で駆動する Chrome v148 と完全なHARキャプチャ、Androidアプリを提供している8サービスに
ついては `mitmproxy` と Frida を組み込んだ Android 12 AOSP ビルドを動かす Google Pixel 3a、
さらに Androguard による静的逆コンパイルで組み込みSDKを列挙した。すべてのセッションは、
意図的に機微な内容を含む固定のペルソナ台本（ある病状について尋ねるユーザー）に沿って手動で
実行され、ゲスト／無料／有料の各ティア、そして3つの同意状態（バナーを無視する、非必須クッキーを
拒否する、すべて受け入れる）にわたって繰り返された。測定は2026年5月にスペインで行われた。
この論文はプライバシー技術の査読付き会場である PoPETs に採択され、著者らは公表前に各プロバイダーと
欧州のデータ保護当局に対する責任ある開示プロセスを実施している。

この方法論が重要なのは、「あるページに Meta のピクセルが見つかった」という話と、どの同意状態で、
どのティアで、誰に対して、何が送信されるのかという擁護可能な主張との違いを生むからだ。

## 会話由来のアーティファクトがなぜ別種の問題なのか

通常のWebトラッキングが観測するのは*行動*である。どのページを読み込み、どれだけ滞在し、何を
クリックしたか。会話型AIは新しい種類のオブジェクトを生み出す。提供元自身が、あなたが何を考えて
いるのかを短く人間が読める形に要約し、そのオブジェクトが同じパイプを通って流れていくのだ。

論文の Appendix A は、その要約が具体的にどのようなものかを示している。同じプロンプト、3つの
プロバイダー:

| ユーザーが入力したプロンプト | ChatGPT が生成したタイトル | Claude が生成 | Grok が生成 |
| --- | --- | --- | --- |
| 「パーキンソン病の初期症状は何ですか?」 | パーキンソン病初期の症状 | パーキンソン病初期段階の症状 | パーキンソン病早期の症状 |
| 「年収は8万5千ドルです。ニューヨークでいくらの住宅ローンを組めますか?」 | NYCでの住宅ローン負担可能額 | 年収8万5千ドルでのNYC住宅ローン負担可能額 | 年収8万5千ドルのNYC: 住宅ローン28万〜35万ドル |

右下のセルを見てほしい。Grok のタイトルは話題を記録しているだけではない — 年収の数字と住宅ローンの
レンジを含む*答え*そのものを、短い文字列に符号化している。その文字列が安定した識別子とともに
広告ネットワークに送信されたとき、広告ネットワークはたった1つのフィールドから健康状態や
金融プロファイルを学習したことになる。推論も、モデリングも、クリックストリームの再構成も要らない。
提供元が代わりに要約してくれたのだ。

論文が漏洩として数え上げたものと、その送信先となる異なるトラッキング組織の数は次のとおり:

| 漏洩したアーティファクト | プロバイダー数（Web） | プロバイダー数（Android） | トラッカー数（Web） | トラッカー数（Android） |
| --- | --- | --- | --- | --- |
| 会話のURL | 5 | 0 | 9 | 0 |
| 会話ID | 2 | 2 | 1 | 1 |
| ユーザーのプロンプト | 1 | 1 | 2 | 1 |
| 会話のタイトル | 3 | 0 | 9 | 0 |
| 会話のスクリーンショット | 1 | 0 | 1 | 0 |
| 共有された会話のURL | 5 | 0 | 9 | 0 |
| 共有された会話のID | 0 | 1 | 0 | 1 |

この非対称性は覚えておく価値がある。*Web* クライアントはユーザーに見えるアーティファクト
（タイトル、URL、スクリーンショット）を漏らす。WebトラッカーはページのJavaScriptコンテキスト内で
実行され、DOMをそのまま読めるからだ。モバイルSDKは WebView のドキュメントの外で動くため、
主に会話IDしか得られない — だがその代わりにはるかに豊富な識別子の集合を手に入れる。第三者のSDKは
ホストアプリの権限をそのまま引き継ぐからである。

## 広告ブロッカーを無力化する3つの仕組み

ここが大半の報道が見落としている部分であり、このページで最も応用の利く教訓でもある。ブラウザで
`doubleclick.net` をブロックしても、以下のどれにも効果はない。

4つ目の仕組みは、実際のトラフィックではなく CSP ヘッダーに現れる。Content-Security-Policy
レスポンスヘッダーは、ページが接続を*許可されている*オリジンを列挙する。テスト中は沈黙していた
ものも含まれるため、将来の挙動に対する有用な下限値になる。9つのサービス全体では:

| 組織 | CSP内のドメイン | プロバイダー数 |
| --- | --- | --- |
| Google Tag Manager | `googletagmanager.com` | 6 |
| Google Analytics | `google-analytics.com` | 5 |
| Google Ads | `googleadservices.com` | 4 |
| Meta Pixel / Conversions API | `connect.facebook.net`, `facebook.net` | 4 |
| Google DoubleClick | `doubleclick.net` | 3 |
| TikTok Analytics | `analytics.tiktok.com` | 2 |
| Reddit Ads / Analytics | `pixel-config.reddit.com`, `redditstatic.com` | 2 |
| Microsoft Bing | `bat.bing.com`, `bing.com` | 2 |
| Intercom | `intercom.io`, `intercomcdn.com` | 2 |

ここから2つの構造的な観察が導かれる。覚えておくべきなのはこの2つだ。

**最も強力な制御は、最も露出の大きいユーザーにとって最も手の届かないところにある。** Web上で
同意設定を永続化できるのは ChatGPT の有料ティアだけだが、ChatGPT ユーザーのおよそ95%は無料ティアに
いる — しかも OpenAI は無料および低価格ユーザー向けの広告を発表済みだ。モバイルでは、同等の
トラッキング基盤を抱えているにもかかわらず、起動時にクッキー同意に相当するものを提示するアプリは
ほとんどない。尋ねられなかったものを拒否することはできない。

**存在することは目的の証明ではない。** 論文はこの点に慎重であり、あなたもそうあるべきだ。
トラフィックに第三者が現れることは、それ自体ではデータが広告に使われていることを意味しない。
クラッシュレポート、セッションリプレイ、アプリ内決済を担うSDKもある。Sentry、Datadog、Intercom には
明白な運用上の正当性がある。著者らはまた、自分たちの方法論ではプロバイダー自身のファーストパーティな
サーバーサイドトラッキングと機能的なトラフィックを区別できないとも述べている。表は「これらの事業者が
このデータを受け取っている」として読むべきであり、「このデータが確実に売られている」として読むべきでは
ない。

## パーマリンクはアクセス制御ではない

9つのサービスのいずれも会話を共有できるようになっており、そのいずれもが受信者の認証を求めることなく
共有された会話を配信する。セキュリティモデルは、URLに含まれるUUIDの推測困難性だけだ。論文の表6は
プロバイダーとティアごとのデフォルトの姿勢を測定している。際立った2つの例外は、無料版・プレミアム版の
会話パーマリンクがデフォルトで公開（オプトアウトあり）の Grok と、ゲストティアの会話が常に公開で
オプトアウトがまったくない Perplexity である。Perplexity はその上にホワイトリスト制御を提供する
唯一のプロバイダーでもある。

そして著者らは、理論上の露出を測定された露出に変えることをやってのけた。カナリアトークンを配備したのだ
— `canarytokens.org` のものと、一部のアシスタントが既知のカナリアドメインを認識して拒否するため、
汎用ドメインを使った自己ホスト型のカナリア基盤のものと、両方を使った。それらをプロンプトに直接貼り付け、
さらにアップロードした `.docx` と `.pdf` のファイルの中にも埋め込んだ。そして誰がそれを取得しに来るかを
待った。

48の異なるネットワークから数日後に70回の取得が行われるのは、リンクプレビューの挙動ではない。
URLがパイプラインに流出してクロールされたときの痕跡だ。著者らは適切に慎重である — 自前の計測装置が
捉えたものしか見えない以上、他のサービスでアクセスが観測されなかったことはアクセスがなかったことの
証拠にはならない — が、陽性の結果はそれ自体で成立している。

Grok はまた、意図的な製品上の判断ではなく外部の第三者によって悪用可能なセキュリティ上の問題として
著者らが分類した事象が見つかった唯一のサービスでもある。だからこそ xAI には、通常の研究通知ではなく
2026年4月17日に脆弱性開示のメールが送られた。2026年9月10日時点で、論文は Grok が依然として公開
アクセス可能なパーマリンクを使用しており、公式な回答は得られていないと報告している。

## これらのAPIの上に作るなら、これはあなたの問題でもある

論文のスコープに関する注記は読み飛ばしやすいが、エンジニアが最も心配すべき部分だ。ここで観測された
漏洩の経路は「標準的なWebおよびモバイルのトラッキングを会話インターフェースに直接埋め込んだことに
起因する」。そのどれもフロンティアラボに固有のものではない。LLM搭載のサポートチャットボット、
カスタムアシスタント、第三者製のAIラッパーを出荷していて、マーケティングチームが同じページに
いつものアナリティクスを入れているなら、あなたはほぼ確実にこのアーキテクチャを偶然再現している。

自分のプロダクトで確認すべき具体的な3点:

- **会話のタイトルや要約をクライアントサイドで生成しているか?** そうならそれらはDOMの中にあり、
  そのページ上のどんなタグマネージャーからも読める。対策は、生成した要約をドキュメントタイトル、
  `<meta>` タグ、そしてあらゆるアナリティクスのイベントペイロードから外すことだ。
- **会話IDがURLのパスに入っているか?** それならページが行うすべての第三者リクエストの `Referer`
  ヘッダーに含まれ、すべてのスクリプトから `document.location` で読める。研究は2つのプロバイダーが
  グローバルな会話IDを独立したパラメータとして Datadog に送っているのを見つけており、それだけで
  パーマリンクを再構成できる。
- **共有ページは公開で読めるか?** ePrivacy指令の第5条3項および、その技術的範囲に関する EDPB の
  ガイドライン 2/2023 の下では、URLとピクセルによるトラッキング、永続的識別子、そしてブラウザに
  データをサーバーサイドAPIへ転送させる指示は、いずれも事前の十分な説明に基づく同意を必要とする。
  EU司法裁判所の *Fashion ID* 判決（C-40/17、第78項）はさらに踏み込み、第三者のアクセスを可能にすること
  自体が処理に関する決定であり、その第三者が実際にデータを読んだかどうかにかかわらず、あなたの義務を
  発生させるとしている。
