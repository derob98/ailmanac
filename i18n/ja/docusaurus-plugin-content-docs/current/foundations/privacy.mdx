<VerifyNote lastVerified="2026-11-09" source="https://www.anthropic.com/legal/privacy">
データの扱いと学習に関するポリシーは、プロバイダー、製品、プラン（コンシューマー・API・エンタープライズ）によって異なり、時間とともに変わります。このページの内容は、ご利用のプロバイダーの最新の規約を読むことの代わりにはなりません。ここにあるのは答えではなく、尋ねるべき質問のリストだと考えてください。
</VerifyNote>

シンプルですが重要な問いです。**AIに送ったテキストはどうなるのか？** その答えはプロバイダー、製品、プランによって変わります。だから安全な習慣は、*貼り付ける前に知っておく*ことです。

最もよくある間違いは、保証が**話題**に付いてくると思い込むことです。ほとんどの場合、そうではありません。保証は**サーフェス**（この機能、このハブ、このAPI）や**プラン**（エンタープライズ、ゼロリテンション）に紐づきます。つまり、給与についての同じ一文でも、同じアプリのどこに入力したかによって、まったく違う扱いを受けることがあります。

## 1つではなく4つの問い

「プライベートか？」という問いには、独立した4つの性質がまとめられています。ツールはどれか1つで高得点でも、別の1つでは低いことがあるので、別々に尋ねましょう。

## 保証は話題ではなくサーフェスに付く

最も分かりやすい実例は、Anthropicの**Personal Finance**機能です。Personal Financeハブ内の会話はAnthropicのモデルの学習に使われず、メモリや月次サマリーにも含まれません。同じ銀行明細を通常のClaudeのチャットに貼り付けた場合は、代わりに**通常のアカウントのプライバシー設定**が適用されます。除外はハブに付いてくるのであって、お金について話していたという事実に付いてくるのではありません。

<Callout type="warning" items={[
  "例ではなく教訓を一般化しましょう。プライバシーの約束を読むときは、それが何に限定されているかという名詞を探してください。「このワークスペースで」「このプランで」「このAPI経由で」「このハブで」— その名詞が実際の境界線です。範囲を示す名詞のない約束は、たいていあなたのデータについてではなく、ベンダーの意図についての約束です。"
]} />

## 実践的な経験則

- **シークレットを貼り付けない** — APIキー、パスワード、トークンは、どのAIツールにも絶対に貼らないでください。ベンダーが信用できないからではなく、トランスクリプトの中のシークレットは、ログの中の、バックアップの中の、共有リンクの中の、場合によってはサポートチケットの中のシークレットになるからです。
- **個人データを最小限にする。** タスクに必要なものだけを送り、可能なら名前、ID、口座番号は伏せましょう。推論するのに識別子が必要になることはめったにありません。
- **他人のデータは他人のもの。** 顧客の個人情報、健康情報、金融情報の扱いには注意してください。あなた個人の感覚では覆せない法的義務（GDPR、HIPAAなど）があるかもしれません。
- **適切なプランを使う。** 規制対象や機密の業務には、個人アカウントではなく、ビジネス／エンタープライズ／ゼロリテンションのオプションを使いましょう。このページで最も効果の大きい一手です。
- **データが環境の外に出てはならないときは、ローカル／セルフホストのモデルを検討する** — 性能を少し手放す代わりに、完全なコントロールを得られます。[プライベートなローカルAIスタック](/docs/models/private-local-ai-stack)を参照してください。

## 見落とされがちな3つのサーフェス

プロンプトは分かりやすいものです。次の3つは、人が驚くような形で漏れます。

| サーフェス | 見落としやすい理由 | 対処 |
| --- | --- | --- |
| **接続したアカウント**（銀行、メール、ドライブ、CRM） | 許可は、AIアプリではなく*アグリゲーターやOAuthプロバイダー*側にあります。サブスクリプションを解約したりアプリを削除したりしても、接続が生きたままになることがよくあります。 | 大元で監査・取り消しをします — アグリゲーターのポータル、GoogleやMicrosoftアカウントのサードパーティアプリ一覧です。AIアプリ側のトグルは便宜上のものと考えてください。[コネクタ](/docs/claude-app/connectors)を参照。 |
| **メモリ** | 会話*をまたいで*文脈を持ち運ぶように設計されているため、一度した打ち明け話を、予想していないチャットまで持ち込んでしまいます。 | ツールにメモリがあるか、何が保存されているか、全部ではなく1件だけ消すにはどうするかを把握しておきましょう。[チャットをまたぐメモリ](/docs/claude-app/memory)を参照。 |
| **公開・共有したものすべて** | 共有リンクや公開したアーティファクトは、多くの場合、独自の寿命を持つ*別のオブジェクト*です。元の会話より長く残ることがあり、インタラクティブなものは閲覧者自身の接続済みデータを読めます。 | 共有する前に、受け取った側のコピーが何を表示するかだけでなく、何ができるかを考えましょう。チャットを削除してもクリーンアップにならないことがよくあります。 |

## オンデバイスとクラウド

| | クラウド（ホスト型） | ローカル／セルフホスト |
|---|---|---|
| 性能 | 最高 | 低め（ただし向上中） |
| データがマシンの外に出る | はい（プロバイダーの規約による） | いいえ |
| セットアップ／コスト | 簡単、従量課金 | 手間がかかる、自前のハードウェア |
| 信頼しなければならない相手 | プロバイダーの規約と管理 | 自分のマシン、パッチ適用、バックアップ |

ローカルが自動的により安全なわけではありません。*別の形で*プライベートなのです。2年分のトランスクリプトが入った暗号化されていないノートPCは、ゼロリテンションのプランにいる信頼できるプロバイダーよりも悪い結果です。ローカルを選ぶのは、要件が本当に「これはネットワークの外に出てはならない」のときであり、反射的に選ぶものではありません。
