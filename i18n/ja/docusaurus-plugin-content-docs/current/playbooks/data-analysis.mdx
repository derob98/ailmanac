AIでデータから答えを得るのに、データサイエンティストである必要はありません — ただし、AIを正直に保つ必要はあります。AIがクエリを書いて結果を説明し、**あなた**が数値が本物であることを確認します。

## AIが役立つこと

- 平易な言葉の質問から**SQL / スプレッドシートの数式 / pandas を書く**。
- クエリや結果がビジネス上どういう意味を持つかを**説明する**。
- 雑然としたデータを**クリーニングして変換する**(雑然とした状態を説明すると、手順が得られます)。
- 質問に**適したグラフを提案する**。
- 出力を**解釈し**、次の質問を提案する。

## ガードレール

:::warning AIが計算していない数値を決して信用しない
AIがあなたのデータに対してクエリを実行せずに結果を述べた場合、その数値は**でっち上げ**かもしれません。クエリは自分で実行し、自分で計算していない数値はすべて未検証として扱ってください。そして**相関 ≠ 因果**を忘れずに — 関連性に基づく主張にフラグを立てるよう求めてください。[ハルシネーション](/docs/foundations/hallucinations)を参照。
:::

- **桁の妥当性を確認する** — ありえない結果? 公表する前に調査してください。
- **前提を述べる**(NULL、重複排除、タイムゾーン、通貨)。
- **機密データ/個人情報を貼り付けない** — 検証していないツールには([プライバシー](/docs/foundations/privacy))。

この4つの前提が特定の順序で並んでいるのは、おおよそその順でよく痛い目に遭うからです。NULLは分母を静かに縮め、重複行は合計を静かに膨らませ、UTCで保存されたタイムスタンプをローカル時刻として読むと売上が月の境界を越えて移動し、通貨が混在した `total` カラムは算術的には正しく経済的には無意味な数値を生みます。

<Callout type="tip" items={["クエリと、それを常識的に検算する2本目のクエリの両方を求めましょう — 行数、日付範囲、目で確認できる合計など。検証できないエレガントな1本より、安価な2本が勝ちます。","結果に驚いたときは、ビジネスを疑う前に結合を疑いましょう。ファンアウト結合は、数値が突然3倍になる最も多い原因です。","スプレッドシート作業では、数式に加えて1セル分の計算例も求めましょう。例が間違っていれば、本番ファイルに触れずにバグを見つけたことになります。"]} />
