आप पहले से ही Claude में सोचते हैं। अब कोई साथी एक Custom GPT साझा करता है, या कोई क्लाइंट ChatGPT में रहता है, और आपको वहाँ **आज ही** उत्पादक बनना है — बिना यह दोबारा सीखे कि AI असिस्टेंट को शुरू से कैसे इस्तेमाल करें। अच्छी खबर: आप जो कुछ भी जानते हैं, लगभग सब कुछ ट्रांसफर हो जाता है। यह पेज आपके Claude मानसिक मॉडल को ChatGPT पर मैप करता है, उन गिनी-चुनी चीज़ों को चिह्नित करता है जो सचमुच अलग तरीके से काम करती हैं, और आपको बताता है कि हर एक कब चमकता है।

:::warning Custom GPTs विदा हो रहे हैं — उनकी जगह plugins ले रहे हैं
OpenAI **custom GPTs को plugins में स्थानांतरित कर रहा है**, और विदाई (retirement) पर custom GPTs काम करना बंद कर देंगे। अगर कोई साथी आज आपको एक Custom GPT देता है तो वह अभी भी चलता है, पर उस पर कुछ नया न बनाएँ — निवेश करने से पहले नीचे **Projects बनाम Custom GPTs** पढ़ें।
:::

## 60-सेकंड की अवधारणा-मैप

अगर आप केवल एक ही सेक्शन पढ़ें, तो यह पढ़ें। यहाँ बताया गया है कि Claude में आप जो चीज़ें जानते हैं वे ChatGPT से कैसे मेल खाती हैं:

| Claude में आप इसे कहते हैं… | ChatGPT में यह है… | वही विचार? |
| --- | --- | --- |
| Claude Projects (workspace + files + project instructions) | **Projects** | हाँ — लगभग वही अवधारणा |
| Custom Style / एक सहेजा हुआ system prompt जिसे आप दोबारा इस्तेमाल करते हैं | **Custom GPTs** — जिनकी जगह **Plugins** (skills + apps) ले रहे हैं | करीब, एक पेच के साथ (नीचे देखें) |
| आपकी अकाउंट-स्तरीय प्राथमिकताएँ / "मैं कैसे जवाब चाहता हूँ" | **Custom instructions** | हाँ |
| पिछले चैट की Claude की स्मृति | **Memory** | हाँ — वही विचार, अक्सर विकसित होता है |
| Artifacts (दस्तावेज़ों/कोड के लिए साइड पैनल) | **Canvas** | हाँ — वही विचार |
| Model selector (Opus / Sonnet / Haiku) | **model picker** (गति बनाम reasoning टियर) | हाँ — वही विचार, अलग नाम |
| Tool use / function calling (API) | **Function calling** | हाँ — वही आकार, अलग JSON विवरण |

निष्कर्ष: सीखने के लिए लगभग कोई *नई अवधारणा* नहीं है। यह ज़्यादातर उन चीज़ों को **नया नाम देना और स्थान बदलना** है जिन्हें आप पहले से समझते हैं।

## Projects बनाम Custom GPTs — वह एक भेद जिसे सही समझना ज़रूरी है

यह वह एकमात्र बिंदु है जहाँ Claude उपयोगकर्ता सबसे अधिक भ्रमित होते हैं, क्योंकि ChatGPT में **दो** ऐसी चीज़ें हैं जो दोनों "एक अनुकूलित Claude" जैसी महसूस होती हैं, और वे अलग-अलग कामों के लिए हैं।

- **Projects** *संगठनात्मक* हैं — एक workspace जो एक चल रहे प्रयास के आसपास कई चैट, अपलोड की गई फ़ाइलें, और साझा निर्देशों को बंडल करता है। कई बातचीतों में निरंतरता ही मुख्य बात है। किसी Project की ओर तब हाथ बढ़ाएँ जब आप एक Claude Project खोलेंगे: एक लंबा शोध सूत्र, एक विकसित होता लेखन, संदर्भ दस्तावेज़ों वाली कोई कार्यधारा। <VerifyNote lastVerified="2026-10-07" source="https://learn.chatgpt.com/docs/projects">OpenAI के अपने शब्दों में: "संबंधित चैट, फ़ाइलें, निर्देश, और स्रोत एक साथ रखने के लिए project का उपयोग करें" ("Use a project to keep related chats, files, instructions, and sources together") — उस काम के लिए जो "समय के साथ जारी रहेगा, एक से अधिक आउटपुट देगा, या उन्हीं फ़ाइलों और स्रोतों पर निर्भर करेगा" ("will continue over time, produce more than one output, or depend on the same files and sources.")। मुफ़्त और भुगतान वाले प्लान में उपलब्धता समय के साथ बदलती है — मौजूदा पेज देखें।</VerifyNote>

- **Custom GPTs** *पैकेज्ड असिस्टेंट* हैं — एक सहेजा हुआ कॉन्फ़िगरेशन (एक system prompt, वैकल्पिक knowledge फ़ाइलें, सक्षम किए गए tools, कभी-कभी API actions) जिसे आप एक निश्चित persona के साथ एकल, नई चैट के रूप में शुरू करते हैं। ये पुनः इस्तेमाल और साझा करने के लिए बनाए गए हैं, ताकि एक व्यक्ति विशेषज्ञता बनाए और कई लोग उसे चलाएँ। **इन्हें विदा किया जा रहा है।**

- **Plugins** उनका विकल्प हैं: OpenAI के शब्दों में, "किसी workflow के लिए एक पुनः-प्रयोज्य पैकेज जिसमें skills, apps, या दोनों शामिल हो सकते हैं" — *skills* में काम कैसे करना है उसके निर्देश होते हैं, *apps* ChatGPT को दूसरी सेवाओं से जोड़ते हैं। Custom GPT जैसा ही स्वभाव, बड़ा दायरा। <VerifyNote lastVerified="2026-10-07" source="https://learn.chatgpt.com/codex/migrate-custom-gpts">OpenAI: "हम custom GPTs को plugins में स्थानांतरित कर रहे हैं। custom GPTs विदा होने से पहले अपने माइग्रेशन की योजना बनाने के लिए नीचे दिए मील-पत्थरों का उपयोग करें" ("We're transitioning custom GPTs to plugins. Use the milestones below to plan your migration before custom GPTs are retired.")। प्रकाशित मील-पत्थर हैं Admin notice → Migration → Custom GPT retirement, जिस बिंदु पर "custom GPTs चलना बंद कर देते हैं और GPT directory से हट जाते हैं" ("custom GPTs stop running and leave the GPT directory.")। मूल GPT "विदाई तक उपयोग योग्य रहता है" ("remains usable until retirement,"), और किसी GPT को विदाई के बाद भी माइग्रेट किया जा सकता है, भले वह अब चलता न हो। विशिष्ट तारीख़ें workspace-स्तर पर तय होती हैं (यह गाइड ChatGPT Enterprise एडमिन और GPT निर्माताओं के लिए लिखी गई है) और बदल सकती हैं — यहाँ दी किसी तारीख़ पर भरोसा करने के बजाय लिंक किए गए पेज पर मील-पत्थर पढ़ें।</VerifyNote>

मानसिक शॉर्टकट:

- **कई चैट में साझा संदर्भ के साथ निरंतरता चाहिए?** → Project.
- **एक पुनः-प्रयोज्य, साझा करने योग्य विशेषज्ञ चाहिए जो हर बार एक जैसा व्यवहार करे?** → एक Plugin (और आपके पास पहले से जो Custom GPT है उसे माइग्रेट करें)।

Claude उपयोगकर्ताओं के लिए दो पेच:

- एक Custom GPT या Plugin चैट हर बार केवल अपने पूर्व-निर्धारित निर्देशों और उस बातचीत के साथ **नई** शुरू होती है — यह उम्मीद न करें कि यह आपके पिछले सत्र को उस तरह याद रखेगी जैसे एक चालू Project सूत्र रखता है।
- माइग्रेशन **बिना नुकसान का नहीं** है। Custom actions को अलग से दोबारा बनाना पड़ता है — किसी समर्थित connector के विरुद्ध या आपके अपने MCP server के विरुद्ध — इसलिए जो GPT उन पर टिका है उसके लिए असल मेहनत चाहिए, एक-क्लिक रूपांतरण नहीं। अगर आप ही दोबारा बना रहे हैं, तो [Codex Agent Plugins](/docs/models/codex-agent-plugins-catalogs) पैकेजिंग परत को कवर करता है।

## Custom instructions और memory — वही विचार, थोड़ी अलग परतें

Claude में आप वैश्विक प्राथमिकताएँ सेट करते हैं और उसे संदर्भ याद रखने देते हैं। ChatGPT भी वही करता है, बस कुछ अधिक स्पष्ट परतों के साथ जिन पर आप निर्देश सेट कर सकते हैं:

**Memory** अपनी एक विकसित होती प्रणाली है: ChatGPT अलग-अलग चैट में संदर्भ ले जा सकता है। *क्या* यह याद रखता है, *कितना*, और *कहाँ उपलब्ध है* (जैसे किसी पैकेज्ड असिस्टेंट के भीतर या नहीं) — इसे **अस्थिर** मानें: यह अक्सर बदलता है, इसलिए मान लेने के बजाय मौजूदा व्यवहार सत्यापित करें। <VerifyNote lastVerified="2026-10-07" source="https://learn.chatgpt.com/codex/personalize">OpenAI: "उन प्राथमिकताओं के लिए custom instructions का उपयोग करें जिनका पालन आप ChatGPT से सभी चैट में करवाना चाहते हैं, जैसे आपकी पसंदीदा उत्तर-शैली" ("Use custom instructions for preferences you want ChatGPT to follow across chats, such as your preferred response style.")। परतबद्धता असली है — Codex में व्यक्तिगत परत आपके वैश्विक `AGENTS.md` में रहती है, और "projects और repositories भी अपने निर्देश दे सकते हैं" ("projects and repositories can also provide their own instructions.")। विशिष्टताएँ और उपलब्धता बदलती हैं — मौजूदा पेज देखें।</VerifyNote>

## Canvas ChatGPT का Artifacts है

अगर आपको Claude Artifacts पसंद है — एक साइड पैनल जहाँ कोई दस्तावेज़ या कोड ब्लॉक एक जीवंत, संपादन योग्य वस्तु बन जाता है — तो आप **canvas** के साथ सहज महसूस करेंगे। यह लेखन और कोडिंग के लिए एक समर्पित संपादन सतह खोलता है ताकि आप और मॉडल पूरे संदेश को दोबारा जनरेट करने के बजाय जगह पर ही संशोधन कर सकें। वही स्वभाव, अलग नाम।

एक बात जिस पर ध्यान दें (और यह इसका एक अच्छा उदाहरण है कि हम विशिष्टताओं को हार्ड-कोड क्यों नहीं करते): **आपको कौन-सी संपादन सतह मिलती है यह इस पर निर्भर करता है कि आप कहाँ हैं**, न कि केवल इस पर कि आपने क्या माँगा। OpenAI के मौजूदा दस्तावेज़ preview-and-edit व्यवहार को सतह के हिसाब से अलग बताते हैं — डेस्कटॉप ऐप जनरेट किए गए दस्तावेज़ों का चैट के साथ-साथ पूर्वावलोकन दिखाता है, CLI में कोई विज़ुअल पूर्वावलोकन ही नहीं है, और IDE एक्सटेंशन फ़ाइलों की समीक्षा एडिटर में करता है। चुना गया मॉडल भी मायने रख सकता है। अगर साइड पैनल नहीं दिखता, तो बग पर शक करने से पहले अपनी सतह या मॉडल पर शक करें। <VerifyNote lastVerified="2026-10-07" source="https://learn.chatgpt.com/codex/artifacts-viewer">OpenAI के फ़ाइल-पूर्वावलोकन दस्तावेज़ उपलब्धता को सतह के हिसाब से रखते हैं: डेस्कटॉप ऐप "जनरेट किए गए दस्तावेज़, प्रस्तुतियाँ, स्प्रेडशीट, और PDF फ़ाइलों का चैट के साथ-साथ पूर्वावलोकन दिखाता है" ("previews generated documents, presentations, spreadsheets, and PDF files alongside the chat,"), CLI में "कोई विज़ुअल फ़ाइल पूर्वावलोकन शामिल नहीं है" ("doesn't include a visual file preview,"), और IDE एक्सटेंशन टेक्स्ट व कोड फ़ाइलों की समीक्षा एडिटर में करता है। पेज मॉडल-आधारित गेटिंग का दावा नहीं करता, इसलिए मॉडल वाली चेतावनी को एक सावधानी मानें, दस्तावेज़ीकृत नियम नहीं। canvas खुद OpenAI के हेल्प सेंटर पर अलग से दस्तावेज़ीकृत है (Sources में लिंक किया गया)।</VerifyNote>

## Model picker — नाम से नहीं, काम से चुनें

जैसे आप Opus बनाम Sonnet बनाम Haiku चुनते हैं, ChatGPT आपसे एक मॉडल चुनने को कहता है — आम तौर पर एक **गति ↔ reasoning** स्पेक्ट्रम पर (त्वरित मोड़ों के लिए तेज़/तत्काल विकल्प, कठिन समस्याओं के लिए उच्च-reasoning विकल्प, जिसमें शीर्ष टियर भुगतान वाले प्लान तक सीमित होते हैं)। *नाम और टियर की संख्या अक्सर बदलती है*; टिकाऊ कौशल वही है जो आप पहले से Claude के साथ इस्तेमाल करते हैं: **मॉडल को कार्य की कठिनाई और अपनी latency/लागत सहनशीलता से मिलाएँ।**

यह बिल्कुल वही ढाँचा है जो [एक मॉडल चुनना](/docs/models/choosing-a-model) और [मुझे कौन-सा Claude इस्तेमाल करना चाहिए?](/docs/start-here/which-claude) में है — यह प्रोवाइडर-निरपेक्ष है। किसी मॉडल का नाम रटें नहीं; "तेज़ बनाम गहरा" पढ़ना सीखें और उसी हिसाब से चुनें।

बात को ठोस बनाने के लिए, रटने के लिए नहीं: **7 अक्तूबर 2026** तक picker में **Astra** (सबसे सक्षम), **GPT-6.1 Sol** ("जटिल काम के लिए Astra के करीब प्रदर्शन, Astra से कम लागत पर" — "near-Astra performance for complex work at a lower cost than Astra", जो Plus, Pro, Business, Enterprise और Edu पर रोल आउट हो रहा है) और **GPT-6 Luna** (केंद्रित, उच्च-मात्रा वाले काम के लिए किफ़ायती मॉडल) चलते हैं — जबकि **GPT-5.5 14 अक्तूबर 2026 को ChatGPT, ChatGPT Work और Codex से विदा हो जाता है**, और API पर उपलब्ध रहता है। अगर आप इसे उस तारीख़ के काफ़ी बाद पढ़ रहे हैं, तो इस पैराग्राफ़ का हर नाम शायद बदल चुका है। बात यही है। <VerifyNote lastVerified="2026-10-07" source="https://learn.chatgpt.com/docs/models">मॉडल लाइन-अप, प्लान उपलब्धता और GPT-5.5 की विदाई तारीख़ OpenAI के मौजूदा models पेज से पढ़ी गई। वहाँ सूचीबद्ध पहले की विदाइयाँ: GPT-5.3-Codex-Spark 14 सितंबर 2026 को, GPT-5.4 और GPT-5.4-mini 31 अगस्त 2026 को। यह सूची डिज़ाइन से ही तेज़ी से पुरानी होती है — यहाँ भरोसा करने के बजाय स्रोत दोबारा पढ़ें।</VerifyNote>

## Function calling — वही आकार, अलग JSON विवरण

अगर आपने Claude के साथ [tool use](/docs/api/tool-use) किया है, तो OpenAI का **function calling** तुरंत परिचित लगेगा, क्योंकि *लूप वही है*:

  {title: "Tools घोषित करें", body: "आप हर tool का वर्णन एक नाम, एक विवरण, और उसके पैरामीटरों के JSON-schema (कौन-से आवश्यक हैं, उनके प्रकार) के साथ करते हैं। Claude tool definition जैसा ही विचार।"},

  {title: "परिणाम लौटाएँ", body: "आप tool का आउटपुट वापस मॉडल को खिलाते हैं।"},

क्या समान है: describe → model-requests → you-execute → return-result → answer लूप, कई/समानांतर कॉल, और यह सिद्धांत कि *मॉडल प्रस्ताव देता है, आपका कोड निपटारा करता है*। <VerifyNote lastVerified="2026-10-07" source="https://developers.openai.com/api/docs/guides/function-calling">OpenAI की गाइड के विरुद्ध हूबहू पुष्टि किया गया, जो "एक function" को "tool का एक विशिष्ट प्रकार, जिसे JSON schema से परिभाषित किया जाता है" ("a specific kind of tool, defined by a JSON schema") बताती है, जिसमें `type`, `name`, `description`, `parameters` और `strict` होते हैं, और वही पाँच चरण सूचीबद्ध करती है: मॉडल को उन tools के साथ अनुरोध भेजें जिन्हें वह कॉल कर सकता है → एक tool call प्राप्त करें → एप्लिकेशन की तरफ़ कोड निष्पादित करें → tool आउटपुट के साथ दूसरा अनुरोध करें → अंतिम प्रतिक्रिया (या और tool calls) प्राप्त करें। सटीक फ़ील्ड नाम और विकल्प बदलते हैं — मौजूदा API गाइड देखें।</VerifyNote>

क्या **अलग** है और अगर आप कॉपी-पेस्ट करते हैं तो आपको फँसा देगा: सटीक JSON फ़ील्ड नाम, tool calls और परिणाम संदेश सूची में कैसे दर्शाए जाते हैं, "strict"/structured-output विकल्प, और विशिष्ट API endpoint आकार। प्रोवाइडरों के बीच एक नियम के रूप में, **प्रॉम्प्टिंग और आर्किटेक्चर ट्रांसफर होते हैं; wire-format विवरण नहीं** — हमेशा प्रति-प्रोवाइडर schema दोबारा जाँचें।

## क्या ट्रांसफर होता है (स्पॉइलर: लगभग सब कुछ)

आपकी कड़ी मेहनत से अर्जित Claude आदतें बेकार नहीं जातीं। ये अनिवार्य रूप से बिना बदले चलती हैं:

- **प्रॉम्प्ट संरचना** — स्पष्ट भूमिका, स्पष्ट कार्य, उदाहरण, अनुरोधित आउटपुट प्रारूप → [प्रॉम्प्टिंग की बुनियादी बातें](/docs/prompting/basics)
- **जानबूझकर संदर्भ देना** — सही सामग्री पेस्ट करें, उसे सीमित करें, सब कुछ न उड़ेल दें
- **किसी विशिष्ट आउटपुट प्रारूप की माँग करना** — टेबल, JSON, चरण; एक जैसा काम करता है
- **जगह पर ही दोहराना** — फ़ॉलो-अप के ज़रिए परिष्कृत करें (और अब canvas के ज़रिए)
- **tool-use लूप** — tools का वर्णन करें, मॉडल को उन्हें कॉल करने दें, परिणाम लौटाएँ → [Tool Use](/docs/api/tool-use)
- **कार्य की कठिनाई से मॉडल चुनना** — तेज़ बनाम गहरा, वही निर्णय

## क्या सचमुच समायोजित करना है

उन चीज़ों की एक छोटी, ईमानदार सूची जो असल में अलग हैं:

- **दो "customization" वस्तुएँ, एक नहीं।** पहले ही तय करें: चालू workspace (Project) या पुनः-प्रयोज्य पैकेज्ड असिस्टेंट (एक Plugin — या कोई Custom GPT जो Plugin बनने की राह पर है)? गलत को चुनना सबसे आम शुरुआती गलती है।
- **Custom GPTs एक माइग्रेशन लक्ष्य हैं, मंज़िल नहीं।** OpenAI उन्हें Plugins में ले जा रहा है और विदा कर रहा है। कोई विरासत में मिले, तो उसके माइग्रेशन की योजना बनाएँ; नया शुरू न करें।
- **फ़ीचर ↔ सतह जोड़ी।** ChatGPT में, कोई पूर्वावलोकन/संपादन पैनल (या कोई दिया गया tool) उपलब्ध है या नहीं, यह इस पर निर्भर कर सकता है कि आप उसे कहाँ चला रहे हैं — और कभी-कभी चुने गए मॉडल पर। जब कुछ गायब हो, तो किसी और चीज़ से पहले ये जाँचें।
- **Tools के लिए wire-format।** function-calling *अवधारणा* समान है; JSON विवरण नहीं — Claude के सटीक tool JSON को कभी हूबहू दोबारा इस्तेमाल न करें।
- **अस्थिर विशिष्टताएँ।** मॉडल नाम, टियर, सीमाएँ, और कीमतें तेज़ी से बदलती हैं। स्रोत पर पुष्टि करने की आदत बनाएँ, ठीक वैसे ही जैसे आपको Claude के लिए भी करनी चाहिए।

## हर एक कब चमकता है

दोनों उत्कृष्ट सामान्य असिस्टेंट हैं और किसी भी दिए गए कार्य पर अंतर अक्सर छोटा और बदलता रहता है — इसलिए इसे *प्रवृत्तियाँ* मानें, नियम नहीं, और अपने खुद के [अपने डेटा पर eval](/docs/models/choosing-a-model) को निर्णय लेने दें:

- **ChatGPT की ओर तब हाथ बढ़ाएँ जब** आपको उसका विशिष्ट पारिस्थितिकी तंत्र चाहिए — कोई Custom GPT जिसे कोई टीम पहले से बनाए रखती है, कोई Project जिसे किसी सहयोगी ने सेट किया, या कोई अंतर्निहित tool/integration जिस पर आप वहाँ निर्भर हैं। अगर आपका क्लाइंट या सहकर्मी ChatGPT में रहते हैं, तो उनसे वहीं मिलना घर्षण से बेहतर है।
- **Claude की ओर तब हाथ बढ़ाएँ जब** आप पहले से ही उस Claude वर्कफ़्लो में हैं जिसके आसपास यह साइट बनी है — Projects, Artifacts, और AILmanac में दस्तावेज़ीकृत प्रॉम्प्टिंग/एजेंट पैटर्न — और उन पर गहराई तक जाना चाहते हैं।

ज़्यादातर समय ईमानदार जवाब: **जिसमें भी आप (या आपकी टीम) पहले से सेट अप हैं।** कौशल पोर्टेबल है; सेटअप की लागत ही असली स्विचिंग लागत है।
