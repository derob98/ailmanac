`claude mcp` कमांड, कॉन्फ़िगरेशन स्कोप और ट्रांसपोर्ट बदलते रहते हैं — Claude Code के आधिकारिक MCP दस्तावेज़ों और modelcontextprotocol.io पर पुष्टि करें। नीचे दिए गए चारों ट्रांसपोर्ट, स्कोप के स्टोरेज पथ, SSE का अप्रचलन और प्रोजेक्ट-अनुमोदन का व्यवहार, सब उसी पेज से लिए गए हैं।
</VerifyNote>

**Model Context Protocol (MCP)** AI को बाहरी टूल और डेटा से जोड़ने का एक ओपन स्टैंडर्ड है। एक **MCP सर्वर** क्षमताएँ उपलब्ध कराता है (डेटाबेस क्वेरी करना, GitHub PR खोलना, ब्राउज़र चलाना); Claude Code उससे जुड़ता है और सेशन के दौरान **उन टूल को कॉल** कर सकता है। इसी तरह आप Claude को अपने फ़ाइलसिस्टम और शेल से आगे बढ़ाते हैं।

## ट्रांसपोर्ट

Claude चार तरीक़ों से सर्वर तक पहुँचता है। चुनाव इस पर निर्भर है कि सर्वर कहाँ चलता है और कैसे बात करता है।

- **stdio** — एक लोकल प्रोसेस जिसे Claude लॉन्च करता है (लोकल टूल/CLI के लिए बढ़िया)। बिना `type` वाली JSON एंट्री का यही मतलब है।
- **HTTP** — एक होस्टेड सर्वर, अक्सर OAuth के साथ। किसी भी रिमोट चीज़ के लिए डिफ़ॉल्ट पसंद।
- **SSE** — **अप्रचलित**; जहाँ संभव हो HTTP इस्तेमाल करें। कुछ सेवाएँ अब भी सिर्फ़ SSE एंडपॉइंट देती हैं, और Claude Code v2.1.265 से `--transport http` पहले HTTP आज़माता है और अपने आप SSE पर चला जाता है, इसलिए `--transport sse` को साफ़ तौर पर देने की ज़रूरत शायद ही पड़ती है।
- **WebSocket** (`ws` / `wss`) — एक स्थायी द्विदिशीय कनेक्शन, उस सर्वर के लिए जो बिना माँगे इवेंट पुश करता है। `--transport`, `ws` को स्वीकार *नहीं* करता: इसे `claude mcp add-json '{"type":"ws","url":"wss://…"}'` से जोड़ें या `.mcp.json` में लिखें। कोई OAuth नहीं — प्रमाणीकरण सिर्फ़ हेडर से होता है।

<Callout type="warning" items={["url वाली लेकिन बिना type की JSON एंट्री एक कॉन्फ़िगरेशन त्रुटि है, कोई समझदार डिफ़ॉल्ट नहीं: Claude Code बिना type वाली एंट्री को stdio सर्वर की तरह पढ़ता है, उसे छोड़ देता है, और बताता है कि उसमें \"url\" है पर \"type\" नहीं। हाथ से लिखे जाने वाले रिमोट सर्वर पर हमेशा \"type\": \"http\" (या \"sse\" / \"ws\") सेट करें।"]} />

## सर्वर कॉन्फ़िगर करना

सबसे तेज़ रास्ता `claude mcp add` कमांड है — यह आपके लिए कॉन्फ़िग लिख देता है। शून्य से जुड़े हुए सर्वर तक पहुँचने के लिए यह क्रम अपनाएँ।

<Steps items={[{title: "लोकल stdio सर्वर जोड़ें", body: "claude mcp add चलाएँ — -- के बाद की हर चीज़ वह लॉन्च कमांड है जिसे Claude आपके लिए चलाता है।"}, {title: "या रिमोट HTTP सर्वर जोड़ें", body: "--transport http और एक स्कोप दें, फिर सर्वर का URL। रिमोट सर्वर अक्सर होस्टेड होते हैं और OAuth इस्तेमाल करते हैं।"}, {title: "देखें क्या जुड़ा है", body: "कॉन्फ़िगर किए गए सर्वर और उनकी कनेक्शन स्थिति देखने के लिए claude mcp list चलाएँ।"}, {title: "जाँचें और प्रमाणित करें", body: "किसी सेशन के भीतर /mcp से सर्वर के टूल जाँचें और रिमोट सर्वर को प्रमाणित करें।"}]} />

<PromptCard title="लोकल stdio सर्वर जोड़ें">{`# A local stdio server (everything after -- is the launch command)
claude mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem ~/code/myproject`}</PromptCard>

<PromptCard title="रिमोट HTTP सर्वर जोड़ें (प्रोजेक्ट के साथ साझा)">{`# A remote HTTP server, shared with everyone on the project
claude mcp add --transport http --scope project github https://api.githubcopilot.com/mcp/`}</PromptCard>

अंदर से यह बस JSON है। **project** स्कोप वाला सर्वर रिपॉज़िटरी की रूट में `.mcp.json` में जाता है — इसे कमिट करें और आपके साथियों को वर्कस्पेस पर भरोसा करते ही वही टूल मिल जाते हैं:

```json
{
  "mcpServers": {
    "github": { "type": "http", "url": "https://api.githubcopilot.com/mcp/" }
  }
}
```

<Callout type="warning" items={["पुराने ट्यूटोरियल में मिलने वाले @modelcontextprotocol/server-github, -postgres, -slack या -puppeteer पैकेज इस्तेमाल न करें। ये आर्काइव हो चुके हैं और इन पर npm का अप्रचलन नोटिस लगा है: \"Archived and unmaintained; no security guarantees\"। जहाँ वेंडर का अपना सर्वर हो, वही इस्तेमाल करें — GitHub का ऊपर दिया HTTP एंडपॉइंट है, और ब्राउज़र कंट्रोल @playwright/mcp पर चला गया है। TypeScript रेफ़रेंस सर्वरों में सिर्फ़ filesystem, memory, everything और sequential-thinking का रखरखाव अब भी होता है।"]} />

### स्कोप तय करता है कि सर्वर कौन देखेगा

| स्कोप | कहाँ संग्रहीत | कहाँ लोड होता है | किसके लिए इस्तेमाल करें |
|---|---|---|---|
| `local` (डिफ़ॉल्ट) | `~/.claude.json`, इस प्रोजेक्ट के पथ के अंतर्गत | सिर्फ़ यह प्रोजेक्ट | निजी प्रयोग, सीक्रेट |
| `project` | रेपो में `.mcp.json` (कमिट की गई) | सिर्फ़ यह प्रोजेक्ट, टीम के साथ साझा | वे टूल जो पूरी टीम को साझा करने चाहिए |
| `user` | `~/.claude.json` | आपके सभी प्रोजेक्ट | वे सर्वर जो आप हर जगह चाहते हैं |

<Callout type="warning" items={["MCP का \"local स्कोप\" लोकल सेटिंग्स जैसा नहीं है। local स्कोप वाला MCP सर्वर आपकी होम डायरेक्टरी की ~/.claude.json में रहता है — प्रोजेक्ट की .claude/settings.local.json में नहीं। उसे प्रोजेक्ट फ़ोल्डर में ढूँढना बेकार है।"]} />

क्या जुड़ा है यह देखने के लिए `claude mcp list` चलाएँ और टूल जाँचने व रिमोट सर्वर प्रमाणित करने के लिए सेशन के भीतर `/mcp`। कॉपी-पेस्ट करने लायक शुरुआती नमूनों के लिए [MCP कॉन्फ़िग और सर्वर स्कैफ़ोल्ड](/docs/templates/mcp-config) देखें।

## व्यावहारिक उदाहरण: Claude को अपना डेटाबेस दें

मान लें आप चाहते हैं कि क्वेरी के नतीजे खुद पेस्ट करने के बजाय Claude एक लोकल Postgres से जुड़े सवालों के जवाब दे। सर्वर को project स्कोप में जोड़ें, ताकि साथियों को भी मिले।

आर्काइव हो चुके सर्वरों की समस्या सबसे ज़्यादा डेटाबेस में चुभती है: पुराना `@modelcontextprotocol/server-postgres` अब बनाए रखा नहीं जाता और कोई आधिकारिक विकल्प नहीं है, इसलिए पैकेज का नाम ही वह एकमात्र फ़ैसला है जो आपको खुद करना है। कोई रखरखाव में चल रहा कम्युनिटी सर्वर चुनें, [उसकी समीक्षा करें](/docs/security/reviewing-third-party-code), फिर उसे जोड़ें — आप जो भी चुनें, ढाँचा वही रहता है:

<PromptCard title="project स्कोप में Postgres सर्वर जोड़ें">{`# Replace the package with a maintained Postgres MCP server you have reviewed.
# The connection string is read-only on purpose — see below.
claude mcp add --scope project db -- npx -y <postgres-mcp-server> "postgresql://readonly@localhost/app"`}</PromptCard>

अब सेशन में आप सवाल सामान्य भाषा में पूछ सकते हैं और क्वेरी का चक्र Claude पर छोड़ सकते हैं:

<PromptCard title="डेटाबेस से सवाल पूछें">{`How many users signed up last week? Check the DB.`}</PromptCard>

Claude सर्वर द्वारा प्रकाशित क्वेरी टूल को कॉल करता है, पंक्तियाँ पाता है और जवाब देता है — कॉपी-पेस्ट का चक्र नहीं। कनेक्शन स्ट्रिंग को रीड-ओनली रखें, जब तक Claude को सचमुच लिखना न हो। और अगर आपको बस एक ही क्वेरी चाहिए थी, तो ध्यान रखें कि Bash के ज़रिए `psql -c '…'` में टोकन का एक छोटा-सा हिस्सा ही लगता है; कब कौन-सा बेहतर है, यह [MCP टोकन टैक्स](/docs/claude-code/mcp-token-cost) में बताया गया है।

क्योंकि यह project स्कोप का है, रिपॉज़िटरी pull करने वाले साथी को वही क्षमता मिलती है — लेकिन **चुपचाप नहीं, और तुरंत नहीं**। कमिट की गई `.mcp.json` का सर्वर तब तक `⏸ Pending approval` पर रहता है जब तक वे फ़ोल्डर में `claude` चलाकर वर्कस्पेस-ट्रस्ट डायलॉग स्वीकार नहीं कर लेते। क्लोन की गई रिपॉज़िटरी अपने सर्वरों को पहले से अनुमोदित नहीं कर सकती: प्रोजेक्ट की `.claude/settings.json` में कमिट किए गए `enableAllProjectMcpServers` या `enabledMcpjsonServers` को अविश्वसनीय फ़ोल्डर में *अनदेखा* कर दिया जाता है। यूज़र-स्तर की `~/.claude/settings.json`, मैनेज्ड सेटिंग्स से, या `--settings` के साथ दिए गए अनुमोदन वहाँ भी लागू होते हैं। "मेरे साथी को सर्वर क्यों नहीं दिखता?" का यही आम जवाब है।

## ऐप्स में भी MCP

MCP, Claude ऐप्स में **कनेक्टर** को भी चलाता है — वही स्टैंडर्ड, अलग सतह। देखें [ऐप्स में कनेक्टर (MCP)](/docs/claude-app/connectors) और API के लिए [MCP और टूल से जुड़ना](/docs/api/mcp)।

## आम ग़लतियाँ

- **ग़लत स्कोप।** `local` स्कोप में जोड़ा गया सर्वर साथियों को नहीं दिखेगा; जो सर्वर आपने सिर्फ़ अपने लिए चाहा था उसे `project` स्कोप में कमिट नहीं करना चाहिए। सोच-समझकर चुनें।
- **बहुत ज़्यादा सर्वर, बहुत ज़्यादा टूल।** टूल सर्च डिफ़ॉल्ट रूप से चालू है, इसलिए जुड़ा हुआ सर्वर आम तौर पर हर टर्न में अपने पूरे स्कीमा की जगह सिर्फ़ टूल के *नाम* और सर्वर के निर्देश का ख़र्च लेता है — पर यह फिर भी हर टर्न का टैक्स है, और जैसे ही Claude स्कीमा खोजता है, वे संदर्भ में आ जाते हैं। उतना ही जोड़ें जितना काम को चाहिए, अपना पूरा कैटलॉग नहीं। असली आँकड़ों, `ENABLE_TOOL_SEARCH` के मोड और कोड एक्ज़ीक्यूशन दूसरे ख़र्च को कैसे घटाता है, इसके लिए [MCP टोकन टैक्स](/docs/claude-code/mcp-token-cost) देखें।
- **ज़रूरत से ज़्यादा अनुमति वाले कनेक्शन।** डेटाबेस सर्वर को रीड-ओनली रोल दें, जब तक Claude को सचमुच लिखना न हो। MCP क्षमताओं को असली बनाता है — उन्हें सीमित रखें।
- **इंजेक्शन का जोखिम भूल जाना।** सर्वर जो कुछ भी लौटाता है (वेब पेज, issue की बॉडी, कोई पंक्ति) वह अविश्वसनीय टेक्स्ट है जिसमें [प्रॉम्प्ट इंजेक्शन](/docs/security/prompt-injection) हो सकता है। बिना सोचे-समझे किसी शक्तिशाली लिखने-योग्य सर्वर को किसी अविश्वसनीय पढ़ने-योग्य सर्वर के बगल में न जोड़ें।
