Se fai **una** sola cosa per migliorare [Claude Code](/docs/claude-code/what-is-claude-code), fai questa. `CLAUDE.md` è un file di testo semplice che Claude legge all'inizio di ogni sessione: il briefing permanente del tuo progetto.

## Perché è l'impostazione con il maggior impatto

Senza di esso, devi rispiegare il tuo progetto a ogni sessione ("usiamo pnpm, i test sono in `__tests__`, non toccare `/generated`…"). Con esso, Claude lo sa già. Buone istruzioni qui migliorano *ogni* interazione futura in un colpo solo.

## La gerarchia della memoria

Claude Code carica la memoria da diverse posizioni e le fonde nell'ordine di caricamento, partendo dall'ambito più ampio: così un'istruzione di progetto entra nel contesto *dopo* un'istruzione utente.

```mermaid
flowchart TD
  A["Managed policy<br/>/etc/claude-code/CLAUDE.md (org-wide, IT-managed)"] --> B["User instructions<br/>~/.claude/CLAUDE.md (all your projects)"]
  B --> C["Project instructions<br/>./CLAUDE.md or ./.claude/CLAUDE.md (committed)"]
  C --> D["Local instructions<br/>./CLAUDE.local.md (yours only — gitignore it)"]
```

- **Policy gestita** — istruzioni a livello di organizzazione che distribuisce il tuo team IT/DevOps. Il percorso dipende dal sistema operativo: `/Library/Application Support/ClaudeCode/CLAUDE.md` su macOS, `/etc/claude-code/CLAUDE.md` su Linux e WSL, `C:\Program Files\ClaudeCode\CLAUDE.md` su Windows.
- **Istruzioni utente** (`~/.claude/CLAUDE.md`) — le tue preferenze personali su ogni progetto.
- **Istruzioni di progetto** (`./CLAUDE.md` *oppure* `./.claude/CLAUDE.md`, sotto commit) — come funziona *questo* repo. Condivise con il tuo team. Se il tuo repo usa [`AGENTS.md`](/docs/claude-code/agents-md), quello può caricarsi al posto di questi file o insieme a essi.
- **Istruzioni locali** (`./CLAUDE.local.md`) — note specifiche del progetto solo per te, come l'URL di un ambiente sandbox. Aggiungilo a `.gitignore`.

I file nella gerarchia di cartelle *sopra* la tua directory di lavoro vengono caricati all'avvio; i file nelle **sottocartelle vengono caricati su richiesta**, quando Claude mette mano a qualcosa in quell'area.

<Callout type="tip" items={["Un solo file non ti basta più? Spezza le istruzioni in .claude/rules/*.md, un argomento per file, scoperti ricorsivamente. Le regole senza frontmatter paths si caricano all'avvio con la stessa priorità di .claude/CLAUDE.md; aggiungi il frontmatter paths per caricare una regola solo quando Claude lavora su file corrispondenti, e risparmi contesto."]} />

## L'altra metà: l'auto-memoria

CLAUDE.md è la metà della memoria che scrivi *tu*. Claude Code tiene anche un'**auto-memoria**: note che Claude scrive da sé partendo dalle tue correzioni e preferenze, salvate per repository e caricate in ogni sessione insieme ai tuoi file CLAUDE.md.

| | File CLAUDE.md | Auto-memoria |
| --- | --- | --- |
| **Chi la scrive** | Tu | Claude |
| **Cosa contiene** | Istruzioni e regole | Apprendimenti e pattern |
| **Ambito** | Progetto, utente od organizzazione | Per repository, condivisa tra i worktree |

Entrambe sono *contesto*, non imposizione: Claude le tratta come indicazioni da soppesare, non come configurazione a cui deve obbedire. Per bloccare in modo assoluto un'azione, a prescindere da ciò che Claude decide, usa invece un [hook PreToolUse](/docs/claude-code/hooks).

<Callout type="warning" items={["L'auto-memoria carica solo le prime 200 righe o 25 KB: un MEMORY.md gonfio viene troncato silenziosamente. Vedi Audit del budget di contesto per il dettaglio completo dei costi di avvio."]} />

## Cosa metterci dentro

- Cos'è il progetto, in due frasi.
- Lo stack tecnologico e come **eseguire / testare / fare il lint**.
- Convenzioni che Claude non può dedurre (nomenclatura, struttura, stile dei commit).
- **Protezioni**: "esegui i test prima di dichiarare concluso", "non modificare mai `/vendor`", "non committare mai segreti".

## Import

Includi i documenti esistenti invece di duplicarli: ad esempio, riferisci la tua guida di stile con un import `@path/to/file` così da avere un'unica fonte autorevole. Funzionano sia i percorsi relativi sia quelli assoluti; i percorsi relativi si risolvono rispetto al file che contiene l'import, **non** rispetto alla tua directory di lavoro. I file importati possono importarne altri, fino a una profondità massima di **quattro passaggi**.

Due trappole di sintassi da conoscere prima che ti mordano:

- **Gli spazi vogliono il backslash.** `@Design\ Docs/api-conventions.md` funziona; senza il backslash il percorso si ferma al primo spazio. Racchiuderlo tra virgolette non importa il file per niente.
- **I backtick escludono l'import.** L'analisi degli import salta i code span e i blocchi di codice, quindi `` `@README` `` resta testo letterale mentre `@README` da solo importa il file. È così che *menzioni* un percorso senza caricarlo.

Vedi la [documentazione ufficiale sulla memoria](https://code.claude.com/docs/en/memory) per il riferimento completo.

<Callout type="tip" items={["Un'unica fonte autorevole: riferisci un file con gli @import invece di incollarne il contenuto in CLAUDE.md.", "Se un documento esiste già, collegalo: non copiarlo. Le copie si disallineano col tempo."]} />
