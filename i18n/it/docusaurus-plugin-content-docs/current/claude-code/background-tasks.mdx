## Task in background

Avvia un comando di lunga durata (un dev server, un test watcher, una build) **senza bloccare** la sessione. Claude continua a lavorare e viene avvisato quando il task produce output o termina. Usalo per tutto ciò che di solito metteresti in background con `&` — ma in forma gestita, così Claude può leggere l'output più tardi.

:::tip Niente attesa attiva
Avvia il task in background e prosegui; lascia che sia la notifica di completamento a riportarti indietro, invece di controllarlo in un ciclo serrato.
:::

## Loop ricorrenti (`/loop`)

`/loop` esegue un prompt o un comando a **intervalli ricorrenti** all'interno di una sessione — ad es. "ogni 5 minuti, controlla lo stato del deploy". Gli dai un intervallo, oppure lasci che Claude decida il ritmo da sé. Ottimo per tenere d'occhio una run di CI o interrogare un job esterno di cui l'harness non può altrimenti avvisarti.

<PromptCard title="Controlla un deploy ogni cinque minuti, nella sessione">
{`/loop 5m check the deploy status and tell me the moment it goes green or fails`}
</PromptCard>

Se ometti l'intervallo, Claude regola il ritmo da solo invece di seguire il tuo orologio.

## Agenti cloud pianificati

Per il lavoro che deve avvenire **a orari fissi, in modo continuativo** — "ogni mattina riassumi le nuove issue", "ogni ora cerca novità e aggiorna la documentazione" — usa **task / routine pianificati** (in stile cron). Ogni esecuzione parte da zero, quindi le sue istruzioni devono essere **autosufficienti**.

```mermaid
flowchart LR
  A[Background task] -->|outlives one prompt, same session| A
  B[/loop/] -->|recurring within a session| B
  C[Scheduled routine] -->|cron, fresh run each time| C
```

## Scegliere fra i tre

| Esigenza | Usa |
|---|---|
| Eseguire un comando lungo e continuare a lavorare | Task in background |
| Controllare qualcosa ogni N minuti in questa sessione | `/loop` |
| Fare qualcosa a orari fissi, a tempo indeterminato | Routine pianificata |
