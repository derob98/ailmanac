Ogni versione, data e nome di impostazione in questa pagina proviene dal changelog ufficiale di Claude Code di Anthropic. Claude Code pubblica diversi rilasci a settimana — ricontrolla il changelog per qualsiasi cosa successiva a v2.1.322 (10 novembre 2026).
</VerifyNote>

La [modalità auto](/docs/claude-code/permissions) è la modalità in cui ormai gira la maggior parte delle persone: invece di chiederti conferma per ogni azione, un **classificatore di sicurezza** vaglia ciascuna di esse. Nella **v2.1.319** (6 novembre 2026) Anthropic ha cambiato ciò che accade quando quel classificatore non è raggiungibile — e la modifica non compare in nessun elenco di "novità", perché non è una funzionalità. È una decisione di applicazione rigorosa che trasforma un degrado prima silenzioso in un arresto netto.

Se esegui Claude Code senza presidio — cron, CI, un'attività pianificata, un runner self-hosted — leggi le prossime due sezioni prima della tua prossima esecuzione di pipeline.

## Cosa è cambiato

Il controllo della modalità auto gira **lato server**. Prima della v2.1.319, una sessione che non riusciva a raggiungerlo ripiegava su un **classificatore locale integrato** e andava avanti. Ora non più: le chiamate che il server non può controllare vengono **richieste all'utente o negate**, senza alcun ripiego.

| | Prima della v2.1.319 | Dalla v2.1.319 |
|---|---|---|
| Controllo del server raggiungibile | Il classificatore del server vaglia la chiamata | Invariato |
| Controllo del server non raggiungibile | Ripiega sul classificatore locale integrato | **Chiede a te, oppure nega** |
| Sessione non presidiata (`-p`, cron, CI) | Continuava con il classificatore locale | **Il turno si ferma** |
| Codice di uscita di `claude -p` in quel caso | `0` | **`1`** |

L'ultima riga è quella che arriva in produzione. La modifica del codice di uscita è classificata come *correzione*: `claude -p` usciva con `0` quando le sue azioni erano state rifiutate perché non era disponibile alcun controllo di sicurezza, e ora l'output di testo e JSON esce con `1`. È una correzione: una pipeline che segnalava successo senza fare nulla ti stava mentendo. Ma il sintomo che vedrai è un job verde che diventa rosso dopo un aggiornamento, con la causa reale a un livello di distanza dal messaggio di errore.

:::warning[Tre ambienti lo scatenano, e due non si assomigliano affatto]
- **Telemetria disattivata** — il controllo del server percorre lo stesso canale.
- **Feature flag non recuperati** — idem.
- **Dietro un gateway LLM** — il gateway scarta il controllo.

**Bedrock, Vertex e Foundry sono esplicitamente invariati.** Quindi un'organizzazione su Bedrock non vede nulla, mentre il team accanto, dietro un gateway, perde ogni esecuzione non presidiata sulla stessa versione.
:::

Due correzioni collegate sono arrivate nello stesso rilascio, ed entrambe dicono che questa modalità di errore era rimasta nascosta:

- `/status` mostrava **"Auto mode server: Enabled"** anche quando la revisione lato server non raggiungeva davvero la sessione — per esempio dietro un gateway che la scarta. Quindi la diagnostica a cui ricorrevi per prima, fino alla v2.1.319, confermava il contrario della verità.
- La modalità auto **falliva a ogni turno** quando un gateway rispondeva `403` o `422` al controllo di sicurezza. (Un `403` con un `apiKeyHelper` è invariato.)

## Altre cinque modifiche che cambiano il comportamento in silenzio

Tra il **7 ottobre e il 10 novembre 2026** sono usciti venticinque rilasci (v2.1.293 → v2.1.322). Queste sono le modifiche che cambiano ciò che fa la tua configurazione esistente, senza annunciarsi come breaking.

### 1. La modalità fast di Opus 4.8 viene rimossa il 30 novembre 2026

Deprecata dal **30 ottobre 2026** (arrivata con la v2.1.316). Dopo la rimozione, le richieste in modalità fast su Opus 4.8 **restituiscono un errore e non ripiegano** su Opus 4.8 standard. Passare a Opus 5.5 mantiene l'accelerazione. Una data rigida senza degrado graduale è il tipo di modifica più raro in questo changelog — vedi [Modelli e prezzi](/docs/whats-new/models-and-pricing).

### 2. Il caricamento delle skill si è ristretto due volte, in due modi diversi

- **v2.1.319:** con il sandbox di Bash attivo, le skill nelle cartelle `.claude/skills` *sotto* la cartella di partenza si caricano solo se avvii Claude Code lì o fai `/cd` lì.
- **v2.1.321** (9 novembre): le cartelle `.claude/skills` dentro `~/.claude/plugins` **non si caricano più** quando Claude lavora sui file lì.

Se una [skill](/docs/claude-code/skills) ha smesso silenziosamente di essere disponibile, questa è la prima cosa da controllare — il sintomo è l'assenza, che non produce alcun errore.

### 3. Le chiamate agli strumenti MCP ora vanno in background da sole

La **v2.1.319** ha aggiunto il supporto ai task MCP nel terminale: quando un server MCP esegue la chiamata a uno strumento come task, Claude Code la sposta in background **subito** e comunica il risultato a Claude quando termina. Imposta `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND` per farlo attendere dentro la chiamata allo strumento.

I task MCP ora funzionano anche **senza recupero dei feature flag** (Bedrock, Vertex, Foundry, gateway LLM, `DISABLE_TELEMETRY`); `CLAUDE_CODE_DISABLE_MCP_TASKS=1` li disattiva del tutto. Vedi [Server MCP](/docs/claude-code/mcp) e [Task in background](/docs/claude-code/background-tasks).

### 4. Rileggere un file invariato restituisce di nuovo il suo contenuto

La **v2.1.317** (3 novembre) ha rimosso il segnaposto `"file unchanged since your last Read"` dello strumento Read. Leggere due volte lo stesso file ora restituisce il file, non un segnaposto. Meglio per la correttezza — Claude non può più agire su un presupposto obsoleto — e un vero cambiamento nella velocità con cui una sessione lunga riempie il proprio [budget di contesto](/docs/claude-code/context-budget-audit).

### 5. `sed -i` ora è un vero comando Bash

La **v2.1.309** (22 ottobre) ha fatto sì che `sed -i` ricevesse la richiesta standard di Bash e venisse eseguito così com'è, invece che come anteprima simulata di modifica di un file. Come le altre modifiche via Bash, **non viene più ripristinato da `/rewind`**. Se il tuo flusso di lavoro contava su `/rewind` per annullare modifiche in loco sullo stream, quella rete di sicurezza non c'è più — vedi [Checkpoint e Rewind](/docs/claude-code/checkpoints-and-rewind).

Una sesta, più piccola, da conoscere se automatizzi: il `/loop` auto-cadenzato ora **termina** quando un turno finisce invece di pianificare un risveglio di ripiego (v2.1.319). `CLAUDE_CODE_LOOP_KEEPALIVE=1` ripristina il vecchio comportamento.
