Ogni conversazione con l'AI è costruita a partire da **messaggi**, e ogni messaggio ha un **ruolo**. Comprendere i tre ruoli spiega come orientare il modello — e perché alcune istruzioni attecchiscono mentre altre no.

## Perché il system prompt è la tua leva più potente

Il messaggio system inquadra **tutto ciò che segue**. È dove imposti il ruolo del modello, gli standard, il tono e le regole ferree — e il modello gli dà molto peso. Se vuoi un comportamento coerente lungo un'intera conversazione (o app), mettilo qui, non sepolto in un turno user.

Stessa idea, tre superfici:

| Superficie | Cosa svolge il ruolo di system prompt |
|---|---|
| **App di chat** (Claude.ai, ChatGPT, Gemini) | Le [istruzioni personalizzate](/docs/claude-app/custom-instructions) del tuo account |
| **Claude Code** | [`CLAUDE.md`](/docs/claude-code/claude-md) alla radice del progetto |
| **L'API** | Il parametro `system` nella richiesta ([prima chiamata](/docs/api/first-call)) |

## Un before/after concreto

L'errore più comune è mettere le regole permanenti in ogni turno user invece che nel messaggio system. Guarda cosa cambia.

**Prima — regole ficcate in un turno user, ripetute ogni volta:**

<PromptCard title="Regole nel turno user (fragile)">{`user: You are a precise financial analyst. Always show your assumptions.
Never invent numbers. Now: summarize this 10-K.
[10-K text]`}</PromptCard>

**Dopo — regole sollevate nel messaggio system, i turni user restano puliti:**

<PromptCard title="Regole nel messaggio system (durevoli)">{`system: You are a precise financial analyst. Always show your assumptions.
Never invent numbers. Cite the section of the filing for each claim.

user: Summarize this 10-K.
[10-K text]

user: Now flag the risks.`}</PromptCard>

La versione "dopo" tiene il comportamento stabile lungo i turni, dimezza i token che rispedisci a ogni turno e rende l'app più facile da cambiare — modifichi il brief permanente in un solo posto.

## Mettere parole in bocca all'assistant

Una mossa sottoutilizzata: puoi anteporre un turno `assistant` come **esempio few-shot** o **primer di formato**, e il modello continuerà in quello stile. È così che template e rubriche vengono imposti senza un prompt enorme.

<PromptCard title="Primare l'assistant a seguire un formato">{`system: You are a code reviewer. Return only the sections below.

user: Review this pull request. [diff]

assistant: ## Summary
- 
## Risks
- 
## Suggested changes
-`}</PromptCard>

Il modello tratta il turno assistant che hai seminato come una risposta precedente e completa nella stessa forma.
