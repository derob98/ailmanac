<VerifyNote lastVerified="2026-10-09" source="https://code.claude.com/docs/en/permission-modes">
Способ входа в режим планирования (сочетание клавиш/флаг) и то, какие именно shell-команды он позволяет Claude выполнять во время планирования, меняются от релиза к релизу — сверяйтесь с официальной документацией Claude Code.
</VerifyNote>

## Главная идея

Представьте, что вы отдаёте подрядчику ключи от дома — или сначала просите его пройтись по дому и расписать, *что именно* он собирается изменить. Режим планирования — это и есть тот обход.

**Режим планирования** говорит Claude **исследовать и предлагать изменения, не внося их**: он читает файлы, выполняет shell-команды для исследования и пишет план — но он **не редактирует ваш исходный код**. Правки остаются заблокированными, пока вы не одобрите план.

<Callout type="tip" items={["Режим планирования означает, что Claude ИССЛЕДУЕТ, но не МЕНЯЕТ ваш исходный код — он создаёт план и ждёт вашего сигнала."]} />

### Это не строго режим только для чтения

Исследование иногда требует команды, поэтому режим планирования — это про *отсутствие правок*, а не про *отсутствие выполнения*. Что произойдёт с shell-командой во время планирования, зависит от сессии — срабатывает первый подходящий случай:

Одобренные команды выполняются, отклонённые блокируются."}, {title: "Auto mode недоступен или useAutoModeDuringPlan выключен", body: "Команды вне встроенного набора только для чтения запрашивают у вас одобрение."}, {title: "Интерактивные сессии в терминале, где доступен bypass permissions", body: "Блокировки режима планирования НЕ применяются. Во всех остальных случаях режим планирования сохраняет свои блокировки — в headless-запусках -p, в Agent SDK и в панели чата расширения VS Code."}]} />

## Почему это самый безопасный способ начать

Для всего крупного, рискованного или незнакомого вы хотите увидеть, *что* Claude намеревается сделать, прежде чем он тронет ваш репозиторий. Режим планирования разделяет **мышление** и **действие**:

```mermaid
flowchart LR
  A[Goal] --> B[Claude investigates<br/>no source edits]
  B --> C[Presents a plan]
  C --> D{You approve?}
  D -->|edit/refine| C
  D -->|approve| E[Claude executes the plan]
```

Выигрыш: вы ловите неверные предположения *до* того, как они станут неверным кодом.

## Когда его использовать

<Callout type="tip" items={["ВСЕГДА для крупных или многофайловых изменений, миграций или рефакторингов", "Когда работаете в кодовой базе, которую ещё не полностью знаете", "Когда вам нужен пригодный для проверки план, чтобы поделиться с коллегой"]} />

Для крошечных, очевидных правок его можно пропустить — но при сомнении сначала планируйте.

Чтобы выйти из режима планирования, не одобряя план, снова нажмите `Shift+Tab`. Чтобы сделать его режимом по умолчанию для терминальных сессий проекта, задайте `defaultMode` равным `plan` в `.claude/settings.json` — см. [Настройки](/docs/claude-code/settings).

## Режим планирования против разрешений

Классическая путаница. Они решают разные задачи и работают вместе:

- **Режим планирования** = «исследуй и предлагай, пока не редактируй». (Эта страница.)
- **[Разрешения](/docs/claude-code/permissions)** = когда уже действуешь, *какие* действия разрешены без запроса.

Воспринимайте это как **действовать ли сейчас** (режим планирования) против **какие действия разрешены, когда уже действуешь** (разрешения).
