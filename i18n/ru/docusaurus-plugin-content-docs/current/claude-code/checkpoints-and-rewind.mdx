## Главная идея

Когда вы отпускаете Claude на амбициозное, масштабное изменение, самый страшный вопрос — «а что, если всё пойдёт не так на третьей правке?» Ответ — **контрольные точки** (checkpointing): Claude Code автоматически делает снимок вашего кода перед каждой правкой, и вы можете откатиться к любому прежнему состоянию, а не вручную распутывать недоделанный рефакторинг.

Считайте это **локальной отменой для всей сессии** — страховочной сеткой, которая позволяет без страха сказать: «да, пробуй смелый подход».

## Как создаются контрольные точки

Вы не создаёте контрольные точки — они появляются автоматически.

Есть два способа:

<PromptCard title="Открыть меню отката">{`/rewind`}</PromptCard>

Меню перечисляет **каждый запрос, отправленный в этой сессии**. Выберите точку, с которой хотите работать, а затем одно действие.

## Restore и summarize: ключевое различие

Именно здесь путаются. Меню предлагает два *вида* действий:

- Действия **Restore** меняют состояние на диске и/или в разговоре — они отменяют.
- Действия **Summarize** никогда не трогают ваши файлы — они сжимают разговор, чтобы освободить место в окне контекста.

<Callout type="warning" items={["Restore = отмена (возвращает код, разговор или и то и другое). Summarize = сжатие контекста (файлы на диске не затрагиваются).", "Используйте restore, когда правка что-то сломала. Используйте summarize, когда сессия раздулась, но с кодом всё в порядке."]} />

### Действия восстановления

<Steps items={[{title: "Restore code and conversation", body: "Возвращает и ваши файлы, и историю чата к выбранной точке — чистая «перемотка времени» к этому моменту."}, {title: "Restore conversation", body: "Откатывает чат к этому сообщению, но сохраняет ваш текущий код. Полезно, чтобы задать вопрос заново, не потеряв правки, которые вы хотите оставить."}, {title: "Restore code", body: "Откатывает изменения файлов, но сохраняет разговор. Отменяете правки, сохраняя обсуждение."}]} />

Две опции восстановления **кода** появляются, только если у выбранной контрольной точки действительно есть отслеживаемые изменения файлов для отката. Если после этой точки правок файлов не зафиксировано, меню предлагает лишь **Restore conversation**, два варианта summarize и **Never mind** (возвращает к списку сообщений без каких-либо изменений).

После восстановления разговора (или выбора «Summarize from here») исходный запрос выбранного сообщения возвращается в поле ввода, чтобы вы могли отправить его снова или отредактировать.

### Действия summarize

Оба сжимают часть разговора в сгенерированное ИИ резюме — как **точечный `/compact`**, где вы выбираете, какую сторону от выбранного сообщения сжать.

<Steps items={[{title: "Summarize from here", body: "Сообщения ДО выбранного остаются нетронутыми. Выбранное сообщение и всё после него превращаются в резюме. Используйте, чтобы отбросить побочное обсуждение, сохранив ранний контекст во всех подробностях."}, {title: "Summarize up to here", body: "Сообщения ДО выбранного превращаются в резюме; выбранное сообщение и всё после него остаются нетронутыми. Вы остаётесь в конце разговора. Используйте, чтобы сжать ранние вводные разговоры, сохранив недавнюю работу дословно."}]} />

В обоих случаях исходные сообщения остаются в журнале сессии, так что Claude по-прежнему может обращаться к деталям, а на месте сжатых сообщений появляется метка **Summarized conversation**. Чтобы направить резюме, выделите стрелками вариант **Summarize** и введите инструкции там, где в строке написано **add context (optional)**, затем нажмите Enter — выбор варианта цифровой клавишей запускает сжатие сразу, без инструкций.

Весь процесс описан в разделе [Управление контекстом](/docs/claude-code/context-management) — действия summarize в `/rewind` это скальпель, тогда как `/compact` — широкая кисть.

<Callout type="note" items={["Summarize оставляет вас в той же сессии. Чтобы ответвиться и попробовать другой подход, не трогая исходную сессию, используйте /branch или claude --continue --fork-session."]} />

## Откат за пределы `/clear`

Если ранее в том же процессе Claude Code вы выполняли `/clear`, меню отката показывает дополнительную запись сверху: `/resume <session-id> (previous session)`. Выберите её, чтобы вернуться к разговору, который был активен до `/clear`.

<VerifyNote lastVerified="2026-10-09" source="https://code.claude.com/docs/en/checkpointing">
Эта запись доступна только до тех пор, пока вы не выйдете из Claude Code или не возобновите другую сессию. Когда она исчезнет, выполните `/resume` и выберите предыдущую сессию из списка.
</VerifyNote>

## Где контрольные точки заканчиваются — ограничения, которые бьют больнее всего

Контрольные точки кажутся волшебством, пока не перестают им быть. Эти пробелы важны:

```mermaid
flowchart TD
    A[Claude does work] --> B{How was the file changed?}
    B -->|Edit / Write file tool| C[Tracked — rewindable]
    B -->|Bash command: rm / mv / cp| D[NOT tracked]
    B -->|Manual edit or other session| E[NOT tracked]
    B -->|Background subagent| E
    C --> H{Is the path a symlink<br/>or hard link?}
    H -->|No| F[/rewind can restore it/]
    H -->|Yes| G[Only Git can recover it]
    D --> G
    E --> G
```

## Контрольные точки и Git: используйте оба

Они решают разные задачи, поэтому сочетайте их.

| | Контрольные точки (`/rewind`) | Git |
|---|---|---|
| Охват | Одна сессия | Вся история проекта |
| Детализация | На каждый запрос, начинающий ход, автоматически | На каждый коммит, осознанно |
| Отслеживает изменения через bash? | Нет | Да (после добавления в индекс/коммита) |
| Срок жизни | 100 последних контрольных точек, очистка ~через 30 дней после сессии | Постоянно |
| Можно делиться / совместная работа | Нет | Да |
| Мысленная модель | «Локальная отмена» | «Постоянная история» |
