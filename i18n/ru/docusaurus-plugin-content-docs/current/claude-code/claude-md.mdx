Расположения, порядок загрузки и синтаксис импортов взяты из официальной документации по памяти («How Claude remembers your project»), которая теперь описывает **два** механизма: файлы CLAUDE.md, которые пишете вы, и **автопамять**, которую Claude пишет сам. Импорты разрешаются на глубину не более четырёх переходов. Уточняйте детали там — они меняются.
</VerifyNote>

Если вы сделаете **одну** вещь, чтобы улучшить [Claude Code](/docs/claude-code/what-is-claude-code), сделайте именно это. `CLAUDE.md` — это текстовый файл, который Claude читает в начале каждой сессии: постоянный брифинг по вашему проекту.

## Почему это настройка с максимальной отдачей

Без него вы заново объясняете свой проект каждую сессию («мы используем pnpm, тесты лежат в `__tests__`, не трогай `/generated`…»). С ним Claude уже всё знает. Хорошие инструкции здесь сразу улучшают *каждое* будущее взаимодействие.

## Иерархия памяти

Claude Code загружает память из нескольких мест и объединяет их в порядке загрузки, начиная с самой широкой области действия, — поэтому инструкция проекта попадает в контекст *после* пользовательской инструкции:

```mermaid
flowchart TD
  A["Managed policy<br/>/etc/claude-code/CLAUDE.md (org-wide, IT-managed)"] --> B["User instructions<br/>~/.claude/CLAUDE.md (all your projects)"]
  B --> C["Project instructions<br/>./CLAUDE.md or ./.claude/CLAUDE.md (committed)"]
  C --> D["Local instructions<br/>./CLAUDE.local.md (yours only — gitignore it)"]
```

- **Управляемая политика** — инструкции уровня организации, которые поставляет ваша команда IT/DevOps. Путь зависит от ОС: `/Library/Application Support/ClaudeCode/CLAUDE.md` на macOS, `/etc/claude-code/CLAUDE.md` на Linux и WSL, `C:\Program Files\ClaudeCode\CLAUDE.md` на Windows.
- **Пользовательские инструкции** (`~/.claude/CLAUDE.md`) — ваши личные предпочтения во всех проектах.
- **Инструкции проекта** (`./CLAUDE.md` *или* `./.claude/CLAUDE.md`, закоммичены) — как устроен *этот* репозиторий. Общие с вашей командой. Если в вашем репозитории используется [`AGENTS.md`](/docs/claude-code/agents-md), он может загружаться вместо этих файлов или вместе с ними.
- **Локальные инструкции** (`./CLAUDE.local.md`) — заметки по проекту только для вас, например URL песочницы. Добавьте файл в `.gitignore`.

Файлы в иерархии каталогов *выше* вашего рабочего каталога загружаются при запуске; файлы в **подкаталогах загружаются по требованию**, когда Claude обращается к чему-то в этой области.

<Callout type="tip" items={["Один файл стал тесен? Разнесите инструкции по .claude/rules/*.md — по одной теме на файл, они обнаруживаются рекурсивно. Правила без frontmatter paths загружаются при запуске с тем же приоритетом, что и .claude/CLAUDE.md; добавьте frontmatter paths, чтобы правило загружалось только тогда, когда Claude работает с подходящими файлами, — это экономит контекст."]} />

## Вторая половина: автопамять

CLAUDE.md — это та половина памяти, которую пишете *вы*. Claude Code также ведёт **автопамять** — заметки, которые Claude пишет сам на основе ваших правок и предпочтений; они хранятся отдельно для каждого репозитория и загружаются в каждую сессию вместе с вашими файлами CLAUDE.md.

| | Файлы CLAUDE.md | Автопамять |
| --- | --- | --- |
| **Кто пишет** | Вы | Claude |
| **Что содержит** | Инструкции и правила | Выводы и закономерности |
| **Область действия** | Проект, пользователь или организация | Отдельно для каждого репозитория, общая для всех worktree |

И то, и другое — *контекст*, а не принуждение: Claude относится к ним как к рекомендациям, которые можно взвесить, а не как к конфигурации, которой он обязан подчиняться. Чтобы жёстко заблокировать действие независимо от того, что решит Claude, используйте [хук PreToolUse](/docs/claude-code/hooks).

<Callout type="warning" items={["Автопамять загружает только первые 200 строк или 25 КБ — раздутый MEMORY.md молча обрезается. Полную разбивку стоимости запуска смотрите в Аудите бюджета контекста."]} />

## Что в него класть

- Что представляет собой проект, в двух предложениях.
- Технологический стек и как его **запускать / тестировать / линтить**.
- Соглашения, которые Claude не может вывести сам (именование, структура, стиль коммитов).
- **Ограничители**: «прогоняй тесты, прежде чем объявлять работу завершённой», «никогда не редактируй `/vendor`», «никогда не коммить секреты».

## Импорты

Подтягивайте существующие документы вместо их дублирования — например, ссылайтесь на ваш гайд по стилю через импорт `@path/to/file`, чтобы был единый источник истины. Работают и относительные, и абсолютные пути; относительные пути разрешаются относительно файла, в котором находится импорт, а **не** вашего рабочего каталога. Импортированные файлы могут импортировать другие — на глубину максимум **четыре перехода**.

Две ловушки синтаксиса, о которых стоит узнать до того, как они вас укусят:

- **Пробелы требуют обратных слэшей.** `@Design\ Docs/api-conventions.md` работает; без обратного слэша путь обрывается на первом пробеле. А если взять его в кавычки, файл не импортируется вовсе.
- **Обратные кавычки отключают импорт.** Разбор импортов пропускает code-спаны и огороженные блоки, поэтому `` `@README` `` остаётся обычным текстом, а `@README` сам по себе импортирует файл. Так можно *упомянуть* путь, не загружая его.

Полный справочник смотрите в [официальной документации по памяти](https://code.claude.com/docs/en/memory).

<Callout type="tip" items={["Единый источник истины: ссылайтесь на файл через @imports, а не вставляйте его содержимое в CLAUDE.md.", "Если документ уже существует, дайте на него ссылку — не копируйте его. Копии устаревают."]} />
