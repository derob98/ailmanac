## 它们如何工作

命令就是一个 Markdown 文件。把它放进你的命令目录，文件名就成为命令。文件正文就是你调用时 Claude 运行的提示词。

文件的*位置*决定它的作用范围：

<Steps items={[{title: "项目命令（可共享）", body: "保存到 .claude/commands/changelog.md → /changelog。它位于仓库中，因此整个团队都能使用。"}, {title: "个人命令（所有项目）", body: "保存到 ~/.claude/commands/changelog.md → /changelog。它会跟随你在本机的每一个项目。"}, {title: "调用它", body: "在 Claude Code 中输入 /词。文件正文就成为 Claude 运行的提示词。"}]} />

<Callout type="tip" items={["决定命令名称的是文件名，而不是 frontmatter：changelog.md 就是 /changelog。命令文件接受与技能相同的 frontmatter，但不包括 name 和 paths，所以你无法在文件内部给命令改名。", "子目录会用冒号为命令加上命名空间：.claude/commands/frontend/component.md 是 /frontend:component，而不是 /component。"]} />

## 一个最小示例

下面是一个完整的命令文件。frontmatter 里放 `description`，其下的所有内容就是提示词。

<PromptCard title="commit.md — 起草一条 Conventional Commit">{`---
description: Draft a Conventional Commit message from the staged diff
---

Look at the staged changes with \`git diff --cached\` and write a single
Conventional Commit message (feat/fix/docs/refactor/chore). Output only the
message, no preamble.`}</PromptCard>

把它保存为 `commit.md`，之后 `/commit` 每次都会这样做。（名称取决于文件名——同样的正文如果保存为 `changelog.md`，就会是 `/changelog`。）

## 实用的构建块

四种要素能把静态提示词变成灵活的命令：

| 构建块 | 它的作用 |
| --- | --- |
| **`$ARGUMENTS`** | 注入用户在命令之后输入的全部内容。`/review src/auth.ts` → 该路径会进入你的提示词。 |
| **`$ARGUMENTS[N]` / `$N`** | 按**从 0 开始**的索引取单个参数。`$ARGUMENTS[0]`（简写 `$0`）是*第一个*参数——所以 `$1` 是**第二个**，而不是像 shell 脚本里那样的第一个。 |
| **运行 bash 并嵌入输出** | 命令可以包含 shell 输出（例如当前的 diff），让 Claude 基于实时状态行动。 |
| **引用文件** | 指向文件即可包含其内容。 |
| **Frontmatter** | `description`（显示在菜单中）、`argument-hint`、`allowed-tools`、`disallowed-tools`、`disable-model-invocation`。 |

参数、bash 和文件引用的确切语法见[官方文档](https://code.claude.com/docs/en/skills)。

## 命令 vs 技能 vs 子智能体

三种打包工作的方式——区别在于*谁来触发*以及*运行时的隔离程度*：

- **斜杠命令**——*你*按需触发一个已知的工作流。
- **[技能](/docs/claude-code/skills)**——Claude 在相关时*自动*加载专长。
- **[子智能体](/docs/claude-code/subagents)**——把一部分工作委派给一个隔离的智能体。
