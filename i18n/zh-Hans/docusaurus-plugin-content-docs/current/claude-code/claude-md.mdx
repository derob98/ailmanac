文件位置、加载顺序和导入语法均来自官方记忆文档（「Claude 如何记住你的项目」），该文档现在描述了**两种**机制：由你编写的 CLAUDE.md 文件，以及 Claude 自己编写的**自动记忆**。导入最多解析到四跳深度。具体细节请在那里确认——这些细节会变化。
</VerifyNote>

如果你只做**一件**事来让 [Claude Code](/docs/claude-code/what-is-claude-code) 变得更好，那就做这件。`CLAUDE.md` 是一个纯文本文件，Claude 会在每次会话开始时读取它——它是你项目的常驻简报。

<Callout type="objectives" items={["为什么 CLAUDE.md 是收益最高的单一 Claude Code 设置", "记忆层级如何加载，从托管策略一直到 CLAUDE.local.md", "自动记忆与你自己编写的 CLAUDE.md 有何不同", "如何用 /init 生成一份起始文件并精简它", "什么内容应该写进 CLAUDE.md——以及什么应该排除在外", "@imports 如何让你引用文档而无需重复其内容"]} />

## 为什么它是收益最高的设置

没有它，你每次会话都要重新解释你的项目（「我们用 pnpm，测试在 `__tests__` 里，别碰 `/generated`……」）。有了它，Claude 早已知晓。这里写好的指令会一次性改善*未来每一次*交互。

## 记忆层级

Claude Code 会从多个位置加载记忆，并按加载顺序合并它们，作用域最宽泛的在前——因此项目指令会*在*用户指令*之后*进入上下文：

```mermaid
flowchart TD
  A["Managed policy<br/>/etc/claude-code/CLAUDE.md (org-wide, IT-managed)"] --> B["User instructions<br/>~/.claude/CLAUDE.md (all your projects)"]
  B --> C["Project instructions<br/>./CLAUDE.md or ./.claude/CLAUDE.md (committed)"]
  C --> D["Local instructions<br/>./CLAUDE.local.md (yours only — gitignore it)"]
```

- **托管策略**——由你的 IT/DevOps 团队分发的组织级指令。路径因操作系统而异：macOS 上是 `/Library/Application Support/ClaudeCode/CLAUDE.md`，Linux 和 WSL 上是 `/etc/claude-code/CLAUDE.md`，Windows 上是 `C:\Program Files\ClaudeCode\CLAUDE.md`。
- **用户指令**（`~/.claude/CLAUDE.md`）——你在所有项目中的个人偏好。
- **项目指令**（`./CLAUDE.md` *或* `./.claude/CLAUDE.md`，已提交）——*这个*仓库如何运作。与团队共享。如果你的仓库使用 [`AGENTS.md`](/docs/claude-code/agents-md)，它可以代替这些文件加载，也可以与它们一起加载。
- **本地指令**（`./CLAUDE.local.md`）——只属于你自己的项目专属笔记，比如一个沙箱 URL。把它加进 `.gitignore`。

位于你工作目录*之上*的目录层级中的文件会在启动时加载；而**子目录中的文件按需加载**——当 Claude 接触到那个区域里的东西时才加载。

<Callout type="tip" items={["一个文件已经不够用了？把指令拆分到 .claude/rules/*.md——每个文件一个主题，会被递归发现。没有 paths frontmatter 的规则会在启动时加载，优先级与 .claude/CLAUDE.md 相同；加上 paths frontmatter 之后，规则只在 Claude 处理匹配的文件时才加载，这能节省上下文。"]} />

## 另一半：自动记忆

CLAUDE.md 是记忆中由*你*编写的那一半。Claude Code 还会保留**自动记忆**——Claude 从你的纠正和偏好中自己写下的笔记，按仓库存储，并在每次会话中与你的 CLAUDE.md 文件一起加载。

| | CLAUDE.md 文件 | 自动记忆 |
| --- | --- | --- |
| **谁来编写** | 你 | Claude |
| **包含什么** | 指令和规则 | 学到的经验和模式 |
| **作用范围** | 项目、用户或组织 | 按仓库，跨 worktree 共享 |

两者都是*上下文*，而不是强制约束：Claude 把它们当作可以权衡的指引，而不是必须服从的配置。如果要无论 Claude 怎么决定都硬性拦截某个操作，请改用 [PreToolUse 钩子](/docs/claude-code/hooks)。

<Callout type="warning" items={["自动记忆只会加载它的前 200 行或 25 KB——一个臃肿的 MEMORY.md 会被静默截断。完整的启动开销拆解见上下文预算审计。"]} />

## 应该写什么

- 用两句话说明项目是什么。
- 技术栈，以及如何**运行 / 测试 / lint**。
- Claude 推断不出来的约定（命名、结构、提交风格）。
- **护栏**：「声明完成前先跑测试」、「绝不编辑 `/vendor`」、「绝不提交密钥」。

## 不应该写什么

<Callout type="warning" items={["Claude 会字面地遵循 CLAUDE.md——过时、含糊或一厢情愿的指令反而有害。", "描述项目当下实际的运作方式；简短且真实，胜过冗长且理想化。", "避免粘贴巨大的文档（改用 @imports），避免密钥，避免你实际并不遵循的规则。", "定期复查它，让它随项目演进而保持准确。"]} />

## 导入

引入已有文档而不是复制它们——例如用 `@path/to/file` 导入引用你的风格指南，这样就只有一个权威来源。相对路径和绝对路径都可以；相对路径是相对于*包含该导入的那个文件*解析的，**而不是**相对于你的工作目录。被导入的文件还可以再导入其他文件，最多到**四跳**深度。

在被坑到之前，有两个语法陷阱值得先知道：

- **空格需要反斜杠。** `@Design\ Docs/api-conventions.md` 可以工作；没有反斜杠的话，路径会在第一个空格处截断。而用引号把它包起来则完全不会导入该文件。
- **反引号表示退出解析。** 导入解析会跳过代码片段和围栏代码块，所以 `` `@README` `` 仍然是字面文本，而单独写 `@README` 则会导入该文件。你就是这样在*提到*一个路径时不去加载它。

完整参考见[官方记忆文档](https://code.claude.com/docs/en/memory)。

<Callout type="tip" items={["单一权威来源：用 @imports 引用文件，而不是把它的内容粘贴进 CLAUDE.md。", "如果文档已经存在，链接它——别复制它。副本会逐渐过时。"]} />
