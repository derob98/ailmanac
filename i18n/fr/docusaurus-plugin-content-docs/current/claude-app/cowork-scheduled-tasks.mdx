Cowork a cessé d'être un espace de travail desktop uniquement le **7 juillet 2026**. Il tourne maintenant sur **web (claude.ai)**, **iOS et Android**, et — la partie que la plupart des articles enterrent — les sessions s'exécutent sur les **serveurs d'Anthropic**, pas sur votre machine. Ce seul changement architectural débloque la fonctionnalité phare : **des tâches planifiées qui tournent avec votre portable fermé, votre téléphone en poche, et aucun appareil en ligne**.

Cette page est le guide pratique de terrain : ce qui fonctionne réellement sur quelle surface, comment configurer une tâche planifiée correctement du premier coup, et la poignée de pièges que vous ne remarquez qu'après que votre briefing du lundi 6h a silencieusement échoué parce qu'il avait besoin d'un fichier local.

## Le seul changement qui compte : les sessions ont bougé vers les serveurs d'Anthropic

Avant juillet 2026, une session Cowork était un processus dans l'app Claude Desktop sur votre Mac ou PC. Fermez le portable, la session meurt. Tuez l'app, la session meurt. C'est pourquoi la boucle Cowork pré-juillet commençait toujours par « ouvrir desktop, garder éveillé ».

Le lancement de juillet introduit les **sessions distantes** : la boucle Cowork vit dans le cloud d'Anthropic, l'état de votre session et vos fichiers persistent contre votre compte Claude, et toute surface (web, mobile, desktop) n'est qu'un visualiseur + périphérique d'entrée pour la même session sous-jacente.

Deux conséquences directes :

1. **Les tâches planifiées sont possibles.** Une tâche récurrente peut se réveiller le lundi 6h, faire 45 minutes de travail et déposer un brouillon dans votre compte — avec zéro appareil en ligne, parce qu'il n'y a pas d'appareil dans la boucle.
2. **Le handoff cross-device est gratuit.** Démarrez une tâche à votre bureau, fermez le portable, et voyez la même session en cours sur votre téléphone. Rien à synchroniser — la session n'a jamais été sur votre portable.

Le compromis est la matrice de capacités ci-dessous : tout ce qui doit toucher **votre machine locale** (fichiers sur disque, votre navigateur, votre OS) ne peut tourner que sur desktop, parce que c'est la seule surface avec un pied dans les deux mondes.

## Matrice de capacités par surface

| Capacité | App Desktop | Web (claude.ai) | Mobile (iOS/Android) |
| --- | --- | --- | --- |
| Sessions Cowork (interactives) | ✓ | ✓ (bêta) | ✓ (bêta) |
| Tâches Cowork **planifiées** | ✓ (créer + surveiller) | ✓ (créer + surveiller) | ✓ (surveiller + approuver) |
| Accès fichiers locaux | ✓ | ✗ | ✗ |
| Browser use (automation du navigateur local) | ✓ | ✗ | ✗ |
| Computer use (contrôle OS) | ✓ | ✗ | ✗ |
| Artefacts live (aperçu en session) | ✓ | ✗ | ✗ |
| Outils connectés (Gmail, Slack, GDrive, Calendar, web) | ✓ | ✓ | ✓ |
| **Skills** installées | ✓ | ✓ | ✓ |
| **Plugins** | ✓ | ✓ | ✓ |
| Push mobile pour prompts d'approbation | (via téléphone lié) | (via téléphone lié) | ✓ (natif) |
| Modèle Fable 5 dans Cowork | ✓ (dernier Desktop uniquement) | voir pièges | voir pièges |

:::info La règle du pouce
Si la tâche a seulement besoin d'**outils connectés + Skills + web** (triage email, « lis ces trois docs et rédige-moi une mise à jour », rapport hebdo depuis Google Sheets), elle tourne partout — planifiez-la. Si elle a besoin de **vos fichiers, votre navigateur ou votre machine**, elle reste desktop-et-live uniquement.
:::

## Cowork interactif vs Tâche planifiée vs Dispatch

Les trois modes sont confondus. Ce sont des bêtes différentes :

<Steps items={[
  {title: "Session Cowork interactive", body: "Vous la démarrez, vous regardez, Claude travaille sur un long horizon sur votre objectif actif. Vit sur les serveurs d'Anthropic maintenant, donc vous pouvez la passer d'un appareil à l'autre. Idéal pour : travail multi-heures que vous voulez piloter au fur et à mesure."},
  {title: "Tâche Cowork planifiée", body: "Vous définissez un prompt + une cadence (horaire / quotidien / jours ouvrés / hebdomadaire / manuel). Chaque run lance une session Cowork fraîche avec les outils, skills et plugins que vous avez spécifiés. Tourne à distance, sur planning, qu'un appareil soit en ligne ou non. Idéal pour : travail de prep récurrent — briefings du lundi 6h, triage horaire de la boîte, rollups de fin de journée."},
  {title: "Dispatch (desktop uniquement)", body: "Forme legacy : lancez une tâche en arrière-plan depuis une session desktop active qui continue de tourner pendant que vous continuez à discuter. Nécessite que l'app desktop reste éveillée parce que le processus vit encore localement. Idéal pour : travail sur machine locale que vous voulez mettre en arrière-plan pendant que vous continuez à collaborer. Ne le confondez PAS avec une tâche planifiée distante — Dispatch meurt quand l'app se ferme."}
]} />

Le raccourci mental : **Dispatch = arrière-plan local, Tâche planifiée = cloud sur cadence, Interactif = vous êtes au volant.**

## Configurer une tâche planifiée, la bonne méthode

Une tâche planifiée a besoin de six choses — cinq paramètres et un prompt. Ratez un des paramètres et le run aura l'air « réussi » mais fera la mauvaise chose.

<Steps items={[
  {title: "Nom de la tâche", body: "Court, humain. C'est ce que vous verrez dans la liste des tâches planifiées et dans les notifications mobiles. 'Prep client lundi' bat 'briefing-v2'."},
  {title: "Prompt / instructions", body: "Écrivez-le comme si vous parliez à un collègue qui rejoint à zéro à chaque run — parce que chaque run EST une session fraîche. Énoncez l'objectif, les sources (quels connecteurs, quelles skills, quels dossiers), la forme de sortie que vous voulez, et tout invariant (par exemple 'ne jamais envoyer d'email, toujours laisser en brouillon')."},
  {title: "Fréquence", body: "Choisissez parmi horaire / quotidien / jours ouvrés / hebdomadaire / manuel. Il n'y a pas de syntaxe cron et pas d'options sous-horaires — si vous avez besoin de 'toutes les 5 min', vous êtes sur le mauvais outil (utilisez l'API + votre propre scheduler)."},
  {title: "Mode d'approbation", body: "Le paramètre critique. Les options sont auto-approve (Claude procède sans demander, bien pour les tâches en lecture seule), ask-on-mobile (Claude s'arrête à un point de décision et ping votre téléphone — défaut sûr pour tout ce qui écrit), ou hold-for-review (la tâche se termine toujours par un brouillon que vous relisez plus tard)."},
  {title: "Modèle (optionnel)", body: "Par défaut le Cowork par défaut de votre plan. Choisissez un modèle plus petit/moins cher pour les boucles lourdes de lecture-résumé ; choisissez top-tier seulement quand la qualité du raisonnement bouge vraiment le résultat."},
  {title: "Dossier de travail (optionnel)", body: "Scopes les écritures de fichiers de la session à un projet/dossier spécifique dans votre compte Claude. Sautez-le et les sorties atterrissent dans un emplacement par défaut — ce qui va pour une tâche, une pagaille avec douze."}
]} />

<PromptCard title="Template de prompt pour tâche planifiée : briefing client lundi 6h">{`You are preparing my Monday morning brief for the Acme account.

Every Monday at 06:00 local:

1. Read the last 7 days of email in the "Acme" Gmail label. Group by
   thread; note anything that expects a reply from me.
2. Pull calendar events with "Acme" in the title or attendees from
   the coming week. Note prep needed for each.
3. Search the web for news about Acme (company name + "acquisition",
   "layoffs", "product launch") in the last 7 days. Cite sources.
4. Read the Google Doc "Acme - Running Notes" for open questions.

Produce a single briefing doc titled "Acme brief — <this-monday-date>"
in the "Client briefings" project folder. Structure:

- 3-bullet TL;DR at the top
- "Needs a reply from me" list (with links)
- "This week" list (calendar + prep)
- "News since last brief" (with sources)
- "Open questions" (from the running-notes doc)

DO NOT send any email. Leave a follow-up email as a DRAFT in Gmail
titled "Acme weekly check-in" pre-filled with the TL;DR — I'll edit
and send.`}</PromptCard>

Deux choses à noter sur ce prompt :

- L'**invariant** (« DO NOT send any email... leave as DRAFT ») est explicité. Dans un run planifié vous ne pouvez pas poser un « êtes-vous sûr ? » de suivi — les invariants doivent être dans le prompt.
- L'**emplacement de sortie + nommage** est précis. Quand ceux-ci tournent hebdomadairement pendant des mois, vous les voulez trouvables, pas éparpillés sous des titres par défaut.

## Flux d'approbation mobile — concevoir pour « je dors »

`ask-on-mobile` semble amical jusqu'à ce qu'il tire à 3h et que le run cale silencieusement en vous attendant. Deux règles rendent cela fiable :

<Steps items={[
  {title: "Adaptez le mode d'approbation au rayon d'impact", body: "Actions en lecture seule ou brouillon uniquement → auto-approve. Tout ce qui envoie, publie, supprime ou dépense de l'argent → ask-on-mobile avec un fallback dans le prompt : 'si je n'ai pas répondu dans les 30 minutes, sauvegarde en brouillon et termine la tâche'. Le fallback au niveau du prompt est important parce que la plateforme ne va pas vous timer out à votre place."},
  {title: "Faites en sorte que le titre de la notification vous dise ce qui va se passer", body: "Dans le prompt, enveloppez les points de décision dans une demande spécifique : 'Avant d'envoyer quoi que ce soit, demande l'approbation avec la ligne de sujet exacte et les 200 premiers caractères du corps.' Les notifications push tronquent — mettez les bits importants en tête pour que vous puissiez approuver/refuser depuis l'écran de verrouillage sans ouvrir l'app."}
]} />

<Callout type="warning" items={[
  "Les approbations push bloquent la tâche jusqu'à ce que vous répondiez. Si vous ne répondez jamais, le run reste là — il ne retombe pas automatiquement sur un défaut sûr. Intégrez un timeout 'si pas de réponse, faire X' dans le prompt lui-même, ou utilisez hold-for-review à la place."
]} />

## Les quatre pièges qui cassent les runs Cowork planifiés

<Steps items={[
  {title: "1. Les outils locaux uniquement désactivent silencieusement le run", body: "Si le prompt demande à la tâche d'« ouvrir mon dossier téléchargements », « automatiser mon navigateur », ou « prendre une capture d'écran de mon écran », la session distante n'a aucun moyen de le faire. Le run ne plantera pas — il sautera ou improvisera. Correctif : auditez vos prompts planifiés et remplacez les actions machine locale par des équivalents outil connecté (Google Drive au lieu des fichiers locaux, web fetch au lieu du navigateur local, etc.)."},
  {title: "2. Fable 5 dans Cowork nécessite toujours le dernier Desktop", body: "Au lancement de juillet 2026, exécuter le modèle Fable 5 dans une session Cowork nécessite la dernière app Claude Desktop. Si vous planifiez une tâche qui épingle Fable 5 et comptez sur son exécution distante, vérifiez le support actuel — cette contrainte devrait se relâcher mais vérifiez avant d'épingler."},
  {title: "3. Dispatch n'est PAS une tâche planifiée", body: "Le travail Dispatch en arrière-plan depuis une session desktop active meurt quand vous fermez l'app. Si vous avez vraiment besoin de 'tourner ceci hebdomadairement, coûte que coûte', ne Dispatchez pas — créez une tâche planifiée."},
  {title: "4. La dérive d'auth des connecteurs tue les runs silencieux", body: "Les tokens OAuth vers Gmail, Slack, Google Drive peuvent expirer, être révoqués, ou subir des changements de permissions. Une tâche planifiée sous un connecteur expiré produit une sortie vide et aucune erreur évidente. Correctif : pour tout ce qui tourne hebdomadairement ou moins souvent, ajoutez une première étape d'auto-vérification dans le prompt ('confirme que tu peux lire le label Gmail Acme ; sinon produis une erreur d'une ligne en haut du doc et arrête')."}
]} />

## Quand se tourner vers l'API à la place

Les tâches Cowork planifiées sont une fonctionnalité produit — excellentes pour du travail récurrent personnel / petite équipe que vous voulez visible dans votre compte Claude, avec l'approbation humaine dans la boucle. Elles sont le mauvais outil quand vous avez besoin de :

- **Cadence sous-horaire** — le plus petit intervalle de tâche planifiée est horaire.
- **Orchestration programmatique** — des dizaines de runs parallèles, planification dynamique, ou intégration serrée avec votre infra. Tournez-vous vers les [Managed Agents](/docs/api/managed-agents), ou faites le vôtre avec l'[Agent SDK](/docs/claude-code/headless-and-agent-sdk) + un cron/queue que vous exploitez déjà.
- **Mémoire côté serveur entre les runs** — les tâches Cowork passent l'état via des fichiers dans votre compte, ce qui va pour des docs mais est grossier pour l'état structuré. Pour la mémoire structurée cross-run, utilisez les [Managed Agents Memory Stores](/docs/api/managed-agents-memory-stores).
- **Coordination multi-agents profonde** — pour la collaboration entre beaucoup d'agents, voir [Cowork & Agent Teams](/docs/api/cowork-and-agent-teams) et [Native Multi-Agent APIs](/docs/models/native-multi-agent-apis).
