A maioria das pessoas aprende três coisas da linha de comando do Claude Code — `claude`, `claude -c` e `claude -p` — e para por aí. É um ponto justo para parar se você só o usa sentado diante dele. No momento em que você coloca o Claude Code num script, num job de CI, numa fila em segundo plano ou nas mãos de um colega, as flags deixam de ser conveniências e passam a ser a diferença entre uma execução que custa um dólar e uma que fica travada por uma hora.

Esta página não é uma segunda cópia da tabela de referência. Ela é a **ordem em que vale aprender a superfície**, as flags que de fato mudam o que acontece e as quatro armadilhas que já custaram tempo real às pessoas.

## Comece pela pergunta: que tipo de sessão é esta?

Toda outra decisão decorre desta. O Claude Code pode iniciar seis coisas materialmente diferentes, e a flag que escolhe uma delas costuma ser a primeira coisa que você digita.

| Você quer | Flag | Isso lhe dá |
| --- | --- | --- |
| Uma conversa que você acompanha | *(nenhuma)* | Sessão interativa neste terminal |
| Uma resposta e sair | `-p` / `--print` | Execução não interativa, saída para stdout |
| Trabalho que sobreviva a este terminal | `--bg` / `--background` | Uma sessão em segundo plano; imprime seu ID e como gerenciá-la |
| Uma branch isolada para experimentar | `-w` / `--worktree` | Um git worktree em `<repo>/.claude/worktrees/<name>` |
| Trabalho nas máquinas da Anthropic | `--cloud` | Uma sessão na nuvem, ou um acompanhamento enfileirado em uma existente |
| Conduzir esta sessão pelo celular | `--rc` / `--remote-control` | Uma sessão interativa que também pode ser controlada pelo claude.ai ou pelo app do Claude |

Duas delas não podem ser combinadas: `--bg` e `-p` são mutuamente exclusivas, porque uma retorna imediatamente e a outra espera uma resposta. Se você quer um comando de shell, e não uma sessão do Claude, em segundo plano, combine `--bg` com `--exec`:

<PromptCard title="Run the test suite as a background job, not a Claude session">
{`claude --bg --exec 'pytest -x'`}
</PromptCard>

E o `--bg` verifica a confiança do workspace para o diretório antes de começar — assim, uma sessão em segundo plano num repositório não confiável falha logo de início, e não no meio do caminho.

## O contrato de cinco flags para execuções sem supervisão

Esta é a coisa de maior valor desta página. Uma execução de `claude -p` sem supervisão tem três jeitos de dar errado que uma sessão interativa simplesmente não tem: ela pode **travar** em pedidos de permissão que ninguém está lá para responder, pode **entrar em loop** por muito mais tempo do que você esperava e pode **emitir prosa** quando seu script precisava de dados. Cinco flags fecham os três.

<Steps items={[
  {title: "Execute de forma não interativa — -p", body: "`claude -p \"query\"` imprime a resposta e sai. Tudo abaixo é exclusivo do modo print, então esta flag é a porta de entrada para o resto."},
  {title: "Decida quem responde aos pedidos de permissão — --permission-prompts", body: "O padrão é `host`, que envia os pedidos ao host do Agent SDK ou a um `--permission-prompt-tool`. Passe `--permission-prompts none` quando ninguém pode responder, como num cron ou num passo de CI: a execução para de consultar ou esperar um host, tudo o que pediria permissão é negado a menos que um hook `PermissionRequest` permita, e o Claude é instruído a não tentar de novo. Uma execução `-p` sem nenhum host já nega esses pedidos; nesse caso a flag basicamente impede as novas tentativas. Requer v2.1.259 ou posterior. Combine com regras `--allowedTools` estreitas para que as negações sejam raras, não constantes."},
  {title: "Limite o loop — --max-turns", body: "Não há limite de turnos por padrão. `--max-turns 3` sai com erro quando o limite é atingido. Use-o como um fio de alarme contra loops agênticos descontrolados, não como orçamento."},
  {title: "Limite o gasto — --max-budget-usd", body: "`--max-budget-usd 5.00` para quando a estimativa de custo do lado do cliente atinge o teto. O gasto dos subagentes conta; ao atingi-lo, criar outro subagente falha com `Budget limit reached` e os subagentes em segundo plano em execução são interrompidos. A aplicação do teto requer v2.1.217 ou posterior."},
  {title: "Torne a saída analisável — --output-format ou --json-schema", body: "`--output-format json` dá um envelope estruturado. `--json-schema '<schema>'` vai além: o Claude Code valida a resposta final contra o seu JSON Schema e dá erro logo de início se o schema for inválido, de modo que seu script nunca precisa aplicar regex em prosa."}
]} />

<PromptCard title="A CI step that cannot hang, cannot loop forever, and cannot overspend">
{`claude -p "Review the staged diff and list bugs" \\
  --permission-prompts none \\
  --allowedTools "Read" "Bash(git diff *)" \\
  --max-turns 6 \\
  --max-budget-usd 2.00 \\
  --output-format json`}
</PromptCard>

<Callout type="warning" title="--max-budget-usd é uma estimativa, não a sua fatura" items={["O Claude Code compara o teto com a própria estimativa de custo do lado do cliente, que pode diferir do que você é cobrado.","Quando você volta a uma conversa com --continue ou --resume, os totais restaurados de execuções anteriores não contam para o teto — então três execuções retomadas sob um teto de US$ 2 podem gastar mais de US$ 2 no total.","Trate-o como um disjuntor para uma única execução. Para um teto real sobre uma conta ou um projeto inteiro, veja Hard Spend Caps."]} />

## A família do prompt de sistema, e a armadilha dentro dela

Cinco flags moldam o prompt de sistema. Quatro definem o texto dele; a quinta decide se a conversa mantém o texto com o qual começou.

| Flag | O que faz |
| --- | --- |
| `--system-prompt` | Substitui todo o prompt padrão pelo seu texto |
| `--system-prompt-file` | Substitui pelo conteúdo de um arquivo |
| `--append-system-prompt` | Acrescenta seu texto ao prompt padrão |
| `--append-system-prompt-file` | Acrescenta o conteúdo de um arquivo ao prompt padrão |
| `--system-prompt-snapshot` | `off` reconstrói o prompt a cada requisição; `on` (o padrão) reutiliza o gravado |

A escolha entre *acrescentar* e *substituir* é uma escolha de identidade. Acrescentar mantém a orientação de ferramentas, as instruções de segurança e as convenções de código padrão do Claude Code, e coloca suas regras por cima — certo para instruções por execução, formatação de saída ou contexto do projeto. Substituir descarta **tudo** isso, inclusive a orientação de ferramentas, o que só é adequado quando a superfície realmente não é um assistente de código: um agente que não programa, num pipeline que ninguém observa. Se você substitui, é responsável por tudo o que a tarefa ainda precisa.

Você pode combiná-las. Passar uma flag de acrescentar junto com uma de substituir substitui o padrão e depois acrescenta seu texto. A partir da v2.1.283 você também pode passar uma flag junto com a sua própria forma de arquivo — `--append-system-prompt` *e* `--append-system-prompt-file` — e o Claude Code usa as duas, com o conteúdo do arquivo primeiro, independentemente da ordem em que você as digitou.

<Callout type="warning" title="A armadilha: uma conversa retomada reutiliza o prompt com o qual nasceu" items={["O Claude Code constrói o prompt de sistema uma vez, na primeira requisição de uma conversa, e o grava na sessão.","Até a conversa ser compactada, toda requisição seguinte usa esse prompt gravado — inclusive depois de --resume ou --continue.","Então você edita o texto do --append-system-prompt, roda claude --continue de novo e nada muda. A flag não está quebrada; a conversa ainda está usando a gravação.","O texto novo passa a valer quando a conversa é compactada, ou numa conversa totalmente nova.","Para iterar na redação entre execuções com --continue, passe --system-prompt-snapshot off e o prompt é reconstruído a cada requisição. Requer v2.1.257 ou posterior."]} />

Há mais um truque que vale conhecer num prompt de substituição que mistura instruções estáveis com contexto por execução. Coloque entre eles uma linha contendo apenas `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__`: o Claude Code divide na primeira linha assim e a remove, de modo que a parte de cima continua em cache enquanto a de baixo muda. Requer v2.1.275 ou posterior. Por que isso importa para a sua fatura é o assunto de [Prompt Caching](/docs/api/prompt-caching).

E para cargas de trabalho com scripts e vários usuários, `--exclude-dynamic-system-prompt-sections` move o contexto por usuário, como o local da memória automática, do prompt de sistema para a primeira mensagem do usuário — assim a mesma tarefa em máquinas diferentes compartilha um único prefixo em cache. Aplica-se apenas ao prompt padrão e é ignorada quando você define `--system-prompt` ou `--system-prompt-file`.

## Três flags que desligam coisas, e não são a mesma coisa

As pessoas as usam de forma intercambiável e depois se perguntam por que o sintoma não se moveu. Elas resolvem três problemas diferentes.

| | `--bare` | `--safe-mode` | `--restricted` |
| --- | --- | --- | --- |
| O problema que resolve | A inicialização é lenta demais para uma chamada em script | Minha configuração está quebrada e não sei qual parte | Um harness de avaliação não pode tocar nesta máquina compartilhada |
| CLAUDE.md, skills, comandos, subagentes, plugins, MCP, memória automática | Não são descobertos | Não são carregados | Só as configurações gerenciadas e `--settings` são carregadas |
| Ferramentas embutidas | Bash, leitura de arquivo, edição de arquivo | Funcionam normalmente | As ferramentas que executam comandos/código e o WebFetch são **removidos**, a menos que citados individualmente em `--tools` |
| Acesso a arquivos | Normal | Normal | Confinado aos diretórios de trabalho |
| `bypassPermissions` | Permitido | Permitido | **Recusado** |
| Política gerenciada | Aplica-se | Continua se aplicando, inclusive hooks de política e a linha de status | Aplica-se |
| Efeito colateral | Define `CLAUDE_CODE_SIMPLE` | Define `CLAUDE_CODE_SAFE_MODE` | Recusa criar sessões na nuvem |

Leia a tabela como uma progressão de intenção: `--bare` é sobre **velocidade**, `--safe-mode` é sobre **diagnóstico**, `--restricted` é sobre **contenção**. Um detalhe útil: skills num diretório que você passa com `--add-dir` ainda carregam com `--bare`, e é assim que você mantém exatamente uma capacidade numa execução, de resto, despida.

`--safe-mode` é o primeiro a usar quando algo se comporta mal e você não sabe se é o Claude Code ou a sua própria configuração — inclusive quando você tenta descobrir se uma personalização é o que dispara o fallback automático de modelo. Combine-o com `claude doctor`, que imprime diagnósticos somente leitura da instalação e das configurações sem iniciar sessão alguma. (O comando `/doctor` dentro da sessão é outra coisa: ele também pode aplicar correções.) Mais depuração partindo do sintoma em [Solução de problemas do Claude Code](/docs/claude-code/troubleshooting). `--restricted` requer v2.1.248 ou posterior.

## Conduzindo sessões em segundo plano pelo shell

Depois que você inicia sessões com `--bg`, o terminal vira um plano de controle. Todo o ciclo de vida tem um comando, e nada disso exige abrir a UI interativa.

<Steps items={[
  {title: "Veja o que está rodando — claude agents", body: "Abre a visão de agentes para monitorar e despachar sessões paralelas em segundo plano. Para scripts, `--json` imprime as sessões ativas como um array JSON, e `--json --all` inclui as concluídas. `--cwd <path>` restringe às sessões iniciadas sob aquele diretório. Abrir a visão em si precisa de um terminal interativo; a forma JSON não."},
  {title: "Olhe dentro de uma — claude logs", body: "`claude logs <id|name>` imprime a saída recente de uma sessão em segundo plano. A partir da v2.1.290 você pode passar parte do nome de uma sessão em execução no lugar do ID — então `claude logs auth` costuma bastar."},
  {title: "Assuma o controle — claude attach", body: "`claude attach <id|name>` traz uma sessão em segundo plano para este terminal. A correspondência por nome parcial também requer v2.1.290 ou posterior."},
  {title: "Reinicie — claude respawn", body: "`claude respawn <id>` reinicia uma sessão, em execução ou parada, com a conversa intacta. `--all` reinicia todas as sessões em execução — a jogada certa depois de atualizar o binário do Claude Code."},
  {title: "Pare e limpe — claude stop, claude rm", body: "`claude stop <id>` (também `claude kill`) interrompe uma sessão. `claude rm <id>` a remove da lista; a transcrição fica na sua máquina e continua acessível por `claude --resume`. Se a remoção for recusada por causa do worktree da sessão, a recusa imprime a flag exata a passar em seguida — `--discard-unpushed` (v2.1.260+) ou `--force-remove-worktree` (v2.1.268+)."},
  {title: "Quando tudo travou — claude daemon", body: "As sessões em segundo plano são hospedadas por um processo supervisor. `claude daemon status` imprime seu estado, versão, diretório do socket e número de workers, e sai com 1 se ele não estiver rodando. `claude daemon logs` acompanha `~/.claude/daemon.log`. `claude daemon stop --any --keep-workers` reinicia o supervisor deixando as sessões vivas para o próximo se reconectar a elas."}
]} />

A contrapartida disso de dentro de uma sessão — como o trabalho vai para o segundo plano e o que se mantém quando isso acontece — está em [Tarefas em segundo plano, /loop e agendamento](/docs/claude-code/background-tasks).

## Os pares de flags que as pessoas erram

<Callout type="warning" title="Seis confusões que vale antecipar" items={["--tools restringe quais ferramentas embutidas existem. --allowedTools diz quais chamadas pulam o pedido de permissão. --disallowedTools nega chamadas. São três trabalhos diferentes, e passar o errado é a causa mais comum de “por que ainda está me perguntando”.","--tools não afeta as ferramentas MCP de forma alguma. Para removê-las também, adicione --disallowedTools \"mcp__*\".","Um nome simples em --disallowedTools remove a ferramenta do contexto do Claude; uma regra com escopo como Bash(rm *) deixa a ferramenta disponível e nega apenas as chamadas correspondentes.","--dangerously-skip-permissions inicia em bypassPermissions. --allow-dangerously-skip-permissions só adiciona esse modo ao ciclo do Shift+Tab, para você começar em modo plan e trocar depois. A segunda é quase sempre a que você realmente queria.","--add-dir concede acesso a arquivos, mas o Claude Code não descobre a maior parte da configuração de .claude/ nesses diretórios. Adicionar um diretório não é o mesmo que adotar a configuração dele.","--desktop não aceita prompt nem outras flags além de --verbose e das flags de --debug, porque o app Desktop inicia a sessão por conta própria. Requer v2.1.285 ou posterior."]} />

Um pequeno detalhe de qualidade de vida: se você errar um subcomando, o Claude Code sugere a correspondência mais próxima e sai sem iniciar uma sessão — `claude udpate` imprime `Did you mean claude update?` em vez de abrir uma conversa que você não queria.
