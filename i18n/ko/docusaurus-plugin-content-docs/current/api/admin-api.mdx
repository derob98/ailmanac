공식 소스. Claude Enterprise 사용자 관리 엔드포인트는 2026년 7월 13일 기준 베타 상태입니다(헤더 `ce-user-management-2026-07-13`). 이 페이지의 나머지는 모두 GA(정식) 기능입니다. 엔드포인트 형식은 베타 중 안정화됩니다 — 배포 전 항상 [Admin API 레퍼런스](https://platform.claude.com/docs/en/api/admin)를 교차 확인하세요.
</VerifyNote>

Console에서 사람이 클릭할 수 있는 것이라면 대부분 Admin API로 스크립트화할 수 있습니다 — 그리고 Claude에서 실제 팀을 운영한다면 결국 스크립트화해야 합니다. 이 페이지는 첫 통합을 깨뜨리는 세 가지 함정을 밟지 않고 그 작업을 수행하는 가이드입니다.

## Admin API가 하는 일(그리고 하지 않는 일)

**베이스:** 모든 엔드포인트는 `https://api.anthropic.com/v1/organizations/` 아래에 있습니다. 별도 호스트나 별도 SDK가 없습니다 — 이미 사용 중인 `curl`, `requests`, 또는 그 어떤 HTTP 클라이언트로도 순수 HTTPS 호출을 하면 됩니다.

**할 수 있는 일:** 조직 멤버, 역할, 초대, 워크스페이스와 그 멤버, 기존 API 키, 서비스 계정, 페더레이션 이슈어/규칙 관리 — 그리고 Claude Enterprise의 경우 RBAC 그룹과 (읽기 전용) 커스텀 역할 관리.

**할 수 없는 일:**

- **신규 API 키 생성.** 보안상의 이유로 새 키는 Console에서만 만들 수 있습니다. API는 이미 있는 키를 나열, 이름 변경, 비활성화할 수 있습니다.
- **관리자 멤버 수정.** `admin`, `owner`, `primary_owner` 역할의 멤버는 API로 역할을 바꾸거나 제거할 수 없습니다 — Console에서 처리하세요.
- **ID 공급자 우회.** SSO/SCIM이 특정 영역을 담당하고 있다면, API는 IdP와 싸우지 않고 400을 반환합니다. [SSO + Admin API](#sso--admin-api) 참조.

## 두 가지 자격 증명

모든 요청에는 이 중 하나가 필요합니다 — 호출 단위가 아니라 환경 단위로 선택하세요.

<Callout type="tip" items={["사람용은 전용 OAuth 프로필이 더 안전한 기본값입니다(짧은 수명 토큰, 감사 로그에 실제 사용자).", "장기 수명의 Admin API 키는 CI에 더 간단하지만, 프로덕션 시크릿처럼 다루고 정기적으로 로테이트하세요.", "서비스 계정, 페더레이션 이슈어, 페더레이션 규칙 엔드포인트는 오직 org:admin OAuth 토큰만 받습니다 — 해당 경로에서 Admin API 키는 거부됩니다."]} />

| 자격 증명 | 전송 방법 | 생성 가능한 사람 | 참고 |
|---|---|---|---|
| **Admin API 키** (`sk-ant-admin…`) | `x-api-key: $ANTHROPIC_ADMIN_KEY` | `admin` 역할 멤버 | 장기 수명. 대부분의 엔드포인트 지원. |
| **OAuth 베어러 토큰** (`org:admin` 스코프) | `authorization: Bearer $ANTHROPIC_OAUTH_TOKEN` | `admin`, `owner`, 또는 `primary_owner` 멤버 | 짧은 수명, `ant` CLI로 갱신. 서비스 계정/페더레이션 엔드포인트에 필수. |

둘 다 매 요청에 `anthropic-version: 2023-06-01`도 보내야 합니다(Claude Enterprise 그룹 및 커스텀 역할 요청은 예외 — 아래 [베타 헤더 규칙](#the-beta-header-rule) 참조).

<PromptCard title="첫 호출: 나는 누구인가?">{`# With an Admin API key
curl -sS "https://api.anthropic.com/v1/organizations/me" \\

  -H "x-api-key: $ANTHROPIC_ADMIN_KEY"

# With an OAuth bearer token (org:admin scope)

응답은 조직의 `id`, `type`, `name`입니다. 401로 실패하면 자격 증명이 잘못됨, 403으로 실패하면 역할이 너무 낮음입니다.

## Console vs Claude Enterprise: 호출 가능한 것

두 조직 유형은 URL 공간을 공유하지만 서로 다른 하위 집합을 노출합니다. Admin API에서 가장 혼동되는 부분입니다.

| 엔드포인트 | Claude Console (Platform) | Claude Enterprise (claude.ai) |
|---|---|---|
| 멤버 & 초대 | ✅ GA | ✅ **베타** (추가 헤더 없음) |
| 워크스페이스 + 워크스페이스 멤버 | ✅ GA | ❌ 사용 불가 |
| API 키 (조회 / 이름 변경 / 비활성화) | ✅ GA | ❌ 사용 불가 |
| 사용량 & 비용 리포트, 요율 제한 | ✅ GA | ❌ 사용 불가 |
| 서비스 계정, 페더레이션 이슈어, 페더레이션 규칙 | ✅ GA (OAuth 전용) | ❌ 사용 불가 |
| RBAC 그룹 + 그룹 멤버 | ❌ 사용 불가 | ✅ **베타** (헤더 필수) |
| 커스텀 역할(읽기 전용 카탈로그) | ❌ 사용 불가 | ✅ **베타** (헤더 필수) |
| [Spend Limits API](https://platform.claude.com/docs/en/manage-claude/spend-limits-api) | ❌ 사용 불가 | ✅ GA |

**Claude Platform on AWS**는 세 번째 경우입니다: 워크스페이스 엔드포인트(`/v1/organizations/workspaces`)만 작동합니다. 나머지는 404를 반환합니다.

## 역할 모델

역할은 각 조직 유형마다 다르게 이름 붙여져 있습니다. 감으로 크로스 매핑하지 마세요.

### Claude Console 역할

| 역할 | 가능한 것 |
|---|---|
| `user` | Workbench 사용 |
| `claude_code_user` | Workbench + [Claude Code](/docs/claude-code/what-is-claude-code) |
| `developer` | Workbench + API 키 관리 |
| `billing` | Workbench + 결제 관리 |
| `admin` | 위 모두 + 사용자 관리 |

`admin` 위에는 `owner`와 `primary_owner`가 있습니다 — Console에도 있지만 API 목적상 슈퍼 관리자로 취급됩니다.

### Claude Enterprise 역할

다섯 개 값이 있지만 API는 두 개(`user`, `managed`)만 *할당*할 수 있습니다. 나머지는 `claude.ai` 조직 설정에서 설정되며 API로 수정하거나 제거할 수 없습니다.

| 역할 | 의미 |
|---|---|
| `user` | 표준 멤버 — 권한은 플랜 기본값에서 옵니다. |
| `managed` | 권한은 **그룹에 붙은 커스텀 역할**에서 옵니다(RBAC 경로). |
| `owner` | 조직 소유자. |
| `membership_admin` | 멤버 관리 가능, 결제/설정 관리 불가. |
| `primary_owner` | 정확히 하나만 존재. 제거 불가. |

Enterprise에서 세분화된 권한을 원한다면 레시피는: 사람을 `managed` 역할로 두고, 원하는 역할을 가진 그룹에 추가하세요.

## 베타 헤더 규칙 {#the-beta-header-rule}

Enterprise에서 가장 흔한 통합 버그입니다.

<Callout type="warning" items={["멤버와 초대: 추가 베타 헤더 없음 — 그냥 anthropic-version: 2023-06-01만.", "그룹과 커스텀 역할: anthropic-beta: ce-user-management-2026-07-13를 반드시 보내세요. 없으면 404를 반환합니다.", "그룹과 커스텀 역할 요청은 anthropic-version을 필요로 하지 않습니다 — 공식 예제는 이를 생략합니다. 베타가 정식이 될 때 예기치 못한 드리프트를 피하려면 공식 패턴에 맞추세요."]} />

모든 것에 하나의 HTTP 클라이언트를 쓴다면 URL로 게이트하세요:

```python
BETA_ROUTES = ("/v1/organizations/rbac_groups", "/v1/organizations/rbac_roles")

def headers(path: str, key: str) -> dict:
    h = {"x-api-key": key}
    if path.startswith(BETA_ROUTES):
        h["anthropic-beta"] = "ce-user-management-2026-07-13"
    else:
        h["anthropic-version"] = "2023-06-01"
    return h
```

## Enterprise Admin 키의 스코프

Claude Enterprise Admin API 키는 **스코프가 지정됩니다** — 프라이머리 오너가 생성 시점에 각 키가 할 수 있는 일을 고릅니다. 작동하는 최소 집합을 고르세요.

| 스코프 | 부여하는 권한 |
|---|---|
| `read:members` | 멤버, 초대, **모든 커스텀 역할 엔드포인트**에 대한 GET (별도의 role 스코프는 없음) |
| `write:members` | 멤버와 초대에 대한 POST/DELETE |
| `read:rbac_groups` | 그룹 + 그룹 멤버에 대한 GET |
| `write:rbac_groups` | 그룹 + 그룹 멤버에 대한 POST/DELETE. **초대 생성 시 `rbac_group_ids` 전달에도 필수**입니다(권한을 부여할 수 있으므로). |
| `read:org_audit` | 읽기 전용 "감사 통합" 스코프 — 이 API의 모든 GET + [Compliance API](https://platform.claude.com/docs/en/manage-claude/compliance-api) 읽기를 커버합니다. 보안팀 모니터링 봇에 딱입니다. |

## 페이지네이션 — 두 가지 다른 스타일

작은 짜증, 큰 "왜 내 목록이 비어있지"의 원인:

- **멤버와 초대**는 **ID 기반 페이지네이션**을 사용합니다: `limit`(기본 20, 최대 1000)과 `before_id` 또는 `after_id` 중 최대 하나를 전달. `first_id` / `last_id`로 페이징하고 `has_more`가 `false`일 때 멈춥니다.
- **그룹, 그룹 멤버, 커스텀 역할**은 **불투명 커서**를 사용합니다: 각 응답에서 `next_page`를 읽고 그대로 `page`로 다시 전달. `next_page`가 `null`이면 멈춥니다.

모든 Admin API 엔드포인트의 요율 제한은 **조직당 분당 100 요청**을 공유하며, 초대 생성만 예외로 자체 **시간당 1,200 요청** 예산을 갖습니다. 초과 시 429를 반환합니다.

## 자주 쓰는 레시피

### 모든 멤버 조회 (페이지)

```python
import os, requests

API = "https://api.anthropic.com/v1/organizations/users"
H = {"anthropic-version": "2023-06-01", "x-api-key": os.environ["ANTHROPIC_ADMIN_KEY"]}

after = None
while True:
    params = {"limit": 1000}
    if after:
        params["after_id"] = after
    page = requests.get(API, headers=H, params=params).json()
    for m in page["data"]:
        print(m["email"], m["role"])
    if not page["has_more"]:
        break
    after = page["last_id"]
```

### 분기별 그룹 감사 (Enterprise)

Console을 노려보지 않고 민감 그룹에 있어서는 안 될 멤버를 찾습니다.

```python
import os, requests

H_BETA = {"x-api-key": os.environ["ANTHROPIC_ADMIN_KEY"],
          "anthropic-beta": "ce-user-management-2026-07-13"}

groups = requests.get("https://api.anthropic.com/v1/organizations/rbac_groups?limit=1000",
                     headers=H_BETA).json()["data"]

for g in groups:
    if "prod" not in g["name"].lower():
        continue
    members = requests.get(
        f"https://api.anthropic.com/v1/organizations/rbac_groups/{g['id']}/members?limit=1000",
        headers=H_BETA).json()["data"]
    print(f"{g['name']} ({len(members)} members)")
    for m in members:
        print(f"  {m['email']}")
```

해당 출력을 IdP 로스터와 비교하고 오래된 사람을 `DELETE /rbac_groups/{group_id}/members/{user_id}`로 제거하세요. SCIM 프로비저닝된 그룹(`source_type: "scim"`)은 수정 시 400을 반환합니다 — IdP에서 하세요.

## SSO + Admin API

ID 공급자가 특정 영역을 담당하면 API는 그것에 위임합니다:

| IdP가 하는 일 | 차단되는 API 작업 | HTTP |
|---|---|---|
| JIT 또는 SCIM 사용자 프로비저닝 | 초대 생성 | 400 |
| Advanced SSO / SCIM 역할 프로비저닝 | 멤버 역할 업데이트 | 400 |
| SCIM 멤버십 프로비저닝 | 조직에서 멤버 제거 | 400 |
| SCIM 그룹 프로비저닝 (`source_type: "scim"`) | 그룹 이름 변경, 그룹 삭제, 그룹 멤버 추가/제거 | 400 |

읽기는 항상 작동합니다. 이는 설계상 그렇습니다: IdP가 소유하는 영역의 진실의 원천이며, Admin API는 스크립트가 조용히 IdP에서 벗어나는 것을 거부합니다.

## 시트, 초대, 그리고 한 번은 부딪히는 400

유한 시트 풀이 있는 플랜에서:

- **대기 중 초대는 시트를 소비합니다.** 취소하거나 만료되게 두어 시트를 반환하세요.
- 초대 생성은 **티어 파라미터를 받지 않습니다.** 서버가 사용 가능한 가장 낮은 티어를 고릅니다.
- 여유 시트가 없으면 초대 생성은 **400**을 반환합니다 — 구매가 아닙니다. 플랜 설정에서 시트를 사고 재시도하세요.
- 초대는 **21일** 후 만료되며 연장 방법이 없습니다. 대기 중 초대의 이메일이나 역할을 변경하려면 취소 후 재생성하세요.

## Admin API vs Compliance API vs Inference Hooks

세 가지 거버넌스 표면, 자주 혼동됩니다:

- **Admin API**(이 페이지)는 **누가 조직에 있고** **무엇을 할 수 있는지** 관리합니다.
- **[Compliance API](https://platform.claude.com/docs/en/manage-claude/compliance-api)**는 **그들이 무엇을 했는지** 노출합니다: 감사 이벤트, 활동 피드, (Enterprise의 경우) 법적 보류를 위한 콘텐츠 검색과 삭제.
- **[Inference Hooks](/docs/api/inference-hooks)** — 셋 중 가장 새로운 것(2026년 8월 5일 베타) — 은 DLP 서버가 채팅, Claude Code, Cowork 전반에서 Claude가 보기 전에 **각 프롬프트를 실시간으로** 허용 또는 거부하게 합니다.

보안 도구용으로, `read:org_audit`를 가진 단일 키가 두 API 측 읽기를 커버합니다. Inference Hooks는 admin 콘솔의 별도 구성입니다.
