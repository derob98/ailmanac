프로젝트 기능과 한도는 요금제에 따라 다르고 변경됩니다 — 현재 동작은 앱이나 헬프센터에서 확인하세요. **새로 설계된 프로젝트**(병렬 스레드에 작업을 위임하는 코디네이터)가 2026년 9월 17일 Claude Code에서 베타로 들어갔고, 이후 Claude의 나머지 영역과 Team/Enterprise 요금제로 확대될 예정입니다. 이 페이지는 대부분의 계정이 여전히 사용하는 지식 베이스형 프로젝트를 설명합니다.
</VerifyNote>

**프로젝트**는 Claude.ai의 전용 워크스페이스로, **자체 파일, 지식, 지침**을 하나로 묶습니다. 채팅마다 같은 문서를 다시 업로드하고 맥락을 다시 설명하는 대신, 한 번만 설정해두면 — 프로젝트 안의 모든 대화가 이미 정보를 아는 상태로 시작합니다.

## 프로젝트를 쓰는 이유

- **근거 있는 답.** 문서(핸드북, 스펙, 메모)를 추가하면 Claude가 *그것들로부터* 답합니다 — 코드 없이 내장된 형태의 [RAG](/docs/foundations/rag)입니다.
- **지속되는 맥락.** 프로젝트 지침은 그 안의 모든 것에 적용되는 범위 한정 [시스템 프롬프트](/docs/foundations/roles)처럼 작동합니다.
- **정리됨.** 하나의 주제/고객/이니셔티브에 관한 모든 채팅이 한곳에 모여 있습니다.

## 좋은 활용 사례

- **고객/어카운트** 워크스페이스 (고객 문서 + 내 메모).
- Q&A용 **코드베이스 또는 제품** 지식 베이스.
- 스타일 가이드와 과거 원고를 담은 **글쓰기 프로젝트** (초안이 내 목소리에 맞도록).
- 강의계획서와 자료를 올려둔 강좌 **학습**용.

## 프로젝트 지침의 출발점

<PromptCard title="프로젝트 지침 골격">{`You are helping with [project/client name].

- Answer from the project knowledge first; say so when you are going beyond it.
- Use [our terminology: list the 3-5 terms that matter].
- Match the tone in [named file in the knowledge base].

Never:
- Invent figures, dates, or quotes. If it is not in the knowledge, say it is not in the knowledge.
- [Project-specific constraint: e.g. reference the deprecated v1 API.]`}</PromptCard>

## 팁

- **지식을 큐레이션하세요** — 관련성 있고 최신인 파일이 전부 쏟아붓는 것보다 낫습니다 (노이즈는 검색을 해칩니다).
- **지침은 간결하고 사실에 맞게 유지하세요** ([커스텀 지침](/docs/claude-app/custom-instructions)과 같은 규칙입니다).
- **상황이 바뀌면 정리하세요.** 대체된 스펙을 지식 베이스에 남겨두는 것은 스펙이 없는 것보다 나쁩니다. Claude에게는 그것이 새 스펙과의 논쟁에서 졌다는 것을 알 방법이 없기 때문입니다.
- **저장하기 꺼림칙한 민감 데이터는 추가하지 마세요** — [프라이버시](/docs/foundations/privacy)를 참고하세요.

## "프로젝트"라고 불리는 두 가지

둘은 진짜로 다른 제품이고, 롤아웃 기간 동안 이름이 겹칩니다:

| | 이 프로젝트 (Claude.ai) | [Claude Code 프로젝트](/docs/claude-code/projects-coordinator-threads) |
|---|---|---|
| 무엇인가 | 지식 + 지침을 갖춘 워크스페이스 | 병렬 스레드에 위임하는 코디네이터 |
| 무엇을 하는가 | *내* 채팅을 *내* 파일에 근거시킴 | 작업을 범위 지정하고, 쪼개고, 실행해줌 |
| 코드를 실행하나? | 아니요 | 예 — 각 스레드가 자체 브랜치의 클라우드 세션 |
| 누가 쓸 수 있나 | 널리 제공됨 | 베타, 출시 시점에는 선별된 Pro/Max Claude Code 사용자 |

코디네이터, 스레드, 풀 리퀘스트에 관한 글을 읽고 있다면, 그것은 Claude Code 쪽입니다.
