## 큰 아이디어

모든 세션에는 유한한 [컨텍스트 윈도우](/docs/foundations/tokens-and-context)가 있습니다. 윈도우가 차오르면 오래된 내용이 압축되고, Claude가 "흐트러지기" 시작할 수 있습니다. 컨텍스트를 의도적으로 관리하는 것이 긴 세션을 예리하게 유지하는 비결입니다.

## 두 가지 필수 명령

두 가지 명령으로 거의 모든 상황을 다룰 수 있습니다. 요령은 의도에 맞는 명령을 고르는 것입니다.

<Flashcards cards={[{front: "/clear", back: "대화를 지우고 새로 시작합니다. 관련 없는 작업으로 전환할 때 사용하세요. 깨끗하고 집중된 컨텍스트를 되찾는 가장 저렴한 방법입니다. 별칭: /reset, /new."}, {front: "/compact", back: "지금까지의 대화를 압축된 형태로 요약합니다 — 핵심은 유지하면서 공간을 확보합니다. 같은 작업을 계속하고 싶지만 윈도우가 차오를 때 사용하세요. 선택적으로 포커스 지시를 받을 수 있습니다."}]} />

질문 하나로 결정하세요: 새 작업인가, 같은 작업인가?

```mermaid
flowchart TD
  A{New task or same task?} -->|New / unrelated| B[/clear]
  A -->|Same task, context full| C[/compact]
```

놓치기 쉬운 두 가지 세부 사항:

- **`/compact`는 지시를 받을 수 있습니다.** `/compact focus on the auth bug fix`는 자동 처리가 중요하다고 추측한 내용이 아니라 *당신이* 고른 내용을 남깁니다. 윈도우가 강제로 압축하길 기다리지 말고, 긴 새 작업을 시작하기 전에 의도적으로 실행하세요.
- **`/clear`는 되돌릴 수 없는 지점이 아닙니다.** 이름을 전달하면(`/clear auth refactor`) `/resume` 선택기에서 나가는 대화에 라벨이 붙고, 같은 Claude Code 프로세스 안에서는 되감기 메뉴에 `/resume <session-id> (previous session)` 항목이 계속 표시됩니다 — [체크포인트와 되감기](/docs/claude-code/checkpoints-and-rewind)를 참고하세요.

## 자동 압축 — 그리고 임계값 옮기기

컨텍스트가 한계에 가까워지면 Claude Code는 작업이 갑자기 멈추지 않도록 **자동으로 압축**합니다. 1M 컨텍스트 윈도우 모델에서는 기본적으로 약 967K 토큰에서 발동하고, 이전 모델은 컨텍스트 윈도우의 경계에서 압축합니다. 방치해 둔 대화를 Claude Code가 압축하기도 합니다.

임계값은 직접 옮길 수 있습니다. `/autocompact 500k`는 더 일찍 압축합니다 — 96%가 찼을 때가 아니라 원하는 시점에 요약하고 싶을 때 유용하며, `/autocompact auto`는 모델에 맞게 조정된 윈도우로 되돌립니다.

## 압축 후 살아남는 것

압축은 *대화*를 요약합니다. 설정이 디스크에서 불러오는 모든 것은 별도로 처리됩니다 — 그래서 압축된 세션도 프로젝트 규칙을 계속 알고 있습니다.

:::tip[증상 → 해결]
Claude가 앞선 지시를 잊거나 같은 말을 반복하기 시작하면 윈도우가 가득 찼을 가능성이 높습니다. `/compact`(같은 작업) 또는 `/clear`(새 작업)로 보통 즉시 해결됩니다. `/context`를 실행해 확인하세요 — 대화가 실제로 윈도우를 초과했다면 출력에 얼마나 넘었는지와 어떤 명령으로 공간을 확보할 수 있는지가 표시됩니다. 자세한 내용은 [Claude는 왜 그렇게 했을까?](/docs/contribute/troubleshooting)를 참고하세요.

대신 `Autocompact is thrashing`이 뜬다면, 압축은 작동하고 있지만 크기가 큰 무언가가 윈도우를 계속 다시 채우고 있는 것입니다 — [Claude Code 문제 해결](/docs/claude-code/troubleshooting)을 참고하세요.
:::
