**Model Context Protocol(MCP)** 은 AI를 외부 도구와 데이터에 연결하기 위한 개방형 표준입니다. **MCP 서버** 는 기능(데이터베이스 쿼리, GitHub PR 열기, 브라우저 조작)을 노출하고, Claude Code는 이 서버에 연결해 세션 중에 **그 도구들을 호출** 할 수 있습니다. 이렇게 Claude를 파일 시스템과 셸 너머로 확장합니다.

## 전송 방식

Claude가 서버에 도달하는 방법은 네 가지입니다. 서버가 어디에서 실행되고 어떻게 통신하는지에 따라 고릅니다.

- **stdio** — Claude가 실행하는 로컬 프로세스(로컬 도구/CLI에 적합). `type`이 없는 JSON 항목이 바로 이것을 뜻합니다.
- **HTTP** — 호스팅형 서버로, 주로 OAuth를 사용합니다. 원격이라면 기본 선택입니다.
- **SSE** — **지원 중단**. 가능하면 HTTP를 쓰세요. 일부 서비스는 아직 SSE 엔드포인트만 제공하는데, Claude Code v2.1.265부터 `--transport http`가 먼저 HTTP를 시도하고 스스로 SSE로 전환하므로 `--transport sse`를 명시할 일은 거의 없습니다.
- **WebSocket**(`ws` / `wss`) — 서버가 요청 없이 이벤트를 푸시해야 할 때 쓰는 지속적인 양방향 연결입니다. `--transport`는 `ws`를 *받지 않습니다*: `claude mcp add-json '{"type":"ws","url":"wss://…"}'`로 추가하거나 `.mcp.json`에 직접 작성하세요. OAuth는 없으며 인증은 헤더만 가능합니다.

<Callout type="warning" items={["url은 있는데 type이 없는 JSON 항목은 합리적인 기본값이 아니라 구성 오류입니다: Claude Code는 type이 없는 항목을 stdio 서버로 읽고 건너뛰며, \"url\"은 있는데 \"type\"이 없다고 보고합니다. 직접 작성하는 원격 서버에는 항상 \"type\": \"http\"(또는 \"sse\" / \"ws\")를 지정하세요."]} />

## 서버 구성하기

가장 빠른 방법은 `claude mcp add` 명령입니다 — 구성을 대신 작성해 줍니다. 이 순서를 따르면 처음부터 연결된 서버까지 갈 수 있습니다.

<Steps items={[{title: "로컬 stdio 서버 추가", body: "claude mcp add를 실행하세요 — -- 뒤의 모든 것은 Claude가 대신 실행하는 실행 명령입니다."}, {title: "또는 원격 HTTP 서버 추가", body: "--transport http와 스코프를 지정한 다음 서버 URL을 넣으세요. 원격 서버는 대개 호스팅형이며 OAuth를 사용합니다."}, {title: "연결된 서버 확인", body: "claude mcp list를 실행해 구성된 서버와 연결 상태를 확인하세요."}, {title: "검사 및 인증", body: "세션 안에서 /mcp를 사용해 서버의 도구를 검사하고 원격 서버를 인증하세요."}]} />

<PromptCard title="로컬 stdio 서버 추가">{`# A local stdio server (everything after -- is the launch command)
claude mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem ~/code/myproject`}</PromptCard>

<PromptCard title="원격 HTTP 서버 추가 (프로젝트와 공유)">{`# A remote HTTP server, shared with everyone on the project
claude mcp add --transport http --scope project github https://api.githubcopilot.com/mcp/`}</PromptCard>

내부적으로는 그냥 JSON입니다. **project** 스코프 서버는 저장소 루트의 `.mcp.json`에 기록됩니다 — 이 파일을 커밋하면 팀원이 작업 공간을 신뢰하는 즉시 같은 도구를 쓸 수 있습니다:

```json
{
  "mcpServers": {
    "github": { "type": "http", "url": "https://api.githubcopilot.com/mcp/" }
  }
}
```

<Callout type="warning" items={["오래된 튜토리얼에 나오는 @modelcontextprotocol/server-github, -postgres, -slack, -puppeteer 패키지는 쓰지 마세요. 이들은 보관(archived)되었고, npm에는 \"Archived and unmaintained; no security guarantees\"라는 지원 중단 안내가 붙어 있습니다. 공급업체가 직접 제공하는 서버가 있다면 그것을 쓰세요 — GitHub의 서버는 위의 HTTP 엔드포인트이고, 브라우저 제어는 @playwright/mcp로 옮겨 갔습니다. TypeScript 참조 서버 중 아직 유지보수되는 것은 filesystem, memory, everything, sequential-thinking뿐입니다."]} />

### 스코프가 서버를 누가 볼지 결정한다

| 스코프 | 저장 위치 | 로드되는 곳 | 용도 |
|---|---|---|---|
| `local` (기본값) | `~/.claude.json`, 이 프로젝트 경로 아래 | 이 프로젝트에서만 | 개인 실험, 비밀 정보 |
| `project` | 저장소의 `.mcp.json` (커밋됨) | 이 프로젝트에서만, 팀과 공유 | 팀 전체가 공유해야 하는 도구 |
| `user` | `~/.claude.json` | 내 모든 프로젝트 | 어디서나 쓰고 싶은 서버 |

<Callout type="warning" items={["MCP의 \"local 스코프\"는 로컬 설정과 같은 것이 아닙니다. local 스코프 MCP 서버는 홈 디렉터리의 ~/.claude.json에 저장되며, 프로젝트의 .claude/settings.local.json에는 저장되지 않습니다. 프로젝트 폴더에서 찾으면 헛수고입니다."]} />

연결된 서버는 `claude mcp list`로, 도구 검사와 원격 서버 인증은 세션 안의 `/mcp`로 확인하세요. 복사해서 붙여 넣을 수 있는 출발점은 [MCP 구성 및 서버 스캐폴드](/docs/templates/mcp-config)를 참고하세요.

## 실전 예제: Claude에게 데이터베이스 주기

쿼리 결과를 직접 붙여 넣는 대신 Claude가 로컬 Postgres에 대한 질문에 답하게 하고 싶다고 해 봅시다. 팀원도 쓸 수 있도록 project 스코프로 서버를 추가합니다.

보관된 서버 문제가 가장 크게 와닿는 곳이 데이터베이스입니다. 예전의 `@modelcontextprotocol/server-postgres`는 유지보수되지 않고 공식 대체품도 없으므로, 패키지 이름이 직접 내려야 하는 유일한 결정입니다. 유지보수되는 커뮤니티 서버를 고르고, [검토한](/docs/security/reviewing-third-party-code) 다음 연결하세요 — 무엇을 고르든 형태는 같습니다:

<PromptCard title="Postgres 서버를 project 스코프로 추가">{`# Replace the package with a maintained Postgres MCP server you have reviewed.
# The connection string is read-only on purpose — see below.
claude mcp add --scope project db -- npx -y <postgres-mcp-server> "postgresql://readonly@localhost/app"`}</PromptCard>

이제 세션에서 평범한 말로 질문하면 Claude가 쿼리 반복을 대신 처리해 줍니다:

<PromptCard title="데이터베이스에 질문하기">{`How many users signed up last week? Check the DB.`}</PromptCard>

Claude는 서버가 게시한 쿼리 도구를 호출해 행을 받아 와 답합니다 — 복사·붙여넣기 반복이 필요 없습니다. Claude가 정말 써야 하는 경우가 아니라면 연결 문자열은 읽기 전용으로 유지하세요. 쿼리 한 번이면 충분했다면, Bash를 통한 `psql -c '…'`가 토큰을 훨씬 적게 쓴다는 점도 기억하세요. 어느 쪽이 유리한지는 [MCP 토큰 세금](/docs/claude-code/mcp-token-cost)에서 다룹니다.

project 스코프이므로 저장소를 pull한 팀원도 같은 기능을 얻습니다 — 하지만 **조용히, 즉시 되는 것은 아닙니다**. 커밋된 `.mcp.json`의 서버는 팀원이 해당 폴더에서 `claude`를 실행해 작업 공간 신뢰 대화상자를 수락할 때까지 `⏸ Pending approval` 상태로 남습니다. 복제된 저장소는 자기 서버를 미리 승인할 수 없습니다: 프로젝트의 `.claude/settings.json`에 커밋된 `enableAllProjectMcpServers`나 `enabledMcpjsonServers`는 신뢰할 수 없는 폴더에서 *무시됩니다*. 사용자 수준의 `~/.claude/settings.json`, 관리형 설정, 또는 `--settings`로 전달한 승인은 거기서도 적용됩니다. "왜 팀원에게 서버가 안 보이지?"라는 질문의 흔한 답이 이것입니다.

## 앱에서도 MCP

MCP는 Claude 앱의 **커넥터** 도 구동합니다 — 같은 표준, 다른 화면입니다. [앱의 커넥터(MCP)](/docs/claude-app/connectors)와, API에 대해서는 [MCP 및 도구 연결](/docs/api/mcp)을 참고하세요.

## 흔한 실수

- **잘못된 스코프.** `local` 스코프로 추가한 서버는 팀원에게 보이지 않습니다. 나만 쓰려던 서버는 `project` 스코프로 커밋하면 안 됩니다. 의도를 갖고 고르세요.
- **서버가 너무 많고 도구가 너무 많음.** 도구 검색은 기본으로 켜져 있어서, 연결된 서버는 보통 전체 스키마가 아니라 도구 *이름* 과 서버 지침만 매 턴 비용으로 듭니다 — 하지만 이것도 턴마다 내는 세금이고, Claude가 스키마를 검색하는 순간 스키마가 컨텍스트에 들어옵니다. 카탈로그 전체가 아니라 작업에 필요한 것만 연결하세요. 실제 수치, `ENABLE_TOOL_SEARCH` 모드, 코드 실행이 두 번째 비용을 줄이는 방법은 [MCP 토큰 세금](/docs/claude-code/mcp-token-cost)을 참고하세요.
- **과도한 권한의 연결.** Claude가 정말 써야 하는 경우가 아니라면 데이터베이스 서버에는 읽기 전용 역할을 주세요. MCP는 기능을 현실로 만듭니다 — 범위를 좁히세요.
- **인젝션 위험 간과.** 서버가 반환하는 모든 것(웹 페이지, 이슈 본문, 행)은 [프롬프트 인젝션](/docs/security/prompt-injection)이 담길 수 있는 신뢰할 수 없는 텍스트입니다. 강력한 쓰기 가능 서버를 신뢰할 수 없는 읽기 가능 서버 옆에 충분한 고민 없이 연결하지 마세요.
