위치, 로드 순서, 임포트 문법은 공식 메모리 문서(How Claude remembers your project)에서 가져왔으며, 그 문서는 이제 **두 가지** 메커니즘을 설명합니다: 여러분이 작성하는 CLAUDE.md 파일과 Claude가 스스로 작성하는 **자동 메모리**. 임포트는 최대 네 홉 깊이까지 해석됩니다. 세부는 거기서 확인하세요 — 이런 내용은 변합니다.
</VerifyNote>

[Claude Code](/docs/claude-code/what-is-claude-code)를 더 좋게 만들려고 **한 가지**만 한다면, 이것을 하세요. `CLAUDE.md`는 Claude가 매 세션 시작에 읽는 평문 파일 — 프로젝트의 영구 브리핑입니다.

## 왜 가장 레버리지가 큰 설정인가

이것이 없으면 매 세션마다 프로젝트를 다시 설명하게 됩니다("우리는 pnpm을 쓰고, 테스트는 `__tests__`에 있고, `/generated`는 건드리지 말고…"). 이것이 있으면 Claude가 이미 압니다. 여기 좋은 지침은 *모든* 미래 상호작용을 한 번에 개선합니다.

## 메모리 계층

Claude Code는 여러 위치에서 메모리를 읽어 로드 순서대로 병합하며, 범위가 넓은 것이 먼저입니다 — 그래서 프로젝트 지침은 사용자 지침 *다음에* 컨텍스트로 들어갑니다:

```mermaid
flowchart TD
  A["Managed policy<br/>/etc/claude-code/CLAUDE.md (org-wide, IT-managed)"] --> B["User instructions<br/>~/.claude/CLAUDE.md (all your projects)"]
  B --> C["Project instructions<br/>./CLAUDE.md or ./.claude/CLAUDE.md (committed)"]
  C --> D["Local instructions<br/>./CLAUDE.local.md (yours only — gitignore it)"]
```

- **관리형 정책** — IT/DevOps 팀이 배포하는 조직 전체 지침. 경로는 OS별로 다릅니다: macOS에서는 `/Library/Application Support/ClaudeCode/CLAUDE.md`, Linux와 WSL에서는 `/etc/claude-code/CLAUDE.md`, Windows에서는 `C:\Program Files\ClaudeCode\CLAUDE.md`.
- **사용자 지침** (`~/.claude/CLAUDE.md`) — 모든 프로젝트에 걸친 개인 선호.
- **프로젝트 지침** (`./CLAUDE.md` *또는* `./.claude/CLAUDE.md`, 커밋됨) — *이* 저장소가 어떻게 작동하는지. 팀과 공유됩니다. 저장소가 [`AGENTS.md`](/docs/claude-code/agents-md)를 쓴다면, 이 파일들 대신 또는 함께 로드될 수 있습니다.
- **로컬 지침** (`./CLAUDE.local.md`) — 샌드박스 URL처럼 나만을 위한 프로젝트별 메모. `.gitignore`에 추가하세요.

작업 디렉터리 *위쪽* 디렉터리 계층에 있는 파일은 실행 시점에 로드됩니다; **하위 디렉터리의 파일은 필요할 때 로드**되며, Claude가 그 영역의 무언가를 건드리는 순간입니다.

## 나머지 절반: 자동 메모리

CLAUDE.md는 *여러분이* 작성하는 메모리의 절반입니다. Claude Code는 **자동 메모리**도 유지합니다 — 여러분의 수정과 선호를 보고 Claude가 스스로 작성하는 메모로, 저장소별로 저장되며 여러분의 CLAUDE.md 파일들과 함께 매 세션에 로드됩니다.

| | CLAUDE.md 파일 | 자동 메모리 |
| --- | --- | --- |
| **누가 쓰는가** | 여러분 | Claude |
| **무엇을 담는가** | 지침과 규칙 | 학습과 패턴 |
| **범위** | 프로젝트, 사용자, 또는 조직 | 저장소별, 워크트리 간 공유 |

둘 다 강제가 아니라 *컨텍스트*입니다: Claude는 이것을 반드시 따라야 하는 설정이 아니라, 저울질할 수 있는 안내로 취급합니다. Claude의 판단과 무관하게 어떤 동작을 하드 차단하려면 대신 [PreToolUse 훅](/docs/claude-code/hooks)을 쓰세요.

## 무엇을 넣을까

- 프로젝트가 무엇인지, 두 문장으로.
- 기술 스택과 **실행 / 테스트 / 린트** 방법.
- Claude가 추론할 수 없는 관례(명명, 구조, 커밋 스타일).
- **가드레일**: "완료 선언 전 테스트 실행", "`/vendor` 절대 편집 금지", "비밀 절대 커밋 금지".

## 임포트

문서를 복제하는 대신 기존 문서를 끌어오세요 — 예를 들어 `@path/to/file` 임포트로 스타일 가이드를 참조해 단일 진실 소스를 유지하세요. 상대 경로와 절대 경로 모두 작동하며, 상대 경로는 작업 디렉터리가 **아니라** 임포트를 담은 파일을 기준으로 해석됩니다. 임포트된 파일은 다른 파일을 또 임포트할 수 있고, 최대 깊이는 **네 홉**입니다.

물리기 전에 알아둘 만한 문법 함정 두 가지:

- **공백에는 백슬래시가 필요합니다.** `@Design\ Docs/api-conventions.md`는 작동합니다; 백슬래시가 없으면 경로는 첫 공백에서 끊깁니다. 따옴표로 감싸면 파일이 아예 임포트되지 않습니다.
- **백틱은 제외시킵니다.** 임포트 파싱은 코드 스팬과 펜스 블록을 건너뛰므로, `` `@README` ``는 문자 그대로의 텍스트로 남고 `@README` 단독으로 쓰면 파일을 임포트합니다. 경로를 로드하지 않고 *언급*하는 방법이 바로 이것입니다.

전체 레퍼런스는 [공식 메모리 문서](https://code.claude.com/docs/en/memory)를 참고하세요.
