**2026년 8월 3일**, MiniMax는 **MiniMax-H3**(소비자 명칭: **Hailuo 3.0**)의 가중치를 Hugging Face에 공개했습니다. 이는 **330억 파라미터의 단일 스트림 트랜스포머**로, 텍스트, 이미지, 비디오, 오디오 레퍼런스를 **최대 2K/24fps의 4~15초 클립과 네이티브 스테레오 오디오**로 변환하며, 이 모든 것을 한 번의 패스로 생성합니다. 마지막 부분이 흥미로운데, 별도의 TTS 단계도, 덧붙인 SFX 파이프라인도 없습니다. 대사, 룸 톤, 화면이 같은 모델에서 함께 나옵니다.

3일 앞서 유료 API는 2K 기준 **초당 $0.1625**(분당 약 $9.75)에 오픈되었는데, 이는 유사한 해상도에서 **Kling 3.0이나 Seedance 2.0의 약 절반 가격**입니다. Artificial Analysis 리더보드의 단일 실행 점수에서 H3는 **오디오 포함 비디오 편집 부문 1위**, 텍스트-투-비디오 및 이미지-투-비디오에서 상위 3위를 기록했습니다. 프론티어 수준의 비디오 품질, 오픈 웨이트, 분당 $10 미만의 정직한 가격이라는 이 조합이 이번 주 모든 생성형 미디어 피드에 H3를 올린 이유입니다.

이 페이지는 다른 대부분의 글이 놓치는 부분을 다룹니다. H3가 실제로 *당신에게* 유용한지를 결정하는 요소들 말입니다.

## 헤드라인에서 명확하지 않은 H3에 관한 세 가지

### 1. Community License는 미국, EU, 영국, 한국에서의 셀프 호스팅을 차단합니다

Hugging Face 모델 카드는 **MiniMax H3 Community License Agreement**를 링크하는데, 그 텍스트는 네 지역에 대해 신청 게이트가 있습니다: **미국, 유럽 연합, 영국, 대한민국**. 실제로 이는 다음을 의미합니다: 당신이나 조직이 이러한 지역 중 하나에 있고 자체 하드웨어에서 H3를 실행하려는 경우(또는 사용자에게 서비스하려는 경우) 먼저 `platform.minimax.io/h3-license`에서 H3 라이선스 신청을 완료해야 합니다. 이 제한은 가중치뿐만 아니라 **출력물**에도 적용되며, 이는 대부분의 재게시 글이 놓치는 세부 사항입니다.

이러한 지역 외부에 있다면 표준 Community License가 적용됩니다. 이러한 지역에 있다면 신청이 승인될 때까지 API를 기본 경로로 취급하거나, 가중치를 다루는 것을 배포하기 전에 조직의 라이선스 검토자를 사용하세요. 이는 실제로 집행 가능한 제한이며, 흔한 "나쁜 일 하지 마세요" 조항이 아닙니다.

### 2. 오픈 베이스의 상한은 768p입니다 — 2K는 API 내부에만 존재합니다

H3에 대한 "최대 2K" 헤드라인은 모두 핵심 세부 사항을 생략합니다: 오픈 웨이트 베이스 모델(텍스트-투-비디오/첫-마지막-프레임용 `Base FL2VA`, 멀티 레퍼런스용 `Base Ref2VA`)은 **768p**에서 생성합니다. Hailuo 앱에서 사람들이 감탄하는 2K 출력은 **H3-Regenerate-2K**에서 나오는데, 이는 베이스 모델 *이후*에 실행되는 인컨텍스트 업샘플러이며 MiniMax는 이를 오픈소스로 공개하지 **않았습니다**. 멀티모달 명령 전처리기인 `H3-Context-IR`도 API 전용입니다.

셀프 호스터에게 결과는 간단합니다: 프론티어 시스템이 구축된 것과 동일한 생성 품질을 얻지만, 사후에 자체 업스케일러(Topaz, ESRGAN, 디퓨전 업샘플러)를 체인하지 않으면 **768p가 상한입니다**. 많은 사용 사례에서는 이것으로 충분합니다. 24fps의 768p는 소셜 클립, 스토리보드, 빠른 반복에 충분합니다. 하지만 유료 티어와 동일한 제품은 아닙니다.

### 3. 33B 파라미터 중 약 13B는 미리 계산하고 건너뛸 수 있는 AdaLN 브랜치입니다

모델 카드는 H3-Omni-Transformer를 **33B 밀집** 단일 스트림 트랜스포머로 분해하는데, 그 중 **약 13B 파라미터가 AdaLN 관련 브랜치에 있습니다**. AdaLN(Adaptive Layer Norm)은 디퓨전 스타일 트랜스포머가 조건화 신호(타임스텝, 클래스, 텍스트 임베딩)를 흡수하는 방식이며, 그 출력은 조건화 슬롯별로 **미리 계산 가능합니다**. 이것이 서드파티 제공업체가 순진한 BF16 가중치가 훨씬 더 크더라도 **최소 42.5 GB의 작동 구성**에 도달하는 방법입니다: 프루닝된 INT8 체크포인트(~20 GB)를 NVFP4 AWQ 텍스트 인코더(~16 GB) 및 두 VAE(~5.8 GB)와 결합하고, 추론 시 캐시된 브랜치 가중치를 건너뜁니다.

ComfyUI 생태계의 경험 법칙: **12 GB 카드는 CPU/RAM 오프로딩으로 H3를 실행할 수 있습니다**. 단, 클립당 렌더링 시간이 길어집니다. 24 GB 이상이 있다면 오프로드가 필요하지 않습니다.

## H3가 실제로 무엇인가 (아키텍처를 한 페이지에)

H3는 **단일 스트림, 모달리티 무관 트랜스포머**입니다. 하나의 어텐션 스택, 하나의 FFN 스택이 있으며, 비디오/오디오/텍스트 토큰이 모두 이를 통과합니다. 실제로 로드하는 네 가지 구성 요소는 다음과 같습니다:

| 구성 요소 | 역할 | 오픈소스? |
|---|---|---|
| **H3-Omni-Transformer** | 33B 밀집 생성기 (비디오 + 오디오) | ✅ (BF16, INT8, 프루닝 INT8) |
| **H3-Encoder** | 멀티모달 텍스트/비전 인코더 — **Qwen3-VL-32B** 레이어-50 히든 상태 재사용 | ✅ |
| **H3-VisualVAE** | 시간-인과 비디오 오토인코더, **f16t4d24** 압축 | ✅ |
| **H3-AudioVAE** | 스테레오 오디오, **32 kHz** 출력, 40 Hz 시간 속도 | ✅ |
| **H3-Context-IR** | 멀티모달 명령 전처리기 | ❌ API 전용 |
| **H3-Regenerate-2K** | 2K로 인컨텍스트 업스케일러 | ❌ API 전용 |

H3를 다른 비디오 모델과 비교하는 사람이라면 주목할 만한 두 가지 설계 선택이 있습니다:

- **3D MM-RoPE 위치 임베딩.** 로터리 위치가 세 축(공간 x, 공간 y, 시간)으로 확장되어, 시간적 일관성이 별도의 시간 모듈로 추가되는 것이 아니라 어텐션 패턴에 내장됩니다. 이것이 H3가 15초 클립 전반에 걸쳐 피사체 정체성과 조명을 안정적으로 유지하는 주요 이유 중 하나입니다.
- **H3-VAE는 유효 시퀀스 길이에서 4배 이득을 제공합니다.** 커스텀 토크나이저는 이전 오픈 비디오 모델에서 사용된 표준 VAE보다 토큰당 더 많은 픽셀을 패킹합니다. 이것이 이 파라미터 클래스에서 2K 출력을 가능하게 만드는 이유입니다.

**네이티브 오디오 패스**는 다른 차별화 요소입니다. 대사, SFX, 룸 톤이 화면과 동일한 순전파에서 생성되기 때문에 립싱크와 다이제틱 오디오가 기본적으로 일관되게 나옵니다. 레퍼런스 오디오(WAV/MP3, 클립당 2~15초, 최대 3개 클립)로 음성 복제가 가능합니다. 단, 오디오 레퍼런스는 **이미지 또는 비디오 레퍼런스와 함께 제공되어야 합니다**. API는 오디오 전용 입력을 거부합니다.

## 셀프 호스팅 수학

H3를 로컬에서 실행할 계획이라면 다음 숫자가 무엇이 맞는지 결정합니다:

| 체크포인트 | 디퓨전 모델 | 텍스트 인코더 | 두 VAE | 최소 작동 총합 |

## API를 통한 H3 호출

API는 REST + 폴링입니다. 작업을 POST하고, `task_id`를 받고, `status == "succeeded"`가 될 때까지 쿼리 엔드포인트를 폴링합니다. 공개 URL만 작동합니다. Base64 페이로드는 거부되며, 총 요청 본문은 **64 MB**로 제한됩니다. 레퍼런스 제한: **최대 9개 이미지, 최대 3개 비디오 클립, 최대 3개 오디오 클립, 총 12개 파일, 최대 7,000자 프롬프트**.

    ],
    "resolution": "2K",   # 2K is the only value the API accepts right now
    "duration": 8,        # seconds, 4–15
    "ratio": "16:9",
}

task_id = requests.post(
    "https://api.minimax.io/v2/video_generation",
    headers=headers, json=payload,
).json()["task_id"]

while True:
    time.sleep(10)
    task = requests.get(
        f"https://api.minimax.io/v2/query/video_generation/{task_id}",
        headers=headers,
    ).json()["task"]
    if task["status"] == "succeeded":
        print(task["video_url"])
        break
    if task["status"] == "failed":
        raise RuntimeError(task)`}

## H3 vs 클로즈드 비디오 API — 각각 언제 이기는가

| | **MiniMax H3** | **Kling 3.0** | **Dreamina Seedance 2.0** | **Sora / Veo (프론티어 클로즈드)** |
|---|---|---|---|---|
| 최대 해상도 (API) | 2K/24fps | 1080p | 1080p | 1080p~4K (변형) |
| 네이티브 오디오 | ✅ 대사 + SFX + 룸 톤 | 별도 단계 | 별도 단계 | ✅ (Sora 2), ✅ (Veo) |
| 오픈 웨이트 | ✅ (Community, 지역 제한) | ❌ | ❌ | ❌ |
| 분당 비용 (비교 가능한 티어) | **~$9.75** (2K + 오디오) | ~$20 (1080p) | ~$22 (1080p) | 더 높고 요율 제한 |
| 레퍼런스 제어 | 최대 9개 이미지, 최대 3개 비디오, 최대 3개 오디오 | 유사 | 더 적은 슬롯 | 더 적은 슬롯 |
| 최적 용도 | 최저 $/분에 최고 충실도 출력; 제한 지역 외부라면 온프레미스/셀프 호스팅 | 긴 샷 전반의 스타일 안정성 | 시네마틱 룩, 프롬프트 충실도 | 중국 벤더에 프롬프트를 유출할 수 없고 프론티어 완성도가 필요할 때 |

**다음의 경우 H3를 선택하세요:** 2K에서 프레임 내 오디오가 필요할 때, 분당 비용이 중요하고 클로즈드 API가 예산을 초과할 때, 컴플라이언스로 인해 생성을 온프레미스로 유지해야 *하고* 법적 상황이 Community License를 통과할 때. **다음의 경우 H3를 건너뛰세요:** 팀이 제한된 지역 중 하나에 있고 신청을 통과하지 못했을 때, 워크플로가 네이티브 4K에 의존할 때, 프롬프트를 중국 본토 API로 보낼 수 없을 때(유료 티어는 MiniMax에서 호스팅되며, 출시 시 미국 지역 미러가 없음).
