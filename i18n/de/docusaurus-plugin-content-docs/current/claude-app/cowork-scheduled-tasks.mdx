Verfügbarkeit, Kontingent und die genaue Connector-Abdeckung ändern sich schnell — überprüfe die Zahlen hier gegen den offiziellen Blog-Post und den Hilfe-Artikel [Schedule recurring tasks in Claude Cowork](https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-claude-cowork), bevor du dich auf eine Zahl verlässt.

Cowork ist am **7. Juli 2026** kein reiner Desktop-Arbeitsplatz mehr. Es läuft jetzt auf **Web (claude.ai)**, **iOS und Android** — und, was die meisten Berichte übergehen: Sitzungen werden auf **Anthropics Servern** ausgeführt, nicht auf deinem Rechner. Genau diese architektonische Änderung schaltet das Kern-Feature frei: **geplante Aufgaben, die mit zugeklapptem Laptop, Telefon in der Tasche und ohne irgendein Gerät online laufen**.

Diese Seite ist der praktische Feldbericht: was auf welcher Oberfläche wirklich funktioniert, wie du eine geplante Aufgabe beim ersten Mal richtig einrichtest, und die kleine Handvoll Fallstricke, die dir erst auffallen, wenn dein Montag-6-Uhr-Briefing stumm scheitert, weil es eine lokale Datei brauchte.

## Die eine Verschiebung, die zählt: Sitzungen sind auf Anthropics Server umgezogen

Vor Juli 2026 war eine Cowork-Sitzung ein Prozess innerhalb der Claude-Desktop-App auf deinem Mac oder PC. Laptop zu, Sitzung tot. App beendet, Sitzung tot. Deshalb begann die Cowork-Schleife vor Juli immer mit „Desktop öffnen, wach halten“.

Der Juli-Launch führt **Remote-Sitzungen** ein: Die Cowork-Schleife lebt in Anthropics Cloud, dein Sitzungszustand und deine Dateien bestehen gegen dein Claude-Konto fort, und jede Oberfläche (Web, Mobile, Desktop) ist nur ein Viewer + Eingabegerät für dieselbe zugrunde liegende Sitzung.

Zwei direkte Konsequenzen:

1. **Geplante Aufgaben sind möglich.** Eine wiederkehrende Aufgabe kann Montag um 06:00 Uhr aufwachen, 45 Minuten arbeiten und einen Entwurf in dein Konto legen — mit null Geräten online, weil kein Gerät in der Schleife ist.
2. **Cross-Device-Übergabe ist kostenlos.** Starte eine Aufgabe am Schreibtisch, klapp den Laptop zu und sieh dieselbe Sitzung mitten im Lauf auf dem Handy. Es gibt nichts zu synchronisieren — die Sitzung war nie auf deinem Laptop.

Der Trade-off ist die Fähigkeiten-Matrix unten: Alles, was **deinen lokalen Rechner** anfassen muss (Dateien auf der Platte, dein Browser, dein Betriebssystem), kann nur auf Desktop laufen, weil das die einzige Oberfläche ist, die einen Fuß in beiden Welten hat.

## Fähigkeiten-Matrix nach Oberfläche

| Fähigkeit | Desktop-App | Web (claude.ai) | Mobile (iOS/Android) |
| --- | --- | --- | --- |
| Cowork-Sitzungen (interaktiv) | ✓ | ✓ (Beta) | ✓ (Beta) |
| **Geplante** Cowork-Aufgaben | ✓ (erstellen + überwachen) | ✓ (erstellen + überwachen) | ✓ (überwachen + freigeben) |
| Zugriff auf lokale Dateien | ✓ | ✗ | ✗ |
| Browser-Use (lokale Browser-Automatisierung) | ✓ | ✗ | ✗ |
| Computer-Use (OS-Kontrolle) | ✓ | ✗ | ✗ |
| Live Artifacts (In-Session-Vorschau) | ✓ | ✗ | ✗ |
| Verbundene Tools (Gmail, Slack, GDrive, Kalender, Web) | ✓ | ✓ | ✓ |
| Installierte **Skills** | ✓ | ✓ | ✓ |
| **Plugins** | ✓ | ✓ | ✓ |
| Mobile Push für Freigabe-Prompts | (über verknüpftes Handy) | (über verknüpftes Handy) | ✓ (nativ) |
| Fable 5 Modell in Cowork | ✓ (nur neueste Desktop) | siehe Fallstricke | siehe Fallstricke |

:::info Die Faustregel
Wenn die Aufgabe nur **verbundene Tools + Skills + Web** braucht (E-Mail-Triage, „lies diese drei Docs und entwirf mir ein Update“, Wochenbericht aus Google Sheets), läuft sie überall — plane sie ein. Wenn sie **deine Dateien, deinen Browser oder deinen Rechner** braucht, bleibt sie desktop-und-live-only.
:::

## Interaktives Cowork vs. eine geplante Aufgabe vs. Dispatch

Die drei Modi werden vermischt. Es sind unterschiedliche Biester:

<Steps items={[
  {title: "Interaktive Cowork-Sitzung", body: "Du startest sie, du schaust zu, Claude arbeitet über einen langen Horizont an deinem aktiven Ziel. Lebt jetzt auf Anthropics Servern, also kannst du sie zwischen Geräten übergeben. Am besten für: mehrstündige Arbeit, die du im Verlauf steuern willst."},
  {title: "Geplante Cowork-Aufgabe", body: "Du definierst einen Prompt + eine Kadenz (stündlich / täglich / werktags / wöchentlich / manuell). Jeder Lauf spawnt eine frische Cowork-Sitzung mit den Tools, Skills und Plugins, die du angegeben hast. Läuft remote, nach Plan, ob ein Gerät online ist oder nicht. Am besten für: wiederkehrende Vorbereitungsarbeit — Montag-06:00-Briefings, stündliche Inbox-Triage, End-of-Day-Rollups."},
  {title: "Dispatch (nur Desktop)", body: "Legacy-Form: Feuere eine Hintergrundaufgabe aus einer aktiven Desktop-Sitzung ab, die weiterläuft, während du weiterchattest. Braucht die Desktop-App wach, weil der Prozess weiter lokal lebt. Am besten für: Arbeit auf dem lokalen Rechner, die du im Hintergrund haben willst, während du weiter kollaborierst. Verwechsele es NICHT mit einer geplanten Remote-Aufgabe — Dispatch stirbt, wenn die App zugeht."}
]} />

Die mentale Abkürzung: **Dispatch = lokaler Hintergrund, Geplante Aufgabe = Cloud auf Kadenz, Interaktiv = du sitzt am Steuer.**

## Eine geplante Aufgabe richtig einrichten

Eine geplante Aufgabe braucht sechs Dinge — fünf Einstellungen und einen Prompt. Bekomme irgendeine der Einstellungen falsch, und der Lauf sieht „erfolgreich“ aus, macht aber das Falsche.

<Steps items={[
  {title: "Aufgabenname", body: "Kurz, menschlich. Das siehst du in der Liste der geplanten Aufgaben und in mobilen Benachrichtigungen. 'Montag Kundenvorbereitung' schlägt 'briefing-v2'."},
  {title: "Prompt / Anweisungen", body: "Schreibe ihn, als würdest du mit einer Kollegin sprechen, die jeden Lauf frisch dazukommt — denn jeder Lauf IST eine frische Sitzung. Nenne das Ziel, die Quellen (welche Connectors, welche Skills, welche Ordner), die gewünschte Ausgabeform und alle Invarianten (z. B. 'nie E-Mail senden, immer als Entwurf lassen')."},
  {title: "Frequenz", body: "Wähle eines von stündlich / täglich / werktags / wöchentlich / manuell. Es gibt keine Cron-Syntax und keine sub-stündlichen Optionen — wenn du 'alle 5 min' brauchst, bist du am falschen Werkzeug (nutze die API + deinen eigenen Scheduler)."},
  {title: "Freigabemodus", body: "Die kritische Einstellung. Optionen sind auto-freigeben (Claude läuft ohne zu fragen weiter, gut für Read-Only-Aufgaben), auf-mobile-fragen (Claude pausiert an einem Entscheidungspunkt und pingt dein Handy — sicherer Default für alles, was schreibt), oder zurück-zur-Prüfung-halten (Aufgabe endet immer mit einem Entwurf, den du später prüfst)."},
  {title: "Modell (optional)", body: "Defaultet auf das Cowork-Default deines Plans. Wähle ein kleineres/günstigeres Modell für schwere Read-Summarize-Schleifen; wähle Top-Tier nur, wenn Reasoning-Qualität das Ergebnis wirklich bewegt."},
  {title: "Arbeitsordner (optional)", body: "Scopet die Dateischreibvorgänge der Sitzung auf ein bestimmtes Projekt/Ordner in deinem Claude-Konto. Lässt du es weg, landen Ausgaben an einem Default-Ort — was für eine Aufgabe okay ist, für zwölf ein Chaos."}
]} />

<PromptCard title="Prompt-Vorlage für geplante Aufgabe: Montag 06:00 Kunden-Briefing">{`You are preparing my Monday morning brief for the Acme account.

Every Monday at 06:00 local:

1. Read the last 7 days of email in the "Acme" Gmail label. Group by
   thread; note anything that expects a reply from me.
2. Pull calendar events with "Acme" in the title or attendees from
   the coming week. Note prep needed for each.
3. Search the web for news about Acme (company name + "acquisition",
   "layoffs", "product launch") in the last 7 days. Cite sources.
4. Read the Google Doc "Acme - Running Notes" for open questions.

Produce a single briefing doc titled "Acme brief — <this-monday-date>"
in the "Client briefings" project folder. Structure:

- 3-bullet TL;DR at the top
- "Needs a reply from me" list (with links)
- "This week" list (calendar + prep)
- "News since last brief" (with sources)
- "Open questions" (from the running-notes doc)

DO NOT send any email. Leave a follow-up email as a DRAFT in Gmail
titled "Acme weekly check-in" pre-filled with the TL;DR — I'll edit
and send.`}</PromptCard>

Zwei Dinge fallen an diesem Prompt auf:

- Die **Invariante** („DO NOT send any email... leave as DRAFT“) ist ausbuchstabiert. In einem geplanten Lauf kannst du kein „bist du sicher?“ nachfragen — die Invarianten müssen im Prompt stehen.
- Der **Ausgabeort + die Benennung** sind präzise. Wenn diese wöchentlich über Monate laufen, willst du sie auffindbar, nicht verstreut unter Default-Titeln.

## Mobiler Freigabefluss — Design für „Ich schlafe“

`auf-mobile-fragen` klingt freundlich, bis es um 03:00 feuert und der Lauf stumm auf dich wartet. Zwei Regeln machen das zuverlässig:

<Steps items={[
  {title: "Freigabemodus an den Wirkungsradius anpassen", body: "Read-only oder draft-only Aktionen → auto-freigeben. Alles, was sendet, veröffentlicht, löscht oder Geld ausgibt → auf-mobile-fragen mit einem Fallback im Prompt: 'wenn ich nicht innerhalb von 30 Minuten geantwortet habe, als Entwurf speichern und Aufgabe beenden'. Der prompt-seitige Fallback ist wichtig, weil die Plattform dich nicht für dich auszählen wird."},
  {title: "Den Benachrichtigungstitel sagen lassen, was gleich passiert", body: "Umhülle Entscheidungspunkte im Prompt mit einer spezifischen Frage: 'Bevor du irgendetwas sendest, hole Freigabe mit der exakten Betreffzeile und den ersten 200 Zeichen des Body'. Push-Benachrichtigungen werden abgeschnitten — stell die wichtigen Bits nach vorne, damit du vom Sperrbildschirm freigeben/ablehnen kannst, ohne die App zu öffnen."}
]} />

<Callout type="warning" items={[
  "Push-Freigaben blockieren die Aufgabe, bis du antwortest. Wenn du nie antwortest, sitzt der Lauf — er fällt nicht automatisch auf einen sicheren Default zurück. Baue ein 'wenn keine Antwort, tu X' Timeout in den Prompt selbst ein, oder nutze stattdessen zurück-zur-Prüfung-halten."
]} />

## Die vier Fallstricke, die geplante Cowork-Läufe brechen

<Steps items={[
  {title: "1. Lokale-Only-Tools deaktivieren den Lauf still", body: "Wenn der Prompt die Aufgabe bittet, 'meinen Downloads-Ordner zu öffnen', 'meinen Browser zu automatisieren' oder 'einen Screenshot meines Bildschirms zu machen', hat die Remote-Sitzung keinen Weg, das zu tun. Der Lauf crasht nicht — er überspringt oder improvisiert. Fix: Auditiere deine geplanten Prompts und tausche Aktionen auf dem lokalen Rechner gegen Äquivalente mit verbundenen Tools (Google Drive statt lokaler Dateien, Web Fetch statt lokalem Browser, etc)."},
  {title: "2. Fable 5 in Cowork braucht weiterhin das neueste Desktop", body: "Zum Juli-2026-Launch benötigt der Fable-5-Modell-Lauf innerhalb einer Cowork-Sitzung die neueste Claude-Desktop-App. Wenn du eine Aufgabe planst, die Fable 5 pinnt, und darauf setzt, dass sie remote läuft, prüfe den aktuellen Support — diese Einschränkung soll gelockert werden, aber prüfe vor dem Pinnen."},
  {title: "3. Dispatch ist KEINE geplante Aufgabe", body: "Ins Hintergrund geschobene Dispatch-Arbeit aus einer aktiven Desktop-Sitzung stirbt, wenn du die App schließt. Wenn du wirklich 'diese wöchentlich, egal was' brauchst, dispatche nicht — lege eine geplante Aufgabe an."},
  {title: "4. Connector-Auth-Drift tötet stille Läufe", body: "OAuth-Tokens zu Gmail, Slack, Google Drive können ablaufen, widerrufen werden oder von Berechtigungsänderungen getroffen werden. Eine geplante Aufgabe unter einem abgelaufenen Connector produziert leere Ausgabe und keinen offensichtlichen Fehler. Fix: Für alles, was wöchentlich oder seltener läuft, füge im Prompt eine Selbst-Prüfung als ersten Schritt hinzu ('bestätige, dass du das Acme-Gmail-Label lesen kannst; wenn nicht, produziere eine einzeilige Fehlermeldung ganz oben im Doc und halte an')."}
]} />

## Wann du stattdessen zur API greifst

Geplante Cowork-Aufgaben sind ein Produkt-Feature — großartig für persönliche / Kleinteam-wiederkehrende Arbeit, die du in deinem Claude-Konto sichtbar willst, mit menschlicher Freigabe in der Schleife. Sie sind das falsche Werkzeug, wenn du brauchst:

- **Sub-stündliche Kadenz** — das kleinste Geplante-Aufgabe-Intervall ist stündlich.
- **Programmatische Orchestrierung** — Dutzende parallele Läufe, dynamische Planung oder enge Integration mit deiner Infra. Greif zu [Managed Agents](/docs/api/managed-agents), oder baue eigenes mit dem [Agent SDK](/docs/claude-code/headless-and-agent-sdk) + einem Cron/Queue, den du bereits betreibst.
- **Server-seitiger Speicher über Läufe hinweg** — Cowork-Aufgaben reichen Zustand über Dateien in deinem Konto weiter, was für Docs okay ist, für strukturierten Zustand aber grob. Für strukturierten laufübergreifenden Speicher nutze [Managed Agents Memory Stores](/docs/api/managed-agents-memory-stores).
- **Tiefe Multi-Agenten-Koordination** — für Viele-Agenten-kollaborieren siehe [Cowork & Agent Teams](/docs/api/cowork-and-agent-teams) und [Native Multi-Agent APIs](/docs/models/native-multi-agent-apis).
