Speicherorte, Ladereihenfolge und Import-Syntax stammen aus der offiziellen Memory-Dokumentation („How Claude remembers your project"), die inzwischen **zwei** Mechanismen beschreibt: CLAUDE.md-Dateien, die du schreibst, und **Auto-Memory**, das Claude selbst schreibt. Imports werden bis zu einer maximalen Tiefe von vier Sprüngen aufgelöst. Prüfe die Details dort — sie ändern sich.
</VerifyNote>

Wenn du **eine** Sache tust, um [Claude Code](/docs/claude-code/what-is-claude-code) besser zu machen, dann diese. `CLAUDE.md` ist eine Klartextdatei, die Claude zu Beginn jeder Session liest — das dauerhafte Briefing deines Projekts.

## Warum es die Einstellung mit dem größten Hebel ist

Ohne sie erklärst du dein Projekt in jeder Session erneut ("wir nutzen pnpm, Tests liegen in `__tests__`, fass `/generated` nicht an…"). Mit ihr weiß Claude es bereits. Gute Anweisungen hier verbessern *jede* zukünftige Interaktion auf einmal.

## Die Memory-Hierarchie

Claude Code lädt Memory aus mehreren Quellen und führt sie in Ladereihenfolge zusammen, vom breitesten Geltungsbereich zuerst — eine Projektanweisung landet also *nach* einer User-Anweisung im Kontext:

```mermaid
flowchart TD
  A["Managed policy<br/>/etc/claude-code/CLAUDE.md (org-wide, IT-managed)"] --> B["User instructions<br/>~/.claude/CLAUDE.md (all your projects)"]
  B --> C["Project instructions<br/>./CLAUDE.md or ./.claude/CLAUDE.md (committed)"]
  C --> D["Local instructions<br/>./CLAUDE.local.md (yours only — gitignore it)"]
```

- **Managed Policy** — organisationsweite Anweisungen, die dein IT-/DevOps-Team ausliefert. Der Pfad ist betriebssystemabhängig: `/Library/Application Support/ClaudeCode/CLAUDE.md` unter macOS, `/etc/claude-code/CLAUDE.md` unter Linux und WSL, `C:\Program Files\ClaudeCode\CLAUDE.md` unter Windows.
- **User-Anweisungen** (`~/.claude/CLAUDE.md`) — deine persönlichen Vorlieben über alle Projekte hinweg.
- **Projekt-Anweisungen** (`./CLAUDE.md` *oder* `./.claude/CLAUDE.md`, committed) — wie *dieses* Repo funktioniert. Mit deinem Team geteilt. Wenn dein Repo [`AGENTS.md`](/docs/claude-code/agents-md) nutzt, kann das statt dieser Dateien oder zusätzlich zu ihnen geladen werden.
- **Lokale Anweisungen** (`./CLAUDE.local.md`) — projektspezifische Notizen nur für dich, etwa eine Sandbox-URL. Füge sie zu `.gitignore` hinzu.

Dateien in der Verzeichnishierarchie *oberhalb* deines Arbeitsverzeichnisses werden beim Start geladen; Dateien in **Unterordnern werden bei Bedarf geladen**, wenn Claude etwas in diesem Bereich anfasst.

<Callout type="tip" items={["Eine Datei reicht nicht mehr aus? Teile die Anweisungen in .claude/rules/*.md auf — ein Thema pro Datei, rekursiv erkannt. Regeln ohne paths-Frontmatter werden beim Start geladen, mit derselben Priorität wie .claude/CLAUDE.md; füge paths-Frontmatter hinzu, damit eine Regel nur dann lädt, wenn Claude an passenden Dateien arbeitet — das spart Kontext."]} />

## Die andere Hälfte: Auto-Memory

CLAUDE.md ist die Hälfte des Gedächtnisses, die *du* schreibst. Claude Code führt außerdem ein **Auto-Memory** — Notizen, die Claude selbst aus deinen Korrekturen und Vorlieben schreibt, pro Repository gespeichert und in jeder Session neben deinen CLAUDE.md-Dateien geladen.

| | CLAUDE.md-Dateien | Auto-Memory |
| --- | --- | --- |
| **Wer schreibt es** | Du | Claude |
| **Was es enthält** | Anweisungen und Regeln | Erkenntnisse und Muster |
| **Geltungsbereich** | Projekt, User oder Organisation | Pro Repository, über Worktrees hinweg geteilt |

Beides ist *Kontext*, keine Durchsetzung: Claude behandelt sie als Orientierung, die es abwägen kann, nicht als Konfiguration, der es gehorchen muss. Um eine Aktion unabhängig von Claudes Entscheidung hart zu blockieren, nutze stattdessen einen [PreToolUse-Hook](/docs/claude-code/hooks).

<Callout type="warning" items={["Auto-Memory lädt nur die ersten 200 Zeilen oder 25 KB — eine überfüllte MEMORY.md wird stillschweigend abgeschnitten. Die vollständige Aufschlüsselung der Startkosten findest du im Kontextbudget-Audit."]} />

## Was hineingehört

- Was das Projekt ist, in zwei Sätzen.
- Tech-Stack und wie man **ausführt / testet / lintet**.
- Konventionen, die Claude nicht ableiten kann (Benennung, Struktur, Commit-Stil).
- **Leitplanken**: "führe Tests aus, bevor du etwas für fertig erklärst", "bearbeite niemals `/vendor`", "committe niemals Geheimnisse".

## Imports

Binde vorhandene Dokumente ein, statt sie zu duplizieren — referenziere z. B. deinen Styleguide mit einem `@path/to/file`-Import, sodass es eine einzige Quelle der Wahrheit gibt. Relative und absolute Pfade funktionieren beide; relative Pfade werden gegen die Datei aufgelöst, die den Import enthält, **nicht** gegen dein Arbeitsverzeichnis. Importierte Dateien können weitere importieren, bis zu einer maximalen Tiefe von **vier Sprüngen**.

Zwei Syntaxfallen, die man kennen sollte, bevor sie zuschlagen:

- **Leerzeichen brauchen Backslashes.** `@Design\ Docs/api-conventions.md` funktioniert; ohne den Backslash endet der Pfad beim ersten Leerzeichen. In Anführungszeichen gesetzt wird die Datei überhaupt nicht importiert.
- **Backticks melden sich ab.** Das Import-Parsing überspringt Code-Spans und Code-Blöcke, deshalb bleibt `` `@README` `` wörtlicher Text, während `@README` allein die Datei importiert. So *erwähnst* du einen Pfad, ohne ihn zu laden.

Die vollständige Referenz findest du in der [offiziellen Memory-Dokumentation](https://code.claude.com/docs/en/memory).
