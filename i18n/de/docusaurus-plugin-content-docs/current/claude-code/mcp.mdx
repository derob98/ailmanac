Das **Model Context Protocol (MCP)** ist ein offener Standard, um KI mit externen Tools und Daten zu verbinden. Ein **MCP-Server** stellt Fähigkeiten bereit (eine Datenbank abfragen, einen GitHub-PR öffnen, einen Browser steuern); Claude Code verbindet sich mit ihm und kann **diese Tools** während einer Sitzung **aufrufen**. So erweiterst du Claude über dein Dateisystem und deine Shell hinaus.

## Das Grundprinzip

```mermaid
flowchart LR
  CC[Claude Code] -- calls tool --> S[MCP server]
  S -- result --> CC
  S --- D[(DB / API / Browser / SaaS)]
```

Du deklarierst die Server, die Claude nutzen darf; jeder Server veröffentlicht eine Reihe von Tools mit Schemas; Claude wählt sie aus und ruft sie wie jedes andere Tool auf.

## Transporte

Es gibt vier Wege, wie Claude einen Server erreicht. Wähle danach, wo der Server läuft und wie er kommuniziert.

- **stdio** — ein lokaler Prozess, den Claude startet (ideal für lokale Tools/CLIs). Genau das bedeutet ein JSON-Eintrag ohne `type`.
- **HTTP** — ein gehosteter Server, oft mit OAuth. Die Standardwahl für alles, was entfernt läuft.
- **SSE** — **veraltet**; nutze HTTP, wo es geht. Manche Dienste bieten noch nur einen SSE-Endpunkt an, und ab Claude Code v2.1.265 versucht `--transport http` zuerst HTTP und wechselt von selbst zu SSE, sodass du `--transport sse` selten explizit brauchst.
- **WebSocket** (`ws` / `wss`) — eine dauerhafte bidirektionale Verbindung für einen Server, der unaufgefordert Ereignisse sendet. `--transport` akzeptiert `ws` *nicht*: Füge ihn mit `claude mcp add-json '{"type":"ws","url":"wss://…"}'` hinzu oder schreibe ihn in die `.mcp.json`. Kein OAuth — die Authentifizierung läuft nur über Header.

<Callout type="warning" items={["Ein JSON-Eintrag mit url, aber ohne type ist ein Konfigurationsfehler, kein sinnvoller Standard: Claude Code liest einen Eintrag ohne type als stdio-Server, überspringt ihn und meldet, dass er eine „url“ hat, aber keinen „type“. Setze bei einem von Hand geschriebenen Remote-Server immer \"type\": \"http\" (oder \"sse\" / \"ws\")."]} />

## Server konfigurieren

Der schnellste Weg ist der Befehl `claude mcp add` — er schreibt die Konfiguration für dich. Mit dieser Abfolge kommst du von null zu einem verbundenen Server.

<Steps items={[{title: "Einen lokalen stdio-Server hinzufügen", body: "Führe claude mcp add aus — alles nach dem -- ist der Startbefehl, den Claude für dich ausführt."}, {title: "Oder einen entfernten HTTP-Server hinzufügen", body: "Übergib --transport http und einen Scope, dann die Server-URL. Entfernte Server sind oft gehostet und nutzen OAuth."}, {title: "Sehen, was verbunden ist", body: "Führe claude mcp list aus, um die konfigurierten Server und ihren Verbindungsstatus anzuzeigen."}, {title: "Prüfen und authentifizieren", body: "Nutze /mcp in einer Sitzung, um die Tools eines Servers zu prüfen und entfernte Server zu authentifizieren."}]} />

<PromptCard title="Einen lokalen stdio-Server hinzufügen">{`# A local stdio server (everything after -- is the launch command)
claude mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem ~/code/myproject`}</PromptCard>

<PromptCard title="Einen entfernten HTTP-Server hinzufügen (mit dem Projekt geteilt)">{`# A remote HTTP server, shared with everyone on the project
claude mcp add --transport http --scope project github https://api.githubcopilot.com/mcp/`}</PromptCard>

Im Kern ist das nur JSON. Ein Server mit **project**-Scope landet in einer `.mcp.json` im Repo-Stamm — committe sie, und deine Teammitglieder bekommen dieselben Tools, sobald sie dem Arbeitsbereich vertrauen:

```json
{
  "mcpServers": {
    "github": { "type": "http", "url": "https://api.githubcopilot.com/mcp/" }
  }
}
```

<Callout type="warning" items={["Greife nicht zu den Paketen @modelcontextprotocol/server-github, -postgres, -slack oder -puppeteer, die du in alten Tutorials findest. Sie sind archiviert und tragen einen npm-Veraltungshinweis mit dem Wortlaut \"Archived and unmaintained; no security guarantees\". Nutze den Server des Anbieters selbst, wo es einen gibt — der von GitHub ist der HTTP-Endpunkt oben, und die Browsersteuerung ist zu @playwright/mcp gewandert. Unter den TypeScript-Referenzservern werden nur filesystem, memory, everything und sequential-thinking noch gepflegt."]} />

### Der Scope entscheidet, wer den Server sieht

| Scope | Gespeichert in | Wird geladen in | Einsatz für |
|---|---|---|---|
| `local` (Standard) | `~/.claude.json`, unter dem Pfad dieses Projekts | nur dieses Projekt | persönliche Experimente, Geheimnisse |
| `project` | `.mcp.json` im Repo (committet) | nur dieses Projekt, mit dem Team geteilt | Tools, die das ganze Team teilen soll |
| `user` | `~/.claude.json` | alle deine Projekte | Server, die du überall willst |

<Callout type="warning" items={["Der MCP-„local scope“ ist nicht dasselbe wie lokale Einstellungen. Ein MCP-Server mit local-Scope liegt in ~/.claude.json in deinem Home-Verzeichnis — NICHT in .claude/settings.local.json des Projekts. Im Projektordner danach zu suchen, führt ins Leere."]} />

Führe `claude mcp list` aus, um zu sehen, was verbunden ist, und `/mcp` in einer Sitzung, um Tools zu prüfen und entfernte Server zu authentifizieren. Kopierfertige Startpunkte findest du unter [MCP-Konfiguration und Server-Gerüste](/docs/templates/mcp-config).

## Praxisbeispiel: Gib Claude deine Datenbank

Angenommen, Claude soll Fragen an eine lokale Postgres-Instanz beantworten, statt dass du Abfrageergebnisse einfügst. Füge den Server mit project-Scope hinzu, damit auch dein Team ihn bekommt.

Bei Datenbanken schlägt das Problem der archivierten Server am härtesten zu: Das alte `@modelcontextprotocol/server-postgres` wird nicht mehr gepflegt, und es gibt keinen offiziellen Ersatz — der Paketname ist also die eine Entscheidung, die du selbst treffen musst. Wähle einen gepflegten Community-Server, [prüfe ihn](/docs/security/reviewing-third-party-code) und binde ihn dann ein — die Form ist dieselbe, egal wofür du dich entscheidest:

<PromptCard title="Einen Postgres-Server mit project-Scope hinzufügen">{`# Replace the package with a maintained Postgres MCP server you have reviewed.
# The connection string is read-only on purpose — see below.
claude mcp add --scope project db -- npx -y <postgres-mcp-server> "postgresql://readonly@localhost/app"`}</PromptCard>

Jetzt kannst du in einer Sitzung die Frage in normaler Sprache stellen und Claude die Abfrageschleife für dich erledigen lassen:

<PromptCard title="Der Datenbank eine Frage stellen">{`How many users signed up last week? Check the DB.`}</PromptCard>

Claude ruft das Abfrage-Tool auf, das der Server bereitstellt, erhält Zeilen zurück und antwortet — keine Copy-and-paste-Schleife. Halte den Verbindungsstring schreibgeschützt, es sei denn, Claude muss wirklich schreiben. Und wenn du eigentlich nur eine einzige Abfrage wolltest: `psql -c '…'` über Bash kostet nur einen Bruchteil der Tokens; [Die MCP-Token-Steuer](/docs/claude-code/mcp-token-cost) erklärt, wann welche Variante gewinnt.

Weil der Server project-Scope hat, bekommt ein Teammitglied, das das Repo zieht, dieselbe Fähigkeit — aber **nicht stillschweigend und nicht sofort**. Ein Server aus einer committeten `.mcp.json` bleibt bei `⏸ Pending approval`, bis das Teammitglied `claude` im Ordner ausführt und den Vertrauensdialog für den Arbeitsbereich bestätigt. Ein geklontes Repo kann seine eigenen Server nicht vorab freigeben: `enableAllProjectMcpServers` oder `enabledMcpjsonServers` in der committeten `.claude/settings.json` des Projekts werden in einem nicht vertrauenswürdigen Ordner *ignoriert*. Freigaben aus einer `~/.claude/settings.json` auf Benutzerebene, aus verwalteten Einstellungen oder per `--settings` übergeben gelten dort dagegen. Das ist die übliche Antwort auf „Warum sieht mein Teammitglied den Server nicht?“

## Vertrauen und Sicherheit

<Callout type="warning" items={["Ein MCP-Server führt Code aus und kann Daten lesen und Aktionen ausführen — verbinde nur Server, denen du vertraust.", "Gib jedem Server die minimal nötigen Rechte.", "Jeder externe Inhalt, den ein Server zurückgibt, kann Prompt Injection enthalten.", "Prüfe Server von Drittanbietern, bevor du sie verbindest."]} />

:::warning[Behandle MCP-Server wie die Installation von Software]
Ein MCP-Server führt Code aus und kann Daten lesen und Aktionen ausführen. Verbinde nur Server, denen du vertraust, gib ihnen die **minimal nötigen Rechte** und denke daran, dass jeder externe Inhalt, den sie zurückgeben, [Prompt Injection](/docs/security/prompt-injection) enthalten kann. Prüfe Server von Drittanbietern zuerst — siehe [Code von Drittanbietern prüfen](/docs/security/reviewing-third-party-code).
:::

## Häufige Fehler

- **Falscher Scope.** Ein Server, der mit `local`-Scope hinzugefügt wurde, erscheint nicht für Teammitglieder; einer, den du nur für dich wolltest, sollte nicht mit `project`-Scope committet werden. Wähle bewusst.
- **Zu viele Server, zu viele Tools.** Die Tool-Suche ist standardmäßig aktiv, daher kostet ein verbundener Server dich normalerweise pro Turn seine Tool-*Namen* und Server-Anweisungen statt seiner vollständigen Schemas — aber das ist trotzdem eine Steuer pro Turn, und die Schemas landen im Kontext, sobald Claude nach ihnen sucht. Verbinde, was die Aufgabe braucht, nicht deinen ganzen Katalog. Siehe [Die MCP-Token-Steuer](/docs/claude-code/mcp-token-cost) für die echten Zahlen, die `ENABLE_TOOL_SEARCH`-Modi und wie Code-Ausführung den zweiten Kostenpunkt senkt.
- **Überprivilegierte Verbindungen.** Gib einem Datenbank-Server eine schreibgeschützte Rolle, es sei denn, Claude muss wirklich schreiben. MCP macht Fähigkeiten real — schränke sie ein.
- **Das Injection-Risiko vergessen.** Alles, was ein Server zurückgibt (eine Webseite, ein Issue-Text, eine Zeile), ist nicht vertrauenswürdiger Text, der [Prompt Injection](/docs/security/prompt-injection) enthalten kann. Schalte keinen mächtigen Server mit Schreibrechten neben einen nicht vertrauenswürdigen mit Leserechten, ohne es dir gut zu überlegen.
