Claude Code ist nicht nur interaktiv. Du kannst es **headless** ausführen (nicht interaktiv, skriptbar) und mit dem **Agent SDK** auf demselben zugrunde liegenden Harness **eigene Agenten** bauen.

## Headless-Modus

Führe einen einzelnen Prompt nicht interaktiv aus und erfasse die Ausgabe — ideal für Skripte, Pre-Commit-Hooks und CI:

<PromptCard title="Den gestagten Diff aus einem Skript prüfen">
{`claude -p "Review the staged diff and list any bugs as a Markdown checklist"`}
</PromptCard>

Eingabe hineinleiten, Ergebnis herausbekommen. Kombiniere das mit [Berechtigungen](/docs/claude-code/permissions) in einer sicheren, nicht interaktiven Haltung, damit der Lauf nie auf eine Freigabe wartet und hängt — und **sperre ihn ab**, damit ein automatisierter Lauf keine Secrets anfassen kann (siehe [Autonome Läufe absichern](/docs/security/hardening-autonomous-runs)).

<Steps items={[
  {title: "Mit -p und einem engen Prompt beginnen", body: "Ein Prompt, eine Antwort, Ende. Alles, was ein Headless-Lauf braucht, ist ein Flag, denn es gibt keine Oberfläche, die dich etwas fragen könnte."},
  {title: "Die Berechtigungshaltung vorab festlegen", body: "Eine interaktive Sitzung fragt dich; ein CI-Job hat niemanden, den er fragen kann. Setze explizite Allow-Regeln für die Tools, die die Aufgabe wirklich braucht, und stelle sicher, dass eine unbeantwortbare Rückfrage den Lauf beendet, statt ihn festzuhalten."},
  {title: "Den Lauf begrenzen", body: "Begrenze die Züge und die Ausgaben, damit eine Schleife, die schiefläuft, Minuten und Cent kostet statt Stunden und Dollar."},
  {title: "Strukturierte Ausgabe anfordern", body: "Ein Skript, das Prosa parst, ist ein Skript, das kaputtgeht. Fordere JSON — oder ein Schema — an, damit das Ergebnis von vornherein maschinenlesbar ist."},
  {title: "Absichern, was er erreichen kann", body: "Secrets, Netzwerk und Schreibzugriff sind die drei Dinge, von denen ein unbeaufsichtigter Lauf am wenigsten haben sollte. Siehe Autonome Läufe absichern."}
]} />

Die genauen Flags für jeden Schritt — und die Fallen darin — stehen in [Die claude-CLI: Flags, die das Ergebnis verändern](/docs/claude-code/cli-flags). Ein klassischer Einsatz von alledem zusammen: ein CI-Job, in dem Claude jeden Pull Request prüft — siehe die [PR-Review-Anleitung](/docs/walkthroughs/pr-review-action).

## Das Agent SDK

Das **Claude Agent SDK** (Python und TypeScript) lässt dich produktive Agenten auf derselben Schleife bauen, die Claude Code antreibt — Tool-Nutzung, Datei-/Shell-Zugriff, Berechtigungen, Kontextverwaltung —, nur eingebunden in *deine* Anwendung.

```mermaid
flowchart LR
  A[Your app / CI] --> H[Agent harness]
  H --> T[Tools: files, shell, MCP, custom]
  H --> L[Claude model]
  L --> H --> A
```

Greife dazu, wenn du einem einzelnen API-Aufruf oder einer selbstgebauten Schleife entwachsen bist und eine Agenten-Laufzeit mit allem Drum und Dran willst. Für das Spektrum der Optionen — einzelner Aufruf → Workflow → eigener Agent → verwaltet — siehe [Agenten auf der API bauen](/docs/api/building-agents).

## Headless/SDK vs. interaktiv

| Modus | Wofür |
|---|---|
| Interaktives Claude Code | Alltägliche Entwicklung mit einem Menschen in der Schleife |
| Headless (`claude -p`) | Skripte, Pre-Commit, einmalige CI-Aufgaben |
| Agent SDK | Produktive Agenten, eingebettet in deine Software |
