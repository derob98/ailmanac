Ein Jahr lang bedeutete "Claudes Gedächtnis" einen einzigen sich entwickelnden Absatz, den das Modell jeden Tag neu schrieb — gut für eine Bio, schlecht für alles mit Struktur. Zwischen **Juni und Juli 2026** ersetzte Anthropic das durch ein eintragsbasiertes Modell: Dutzende kleiner, kategorisierter Notizen, die Claude in Echtzeit liest und schreibt. Dieselbe Idee treibt die App *und* die Managed Agents Memory API an. Diese Seite verbindet sie, damit du beide Oberflächen aus einem mentalen Modell verstehst.

<VerifyNote lastVerified="2026-07-24" source="https://platform.claude.com/docs/en/release-notes/overview">
Der Beta-Header `agent-memory-2026-07-22`, die memory_store-Webhook-Ereignisse und die Dreams-Modellunterstützung haben sich alle innerhalb der letzten vier Wochen geändert. Bestätige den aktuellen Beta-Status und die Preise in den Release Notes der Plattform, bevor du in Produktion gehst.
</VerifyNote>

## Das mentale Modell, das beide Seiten vereint

```mermaid

  subgraph App["Claude.ai (Free / Pro / Max / Team / Enterprise)"]
    U[User chats] --> W1[Claude writes an entry]
    W1 --> S["Settings › Memory<br/>(view, edit, delete per entry)"]
  end
  subgraph API["Managed Agents (memory_stores)"]
    A[Agent runs] --> W2[Agent creates memory<br/>at a path]
    W2 --> L["GET /v1/memory_stores/*/memories<br/>list by path_prefix"]

```

Beide Seiten funktionieren jetzt auf die gleiche Weise: **viele kleine Einträge an benannten Orten**, jeder isoliert überschreibbar. Das alte Modell (ein Blob pro Benutzer, komplett neu geschrieben) ist in der App verschwunden und war nie die API-Oberfläche. Sobald du *"Einträge an Pfaden, aufgelistet nach Präfix, einzeln bearbeitet"* verinnerlicht hast, fühlen sich beide Oberflächen nicht mehr wie separate Features an.

### Warum die Formänderung wichtig ist

Die alte tägliche Zusammenfassung hatte einen einzigen Fehlermodus: nicht verwandter Kontext lief ineinander über. Korrigiere einen Fakt über dein Arbeitsprojekt, und Claude könnte etwas über deinen Schreibstil überschreiben. Kleine, kategorisierte Einträge beheben das strukturell — jede Bearbeitung ist auf einen Bereich beschränkt.

Drei Konsequenzen, die die meisten Nutzer übersehen:

- **Retrieval ist jetzt zielgerichtet, nicht assoziativ.** Claude kann "deine Kommunikationspräferenzen" abrufen, ohne den Rest deines Kontexts mitzuziehen. Prompts, die früher "denk daran, ich bevorzuge X, nicht Y" brauchten, um durch die Zusammenfassung zu brechen, treffen jetzt direkt einen bestehenden Eintrag.
- **Du kannst chirurgisch beschneiden.** Lösche einen einzelnen falschen Eintrag in den Einstellungen, anstatt alles zu löschen und Claude neu beizubringen, wer du bist. Die "Verbrenne alles"-Steuer für die Korrektur eines Fehlers ist weg.
- **Kategorien wirken als unsichtbares Schema.** Wenn Claude entscheidet, *wo* ein Eintrag hingehört (z.B. "Kommunikationsstil" vs. "aktuelles Projekt"), wählt es implizit, ob dieser Fakt in zukünftigen persönlichen Chats, zukünftigen Arbeits-Chats oder beiden abgerufen wird. Dinge im Voraus gut zu benennen fördert einen besseren Abruf später.

## Teil 2 — In der API: memory_stores und der neue Beta-Header

Die Managed-Agents-Plattform stellt das Gedächtnis als **Memory Stores** bereit — Sammlungen von Memories, adressiert per Pfad, aufgelistet mit einem `path_prefix` und mit Cursors paginiert. Am **2. Juli 2026** lieferte Anthropic `agent-memory-2026-07-22` aus, einen Beta-Header, der die Semantik genug ändert, um naive Migrationen zu brechen. Am **22. Juli 2026** übernahm der ältere Header `managed-agents-2026-04-01` dasselbe List-Verhalten — so sind die "neuen" Regeln jetzt die *einzigen* Regeln auf memory-store-Endpunkten.

### Die vier Verhaltensänderungen, die du kennen musst

| # | Was sich geändert hat | Altes Verhalten | Neues Verhalten unter `agent-memory-2026-07-22` |
|---|---|---|---|
| 1 | Listenreihenfolge | Vom Client gesteuert über `order_by` / `order` | **Stabile, serverdefinierte Reihenfolge.** `order_by` und `order` werden ignoriert — sortiere clientseitig, falls nötig |
| 2 | Parameter `depth` | Freie Ganzzahl | Akzeptiert nur `0`, `1` oder weggelassen. Jeder andere Wert gibt **400** zurück |
| 3 | `path_prefix`-Matching | Substring-Match | Muss mit `/` enden, matcht **nur ganze Pfadsegmente** |
| 4 | Paginierungscursors | Austauschbar | Ohne den neuen Header ausgegebene Cursors **sind mit ihm nicht gültig**. Beginne neu bei Seite 1, wenn du ihn übernimmst |

Zwei weitere Fallstricke:

- **Header-Kollision.** Auf memory-store-Endpunkten ersetzt `agent-memory-2026-07-22` den Header `managed-agents-2026-04-01`. Beide gleichzeitig zu senden gibt **400** zurück. Migriere nur die memory-store-Aufrufe; lasse die anderen managed-agents-Endpunkte beim ursprünglichen Header.
- **SDKs sind bereits umgestellt.** Python 0.116.0, TypeScript 0.110.0, Go 1.56.0, Java 2.48.0, Ruby 1.55.0, PHP 0.36.0, C# 12.35.0 und das CLI 1.16.0 senden alle automatisch `agent-memory-2026-07-22` auf memory-store-Aufrufen. Wenn dein Code `betas` explizit übergibt, **ersetze** dort `managed-agents-2026-04-01` — füge nicht beide hinzu.

### Webhooks: reagiere auf den memory-store-Lebenszyklus ohne Polling

Ausgeliefert am **22. Juli 2026** zusammen mit dem Header-Standard: **drei `memory_store.*`-Webhook-Ereignistypen** decken jetzt den Lebenszyklus des Memory Store ab, und vier `environment.*`-Ereignisse decken die Sandbox-Umgebung ab. Dies ist der Teil, den die meisten Integratoren übersehen — du kannst jetzt auf einen von einem Agenten erstellten, aktualisierten oder entfernten Memory Store reagieren, anstatt `GET /v1/memory_stores` per Timer zu pollen. Abonniere sie am Managed-Agents-Webhooks-Endpunkt und leite die Ereignisse in dein eigenes Audit-Trail oder Dashboard weiter.

### Dreams: reorganisiere Memory im Hintergrund

Angekündigt in den Release Notes vom 6. Mai 2026 und am 10. Juli erweitert, um Claude Fable 5 und Sonnet 5 zu unterstützen, ist **Dreams** eine Forschungsvorschau, die einen bestehenden Memory Store *plus* vergangene Sitzungstranskripte liest und einen **reorganisierten Output-Memory-Store** erzeugt: Duplikate zusammengeführt, veraltete Einträge ersetzt, neue Erkenntnisse aufgetaucht. Endpunkte werden durch den Beta-Header `dreaming-2026-04-21` gesteuert; Zugriff auf Anfrage. Behandle es als das API-seitige Analogon zur monatlichen Zusammenfassung der App — ein geplanter Reflexionsdurchlauf, der verhindert, dass sich der Store versandet.

## App vs. API — eine Tabelle

| Aspekt | Claude.ai-App | Managed Agents API |
|---|---|---|
| Speichereinheit | Kategorisierter Eintrag | Memory an einem Pfad |
| Gruppierung | Kategorie (beruflicher Kontext, Kommunikationspräferenzen, laufende Projekte, …) | Pfadsegmente (`/projects/acme/…`) |
| Lesen/Schreiben | Live während Chat | Agent-Tool-Aufrufe während einer Sitzung |
| Menschlich bearbeitbar | Ja, pro Eintrag in Einstellungen › Memory | Ja, über memory-store-Endpunkte |
| Löschen | Pro Eintrag, oder alle | Pro Memory, pro Präfix, oder Store löschen |
| Reflexion | Monatliche Zusammenfassung (Einstellungen › Reflect) | Dreams (Forschungsvorschau) |
| Isolation | Inkognito-Chat | Pro-Agent, pro-Sitzung memory-store-Auswahl |
| Verfügbarkeit | Free, Pro, Max, Team, Enterprise (pro Plan verifizieren) | Managed Agents (öffentliche Beta) |

Wo das im Rest von AILmanac lebt:

- [Memory & Context Editing](/docs/api/memory-and-context-editing) — das *clientseitige* Memory-Tool, ein anderes Biest: du implementierst die Speicherung.
- [Memory Across Chats](/docs/claude-app/memory) — die Anfängerübersicht des App-Memory.
- [Agent Memory Architectures](/docs/frontiers/agent-memory-architectures) — die Theorie von episodischem vs. semantischem Gedächtnis, die verständlich macht, warum kategorisierte Einträge eine rollierende Zusammenfassung schlagen.
- [Managed Agents](/docs/api/managed-agents) — das Framework, das die hier beschriebene memory-store-Oberfläche hostet.
