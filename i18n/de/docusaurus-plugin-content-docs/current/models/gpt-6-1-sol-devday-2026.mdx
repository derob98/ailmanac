<LevelBadge level="intermediate" />

Auf der **DevDay am 29. September 2026** hat OpenAI **GPT-6.1 Sol** (`gpt-6.1-sol`)
veröffentlicht, eine Woche nach GPT-6 Sol, mit dem Versprechen **„Astra-nahe
Intelligenz zu einem Fünftel des Preises“.** Das Modell landete umgehend auf Platz
eins von Hacker News.

Für Claude-Nutzer ist nicht das Versprechen die interessante Tatsache. Interessant
ist, dass GPT-6.1 Sol **exakt auf der Preisliste von Claude Sonnet 5.5** landet — 2 $
Eingabe, 10 $ Ausgabe pro MTok — und dabei nur **die Hälfte** der gecachten
Eingaberate von Sonnet 5.5 berechnet. Zwei Modelle, derselbe Schlagzeilenpreis,
unterschiedliche Rechnungen, unterschiedliche Arbeitsprofile. Diese Seite liefert die
Spezifikationen, die Preismechanik, die die meisten Artikel überspringen, eine
ehrliche Lesart der Benchmark-Tabelle und den Rest dessen, was die DevDay für
Entwickler gebracht hat.

## Spezifikationen

| | `gpt-6.1-sol` |
|---|---|
| Kontextfenster | **1.050.000** Tokens |
| Maximale **Eingabe**-Tokens | **922.000** |
| Maximale Ausgabe-Tokens | 128.000 |
| Wissensstand | 30. April 2026 |
| Reasoning-Stufen | low, **medium (Standard)**, high, xhigh, max |
| Eingabe / gecachte Eingabe / Ausgabe | **2,00 $ / 0,10 $ / 10,00 $** pro MTok |
| Cache-Schreibvorgang | 2,50 $ pro MTok |
| Langer Kontext (>272K) | 2× Eingabe- und Cache-Raten, 1,5× Ausgabe |
| Fast Mode | 2× Standardpreis |
| Batch / Flex | 50 % unter Standard |
| Rate-Limits | Tier 1: 500 RPM / 500K TPM → Tier 5: 15K RPM / 40M TPM |

### Die zwei Obergrenzen, die nicht das Kontextfenster sind

**1.050.000 ist das Fenster. 922.000 ist die Eingabegrenze.** Die Differenz ist kein
Puffer, den du für ein größeres Dokument ausgeben kannst — sie ist der Platz, den
Reasoning und Ausgabe brauchen. Wenn du einen Retrieval-Schritt gegen „1 Mio. Kontext“
dimensionierst, läufst du rund 12 % früher als die Marketingzahl gegen ein Limit, und
zwar im schlechtesten Moment: nachdem du bereits dafür bezahlt hast, den Prompt
zusammenzubauen.

**Dazu kommt die Preisklippe bei 272K.** Überschreite sie, und Eingabe sowie gecachte
Eingabe verdoppeln sich, die Ausgabe steigt um die Hälfte. Es ist dieselbe Klippe, die
GPT-6 Astra hat, und sie verändert die Ökonomie von Long-Context-Arbeit drastisch: ein
Prompt mit 300K Tokens kostet nicht 10 % mehr als einer mit 272K, sondern auf der
Eingabeseite ungefähr das Doppelte. Wenn du nahe an der Grenze liegst, ist es echten
Engineering-Aufwand wert, durch Komprimierung darunter zu bleiben. Claude bepreist
sein 1-Mio.-Fenster anders — siehe [was KI bei den verschiedenen Anbietern
kostet](/docs/models/what-ai-costs-across-providers) und [Prompt-Caching im
Anbietervergleich](/docs/models/prompt-caching-across-providers).

## Die Falle: Tool-Calling gibt es nicht auf beiden APIs

Die Modellseite nennt **Chat Completions (ohne Tool-Calling)** und **Responses API
(mit Tool-Calling)**. Lies das zweimal, wenn du eine bestehende Integration portierst.

Wenn dein Code an Chat Completions sendet — den Endpunkt, auf den die meisten
Drittanbieter-Bibliotheken, Gateways und „OpenAI-kompatiblen“ Wrapper standardmäßig
setzen —, **bekommst du bei diesem Modell kein Function Calling.** Die Lösung ist kein
Parameter, sondern ein anderer Endpunkt und ein anderes Request-Format.

Ebenfalls nicht unterstützt: Live, Realtime, Assistants, Fine-Tuning, Embeddings,
Bildgenerierung, Video, Sprache und Transkription, Moderation sowie das alte
Completions-API. Die Liste der unterstützten Tools ist breit — Websuche, Dateisuche,
Bildgenerierung, Code Interpreter, gehostete Shell, Apply Patch, Skills, Computer Use,
MCP, Tool-Suche —, aber es ist eine **Responses-API**-Liste.

<Callout type="warning" items={[
  "Prüfe dein KI-Gateway, bevor du einen Modell-String umstellst. Ein Router, der alles auf Chat Completions normalisiert, entfernt bei gpt-6.1-sol stillschweigend das Tool-Calling — der Request gelingt, die Tools feuern einfach nie."

## Rechne es sauber gegen Claude

Dieselben Schlagzeilenzahlen, andere Mechanik.

| | **GPT-6.1 Sol** | **Claude Sonnet 5.5** | **Claude Opus 5.5** |
|---|---|---|---|
| Eingabe / Ausgabe pro MTok | 2 $ / 10 $ | 2 $ / 10 $ | 4 $ / 20 $ |
| Gecachtes Lesen pro MTok | **0,10 $** | 0,20 $ | 0,20 $ |
| Kontext | 1,05 Mio. (922K Eingabe) | 1 Mio. | 1 Mio. |
| Maximale Ausgabe | 128K | 128K | 128K |
| Long-Context-Aufschlag | **Ja, oberhalb von 272K** | Keine veröffentlichte Klippe | Keine veröffentlichte Klippe |

Zwei Konsequenzen, die mehr zählen als die Preisgleichheit in der Schlagzeile:

**In einer langen Agentenschleife ist das gecachte Lesen von GPT-6.1 Sol die günstigere
Position.** 0,10 $ gegen 0,20 $ ist ein Faktor 2 bei genau dem Posten, den eine
agentische Schleife in jeder einzelnen Runde erneut bezahlt. Wenn dein Prompt aus
einem großen stabilen Präfix plus einem kleinen Delta besteht — und genau das ist ein
Agent —, dann sitzt dort die eigentliche Rechnung.

**Oberhalb von 272K dreht sich die Richtung hart um.** Anthropic veröffentlicht für die
Claude-5.5-Modelle keine entsprechende Klippe, also wird eine Arbeitslast, die
wirklich 400K Kontext braucht, nach sehr unterschiedlichen Kurven bepreist. Finde
heraus, auf welcher Seite der 272K du lebst, bevor du irgendetwas vergleichst.

## Die Benchmarks, ehrlich gelesen

OpenAIs Launch-Zahlen, wie sie zum Launch zusammengestellt wurden. Sie stammen vom
Anbieter; bislang hat sie niemand unabhängig reproduziert.

| Benchmark | GPT-6.1 Sol | GPT-6 Astra | Claude | Kosten pro Aufgabe |
|---|---|---|---|---|
| **DeepSWE v1.1** (Software-Engineering) | **75,2 %** (high) | 74,8 % (high) | Sonnet 5.5: 71,0 % | ~1,50 $ vs. Astra ~7,70 $ |
| **OSWorld 2.0** (Computer Use) | 71,4 % (max) | **73,5 %** (max) | Opus 5: 60,3 % (medium) | 1,30 $ vs. Astra 9,30 $ |
| **GDP.pdf** (Dokumentenanalyse) | 32,0 % | **32,2 %** | Opus 5.5: 28,8 % | — |
| **AutomationBench 1.0.6** (Business-Workflows) | 36,0 % | — | **Sonnet 5.5: 44,7 %** | 0,30 $ vs. Sonnet ~1,14 $ |
| Faktenfehlerquote bei niedrigem Effort | **7,7 %** | — | — | (GPT-6 Sol: 11,4 %) |

Drei Dinge, die aus dieser Tabelle mitzunehmen sind:

**1. Die Kostenaussage ist die starke Aussage.** Astra auf DeepSWE um 0,4 Punkte zu
schlagen, ist Rauschen. Es zu ungefähr einem Fünftel der Kosten pro Aufgabe zu tun,
ist es nicht. Der interessante Vergleich in diesem Release ist nie Sol gegen Astra bei
der Qualität — es ist Sol gegen Astra beim Preis für dieselbe Qualität.

**2. AutomationBench ist die Zeile, mit der OpenAI nicht aufgemacht hat.** Claude
Sonnet 5.5 erreicht **44,7 %** gegenüber **36,0 %** von GPT-6.1 Sol — 8,7 Punkte, bei
der Automatisierung von Business-Workflows, zum rund Vierfachen der Kosten pro
Aufgabe. Das ist ein echter Trade-off, kein Kantersieg in die eine oder andere
Richtung: Wenn dich ein fehlgeschlagener Workflow mehr als 0,84 $ kostet, ist das
teure Modell das günstige. Entscheide mit deinen eigenen Fehlerkosten, nicht mit dem
Leaderboard.

**3. Selbst die beste Computer-Use-Zahl liegt bei 71,4 %.** Rund drei von zehn Aufgaben
scheitern in genau dem Benchmark, der für diese Fähigkeit entworfen wurde. Alles, was
[Computer-Use-Agenten im Vergleich](/docs/models/computer-use-agents) über
Bestätigungs-Gates sagt, gilt weiterhin.

Die Zahl zu den Faktenfehlern ist die leiseste interessante Zahl: **7,7 % bei niedrigem
Effort**, herunter von 11,4 % bei GPT-6 Sol. Dass sich die Fehlerquote gerade *in der
günstigen Einstellung* verbessert, ist das, was ein Arbeitspferd-Modell als Standard
statt nur als Rückfalloption brauchbar macht.
