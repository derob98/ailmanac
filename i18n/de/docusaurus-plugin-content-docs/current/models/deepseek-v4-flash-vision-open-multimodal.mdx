Um 00:00 UTC am 31. August 2026 hat DeepSeek still und leise ein neues Repository auf Hugging Face gepusht: `deepseek-ai/DeepSeek-V4-Flash-Vision-Exp`. Zehn Tage nachdem dasselbe Modell auf ihrer API live ging (21. August), sind die Gewichte jetzt MIT-lizenziert und öffentlich. Es ist das erste Modell der V4-Familie mit **nativer Vision** — kein Textmodell mit angeflanschtem Adapter, sondern ein gemeinsam trainiertes multimodales MoE — und seine Agent-Scores auf der Vision-Seite sprangen auf ApexBench von 26,2 auf 36,5, ohne die reinen Text-Agent-Scores überhaupt zu bewegen. Auf mehreren Agent-Benchmarks erreicht oder überholt es jetzt knapp **Claude Opus 4.8**, während die API 0,22 $ pro Million Input-Tokens kostet.

Diese Seite ist der praktische Field Guide, den der Launch nicht mitgeliefert hat: was sich architektonisch geändert hat, die Zahlen, die zählen, das eine harte Limit, vor dem dich niemand warnt, wie du es betreibst und wann Claude trotzdem die richtige Wahl bleibt.

## Die Ein-Satz-Version

**DeepSeek V4-Flash-Vision-Exp** ist ein multimodales Sparse-MoE-Modell mit 305 Milliarden Parametern — 13B aktiv pro Token, 1,048M Tokens Kontext —, das dem V4-Flash-Text-Backbone gemeinsam trainierte Vision hinzufügt, am 31. August 2026 offen unter MIT auf Hugging Face erschienen ist und multimodale Leistung auf Agent-Niveau zu etwa einem Vierzigstel des Preises pro Token von Claude Opus 4.8 liefert.

## Vier Dinge über V4-Flash-Vision, die nicht in den Release Notes stehen

### 1. Vision wurde hinzugefügt, ohne die Text-Agents zu brechen — das ist der ganze Punkt

Jedes offene Lab, das Vision an ein starkes Textmodell angeflanscht hat, hat dafür auf den Text-Benchmarks bezahlt. DeepSeeks Release-Tabelle ist die Machtdemonstration: auf **Terminal Bench 2.1** erreicht das Vision-Modell **83,9** (vs. 82,7 für das reine Textmodell V4-Flash-0731); auf **DeepSWE** klettert es auf **59,3** (von 54,4); auf **Toolathlon-Verified** auf **75,9** (von 70,3). Keiner davon ist ein Vision-Task — es sind reine Code- und Tool-Use-Agent-Evals. Die Vision-Variante ist bei Text-Agent-Arbeit *besser* als der reine Text-Checkpoint, nicht schlechter.

Das ist wichtig, weil es der "Beweis" ist, auf den das Feld seit Chameleon wartet: Man kann ein riesiges MoE gemeinsam für Text und Vision trainieren, ohne dass der multimodale Zusatz eine Text-Regression verursacht — solange der Vision-Head spät genug landet und der Router weiter Text-Experten spezialisieren darf.

### 2. Der Vision-Encoder hat ein hartes Budget von 384 Tokens pro Bild

Das ist die wichtigste Sache, die du lernen musst, bevor du deinen ersten Prompt schreibst. Der Vision-Encoder in V4-Flash-Vision-Exp vergibt **höchstens 384 Tokens pro Bild** — und diese Obergrenze ist architektonisch, keine kommerzielle Policy. Es gibt keinen "High-Detail"-Modus, der mehr freischaltet. Praktische Konsequenzen:

- **Große Screenshots verlieren feinen Text.** Ein 2560×1440-Dashboard, eine dichte CSV als Bild oder eine lange PDF-Seite werden in der Auflösung kodiert, die 384 Tokens visueller Features ausdrücken können — heißt: kleiner Text überlebt den Round-Trip nicht.
- **Zuschneiden, nicht skalieren.** Wenn du Zahlen von einem Chart ablesen musst, schick das Chart auf die relevante Region zugeschnitten, nicht die ganze Seite.
- **Mehrere Bilder schlagen ein riesiges Bild.** Teile große Dokumente in Kacheln pro Region; jede Kachel bekommt ihr eigenes 384-Token-Budget.

Deshalb landet Chartography bei 64,3 (konkurrenzfähig mit den 65,0 von Claude Opus 4.8), aber deshalb übersieht das Modell trotzdem eine Fußnote in 12-Punkt-Schrift auf einem Ganzseiten-Screenshot. Jeder Vision-Agent-Workflow, den du baust, sollte diese Obergrenze voraussetzen.

<VerifyNote lastVerified="2026-09-01" source="https://rits.shanghai.nyu.edu/ai/deepseek-v4-flash-vision-exp-open-weights" />

### 3. Das MoE-Routing ist ungewöhnlich sparse — 6 von 256 Experten feuern pro Token

Die meisten veröffentlichten MoE-Rezepte aktivieren 8 Experten von 32 oder 64. V4-Flash-Vision-Exp nutzt eine viel breitere Expertenbank: **256 geroutete Experten + 1 geteilter Experte**, wobei nur **6 geroutete Experten pro Token feuern** — eine Aktivierungsrate von 2,3 %. Das Modell hat **43 Layer, Hidden Size 4.096**, und der hybride Attention-Stack kombiniert zwei Mechanismen:

- **Compressed Sparse Attention (CSA)** — sparse Muster für Reads über lange Distanzen.
- **Heavily Compressed Attention (HCA)** — eine aggressiv komprimierte Form für den tiefen Kontext-Schwanz.

Darüber gelegt ersetzen **Manifold-Constrained Hyper-Connections (mHC)** das Standard-Residual durch eine Projektion auf eine beschränkte Mannigfaltigkeit, was laut Paper die Signalausbreitung durch den 43-Layer-Stack stabilisiert. Zusammen sind sie der Grund, warum das Modell ein **Kontextfenster von 1.048.576 Tokens** anpreisen kann, ohne die quadratische Attention-Rechnung.

### 4. Der Preis ist die eigentliche Story

Listenpreise, alle pro Million Tokens:

| Modell | Input | Output | Cache-Read |
|---|---|---|---|
| **DeepSeek V4-Flash-Vision-Exp** (API) | **0,22 $** | **0,66 $** | **0,007 $** |
| Claude Opus 4.8 | 15,00 $ | 75,00 $ | 1,50 $ |
| Kimi K3 (Cache-Miss / Cache-Hit) | 3,00 $ / 0,30 $ | 15,00 $ | 0,30 $ |

Cache-Read zu **0,007 $/M** ist kein Tippfehler — das ist grob ein Zweihundertstel Cent pro tausend Tokens. Für jeden Workload, bei dem ein wiederholter System-Prompt oder ein langer Kontext erneut gesendet wird (Agent-Loops, RAG über ein statisches Korpus, Chat mit fester Persona), bricht der effektive Input-Preis zusammen. Das ist der Grund, warum V4-Flash-Vision-Exp in Agent-Kostentabellen zu einem Bruchteil dessen auftaucht, was Claude Opus 4.8 pro Task kostet, selbst wenn die rohe Qualität nur wenige Punkte auseinanderliegt.

*† Der frühere reine Text-Checkpoint wurde auf Bildern bewertet, die er nicht nativ lesen konnte — eine Untergrenze, kein fairer Kampf.*

Die Tabelle geradeheraus gelesen:

- Bei **Text-Agent-Arbeit** liegt V4-Flash-Vision-Exp durchgehend nur wenige Punkte hinter Claude Opus 4.8 und **schlägt V4-Flash-0731** aktiv auf jedem Eval. Vision wurde ohne Regression hinzugefügt.
- Bei **multimodalen Agents** schlägt es Claude Opus 4.8 auf **Agents' Last Exam** und **ZeroBench Pass@5**, liegt knapp zurück auf **ApexBench** und **Chartography**. Das ist der erste Open-Weight-Release, bei dem "erreicht Opus bei multimodalen Agents" kein Marketing-Satz ist.
- Der eine Benchmark, der nicht knapp ist, ist **NL2Repo** (57,7 vs. 69,7). Code-Übersetzung ganzer Repositories ist weiterhin ein Ort, an dem die geschlossene Frontier einen echten Vorsprung hält.

## Das Release-Muster — API zuerst, Gewichte zehn Tage später

V4-Flash-Vision-Exp startete am **21. August 2026** auf der DeepSeek-API und landete erst am **31. August** als Open Weights auf Hugging Face. Diese zehntägige Lücke ist DeepSeeks neuer Standard. Vergleiche Z.ai (GLM), die API + Gewichte gleichzeitig ausliefern; DeepSeek sequenziert absichtlich.

Die Lesart der Branche: Die Labs sind sich jetzt einig, dass große offene MoEs ausgeliefert werden. Die verbleibende Frage ist, *wann* im Release-Zyklus die Gewichte ankommen. Für die Produktionsplanung heißt das:

- Wenn du On-Prem ab Tag null brauchst, achte auf Releases der GLM-Familie.
- Wenn du auf der API starten und ein bis zwei Wochen später auf Self-Hosted umschwenken kannst, ist DeepSeek das Muster.

## Wann du zu V4-Flash-Vision greifst — und wann du bei Claude bleibst

**Greif zu V4-Flash-Vision, wenn:**

- Du multimodale Agent-Qualität etwa auf Opus-4.8-Niveau brauchst und die Kosten eine Rolle spielen. Der Cache-Read-Preis zermalmt alles auf der geschlossenen Frontier.
- Der Workload von einem 1M-Token-Kontext profitiert (Long-Document-VQA, Analyse ganzer Video-Frames, Review großer Repos mit Screenshots).
- Du Open Weights für Compliance, Air-Gapped-Arbeit oder Fine-Tuning brauchst und Frontier-Hardware hast (oder mietest).
- Du eine Chart-lastige oder Dashboard-parsende Pipeline baust, in der du das Bild-Tiling kontrollieren kannst.

**Bleib bei Claude Opus 4.8 (oder Sonnet 5), wenn:**

- Der Job Code-Übersetzung oder -Synthese ganzer Repositories ist — NL2Repo ist der Ausreißer, bei dem der Abstand real ist (57,7 vs. 69,7).
- Du Claude-spezifische Features brauchst: Extended Thinking mit Budget, [Skills](/docs/claude-code/skills), Sub-Agent-Orchestrierung in [Claude Code](/docs/claude-code/what-is-claude-code) oder die [Session-Budget-Kontrollen von Managed Agents](/docs/api/managed-agents-session-budgets).
- Deine Prompts Bilder mit winzigem, kritischem Text enthalten und du nicht kacheln kannst — du triffst das 384-Token-Limit und verlierst Genauigkeit.
- Du einen einzelnen Anbieter / SLA / Support-Kontakt willst und bereits in Anthropic-Tooling investiert bist.

Für ein breiteres Framework zur Modellwahl siehe [Wie man ein Modell wählt](/docs/models/choosing-a-model). Für einen Seite-an-Seite-Vergleich der ganzen Open-Weight-Welle ist [DeepSeek, Qwen & die Open-Weight-Welle](/docs/models/deepseek-qwen-open-models) der dauerhafte Überblick.

## Die Fallstricke, die dich zuerst beißen

1. **Du wirst das 384-Token-Limit vergessen.** Die ersten drei Vision-Agents, die du baust, werden die Auflösung überschießen und still Genauigkeit auf kleinem Text verlieren. Instrumentiere dafür: logge die Dimensionen pro Bild und skaliere + kachle bewusst herunter.
2. **DSpark fällt still weg, wenn du `--speculative-config` weglässt.** Ohne das Flag serviert vLLM das Modell fröhlich mit 1/3 des Throughputs, den der Release angekündigt hat. Übergib die Speculative-Config in Produktion immer.
3. **Das GGUF ist kein Laptop-Modell.** UD-Q4_K_XL ist 155 GB groß. Community-Threads, die es auf kleineren Kisten "laufen" zeigen, betreiben es mit Bruchteilen von Tokens/s über SSD-Swap — technisch funktionierend, nicht nutzbar.
4. **Versionsparität zwischen API und Gewichten ist nicht garantiert.** Das API-Modell kann still aktualisiert werden; die Hugging-Face-Gewichte sind auf `Vision-Exp` gepinnt. Wenn ein Benchmark auf der API von Monat zu Monat um ein paar Punkte wandert, liegt es daran.
5. **`Exp` heißt experimentell.** Die Vision-Variante wird nicht garantiert in produktive V4-Releases übernommen. Bau keine kritische Pipeline auf der Annahme, dass genau dieser Checkpoint in einem Jahr noch da ist.
