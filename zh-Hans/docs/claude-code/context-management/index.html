上下文管理

进阶
What you'll learn
  • 区分 /clear 与 /compact，并立刻选对命令
  • 主动引导一次压缩而不是任由它猜测，并调整自动压缩的触发时机
  • 准确了解压缩后哪些内容会保留、哪些会被摘要掉
  • 运用四种技巧让长会话保持敏锐
  • 识别上下文窗口已满的症状并快速修复
最后验证时间：2026-11-08。

命令名称、自动压缩窗口以及“压缩后保留内容”的对照表会随版本变化——请以官方文档为准。

请对照以下来源核实： 官方来源.

核心思想​

每个会话的上下文窗口都是有限的。窗口被填满时，较早的内容会被压缩，Claude 可能开始“跑偏”。有意识地管理上下文，才能让长会话保持敏锐。

两个必备命令​

两个命令几乎覆盖所有情形。关键是让命令与你的意图相匹配。

按 Enter 或空格键翻转卡片。使用左右方向键在卡片之间切换。已显示术语。
1 / 2

用一个问题来决定：是新任务，还是同一个任务？

两个容易忽略的细节：

  • /compact 接受指令。 /compact focus on the auth bug fix 会保留你选择的内容，而不是自动处理猜测的重点。在开始一个长的新任务之前主动运行它，而不是等窗口逼你去做。
  • /clear 并非不可回头。 传入一个名称（/clear auth refactor），可在 /resume 选择器中为被清除的对话加上标签；在同一个 Claude Code 进程内，回退菜单仍会提供一个 /resume <session-id> (previous session) 条目——参见检查点与回退。

自动压缩——以及如何调整触发点​

当上下文接近上限时，Claude Code 会自动压缩，让工作不至于突然中断。在拥有 1M 上下文窗口的模型上，默认约在 967K token 时触发；更早的模型则在其上下文窗口的边界处压缩。Claude Code 也可能压缩你闲置的对话。

阈值可以由你调整。/autocompact 500k 会更早压缩——当你更想按自己的节奏做摘要，而不是等到 96% 才压缩时很有用——而 /autocompact auto 会恢复为针对你的模型调校过的窗口。

比默认更早压缩

/autocompact 500k
Guided walkthrough1 of 3
  1. 原始 token 数（500000）、带后缀的数值（500k、1m）、auto（恢复为模型调校过的窗口），或 off（在本会话中禁用自动压缩）。不带参数运行 /autocompact 可查看当前窗口。
  2. /autocompact 命令会保存到你的用户设置中 modelSettings 下的当前模型。你也可以在设置 JSON 的顶层设置 autoCompactWindow，或在 modelSettings 下按模型设置，或使用环境变量 CLAUDE_CODE_AUTO_COMPACT_WINDOW。
  3. CLAUDE_CODE_AUTO_COMPACT_WINDOW，然后是 modelSettings 中按模型设置的 autoCompactWindow，然后是顶层 autoCompactWindow，最后是模型的默认窗口。如果优先级更高的设置范围（例如托管设置）指定了窗口，/autocompact 会保存你的值，但会话仍使用该范围的值——并且会告知你。
Pro tip
  • 把自动压缩当作兜底，而不是策略。在不相关的任务之间清空，比等窗口填满、自动压缩触发更能保持上下文干净。
  • 要压缩就有意识地压缩：带聚焦指令的 /compact 胜过让自动处理去猜哪些内容重要。

压缩后保留什么​

压缩摘要的是对话。你的配置从磁盘加载的所有内容会被单独处理——这就是为什么压缩后的会话仍然了解你的项目约定。

Guided walkthrough1 of 5
  1. 系统提示词和输出风格依然生效；项目根目录的 CLAUDE.md、无作用域的规则、自动记忆，以及 Claude 在 plan mode 中写下的计划都会回来。技能描述会根据你当前的技能重新生成（Claude Code v2.1.304 或更高版本）。如果会话以 git status 快照开始，Claude Code 会读取一份新的。
  2. 带 paths: frontmatter 的规则以及子目录中嵌套的 CLAUDE.md 文件会被摘要掉，只有当 Claude 下次接触匹配的文件时才会重新加载。如果某条规则必须在压缩后保留，请去掉 paths: frontmatter，或把它移到项目根目录的 CLAUDE.md 中。
  3. Claude Code 会重新读取 Claude 读过或编辑过的最多五个文件，按最近修改的顺序——但超过 5,000 token 的文件只会以路径引用（'Referenced file'）的形式返回，不含内容。被调用的技能正文会重新注入，上限为每个技能 5,000 token、总计 25,000 token，最旧的先被丢弃，并保留文件开头：把重要内容放在 SKILL.md 靠前的位置。
  4. 对话本身，包括此前由钩子添加的上下文。匹配 'compact' 来源的 SessionStart 钩子会再次运行，它们的输出会加入压缩后的上下文——凡是必须回来的内容，都用这个钩子。
  5. 后台命令和后台子智能体会继续运行，Claude Code 还会提醒 Claude 哪些仍在运行，避免它重复启动。

保持高效的技巧​

除了这两个命令，还有四个习惯能从一开始就让上下文保持精简。

Guided walkthrough1 of 4
  1. 不要让一下午互不相关的工作堆积在同一个上下文里。
  2. 把大量阅读交给子智能体——它们消耗的是它们自己的上下文，只返回结论。参见 /docs/claude-code/subagents。
  3. 用 @path 指向文件，而不是粘贴大段内容，并保持 CLAUDE.md 精简（参见 /docs/claude-code/claude-md）。
  4. 运行 /context 可查看按类别划分的实时明细——彩色网格，外加针对占用上下文较多的工具和臃肿记忆的优化建议，包括加载了哪些 CLAUDE.md 和自动记忆文件。传入 'all' 可在全屏模式下展开逐项列表。显示上下文用量的状态栏能被动地给你同样的信号。参见 /docs/claude-code/statusline。

/context

症状 → 修复

如果 Claude 开始忘记之前的指令或重复自己，窗口很可能已满。/compact（同一任务）或 /clear（新任务）通常能立刻解决。运行 /context 来确认——当对话确实超出了窗口时，输出会指出你超出了多少，以及哪个命令可以释放空间。更多内容见Claude 为什么这样做？。

如果你遇到的是 Autocompact is thrashing，说明压缩在正常工作，只是有某个体积过大的东西不断把窗口重新填满——参见Claude Code 故障排查。

Key takeaways
  • /clear 清空对话以重新开始——用于不相关的任务（别名：/reset、/new）
  • /compact 摘要会话以释放空间——窗口变满时用它继续同一任务，并传入聚焦指令，让它保留你关心的内容
  • 自动压缩是安全网，不是策略：在 1M 上下文模型上约在 967K token 触发，/autocompact 500k（或 auto、off）可移动这条线
  • 压缩会摘要对话，但会从磁盘重新注入 CLAUDE.md、无作用域的规则、自动记忆和计划；按路径限定作用域的规则、嵌套的 CLAUDE.md 文件以及大文件内容不会完整回来
  • 保持上下文精简：每个会话一个任务、把繁重阅读委派给子智能体、引用文件而不是粘贴，并查看 /context 或状态栏
  • 遗忘或重复意味着窗口已满——/compact（同一任务）或 /clear（新任务）即可解决
