Claude Code 中的 MCP 服务器

高级
最后验证时间：2026-11-10。

claude mcp 命令、配置作用域和传输方式会不断演进——请在 Claude Code 官方 MCP 文档和 modelcontextprotocol.io 中确认。下文的四种传输方式、作用域的存储路径、SSE 的弃用以及项目审批行为,均出自该页面。

请对照以下来源核实： 官方来源.

Model Context Protocol(MCP) 是把 AI 连接到外部工具和数据的开放标准。MCP 服务器对外提供各种能力(查询数据库、创建 GitHub PR、操控浏览器);Claude Code 连接到它,并能在会话中调用这些工具。这就是把 Claude 扩展到你的文件系统和 shell 之外的方式。

What you'll learn
  • 说明 MCP 服务器是什么,以及 Claude Code 如何调用它的工具
  • 区分两类传输方式:本地 stdio 与远程 HTTP/SSE
  • 用 claude mcp add 添加服务器,并读懂它写入的 JSON
  • 根据谁应该看到某个服务器,选择合适的作用域(local、project、user)
  • 把一个真实的数据库端到端地连接到 Claude
  • 避开大多数人都会踩到的安全与配置陷阱

整体结构​

你声明 Claude 可以使用哪些服务器;每个服务器发布一组带 schema 的工具;Claude 像调用其他工具一样挑选并调用它们。

传输方式​

Claude 连接服务器有四种方式。根据服务器在哪里运行、如何通信来选择。

  • stdio——由 Claude 启动的本地进程(非常适合本地工具/CLI)。没有 type 的 JSON 条目指的就是它。
  • HTTP——托管式服务器,通常使用 OAuth。任何远程服务的默认选择。
  • SSE——已弃用;能用 HTTP 就用 HTTP。有些服务仍然只提供 SSE 端点,而从 Claude Code v2.1.265 起,--transport http 会先尝试 HTTP,并自动切换到 SSE,所以你很少需要显式写 --transport sse。
  • WebSocket(ws / wss)——持久的双向连接,适用于会主动推送事件的服务器。--transport 不接受 ws:请用 claude mcp add-json '{"type":"ws","url":"wss://…"}' 添加,或直接写进 .mcp.json。不支持 OAuth——认证仅限请求头。
Watch out
  • 只有 url 而没有 type 的 JSON 条目是配置错误,而不是合理的默认值:Claude Code 会把没有 type 的条目当作 stdio 服务器读取,跳过它,并报告它有「url」却没有「type」。手写远程服务器时,务必设置 "type": "http"(或 "sse" / "ws")。

配置服务器​

最快的途径是 claude mcp add 命令——它会替你写好配置。按下面的顺序操作,就能从零走到一个已连接的服务器。

Guided walkthrough1 of 4
  1. 运行 claude mcp add——-- 之后的所有内容就是 Claude 替你运行的启动命令。
  2. 传入 --transport http 和作用域,再给出服务器 URL。远程服务器通常是托管式的,并使用 OAuth。
  3. 运行 claude mcp list,查看已配置的服务器及其连接状态。
  4. 在会话中使用 /mcp 检查服务器的工具,并对远程服务器进行认证。

添加本地 stdio 服务器

# A local stdio server (everything after -- is the launch command)
claude mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem ~/code/myproject

添加远程 HTTP 服务器(与项目共享)

# A remote HTTP server, shared with everyone on the project
claude mcp add --transport http --scope project github https://api.githubcopilot.com/mcp/

底层其实就是 JSON。project 作用域的服务器会写入仓库根目录的 .mcp.json——把它提交后,队友一旦信任该工作区,就能获得同样的工具:

{
  "mcpServers": {
    "github": { "type": "http", "url": "https://api.githubcopilot.com/mcp/" }
  }
}
Watch out
  • 不要去用旧教程里出现的 @modelcontextprotocol/server-github、-postgres、-slack 或 -puppeteer 这些包。它们已被归档,并带有 npm 弃用提示:「Archived and unmaintained; no security guarantees」。有厂商官方服务器的就用官方的——GitHub 的就是上面的 HTTP 端点,浏览器控制则已迁移到 @playwright/mcp。在 TypeScript 参考服务器中,仍在维护的只有 filesystem、memory、everything 和 sequential-thinking。

作用域决定谁能看到服务器​

作用域存储位置在何处加载适用场景
local(默认)~/.claude.json,位于此项目路径之下仅此项目个人实验、密钥
project仓库中的 .mcp.json(已提交)仅此项目,与团队共享整个团队都应共享的工具
user~/.claude.json你所有的项目你希望在任何地方都能用的服务器
Watch out
  • MCP 的「local 作用域」与本地设置不是一回事。local 作用域的 MCP 服务器存放在你主目录下的 ~/.claude.json 中——而不是项目里的 .claude/settings.local.json。到项目文件夹里去找只会白费功夫。

运行 claude mcp list 查看已连接的服务器,在会话中用 /mcp 检查工具并认证远程服务器。可复制粘贴的起步模板见 MCP 配置与服务器脚手架。

实战示例:把你的数据库交给 Claude​

假设你希望 Claude 针对本地 Postgres 回答问题,而不是由你自己粘贴查询结果。用 project 作用域添加服务器,这样队友也能用上。

数据库正是已归档服务器问题最突出的地方:旧的 @modelcontextprotocol/server-postgres 已不再维护,也没有官方替代品,所以包名是你必须自己做出的唯一决定。选一个仍在维护的社区服务器,先审查它,再接入——无论选哪个,形式都一样:

用 project 作用域添加 Postgres 服务器

# Replace the package with a maintained Postgres MCP server you have reviewed.
# The connection string is read-only on purpose — see below.
claude mcp add --scope project db -- npx -y <postgres-mcp-server> "postgresql://readonly@localhost/app"

现在,在会话中你可以用自然语言提问,让 Claude 替你完成查询循环:

向数据库提问

How many users signed up last week? Check the DB.

Claude 会调用服务器发布的查询工具,取回数据行并作答——不再需要来回复制粘贴。除非 Claude 确实需要写入,否则请让连接字符串保持只读。另外,如果你其实只想执行一次查询,请注意通过 Bash 运行 psql -c '…' 消耗的 token 只是一小部分;MCP 的 token 税说明了两者各自何时更划算。

由于是 project 作用域,拉取仓库的队友会获得同样的能力——但不是悄无声息,也不是立刻。已提交的 .mcp.json 中的服务器会停留在 ⏸ Pending approval,直到队友在该文件夹中运行 claude 并接受工作区信任对话框。克隆下来的仓库无法预先批准自己的服务器:提交到项目 .claude/settings.json 中的 enableAllProjectMcpServers 或 enabledMcpjsonServers,在不受信任的文件夹中会被忽略。而来自用户级 ~/.claude/settings.json、托管设置或通过 --settings 传入的批准,在那里仍然有效。这就是「为什么我的队友看不到这个服务器?」的常见答案。

信任与安全​

Watch out
  • MCP 服务器会运行代码,并能读取数据、执行操作——只连接你信任的服务器。
  • 只授予每个服务器所需的最小权限。
  • 服务器返回的任何外部内容都可能携带提示注入。
  • 连接第三方服务器之前先审查它们。
把 MCP 服务器当作安装软件来对待

MCP 服务器会运行代码,并能读取数据、执行操作。只连接你信任的服务器,授予它们所需的最小权限,并记住它们返回的任何外部内容都可能携带提示注入。先审查第三方服务器——参见审查第三方代码。

应用里也有 MCP​

MCP 同样驱动着 Claude 应用中的连接器——同一标准,不同界面。参见应用中的连接器(MCP),API 方面则参见 MCP 与连接工具。

常见错误​

  • 作用域选错。 以 local 作用域添加的服务器不会出现在队友那里;只想自己用的服务器,也不应以 project 作用域提交。要有意识地选择。
  • 服务器太多,工具太多。 工具搜索默认开启,所以已连接的服务器通常每一轮只消耗其工具名称和服务器说明,而不是完整 schema——但这仍是每轮都要交的税,而且 Claude 一搜索,schema 就会进入上下文。连接任务需要的,而不是你的整个目录。真实数据、ENABLE_TOOL_SEARCH 的各种模式,以及代码执行如何降低第二项成本,见 MCP 的 token 税。
  • 连接权限过大。 除非 Claude 确实需要写入,否则给数据库服务器一个只读角色。MCP 让能力变得真实——请收窄它们。
  • 忽视注入风险。 服务器返回的任何内容(网页、issue 正文、一行数据)都是不受信任的文本,可能携带提示注入。不要在没有仔细考虑的情况下,把一个强大的可写服务器和一个不受信任的可读服务器接在一起。

Key takeaways
  • MCP 是开放标准;MCP 服务器暴露的工具,Claude Code 会像调用其他工具一样调用。
  • 四种传输方式:stdio(由 Claude 启动的进程)、HTTP(远程的默认选择)、SSE(已弃用——HTTP 会自动切换到它)和 WebSocket ws/wss(推送、请求头认证、仅限 add-json)。
  • claude mcp add 会替你写好配置;底层就是 JSON。project 作用域保存在已提交的 .mcp.json 中,队友那一份会停在 Pending approval,直到他们信任该工作区。
  • 作用域控制可见性:local(你,当前项目)、project(提交给团队)、user(你,所有项目)。
  • 像对待安装软件一样对待服务器:信任、最小权限,并警惕它们返回的一切内容中的提示注入。
