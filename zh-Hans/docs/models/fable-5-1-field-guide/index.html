Claude Fable 5.1：有哪些变化，以及如何迁移

进阶

2026 年 9 月 1 日，Anthropic 发布了 Claude Fable 5.1（claude-fable-5-1）及其需要通过验证才能使用的孪生模型 Claude Mythos 5.1（claude-mythos-5-1）。如果只是扫一眼发布信息，你会把它归为"更好的 Fable"然后继续往下走。别这样。这是第一个仅替换模型 ID 就可能在生产环境返回 400 的 Claude 小版本：强制 tool_choice 被移除，thinking 块现在与产生它们的模型和对话绑定，而修改对话历史在新账户上会被强制作为错误处理。这也是第一个价格表上最便宜的那一行最值得关注的版本：缓存读取从 $1 降到 每 MTok $0.25，这就是为什么 Anthropic 能在标价 $10 / $50 不变的情况下，宣称典型工作负载成本下降约 25%，高度智能体化的工作负载最多下降 45%。

本页是迁移指南：改了什么、哪里会出问题、你能得到什么，以及一份半天就能跑完的清单。

What you'll learn
  • 了解让 claude-fable-5 → claude-fable-5-1 的替换变成 400 的三项破坏性变更，以及各自的修复方法
  • 使用五项新增功能：按消息设置 effort、限定在单轮的系统消息、进度更新、更便宜的缓存读取、内容溯源
  • 识别无需改代码就会出现的七种行为变化（并行工具调用减少、旁白减少、行文更密集、整文件重写）
  • 对照 Fable 5、Opus 5 和 GPT-5.6 Sol 阅读发布时的基准测试，而不被营销话术带着走
  • 为你的工作负载在 Fable 5.1、Opus 5 和 Fable 5 之间做出选择，然后执行迁移清单
最后验证时间：2026-09-14。

模型 ID、定价、破坏性变更、beta 请求头和行为说明均来自 Anthropic 官方的 "What's new in Claude Fable 5.1"、模型概览、迁移指南和定价页面，全部于 2026 年 9 月 14 日读取。基准测试数字是 Anthropic 在发布公告中自行给出的。这里提到的三个 beta 可能会改变形态；上线前请重新核对请求头。最新的模型表见当前模型与定价。

请对照以下来源核实： 官方来源.

一段话版本​

Fable 5.1 是 Fable 5 的继任者：同样是高于 Opus 的 Mythos 级别，同样是 1M token 上下文、128K 最大输出、$10 输入 / $50 输出，同样的分词器，同样始终开启的自适应 thinking，同样是在响应体内返回 stop_reason: "refusal"，同样要求 30 天数据保留（不支持 ZDR）。Anthropic 自己的建议在精神上没有变：大多数工作先用 Opus 5，把 Fable 5.1 留给"高难度推理和长周期智能体工作，或者在更高 effort 下 Claude Opus 5 的评测仍不够用的时候"。新增的内容是：三项破坏性变更、五项新增功能、便宜了 75% 的缓存读取，以及一组你最好在评测套件告诉你之前就了解的行为变化。

三项破坏性变更​

这是你不能直接换个 ID 就完事的原因。每一项都是 400，而不是悄无声息的性能下降。

1. 强制使用工具会返回错误​

tool_choice: {"type": "any"} 和 {"type": "tool", "name": "..."} 现在会返回 400 invalid_request_error：

tool_choice: type "tool" and "any" are not supported for this model.

原因很能说明问题：thinking 始终开启，而强制工具调用会跳过它，于是模型会把推演过程放到工具参数里，参数质量随之下降。该检查适用于 Messages API、Message Batches API 和 token 计数端点。auto（默认）和 none 不变。

修复方法只需改两行：保持 tool_choice 为 auto，在工具上设置 strict: true，并在 schema 中加入 additionalProperties: false，同时在提示词里写明该工具何时适用。Anthropic 的说明是，Fable 5.1"能可靠地遵循明确的工具指令"。如果你真正想要的是符合 schema 的 JSON 而不是工具调用，请改用结构化输出。

强制工具调用 → strict 工具 + 明确指令

# Before (Fable 5) — now a 400 on Fable 5.1
"tool_choice": {"type": "tool", "name": "record_summary"}

# After (Fable 5.1)
"tools": [{
"name": "record_summary",
"description": "Record the structured summary of the document.",
"strict": true,
"input_schema": {
  "type": "object",
  "properties": {"summary": {"type": "string"}},
  "required": ["summary"],
  "additionalProperties": false
}
}],
"tool_choice": {"type": "auto"},
"messages": [{"role": "user",
"content": "Summarize: The meeting moved to Thursday. Call the record_summary tool with your result."}]

2. thinking 块是单向的​

现在每个 thinking 块都会记录是哪个模型产生的，而且保留是单向的：Fable 5.1 可以读取来自 Opus 5、Fable 5、Mythos 5 以及所有更早 Claude 的 thinking 块；它们都无法读取 Fable 5.1 的。 迁移到 Fable 5.1 的对话会保留其推理。迁移离开它的对话（路由器、回退到 Opus 5、会话中途为省钱而降级）会丢失 Fable 5.1 各轮的推理。

API 的处理方式是：在目标模型看到之前，丢弃它读不了的块。被丢弃的块不计费，也不计入 input_tokens。没有 thinking-binding-controls-2026-08-01 beta 请求头时，丢弃是静默的；带上该请求头后，丢弃会在顶层的 input_transformations 数组中报告。如果你在模型之间做路由，请发送该请求头并记录这个数组。静默丢失推理，正是那种在 bug 报告里表现为"模型在第 12 步之后变笨了"的问题。

3. 修改更早的轮次会使 thinking 块失效​

这一条值得读两遍。修改 Fable 5.1 thinking 块之前的任何内容，包括 system 提示词、tools 数组或任何更早的消息，都会使之后的所有 thinking 块失效。在强制执行检查的地方，下一次请求会被拒绝，返回 400，消息内容为 The block is bound to a different conversation。

截至目前的执行规则：

  • 2026 年 8 月 31 日及之后创建的账户： 强制执行。
  • 更早的账户： API 会记录不匹配，但只有在你自己设置了 thinking.block_binding.prefix_mismatch_behavior 时才会采取行动。
  • Mythos 5.1 完全不做这项检查。
  • Claude Code、claude.ai、Managed Agents 和 Agent SDK 会替你保持前缀完整。只有手工构建的 messages 数组有风险。

Anthropic 自己列出的会使块失效的情形，转述出来其实是一份常见智能体框架习惯的清单：

使之后所有 thinking 块失效仍保持有效
编辑、重排或删除较早的轮次，同时保留之后的轮次移除开头的一段 thinking 块，从最旧的开始
在较早的轮次中注入每次请求的提醒或状态行，然后在下一次请求时移除服务端压缩，或裁剪历史的上下文编辑
在同一对话的多次请求之间重新构建顶层的 system 或 tools移动 cache_control 标记
之后返回不同字节的图片或文档 URL（检查按字节进行，所以同一文件的轮换签名 URL 没问题）在请求之间更改 effort

所有修复都归结为一条规则：把对话当作仅追加的。 每轮提醒改用限定在单轮的系统消息（见下文）。工具和指令的变更改用对话中途的系统消息与工具变更。裁剪改用服务端压缩。若想继续而不是报错，请发送 thinking-binding-controls-2026-08-01 请求头并设置 prefix_mismatch_behavior: "drop_block"；之后丢弃会在 input_transformations 中报告，reason 为 prefix_binding_mismatch。

Anthropic 部分地把这视为一项反蒸馏措施：发布文章称，新的 API 账户不能再在保留对话记录的同时手动编辑先前的上下文，这堵住了一种公开记录过的蒸馏手法。对你的实际好处是，同样的纪律也能让提示词缓存保持热状态。

五项新增功能​

按消息设置 effort（beta）​

现在可以在对话中途更改 effort，而不会使提示词缓存失效。难的一步调高，例行的步骤调低。发送 mid-conversation-output-config-2026-07-01 beta 请求头，并插入一条只包含 effort 的系统消息；新的级别从下一个用户轮次开始生效。在 Claude API 和 Google Cloud 上，Fable 5.1、Mythos 5.1 和 Opus 5 均支持。

在总结轮次降低 effort，同时不破坏缓存

{
"model": "claude-fable-5-1",
"max_tokens": 4096,
"output_config": {"effort": "high"},
"messages": [
  {"role": "user", "content": "Plan a migration from SQLite to PostgreSQL in three short steps."},
  {"role": "assistant", "content": "1. Export the SQLite data. 2. Create the PostgreSQL schema. 3. Import the data and verify row counts."},
  {"role": "system", "content": [], "output_config": {"effort": "low"}},
  {"role": "user", "content": "Summarize the plan in one sentence."}
]
}
# header: anthropic-beta: mid-conversation-output-config-2026-07-01

这与 Thinking 与 Effort 以及 Effort 调优中的 effort 指导相配合：默认值是 high，而"整个会话使用同一级别"现在只是偷懒的选择，不再是唯一的选择。

限定在单轮的系统消息（beta）​

在 role: "system" 的消息上设置 clear_at: "next_user_message"，它就只在当前轮次拥有系统提示词的权威，一旦后面出现 user 消息便不再渲染。你需要继续原样回传它，因此之前的内容都不变，缓存保持命中，之后的 thinking 块依然有效，而且已清除的消息不消耗输入 token。请求头：mid-conversation-system-clear-at-2026-08-21。

{
  "role": "system",
  "clear_at": "next_user_message",
  "content": "Results have landed in your inbox. Check it before running more code."
}

这是对"注入提醒、下次请求再删除"这一模式的官方替代方案，而破坏性变更 3 现在会惩罚这种模式。

工具调用之间的进度更新（beta）​

与 Fable 5 一样，Fable 5.1 会在工具调用之间写简短的进度说明，每条都是紧挨在调用之前的一个独立 thinking 块。在默认的 thinking.display: "omitted" 下，这些内容返回时是空的，因此一个很长的智能体轮次在用户看来是静默的。新增：display: "updates"（请求头 thinking-display-updates-2026-08-18）会以文本形式返回进度说明，而推理保持隐藏。此时任何文本非空的 thinking 块都是一条可以渲染的状态行。"summarized" 也会返回它们，并与摘要后的推理混在一起。原始思维链依然不会返回。

在 Fable 5.1 和 Mythos 5.1 上，缓存读取是基础输入的 0.025 倍，而其他所有 Claude 模型是 0.1 倍。写入价格和 512 token 的最小可缓存提示词不变；批处理仍是 5 折（$5 / $25）。对于每轮都要重新读取一大段缓存前缀的长智能体循环，发布文章里"最多便宜 45%"就来自这里。横向说明：三天后发布、标价同为 $10 / $50 的 OpenAI GPT-6 Astra，缓存读取收费 $1.00，是 Fable 5.1 的四倍；参见 Astra 指南。

内容溯源​

所有 Fable 5.1 和 Mythos 5.1 的文本在所有平台上都带有 Anthropic 的统计型文本水印。Claude 生成的文件（例如通过代码执行）在经由 Files API 获取时，会带有已签名的 C2PA Content Credentials。Anthropic 表示，水印不会增加 token 或隐藏字符，不携带任何关于你或你所在组织的信息，也不需要更改请求。背景：Anthropic 于 2026 年 7 月签署了欧盟 AI 法案（EU AI Act）关于 AI 生成内容透明度的行为准则，并面向监管机构、事实核查人员、研究人员以及需要验证的企业，提供处于私有预览阶段的检测 API。

无需改代码就会看到的七种行为变化​

Anthropic 公开记录了这些变化，每一项在官方的 Prompting Claude Fable 5.1 指南中都有提示词层面的修复办法。请在用户发现之前，先在评测里留意它们。

按 Enter 或空格键翻转卡片。使用左右方向键在卡片之间切换。已显示术语。

与 Fable 5 完全一致的部分​

如果你已经正确接入了 Fable 5，以下内容都会原样沿用：

  • 自适应 thinking 始终开启。带 budget_tokens 的 thinking: {"type": "enabled"} 和 {"type": "disabled"} 都会返回 400。请省略 thinking，或发送 {"type": "adaptive"}。
  • thinking.display 默认为 "omitted"；原始思维链永远不会返回。
  • 交错 thinking 是自动的，无需 beta 请求头。
  • 预填充（prefill）返回 400。非默认的 temperature、top_p、top_k 返回 400。
  • 拒绝以 HTTP 200 和 stop_reason: "refusal" 加 stop_details.category 的形式到达；在任何输出之前就到达的拒绝不会计费。允许的回退目标是 Opus 5 和 Opus 4.8，而回退抵扣会退还切换时的提示词缓存成本。完整模式见拒绝与安全。
  • 30 天保留是强制的；来自没有它的组织或工作区的请求会返回 400。两个模型都属于 Covered Models。
  • 一处值得知道的差异：Fable 5.1 和 Mythos 5.1 都不支持 Priority Tier。 Fable 5 支持。如果你购买了优先容量，这是暂时留在 Fable 5 的一个理由。

如实解读发布时的基准测试​

数字是 Anthropic 的，测试框架也是 Anthropic 的。与 GPT-5.6 Sol 的对比是 OpenAI 最先会提出异议的，而 OpenAI 自己的 GPT-6 Astra 三天后就发布了，所以请把它当作 9 月 1 日的状况，而不是 9 月 14 日的。

  1. 从 Fable 5 到 5.1 的提升在长周期智能体工作上最大（Terminal-Bench-Science 翻了一番，AutomationBench 几乎翻了一番）。这与 Anthropic 自己"当更高 effort 的 Opus 5 仍然不够用时再用它"的定位一致：收益在持续数小时的运行上，而不是聊天。
  2. Opus 5 比标题所暗示的更接近，在好几行上都是如此（Terminal-Bench 4.0：52.3 对 55.8；GDPval：1824 对 1853），而标价只有一半。Anthropic 一再让你先用 Opus 5，是有原因的。
  3. 客户引言谈的是 token，而不仅是准确率。 Cognition、Rogo、Browserbase 和 Block 都提到，在结果相同或更好的情况下 token 更少。结合 $0.25 的缓存读取，"同样的工作 Fable 5.1 比 Fable 5 更便宜"比"Fable 5.1 更聪明"这个说法更站得住脚。

Mythos 5.1：同一个模型，不同的安全防护​

Anthropic 表示 Fable 5.1 和 Mythos 5.1 是同一个底层模型，只是安全防护配置不同，规格和定价相同。Mythos 5.1 只提供给通过 Anthropic 验证计划验证的组织：面向防御性安全工作的 Cyber Verification Program，以及面向生物工作的 Life Sciences Verification Program。在安全防护方面，有两处变化对所有人生效：Fable 5.1 现在被允许为防御目的识别软件漏洞（Anthropic 报告每个会话的网络安全防护干预减少约 60%），而渗透测试、漏洞利用生成和二进制漏洞扫描等双重用途任务仍会被重定向到 Opus 模型；并且对于无害的基础生物学和医学问题，生物安全防护的触发减少约 85%。Mythos 5.1 还会跳过 thinking 块的对话绑定检查。如果你没有通过验证，Anthropic 的指示很简单：使用 Fable 5.1。

最后验证时间：2026-10-21。

获得验证是一次申请，而不是邀请：这在 2026 年 10 月 6 日发生了变化，当天 Project Glasswing 被重组为 Cyber Verification Program 的三个层级：Defense Access（组织，以及付费套餐的个人）、Red Team Access（仅限组织）和 Specialized Access（仅限组织，与美国政府合作审核，现有 Glasswing 成员被归入此层级）。每个层级都提供 Opus 5.5、Sonnet 5.5 和 Mythos 5.1。请通过 portal.anthropic.com/programs 的 Verification Portal 申请；决定通常在七个工作日内送达。资格取决于防御是否是你的实际业务："Organizations whose main business falls outside that scope may not be eligible."

请对照以下来源核实： 官方来源.

注意命名：Fable 5 指南把 Mythos 5 解释为"没有安全分类器的 Fable 5"。对于 5.1，Anthropic 的措辞是"不同的安全防护配置"，而且 Mythos 5.1 仍在为 Anthropic 自己的 Claude Security 产品提供支持。把它当作配置不同的部署，而不是不受过滤的版本。

要点回顾​

Key takeaways
  • 只有在你从不强制 tool_choice、从不编辑对话历史、也从不把 thinking 块路由给更旧模型的情况下，Fable 5.1 才能直接替代 Fable 5。替换 ID 之前，先 grep 这三种情况。
  • 把对话当作仅追加：每轮提醒用限定在单轮的系统消息，指令和工具变更用对话中途的消息，裁剪用服务端压缩。这样既能保持 thinking 块有效，又能让缓存保持热状态。
  • 定价的重点是 $0.25 的缓存读取。长智能体循环会变便宜；短对话不会。$5 / $25 的 Opus 5 仍然是 Anthropic 自己说的'从这里开始'。
  • 预期会看到并行工具调用减少、旁白减少、行文更密集和整文件重写；每一项都有一行提示词的修复办法，而 thinking.display: "updates" 能恢复可见的进度。
  • Priority Tier 和 ZDR 是留在 Fable 5 或 Opus 5 的两个合同层面的理由。
