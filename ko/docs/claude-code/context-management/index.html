컨텍스트 관리

중급
What you'll learn
  • /clear와 /compact를 구분하고 즉시 알맞은 것을 고르기
  • 압축을 Claude의 추측에 맡기지 않고 직접 유도하며, 자동 압축이 발동하는 시점을 조정하기
  • 압축 후 무엇이 살아남고 무엇이 요약되어 사라지는지 정확히 알기
  • 긴 세션을 예리하게 유지하는 네 가지 기법 적용하기
  • 컨텍스트 윈도우가 가득 찼을 때의 증상을 알아보고 빠르게 해결하기
최종 검증: 2026-11-08.

명령어 이름, 자동 압축 윈도우, 압축 후 유지되는 항목 표는 릴리스마다 바뀝니다 — 공식 문서에서 확인하세요.

다음에서 확인하세요: 공식 출처.

큰 아이디어​

모든 세션에는 유한한 컨텍스트 윈도우가 있습니다. 윈도우가 차오르면 오래된 내용이 압축되고, Claude가 "흐트러지기" 시작할 수 있습니다. 컨텍스트를 의도적으로 관리하는 것이 긴 세션을 예리하게 유지하는 비결입니다.

두 가지 필수 명령​

두 가지 명령으로 거의 모든 상황을 다룰 수 있습니다. 요령은 의도에 맞는 명령을 고르는 것입니다.

Enter 또는 스페이스 키를 눌러 카드를 뒤집습니다. 좌우 화살표 키로 카드를 이동할 수 있습니다.용어가 표시되었습니다.
1 / 2

질문 하나로 결정하세요: 새 작업인가, 같은 작업인가?

놓치기 쉬운 두 가지 세부 사항:

  • /compact는 지시를 받을 수 있습니다. /compact focus on the auth bug fix는 자동 처리가 중요하다고 추측한 내용이 아니라 당신이 고른 내용을 남깁니다. 윈도우가 강제로 압축하길 기다리지 말고, 긴 새 작업을 시작하기 전에 의도적으로 실행하세요.
  • /clear는 되돌릴 수 없는 지점이 아닙니다. 이름을 전달하면(/clear auth refactor) /resume 선택기에서 나가는 대화에 라벨이 붙고, 같은 Claude Code 프로세스 안에서는 되감기 메뉴에 /resume <session-id> (previous session) 항목이 계속 표시됩니다 — 체크포인트와 되감기를 참고하세요.

자동 압축 — 그리고 임계값 옮기기​

컨텍스트가 한계에 가까워지면 Claude Code는 작업이 갑자기 멈추지 않도록 자동으로 압축합니다. 1M 컨텍스트 윈도우 모델에서는 기본적으로 약 967K 토큰에서 발동하고, 이전 모델은 컨텍스트 윈도우의 경계에서 압축합니다. 방치해 둔 대화를 Claude Code가 압축하기도 합니다.

임계값은 직접 옮길 수 있습니다. /autocompact 500k는 더 일찍 압축합니다 — 96%가 찼을 때가 아니라 원하는 시점에 요약하고 싶을 때 유용하며, /autocompact auto는 모델에 맞게 조정된 윈도우로 되돌립니다.

기본값보다 일찍 압축하기

/autocompact 500k
Guided walkthrough1 of 3
  1. 토큰 수 그대로(500000), 접미사가 붙은 값(500k, 1m), 모델에 맞게 조정된 윈도우로 돌아가는 auto, 세션의 자동 압축을 끄는 off. 인수 없이 /autocompact를 실행하면 현재 윈도우를 볼 수 있습니다.
  2. /autocompact 명령은 사용자 설정의 modelSettings 아래에 현재 모델 기준으로 저장합니다. 설정 JSON의 최상위에 autoCompactWindow를 두거나, modelSettings 아래에 모델별로 두거나, 환경 변수 CLAUDE_CODE_AUTO_COMPACT_WINDOW를 사용할 수도 있습니다.
  3. CLAUDE_CODE_AUTO_COMPACT_WINDOW, 그다음 modelSettings의 모델별 autoCompactWindow, 그다음 최상위 autoCompactWindow, 그다음 모델의 기본 윈도우. 관리형 설정처럼 우선순위가 더 높은 설정 범위가 윈도우를 지정하면, /autocompact는 값을 저장하지만 세션은 그 범위의 값을 유지하며 — 그 사실을 알려 줍니다.
Pro tip
  • 자동 압축은 전략이 아니라 안전망으로 여기세요. 관련 없는 작업 사이에 비우는 편이, 자동 압축이 발동할 때까지 윈도우를 채우는 것보다 컨텍스트를 더 깨끗하게 유지합니다.
  • 압축할 때는 의도적으로 하세요: 포커스 지시가 있는 /compact가 무엇이 중요했는지 추측하는 자동 처리보다 낫습니다.

압축 후 살아남는 것​

압축은 대화를 요약합니다. 설정이 디스크에서 불러오는 모든 것은 별도로 처리됩니다 — 그래서 압축된 세션도 프로젝트 규칙을 계속 알고 있습니다.

Guided walkthrough1 of 5
  1. 시스템 프롬프트와 출력 스타일은 계속 적용됩니다. 프로젝트 루트의 CLAUDE.md, 범위 지정 없는 규칙, 자동 메모리, Claude가 plan mode에서 작성한 플랜이 돌아옵니다. 스킬 설명은 현재 스킬로부터 다시 만들어집니다(Claude Code v2.1.304 이상). 세션이 git status 스냅샷과 함께 시작되었다면 Claude Code가 새로 읽습니다.
  2. paths: 프런트매터가 있는 규칙과 하위 디렉터리의 중첩된 CLAUDE.md 파일은 요약되어 사라지고, Claude가 다음에 일치하는 파일을 건드릴 때만 다시 로드됩니다. 압축 후에도 규칙이 유지되어야 한다면 paths: 프런트매터를 제거하거나 프로젝트 루트의 CLAUDE.md로 옮기세요.
  3. Claude Code는 Claude가 읽거나 편집한 파일 중 최대 다섯 개를, 가장 최근에 수정된 것부터 다시 읽습니다 — 다만 5,000 토큰을 넘는 파일은 내용 없이 경로 참조('Referenced file')로 돌아옵니다. 호출된 스킬 본문은 스킬당 5,000 토큰, 전체 25,000 토큰 상한으로 다시 주입되며, 오래된 것부터 버려지고 파일의 앞부분이 유지됩니다: 중요한 내용은 SKILL.md 위쪽에 두세요.
  4. 대화 자체, 그리고 앞서 훅이 추가한 컨텍스트도 포함됩니다. 'compact' 소스와 일치하는 SessionStart 훅은 다시 실행되고 그 출력이 압축된 컨텍스트에 합류합니다 — 반드시 돌아와야 하는 내용에는 이 훅을 쓰세요.
  5. 백그라운드 명령과 백그라운드 서브에이전트는 계속 실행되며, Claude Code는 어떤 것이 아직 실행 중인지 Claude에게 알려 주어 중복 실행을 막습니다.

효과적으로 유지하는 기법​

두 가지 명령 외에, 네 가지 습관이 처음부터 컨텍스트를 가볍게 유지해 줍니다.

Guided walkthrough1 of 4
  1. 관련 없는 작업을 오후 내내 하나의 컨텍스트에 쌓아 두지 마세요.
  2. 큰 읽기 작업은 서브에이전트에 맡기세요 — 서브에이전트가 자신의 컨텍스트를 쓰고 결론만 돌려줍니다. /docs/claude-code/subagents를 참고하세요.
  3. 큰 덩어리를 붙여넣는 대신 @path로 Claude가 파일을 보게 하고, CLAUDE.md는 간결하게 유지하세요(/docs/claude-code/claude-md 참고).
  4. /context를 실행하면 카테고리별 실시간 내역을 볼 수 있습니다 — 색상 그리드와 함께, 컨텍스트를 많이 쓰는 도구와 비대해진 메모리에 대한 최적화 제안, 그리고 로드된 CLAUDE.md 및 자동 메모리 파일이 표시됩니다. 'all'을 전달하면 전체 화면 모드에서 항목별 목록이 펼쳐집니다. 컨텍스트 사용량을 보여 주는 상태 표시줄은 같은 신호를 수동적으로 제공합니다. /docs/claude-code/statusline을 참고하세요.

컨텍스트가 실제로 어디에 쓰였는지 보기

/context

이들은 최신 문서와 연결됩니다: 서브에이전트, CLAUDE.md, 상태 표시줄.

증상 → 해결

Claude가 앞선 지시를 잊거나 같은 말을 반복하기 시작하면 윈도우가 가득 찼을 가능성이 높습니다. /compact(같은 작업) 또는 /clear(새 작업)로 보통 즉시 해결됩니다. /context를 실행해 확인하세요 — 대화가 실제로 윈도우를 초과했다면 출력에 얼마나 넘었는지와 어떤 명령으로 공간을 확보할 수 있는지가 표시됩니다. 자세한 내용은 Claude는 왜 그렇게 했을까?를 참고하세요.

대신 Autocompact is thrashing이 뜬다면, 압축은 작동하고 있지만 크기가 큰 무언가가 윈도우를 계속 다시 채우고 있는 것입니다 — Claude Code 문제 해결을 참고하세요.

Key takeaways
  • /clear는 새로 시작하기 위해 대화를 지웁니다 — 관련 없는 작업에 사용 (별칭: /reset, /new)
  • /compact는 세션을 요약해 공간을 확보합니다 — 윈도우가 찰 때 같은 작업을 이어 가는 데 사용하고, 중요한 내용이 남도록 포커스 지시를 전달하세요
  • 자동 압축은 전략이 아니라 안전망입니다: 1M 컨텍스트 모델에서는 약 967K 토큰에서 발동하며, /autocompact 500k(또는 auto, off)로 그 선을 옮길 수 있습니다
  • 압축은 대화를 요약하지만 CLAUDE.md, 범위 지정 없는 규칙, 자동 메모리, 플랜은 디스크에서 다시 주입합니다. 경로 범위 규칙, 중첩된 CLAUDE.md 파일, 큰 파일 내용은 온전하게 돌아오지 않습니다
  • 컨텍스트를 가볍게 유지하세요: 세션당 하나의 작업, 무거운 읽기는 서브에이전트에 위임, 붙여넣지 말고 파일 참조, /context나 상태 표시줄로 확인
  • 잊어버림이나 반복은 윈도우가 가득 찼다는 뜻 — /compact(같은 작업) 또는 /clear(새 작업)로 해결
