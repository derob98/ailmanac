MiniMax H3 (Hailuo 3.0): 오픈 웨이트 옴니 비디오 모델

중급

2026년 8월 3일, MiniMax는 MiniMax-H3(소비자 명칭: Hailuo 3.0)의 가중치를 Hugging Face에 공개했습니다. 이는 330억 파라미터의 단일 스트림 트랜스포머로, 텍스트, 이미지, 비디오, 오디오 레퍼런스를 최대 2K/24fps의 4~15초 클립과 네이티브 스테레오 오디오로 변환하며, 이 모든 것을 한 번의 패스로 생성합니다. 마지막 부분이 흥미로운데, 별도의 TTS 단계도, 덧붙인 SFX 파이프라인도 없습니다. 대사, 룸 톤, 화면이 같은 모델에서 함께 나옵니다.

3일 앞서 유료 API는 2K 기준 초당 $0.1625(분당 약 $9.75)에 오픈되었는데, 이는 유사한 해상도에서 Kling 3.0이나 Seedance 2.0의 약 절반 가격입니다. Artificial Analysis 리더보드의 단일 실행 점수에서 H3는 오디오 포함 비디오 편집 부문 1위, 텍스트-투-비디오 및 이미지-투-비디오에서 상위 3위를 기록했습니다. 프론티어 수준의 비디오 품질, 오픈 웨이트, 분당 $10 미만의 정직한 가격이라는 이 조합이 이번 주 모든 생성형 미디어 피드에 H3를 올린 이유입니다.

이 페이지는 다른 대부분의 글이 놓치는 부분을 다룹니다. H3가 실제로 당신에게 유용한지를 결정하는 요소들 말입니다.

What you'll learn
  • H3 아키텍처(단일 스트림 트랜스포머, H3-VAE, MM-RoPE)를 이해하고, 왜 하나의 순전파에서 비디오와 오디오를 생성하는지 파악하기
  • 랜딩 페이지에 없는 세 가지 셀프 호스팅 함정 알기: 지역 제한 라이선스, 오픈 베이스의 768p 상한, AdaLN 파라미터 스킵 트릭
  • 실행 가능한 셀프 호스팅 경로 얻기: 최소 42.5 GB 가중치, 양자화 선택지, 12 GB 카드가 오프로딩으로 실행하는 방법
  • 복사할 수 있는 실제 cURL로 API에서 H3 시도하기, 입력 형태 제한(최대 12개 파일, 본문 ≤64 MB, 공개 URL만) 알기
  • 가격, 제어, 라이선스에서 명확한 결정 기준으로 H3와 클로즈드 대안(Kling 3.0, Seedance 2.0, Veo, Sora) 사이에서 선택하기
최종 검증: 2026-08-08.

비디오 모델 가격, 라이선스 조건, 양자화 체크포인트는 이 분야에서 매주 변합니다. 이 페이지의 달러 기호, GB 수치, 벤치마크 순위가 있는 모든 것은 스냅샷입니다. 커밋하기 전에 공식 모델 카드와 벤더의 가격 페이지를 다시 확인하세요. 아키텍처 사실(33B / 단일 스트림 / MM-RoPE / 네이티브 오디오)이 지속되는 부분입니다.

다음에서 확인하세요: 공식 출처.

헤드라인에서 명확하지 않은 H3에 관한 세 가지​

1. Community License는 미국, EU, 영국, 한국에서의 셀프 호스팅을 차단합니다​

Hugging Face 모델 카드는 MiniMax H3 Community License Agreement를 링크하는데, 그 텍스트는 네 지역에 대해 신청 게이트가 있습니다: 미국, 유럽 연합, 영국, 대한민국. 실제로 이는 다음을 의미합니다: 당신이나 조직이 이러한 지역 중 하나에 있고 자체 하드웨어에서 H3를 실행하려는 경우(또는 사용자에게 서비스하려는 경우) 먼저 platform.minimax.io/h3-license에서 H3 라이선스 신청을 완료해야 합니다. 이 제한은 가중치뿐만 아니라 출력물에도 적용되며, 이는 대부분의 재게시 글이 놓치는 세부 사항입니다.

이러한 지역 외부에 있다면 표준 Community License가 적용됩니다. 이러한 지역에 있다면 신청이 승인될 때까지 API를 기본 경로로 취급하거나, 가중치를 다루는 것을 배포하기 전에 조직의 라이선스 검토자를 사용하세요. 이는 실제로 집행 가능한 제한이며, 흔한 "나쁜 일 하지 마세요" 조항이 아닙니다.

2. 오픈 베이스의 상한은 768p입니다 — 2K는 API 내부에만 존재합니다​

H3에 대한 "최대 2K" 헤드라인은 모두 핵심 세부 사항을 생략합니다: 오픈 웨이트 베이스 모델(텍스트-투-비디오/첫-마지막-프레임용 Base FL2VA, 멀티 레퍼런스용 Base Ref2VA)은 768p에서 생성합니다. Hailuo 앱에서 사람들이 감탄하는 2K 출력은 H3-Regenerate-2K에서 나오는데, 이는 베이스 모델 이후에 실행되는 인컨텍스트 업샘플러이며 MiniMax는 이를 오픈소스로 공개하지 않았습니다. 멀티모달 명령 전처리기인 H3-Context-IR도 API 전용입니다.

셀프 호스터에게 결과는 간단합니다: 프론티어 시스템이 구축된 것과 동일한 생성 품질을 얻지만, 사후에 자체 업스케일러(Topaz, ESRGAN, 디퓨전 업샘플러)를 체인하지 않으면 768p가 상한입니다. 많은 사용 사례에서는 이것으로 충분합니다. 24fps의 768p는 소셜 클립, 스토리보드, 빠른 반복에 충분합니다. 하지만 유료 티어와 동일한 제품은 아닙니다.

3. 33B 파라미터 중 약 13B는 미리 계산하고 건너뛸 수 있는 AdaLN 브랜치입니다​

모델 카드는 H3-Omni-Transformer를 33B 밀집 단일 스트림 트랜스포머로 분해하는데, 그 중 약 13B 파라미터가 AdaLN 관련 브랜치에 있습니다. AdaLN(Adaptive Layer Norm)은 디퓨전 스타일 트랜스포머가 조건화 신호(타임스텝, 클래스, 텍스트 임베딩)를 흡수하는 방식이며, 그 출력은 조건화 슬롯별로 미리 계산 가능합니다. 이것이 서드파티 제공업체가 순진한 BF16 가중치가 훨씬 더 크더라도 최소 42.5 GB의 작동 구성에 도달하는 방법입니다: 프루닝된 INT8 체크포인트(~20 GB)를 NVFP4 AWQ 텍스트 인코더(~16 GB) 및 두 VAE(~5.8 GB)와 결합하고, 추론 시 캐시된 브랜치 가중치를 건너뜁니다.

ComfyUI 생태계의 경험 법칙: 12 GB 카드는 CPU/RAM 오프로딩으로 H3를 실행할 수 있습니다. 단, 클립당 렌더링 시간이 길어집니다. 24 GB 이상이 있다면 오프로드가 필요하지 않습니다.

H3가 실제로 무엇인가 (아키텍처를 한 페이지에)​

H3는 단일 스트림, 모달리티 무관 트랜스포머입니다. 하나의 어텐션 스택, 하나의 FFN 스택이 있으며, 비디오/오디오/텍스트 토큰이 모두 이를 통과합니다. 실제로 로드하는 네 가지 구성 요소는 다음과 같습니다:

구성 요소역할오픈소스?
H3-Omni-Transformer33B 밀집 생성기 (비디오 + 오디오)✅ (BF16, INT8, 프루닝 INT8)
H3-Encoder멀티모달 텍스트/비전 인코더 — Qwen3-VL-32B 레이어-50 히든 상태 재사용✅
H3-VisualVAE시간-인과 비디오 오토인코더, f16t4d24 압축✅
H3-AudioVAE스테레오 오디오, 32 kHz 출력, 40 Hz 시간 속도✅
H3-Context-IR멀티모달 명령 전처리기❌ API 전용
H3-Regenerate-2K2K로 인컨텍스트 업스케일러❌ API 전용

H3를 다른 비디오 모델과 비교하는 사람이라면 주목할 만한 두 가지 설계 선택이 있습니다:

  • 3D MM-RoPE 위치 임베딩. 로터리 위치가 세 축(공간 x, 공간 y, 시간)으로 확장되어, 시간적 일관성이 별도의 시간 모듈로 추가되는 것이 아니라 어텐션 패턴에 내장됩니다. 이것이 H3가 15초 클립 전반에 걸쳐 피사체 정체성과 조명을 안정적으로 유지하는 주요 이유 중 하나입니다.
  • H3-VAE는 유효 시퀀스 길이에서 4배 이득을 제공합니다. 커스텀 토크나이저는 이전 오픈 비디오 모델에서 사용된 표준 VAE보다 토큰당 더 많은 픽셀을 패킹합니다. 이것이 이 파라미터 클래스에서 2K 출력을 가능하게 만드는 이유입니다.

네이티브 오디오 패스는 다른 차별화 요소입니다. 대사, SFX, 룸 톤이 화면과 동일한 순전파에서 생성되기 때문에 립싱크와 다이제틱 오디오가 기본적으로 일관되게 나옵니다. 레퍼런스 오디오(WAV/MP3, 클립당 2~15초, 최대 3개 클립)로 음성 복제가 가능합니다. 단, 오디오 레퍼런스는 이미지 또는 비디오 레퍼런스와 함께 제공되어야 합니다. API는 오디오 전용 입력을 거부합니다.

Guided walkthrough1 of 4
  1. 네이티브 H3 지원은 가중치가 공개된 같은 날(2026년 8월 3일)에 ComfyUI에 병합되었습니다. 최신 버전을 가져오면 새 H3 노드가 자동으로 나타납니다.
  2. 24 GB 이상 카드 → INT8 또는 BF16. 12~16 GB 카드 → 프루닝 INT8 + NVFP4 AWQ 텍스트 인코더 + CPU 오프로드. 12 GB 미만이면 API를 사용하세요. 좋은 경험을 하지 못할 것입니다.
  3. 3개 로컬(텍스트-투-비디오, 이미지-투-비디오, 레퍼런스-투-비디오) 및 3개 API 백드(텍스트-투-비디오, 레퍼런스-투-비디오, 첫/마지막-프레임-투-비디오)가 ComfyUI의 내장 갤러리에 포함됩니다. 노드를 직접 연결하는 대신 템플릿에서 시작하세요.
  4. 조직이 미국, EU, 영국 또는 한국에 있다면 사용자 대상의 무언가에 H3를 배포하기 전에 platform.minimax.io/h3-license에서 신청을 완료하세요.

API를 통한 H3 호출​

API는 REST + 폴링입니다. 작업을 POST하고, task_id를 받고, status == "succeeded"가 될 때까지 쿼리 엔드포인트를 폴링합니다. 공개 URL만 작동합니다. Base64 페이로드는 거부되며, 총 요청 본문은 64 MB로 제한됩니다. 레퍼런스 제한: 최대 9개 이미지, 최대 3개 비디오 클립, 최대 3개 오디오 클립, 총 12개 파일, 최대 7,000자 프롬프트.

음성 레퍼런스가 있는 H3 텍스트-투-비디오 (Python)

import os, time, requests

headers = {"Authorization": f"Bearer {os.environ['MINIMAX_API_KEY']}"}

payload = {
  "model": "MiniMax-H3",
  "content": [
      {"type": "text",
       "text": "Wide shot: a lighthouse keeper walks onto the balcony and says, 'Follow the wind, live free.' Voice follows reference audio 1."},
      {"type": "audio_url",
       "audio_url": {"url": "https://example.com/voice-ref.mp3"},
       "role": "reference_audio"},
      {"type": "image_url",
       "image_url": {"url": "https://example.com/lighthouse.jpg"},
       "role": "reference_image"},
  ],
  "resolution": "2K",   # 2K is the only value the API accepts right now
  "duration": 8,        # seconds, 4–15
  "ratio": "16:9",
}

task_id = requests.post(
  "https://api.minimax.io/v2/video_generation",
  headers=headers, json=payload,
).json()["task_id"]

while True:
  time.sleep(10)
  task = requests.get(
      f"https://api.minimax.io/v2/query/video_generation/{task_id}",
      headers=headers,
  ).json()["task"]
  if task["status"] == "succeeded":
      print(task["video_url"])
      break
  if task["status"] == "failed":
      raise RuntimeError(task)

diffusers를 통한 로컬 H3 (셀프 호스팅, 768p)

from diffusers import DiffusionPipeline
import torch

pipe = DiffusionPipeline.from_pretrained(
  "MiniMaxAI/MiniMax-H3",
  dtype=torch.bfloat16,
  device_map="cuda",
)

video, audio = pipe(
  prompt="Slow dolly-in on a neon-lit ramen shop at night; steam rising; jazz sax outside.",
  num_frames=24 * 8,   # 8 seconds at 24 fps
  height=768, width=1344,
  generator=torch.manual_seed(42),
)
video.save("ramen.mp4"); audio.save("ramen.wav")

최적 용도최저 $/분에 최고 충실도 출력; 제한 지역 외부라면 온프레미스/셀프 호스팅긴 샷 전반의 스타일 안정성시네마틱 룩, 프롬프트 충실도중국 벤더에 프롬프트를 유출할 수 없고 프론티어 완성도가 필요할 때

다음의 경우 H3를 선택하세요: 2K에서 프레임 내 오디오가 필요할 때, 분당 비용이 중요하고 클로즈드 API가 예산을 초과할 때, 컴플라이언스로 인해 생성을 온프레미스로 유지해야 하고 법적 상황이 Community License를 통과할 때. 다음의 경우 H3를 건너뛰세요: 팀이 제한된 지역 중 하나에 있고 신청을 통과하지 못했을 때, 워크플로가 네이티브 4K에 의존할 때, 프롬프트를 중국 본토 API로 보낼 수 없을 때(유료 티어는 MiniMax에서 호스팅되며, 출시 시 미국 지역 미러가 없음).
