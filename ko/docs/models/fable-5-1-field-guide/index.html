Claude Fable 5.1: 무엇이 바뀌었고 어떻게 마이그레이션할까

중급

2026년 9월 1일, Anthropic은 Claude Fable 5.1(claude-fable-5-1)과 검증이 필요한 쌍둥이 모델 Claude Mythos 5.1(claude-mythos-5-1)을 출시했습니다. 출시 소식을 훑어보면 "더 좋아진 Fable" 정도로 분류하고 넘어가기 쉽습니다. 그러지 마세요. 이번은 모델 ID만 바꿔도 프로덕션에서 400이 반환될 수 있는 첫 번째 Claude 포인트 릴리스입니다. 강제 tool_choice가 사라졌고, thinking 블록은 이제 그것을 만든 모델과 대화에 묶이며, 대화 히스토리 편집은 신규 계정에서 오류로 강제됩니다. 또 가격표에서 가장 싼 항목이 가장 흥미로운 첫 릴리스이기도 합니다. 캐시 읽기가 $1에서 MTok당 $0.25로 내려갔고, 그래서 Anthropic은 정가 $10 / $50이 그대로인데도 일반적인 워크로드는 약 25%, 에이전트 비중이 큰 워크로드는 최대 45% 저렴하다고 말할 수 있습니다.

이 페이지는 마이그레이션 가이드입니다. 무엇이 바뀌었는지, 무엇이 깨지는지, 무엇을 얻는지, 그리고 오후 한나절이면 돌려볼 수 있는 체크리스트를 다룹니다.

What you'll learn
  • claude-fable-5 → claude-fable-5-1 교체를 400으로 바꾸는 세 가지 호환성 파괴 변경과 각각의 해결책을 안다
  • 다섯 가지 추가 기능을 활용한다: 메시지별 effort, 턴 범위 시스템 메시지, 진행 상황 업데이트, 더 저렴한 캐시 읽기, 콘텐츠 출처 표시
  • 코드 변경 없이 나타나는 일곱 가지 동작 변화(병렬 도구 호출 감소, 설명 감소, 더 조밀한 문장, 파일 전체 재작성)를 알아본다
  • Fable 5, Opus 5, GPT-5.6 Sol과 비교한 출시 벤치마크를 홍보 문구에 휘둘리지 않고 읽는다
  • 워크로드에 맞게 Fable 5.1, Opus 5, Fable 5 중 하나를 고르고 마이그레이션 체크리스트를 실행한다
최종 검증: 2026-09-14.

모델 ID, 가격, 호환성 파괴 변경, 베타 헤더, 동작 관련 내용은 Anthropic 공식 "What's new in Claude Fable 5.1", 모델 개요, 마이그레이션 가이드, 가격 페이지에서 가져왔으며, 모두 2026년 9월 14일에 확인했습니다. 벤치마크 수치는 출시 발표에 실린 Anthropic 자체 수치입니다. 여기서 언급한 세 가지 베타는 형태가 바뀔 수 있으니 배포 전에 헤더를 다시 확인하세요. 최신 모델 표는 현재 모델과 가격을 참고하세요.

다음에서 확인하세요: 공식 출처.

한 문단 요약​

Fable 5.1은 Fable 5의 후속입니다. Opus 위에 있는 Mythos급 티어라는 점, 1M 토큰 컨텍스트, 128K 최대 출력, $10 입력 / $50 출력, 같은 토크나이저, 항상 켜져 있는 적응형 thinking, 대역 내 stop_reason: "refusal" 동작, 30일 보관 요건(ZDR 불가)이 모두 같습니다. Anthropic의 가이드도 취지는 그대로입니다. 대부분의 작업은 Opus 5로 시작하고, Fable 5.1은 "까다로운 추론과 장기 에이전트 작업, 또는 더 높은 effort의 Claude Opus 5에서도 평가 결과가 부족할 때" 사용하라는 것입니다. 새로운 점은 호환성 파괴 변경 세 가지, 추가 기능 다섯 가지, 75% 저렴해진 캐시 읽기, 그리고 평가 스위트가 알려주기 전에 알아 두어야 할 동작 변화들입니다.

호환성을 깨는 변경 세 가지​

ID만 바꿔서는 안 되는 이유입니다. 각각 조용한 성능 저하가 아니라 400입니다.

1. 강제 도구 사용은 오류를 반환합니다​

tool_choice: {"type": "any"}와 {"type": "tool", "name": "..."}는 이제 400 invalid_request_error를 반환합니다.

tool_choice: type "tool" and "any" are not supported for this model.

이유를 보면 이해가 됩니다. thinking은 항상 켜져 있는데 강제 도구 호출은 그 과정을 건너뛰게 되므로, 모델이 사고 과정을 도구 인자 안에서 처리하게 되어 인자의 품질이 떨어집니다. 이 검사는 Messages API, Message Batches API, 토큰 카운팅 엔드포인트에 모두 적용됩니다. auto(기본값)와 none은 그대로입니다.

해결책은 두 줄 수정입니다. tool_choice는 auto로 두고, 도구에 strict: true를 설정하며 스키마에는 additionalProperties: false를 넣고, 도구를 언제 써야 하는지 프롬프트에 명시하세요. Anthropic의 설명으로는 Fable 5.1이 "명시적인 도구 지시를 안정적으로 따릅니다." 원하는 것이 도구 호출이 아니라 스키마에 맞는 JSON이었다면 구조화된 출력으로 옮기세요.

강제 도구 호출 → strict 도구 + 명시적 지시

# Before (Fable 5) — now a 400 on Fable 5.1
"tool_choice": {"type": "tool", "name": "record_summary"}

# After (Fable 5.1)
"tools": [{
"name": "record_summary",
"description": "Record the structured summary of the document.",
"strict": true,
"input_schema": {
  "type": "object",
  "properties": {"summary": {"type": "string"}},
  "required": ["summary"],
  "additionalProperties": false
}
}],
"tool_choice": {"type": "auto"},
"messages": [{"role": "user",
"content": "Summarize: The meeting moved to Thursday. Call the record_summary tool with your result."}]

2. thinking 블록은 단방향입니다​

이제 모든 thinking 블록에는 어느 모델이 만들었는지가 기록되며, 보존은 한 방향으로만 이루어집니다. Fable 5.1은 Opus 5, Fable 5, Mythos 5, 그리고 이전의 모든 Claude가 만든 thinking 블록을 읽을 수 있지만, 그 모델들은 Fable 5.1의 블록을 읽을 수 없습니다. Fable 5.1으로 넘어오는 대화는 추론을 유지합니다. Fable 5.1에서 나가는 대화(라우터, Opus 5로의 폴백, 세션 중 비용 절감용 다운그레이드)는 Fable 5.1이 진행한 턴의 추론을 잃습니다.

API는 대상 모델이 읽을 수 없는 블록을 모델이 보기 전에 제거하는 방식으로 이를 처리합니다. 제거된 블록은 과금되지 않고 input_tokens에도 포함되지 않습니다. thinking-binding-controls-2026-08-01 베타 헤더가 없으면 제거는 조용히 이루어지고, 헤더가 있으면 최상위 input_transformations 배열에 보고됩니다. 모델 사이를 라우팅한다면 헤더를 보내고 그 배열을 로그에 남기세요. 추론이 조용히 사라지면 버그 리포트에 "12단계 이후 모델이 멍청해졌어요"라고 나타나기 마련입니다.

3. 이전 턴을 편집하면 thinking 블록이 무효화됩니다​

두 번 읽어 볼 항목입니다. Fable 5.1 thinking 블록보다 앞에 있는 어떤 것이든, 즉 system 프롬프트, tools 배열, 이전 메시지를 수정하면 그 뒤의 모든 thinking 블록이 무효화됩니다. 검사가 적용되는 곳에서는 다음 요청이 The block is bound to a different conversation이라는 메시지의 400으로 거부됩니다.

현재 적용 규칙은 다음과 같습니다.

  • 2026년 8월 31일 이후 생성된 계정: 강제 적용됩니다.
  • 이전 계정: API가 불일치를 기록하지만, thinking.block_binding.prefix_mismatch_behavior를 직접 설정한 경우에만 조치합니다.
  • Mythos 5.1은 이 검사를 전혀 수행하지 않습니다.
  • Claude Code, claude.ai, Managed Agents, Agent SDK는 prefix를 알아서 유지해 줍니다. 직접 만든 messages 배열만 위험합니다.

Anthropic이 제시한 무효화 요인 목록을 풀어 쓰면, 흔히 쓰는 에이전트 하네스 습관의 목록입니다.

이후의 모든 thinking 블록을 무효화유효하게 유지
이후 턴은 두고 이전 턴을 편집, 재정렬, 삭제선두의 thinking 블록 묶음을 오래된 것부터 제거
요청마다 리마인더나 상태 줄을 이전 턴에 주입했다가 다음 요청에서 제거서버 측 컴팩션 또는 히스토리를 줄이는 컨텍스트 편집
한 대화 안에서 요청마다 최상위 system이나 tools를 다시 구성cache_control 마커 이동

해결책은 모두 한 가지 규칙으로 모입니다. 대화를 추가 전용(append-only)으로 다루세요. 턴별 리마인더는 턴 범위 시스템 메시지(아래)로 바꿉니다. 도구와 지시의 변경은 대화 중간 시스템 메시지와 도구 변경으로 처리합니다. 히스토리 정리는 서버 측 컴팩션으로 합니다. 오류 대신 계속 진행하려면 thinking-binding-controls-2026-08-01 헤더와 prefix_mismatch_behavior: "drop_block"을 보내세요. 그러면 제거가 input_transformations에 reason: "prefix_binding_mismatch"로 보고됩니다.

Anthropic은 이를 부분적으로 증류 방지 조치로 설명합니다. 출시 글에 따르면 새 API 계정은 더 이상 이전 컨텍스트를 수동으로 편집하면서 대화 기록을 유지할 수 없으며, 이는 공개적으로 알려진 증류 기법을 막습니다. 사용자 입장에서 실질적인 이점은 같은 규율이 프롬프트 캐시도 따뜻하게 유지해 준다는 점입니다.

Fable 5와 완전히 동일하게 유지되는 것​

Fable 5를 이미 제대로 연동했다면 아래는 모두 그대로 이어집니다.

  • 적응형 thinking은 항상 켜져 있습니다. budget_tokens가 있는 thinking: {"type": "enabled"}와 {"type": "disabled"}는 둘 다 400을 반환합니다. thinking을 생략하거나 {"type": "adaptive"}를 보내세요.
  • thinking.display의 기본값은 "omitted"이며, 원본 사고 과정은 반환되지 않습니다.
  • 인터리브드 thinking은 자동이며 베타 헤더가 필요 없습니다.
  • Prefill은 400을 반환합니다. 기본값이 아닌 temperature, top_p, top_k도 400을 반환합니다.
  • 거절은 HTTP 200과 stop_reason: "refusal", stop_details.category로 도착하며, 출력이 나오기 전에 도착한 거절에는 과금되지 않습니다. 허용되는 폴백 대상은 Opus 5와 Opus 4.8이고, 폴백 크레딧이 전환에 드는 프롬프트 캐시 비용을 환불해 줍니다. 전체 패턴은 거절과 안전에 있습니다.
  • 30일 보관은 필수이며, 보관이 설정되지 않은 조직이나 워크스페이스의 요청은 400을 반환합니다. 두 모델 모두 Covered Models입니다.
  • 알아 둘 만한 차이 하나: Fable 5.1과 Mythos 5.1은 모두 Priority Tier를 지원하지 않습니다. Fable 5는 지원합니다. 우선 용량을 구매했다면 당분간 Fable 5에 머물 이유가 됩니다.

Mythos 5.1: 같은 모델, 다른 안전장치​

Anthropic은 Fable 5.1과 Mythos 5.1이 안전장치 구성만 다른 동일한 기반 모델이며 사양과 가격이 같다고 밝힙니다. Mythos 5.1은 Anthropic의 검증 프로그램을 통과한 조직에만 제공됩니다. 방어적 보안 작업을 위한 Cyber Verification Program과 생명과학 작업을 위한 Life Sciences Verification Program이 있습니다. 안전장치 측면에서 모든 사용자에게 바뀐 것이 두 가지 있습니다. Fable 5.1은 이제 방어 목적으로 소프트웨어 취약점을 식별할 수 있고(Anthropic은 세션당 사이버 안전장치 개입이 약 60% 줄었다고 보고), 침투 테스트, 익스플로잇 생성, 바이너리 취약점 스캔 같은 이중 용도 작업은 여전히 Opus 모델로 리디렉션됩니다. 또한 생물학 안전장치는 무해한 기초 생물학 및 의료 질문에서 약 85% 덜 발동합니다. Mythos 5.1은 thinking 블록의 대화 binding 검사도 건너뜁니다. 검증을 받지 않았다면 Anthropic의 안내는 간단합니다. Fable 5.1을 쓰세요.

최종 검증: 2026-10-21.

검증은 초대가 아니라 신청입니다. 이는 2026년 10월 6일에 바뀌었고, 이날 Project Glasswing이 Cyber Verification Program의 세 가지 티어로 재편되었습니다. Defense Access(조직 및 유료 플랜의 개인), Red Team Access(조직 전용), Specialized Access(조직 전용, 미국 정부와 협력하여 심사하며 기존 Glasswing 멤버가 옮겨 간 곳)입니다. 모든 티어가 Opus 5.5, Sonnet 5.5, Mythos 5.1을 제공합니다. portal.anthropic.com/programs의 Verification Portal에서 신청하세요. 결정은 보통 영업일 기준 7일 이내에 나옵니다. 자격은 방어가 실제 본업인지에 달려 있습니다. "Organizations whose main business falls outside that scope may not be eligible."

다음에서 확인하세요: 공식 출처.

이름에 주의하세요. Fable 5 가이드는 Mythos 5를 "안전 분류기가 없는 Fable 5"로 설명했습니다. 5.1에 대한 Anthropic의 표현은 "다른 안전장치 구성"이며, Mythos 5.1은 여전히 Anthropic 자체 Claude Security 제품을 구동합니다. 필터가 없는 모델이 아니라 구성이 다르게 배포된 모델로 보세요.

핵심 정리​

Key takeaways
  • Fable 5.1은 tool_choice를 강제하지 않고, 대화 히스토리를 편집하지 않고, thinking 블록을 이전 모델로 라우팅하지 않는 경우에만 Fable 5의 드롭인 대체입니다. ID를 바꾸기 전에 세 가지를 모두 grep하세요.
  • 대화를 추가 전용으로 다루세요. 턴별 리마인더는 턴 범위 시스템 메시지, 지시와 도구 변경은 대화 중간 메시지, 히스토리 정리는 서버 측 컴팩션입니다. thinking 블록도 유효하게 유지하고 캐시도 따뜻하게 유지합니다.
  • 가격 이야기의 핵심은 $0.25 캐시 읽기입니다. 긴 에이전트 루프는 저렴해지고 짧은 채팅은 그렇지 않습니다. $5 / $25의 Opus 5는 여전히 Anthropic 스스로 권하는 '여기서 시작'입니다.
  • 병렬 도구 호출 감소, 설명 감소, 더 조밀한 문장, 파일 전체 재작성을 예상하세요. 각각 한 줄 프롬프트로 해결할 수 있고, thinking.display: "updates"가 눈에 보이는 진행 상황을 되살려 줍니다.
  • Priority Tier와 ZDR은 Fable 5나 Opus 5에 머물러야 하는 두 가지 계약상의 이유입니다.
