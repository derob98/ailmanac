Cowork 예약 작업: 기기가 켜져 있지 않아도 실행되는 에이전트

중급
최종 검증: 2026-08-05.

웹 + 모바일용 Cowork는 2026년 7월 7일에 출시되었습니다 (Max 요금제가 먼저, 다른 유료 요금제는 몇 주 후 순차적으로). 가용성, 할당량, 정확한 커넥터 커버리지는 빠르게 변하고 있으니 — 여기의 수치에 의존하기 전에 공식 블로그 게시글과 Claude Cowork에서 반복 작업 예약하기 헬프센터 문서로 확인하세요.

다음에서 확인하세요: 공식 출처.

Cowork는 2026년 7월 7일부로 더 이상 데스크톱 전용 워크스페이스가 아닙니다. 이제 웹 (claude.ai), iOS 및 Android에서 실행되며 — 대부분의 리뷰가 잘 다루지 않는 부분은 — 세션이 Anthropic의 서버에서 실행된다는 점입니다. 여러분의 기기가 아닙니다. 이 하나의 아키텍처 변화가 헤드라인 기능을 가능하게 만듭니다: 노트북이 닫혀 있고, 휴대폰이 주머니에 있고, 어떤 기기도 온라인이 아닌 상태에서 실행되는 예약 작업.

이 페이지는 실무 현장 가이드입니다: 어떤 서피스에서 실제로 무엇이 작동하는지, 예약 작업을 처음부터 올바르게 설정하는 방법, 그리고 월요일 오전 6시 브리핑이 로컬 파일이 필요해서 조용히 실패한 뒤에야 알아차리게 되는 소수의 함정들.

What you'll learn
  • Cowork 실행을 기기에서 분리한 것이 제품(예약 실행, 크로스 디바이스 핸드오프, 모바일 승인 프롬프트)을 어떻게 바꾸는지 — 그리고 트레이드오프가 어디에서 발생하는지 이해하기
  • 역량 매트릭스를 사용해 주어진 작업에 맞는 서피스(데스크톱 / 웹 / 모바일)를 선택하기
  • 올바른 승인 모드, 빈도, 작업 폴더로 Cowork 예약 작업을 처음부터 올바르게 설정하기
  • 잠들었거나 비행기 안에 있을 때 조용히 멈추지 않는 모바일 승인 플로우 설계하기
  • 프로덕션에서 예약 실행을 망가뜨리는 네 가지 함정 피하기: 로컬 전용 도구, 데스크톱 전용 Fable 5, Dispatch 대 Remote, 그리고 커넥터 인증 드리프트

중요한 단 하나의 변화: 세션이 Anthropic의 서버로 이동했다​

2026년 7월 이전에는 Cowork 세션이 Mac 또는 PC의 Claude Desktop 앱 내부의 프로세스였습니다. 노트북을 닫으면 세션이 죽습니다. 앱을 종료하면 세션이 죽습니다. 이것이 7월 이전 Cowork 루프가 항상 "데스크톱을 열고 깨어있게 유지하라"로 시작한 이유입니다.

7월 출시는 원격 세션을 도입합니다: Cowork 루프는 Anthropic의 클라우드에서 살고, 세션 상태와 파일은 여러분의 Claude 계정에 대해 유지되며, 어떤 서피스(웹, 모바일, 데스크톱)든 동일한 근본 세션에 대한 뷰어 + 입력 장치일 뿐입니다.

두 가지 직접적인 결과:

  1. 예약 작업이 가능해집니다. 반복 작업이 월요일 06:00에 깨어나 45분간 작업하고 계정에 초안을 남길 수 있습니다 — 어떤 기기도 온라인이 아닌 상태로, 루프에 기기가 없기 때문입니다.
  2. 크로스 디바이스 핸드오프는 무료입니다. 책상에서 작업을 시작하고, 노트북을 닫고, 실행 중인 같은 세션을 휴대폰에서 볼 수 있습니다. 동기화할 것이 없습니다 — 세션은 애초에 노트북에 있었던 적이 없습니다.

트레이드오프는 아래의 역량 매트릭스입니다: 로컬 머신에 접근해야 하는 모든 것(디스크의 파일, 브라우저, OS)은 데스크톱에서만 실행할 수 있습니다. 그것이 두 세계에 발을 걸친 유일한 서피스이기 때문입니다.

인터랙티브 Cowork 대 예약 작업 대 Dispatch​

이 세 가지 모드는 자주 혼동됩니다. 서로 다른 짐승들입니다:

Guided walkthrough1 of 3
  1. 여러분이 시작하고, 지켜보며, Claude가 여러분의 활성 목표에 대해 긴 시간에 걸쳐 작업합니다. 이제 Anthropic 서버에서 실행되므로 기기 간에 핸드오프할 수 있습니다. 최적: 진행되는 동안 조종하고 싶은 여러 시간의 작업.
  2. 프롬프트 + 주기(시간별 / 일별 / 평일 / 주별 / 수동)를 정의합니다. 각 실행은 지정한 도구, 스킬, 플러그인으로 새로운 Cowork 세션을 생성합니다. 어떤 기기가 온라인이든 아니든 예약대로 원격에서 실행됩니다. 최적: 반복적인 준비 작업 — 월요일 06:00 브리핑, 시간별 인박스 분류, 일 마감 정리.
  3. 레거시 형태: 활성 데스크톱 세션에서 백그라운드 작업을 실행시키고 계속 채팅하는 동안에도 계속 실행됩니다. 프로세스가 여전히 로컬에 존재하므로 데스크톱 앱이 깨어 있어야 합니다. 최적: 협업을 계속하면서 백그라운드로 돌리고 싶은 로컬 머신 작업. 예약된 원격 작업과 혼동하지 마세요 — Dispatch는 앱이 닫히면 죽습니다.

정신적 지름길: Dispatch = 로컬 백그라운드, 예약 작업 = 주기에 따라 클라우드, 인터랙티브 = 여러분이 운전석에 있음.

예약 작업 올바르게 설정하기​

예약 작업은 여섯 가지가 필요합니다 — 다섯 개의 설정과 한 개의 프롬프트. 설정 중 어느 하나라도 잘못 되면 실행은 "성공한 것처럼" 보이지만 잘못된 일을 할 것입니다.

Guided walkthrough1 of 6
  1. 짧고, 인간적으로. 이것이 예약된 작업 목록과 모바일 알림에서 보게 될 이름입니다. 'briefing-v2'보다 '월요일 클라이언트 준비'가 낫습니다.
  2. 매 실행마다 새로 합류하는 동료에게 말하듯 작성하세요 — 왜냐하면 매 실행이 새로운 세션이기 때문입니다. 목표, 소스(어떤 커넥터, 어떤 스킬, 어떤 폴더), 원하는 출력 형태, 그리고 불변 조건(예: '절대 이메일을 보내지 마세요, 항상 초안으로 남기세요')을 명시하세요.
  3. 시간별 / 일별 / 평일 / 주별 / 수동 중 하나를 선택하세요. cron 문법이나 시간 미만 옵션은 없습니다 — '5분마다'가 필요하다면 잘못된 도구입니다 (API + 자체 스케줄러 사용).
  4. 핵심 설정입니다. 옵션은 자동 승인(Claude가 묻지 않고 진행, 읽기 전용 작업에 적합), 모바일 확인(Claude가 결정 지점에서 일시 정지하고 휴대폰에 알림 — 쓰기 작업에 대한 안전한 기본값), 또는 검토 대기(작업이 항상 나중에 검토할 초안으로 끝남)입니다.
  5. 요금제의 Cowork 기본값으로 설정됩니다. 무거운 읽기-요약 루프에는 더 작고 저렴한 모델을 선택하세요; 추론 품질이 실제로 결과를 좌우할 때만 최고급을 선택하세요.
  6. 세션의 파일 쓰기를 Claude 계정의 특정 프로젝트/폴더로 범위 지정합니다. 건너뛰면 출력이 기본 위치에 도착합니다 — 작업 하나에는 괜찮지만 열두 개가 되면 엉망이 됩니다.

예약 작업 프롬프트 템플릿: 월요일 06:00 클라이언트 브리핑

You are preparing my Monday morning brief for the Acme account.

Every Monday at 06:00 local:

1. Read the last 7 days of email in the "Acme" Gmail label. Group by
 thread; note anything that expects a reply from me.
2. Pull calendar events with "Acme" in the title or attendees from
 the coming week. Note prep needed for each.
3. Search the web for news about Acme (company name + "acquisition",
 "layoffs", "product launch") in the last 7 days. Cite sources.
4. Read the Google Doc "Acme - Running Notes" for open questions.

Produce a single briefing doc titled "Acme brief — <this-monday-date>"
in the "Client briefings" project folder. Structure:

- 3-bullet TL;DR at the top
- "Needs a reply from me" list (with links)
- "This week" list (calendar + prep)
- "News since last brief" (with sources)
- "Open questions" (from the running-notes doc)

DO NOT send any email. Leave a follow-up email as a DRAFT in Gmail
titled "Acme weekly check-in" pre-filled with the TL;DR — I'll edit
and send.

이 프롬프트에서 주목할 두 가지:

  • 불변 조건("이메일을 보내지 마세요... 초안으로 남기세요")이 명시되어 있습니다. 예약된 실행에서는 "확실합니까?"라는 후속 질문을 할 수 없습니다 — 불변 조건은 프롬프트에 있어야 합니다.
  • 출력 위치 + 명명 규칙이 정확합니다. 이것들이 몇 달 동안 매주 실행될 때, 기본 제목 아래 흩어져 있지 않고 찾을 수 있기를 원할 것입니다.

모바일 승인 플로우 — "잠들어 있을 때"를 위한 설계​

ask-on-mobile은 03:00에 발동되어 실행이 여러분을 기다리며 조용히 멈출 때까지는 친절하게 들립니다. 두 가지 규칙이 이것을 신뢰할 수 있게 만듭니다:

Guided walkthrough1 of 2
  1. 읽기 전용 또는 초안 전용 작업 → 자동 승인. 보내거나, 게시하거나, 삭제하거나, 돈을 쓰는 모든 것 → 프롬프트에 폴백을 넣어 모바일 확인: '30분 이내에 응답하지 않으면 초안으로 저장하고 작업을 종료하세요'. 플랫폼이 여러분을 대신 타임아웃시키지 않기 때문에 프롬프트 수준의 폴백이 중요합니다.
  2. 프롬프트에서 결정 지점을 구체적인 요청으로 감싸세요: '어떤 것이든 보내기 전에 정확한 제목 줄과 본문의 첫 200자로 승인을 요청하세요.' 푸시 알림은 잘립니다 — 앱을 열지 않고도 잠금 화면에서 승인/거부할 수 있도록 중요한 부분을 앞쪽에 배치하세요.
Watch out
  • 푸시 승인은 여러분이 응답할 때까지 작업을 차단합니다. 절대 응답하지 않으면 실행이 앉아 있을 뿐입니다 — 자동으로 안전한 기본값으로 넘어가지 않습니다. '응답이 없으면 X를 하라'는 타임아웃을 프롬프트 자체에 넣거나, 대신 검토 대기를 사용하세요.

예약 Cowork 실행을 망가뜨리는 네 가지 함정​

Guided walkthrough1 of 4
  1. 프롬프트가 작업에게 '내 다운로드 폴더를 열어라', '내 브라우저를 자동화하라' 또는 '내 화면의 스크린샷을 찍어라'라고 요청하면 원격 세션은 그것을 할 방법이 없습니다. 실행이 크래시하지 않을 것입니다 — 그냥 건너뛰거나 즉흥적으로 처리할 것입니다. 수정: 예약된 프롬프트를 감사하고 로컬 머신 작업을 연결된 도구 동등물로 교체하세요 (로컬 파일 대신 Google Drive, 로컬 브라우저 대신 웹 페치 등).
  2. 2026년 7월 출시 시점에서, Cowork 세션 내에서 Fable 5 모델을 실행하려면 최신 Claude Desktop 앱이 필요합니다. Fable 5를 고정하는 예약 작업을 만들고 원격으로 실행되기를 기대한다면, 현재 지원을 확인하세요 — 이 제약은 완화될 것으로 예상되지만 고정하기 전에 확인하세요.
  3. 활성 데스크톱 세션에서 백그라운드로 처리된 Dispatch 작업은 앱을 닫으면 죽습니다. 실제로 '이것을 매주 실행하라, 무슨 일이 있어도'가 필요하다면 Dispatch를 사용하지 마세요 — 예약 작업을 만드세요.
  4. Gmail, Slack, Google Drive에 대한 OAuth 토큰은 만료되거나, 취소되거나, 권한 변경에 부딪힐 수 있습니다. 만료된 커넥터 아래에서 실행되는 예약 작업은 빈 출력을 생성하고 명백한 에러가 없습니다. 수정: 주간 또는 그보다 덜 자주 실행되는 것에 대해 프롬프트에 첫 단계 자체 검사를 추가하세요 ('Acme Gmail 라벨을 읽을 수 있는지 확인하세요; 그렇지 않다면 문서 상단에 한 줄 에러를 생성하고 중단하세요').

대신 API로 넘어가야 할 때​

예약 Cowork 작업은 제품 기능입니다 — 여러분의 Claude 계정에서 볼 수 있고, 루프에 인간 승인이 있는 개인 / 소규모 팀 반복 작업에 훌륭합니다. 다음이 필요할 때는 잘못된 도구입니다:

  • 시간 미만의 주기 — 가장 작은 예약 작업 간격은 시간별입니다.
  • 프로그래밍 방식의 오케스트레이션 — 수십 개의 병렬 실행, 동적 스케줄링 또는 인프라와의 긴밀한 통합. Managed Agents로 넘어가거나, Agent SDK + 이미 실행 중인 cron/큐로 직접 구축하세요.
  • 실행 간 서버 사이드 메모리 — Cowork 작업은 계정의 파일을 통해 상태를 전달하는데, 이는 문서에는 괜찮지만 구조화된 상태에는 조잡합니다. 구조화된 실행 간 메모리에는 Managed Agents Memory Stores를 사용하세요.
  • 깊은 멀티 에이전트 조정 — 많은 에이전트가 협업하는 경우, Cowork & Agent Teams와 Native Multi-Agent APIs를 참조하세요.
