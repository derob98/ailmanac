Task pianificati di Cowork: agenti che girano senza dispositivi accesi

Intermedio
Ultima verifica: 2026-08-05.

Cowork su web + mobile è stato lanciato il 7 luglio 2026 (prima per Max, gli altri piani a pagamento nelle settimane successive). Disponibilità, quota e copertura esatta dei connettori stanno cambiando in fretta — verifica sul blog post ufficiale e sull'articolo del centro assistenza Schedule recurring tasks in Claude Cowork prima di affidarti a un numero preciso qui.

Conferma confrontando con la fonte ufficiale.

Cowork ha smesso di essere un workspace solo desktop il 7 luglio 2026. Ora gira su web (claude.ai), iOS e Android, e — la parte che quasi tutti gli articoli seppelliscono — le sessioni vengono eseguite sui server di Anthropic, non sulla tua macchina. Questo singolo cambiamento architetturale è ciò che sblocca la feature principale: task pianificati che girano con il portatile chiuso, il telefono in tasca e nessun dispositivo online.

Questa pagina è la guida pratica sul campo: cosa funziona davvero su quale superficie, come configurare un task pianificato correttamente al primo colpo, e la manciata di imprevisti che ti accorgi di avere solo dopo che il briefing delle 6:00 del lunedì è fallito in silenzio perché serviva un file locale.

What you'll learn
  • Capire perché spostare l'esecuzione di Cowork fuori dal tuo dispositivo cambia il prodotto (run pianificate, passaggio tra dispositivi, prompt di approvazione mobile) — e dove cadono i tradeoff
  • Scegliere la superficie giusta (desktop / web / mobile) per un dato lavoro, usando la matrice delle capacità
  • Configurare un task Cowork pianificato correttamente al primo tentativo, con la modalità di approvazione, frequenza e cartella di lavoro giusti
  • Progettare un flusso di approvazione mobile che non si blocchi in silenzio mentre dormi o sei in aereo
  • Evitare i quattro imprevisti che rompono le run pianificate in produzione: tool solo locali, Fable 5 solo su desktop, Dispatch vs Remote, e drift di autenticazione dei connettori

L'unico cambio che conta: le sessioni si sono spostate sui server di Anthropic​

Prima di luglio 2026, una sessione Cowork era un processo dentro l'app Claude Desktop sul tuo Mac o PC. Chiudi il portatile, la sessione muore. Uccidi l'app, la sessione muore. È il motivo per cui il loop pre-luglio di Cowork iniziava sempre con "apri il desktop, tienilo sveglio".

Il lancio di luglio introduce le sessioni remote: il loop di Cowork vive nel cloud di Anthropic, lo stato della tua sessione e i file persistono legati al tuo account Claude, e qualsiasi superficie (web, mobile, desktop) è solo un visualizzatore + dispositivo di input per la stessa sessione sottostante.

Due conseguenze dirette:

  1. I task pianificati sono possibili. Un task ricorrente può svegliarsi alle 06:00 di lunedì, fare 45 minuti di lavoro e lasciare una bozza nel tuo account — con zero dispositivi online, perché non c'è un dispositivo nel loop.
  2. Il passaggio tra dispositivi è gratuito. Avvia un task alla scrivania, chiudi il portatile e vedi la stessa sessione a metà run sul telefono. Non c'è nulla da sincronizzare — la sessione non è mai stata sul tuo portatile.

Il tradeoff è la matrice delle capacità qui sotto: qualsiasi cosa che debba toccare la tua macchina locale (file su disco, il tuo browser, il tuo OS) può girare solo su desktop, perché è l'unica superficie con un piede in entrambi i mondi.

Cowork interattivo vs Task pianificato vs Dispatch​

I tre modi vengono confusi. Sono bestie diverse:

Guided walkthrough1 of 3
  1. La avvii tu, la guardi, Claude lavora su un orizzonte lungo sul tuo obiettivo attivo. Ora vive sui server di Anthropic, quindi puoi passarla tra dispositivi. Ideale per: lavori di più ore che vuoi guidare mentre accadono.
  2. Definisci un prompt + una cadenza (orario / giornaliero / feriali / settimanale / manuale). Ogni run apre una sessione Cowork fresca con i tool, skill e plugin che hai specificato. Gira in remoto, secondo pianificazione, che ci sia o meno un dispositivo online. Ideale per: prep ricorrente — briefing del lunedì alle 06:00, triage orario dell'inbox, riepiloghi di fine giornata.
  3. Forma legacy: avvia un task in background da una sessione desktop attiva che continua a girare mentre tu continui a chattare. Richiede che l'app desktop resti sveglia perché il processo vive ancora localmente. Ideale per: lavoro sulla macchina locale che vuoi mettere in background mentre continui a collaborare. NON confonderlo con un task remoto pianificato — Dispatch muore quando chiudi l'app.

La scorciatoia mentale: Dispatch = background locale, Task pianificato = cloud con una cadenza, Interattivo = sei al volante.

Configurare un task pianificato nel modo giusto​

Un task pianificato ha bisogno di sei cose — cinque impostazioni e un prompt. Sbaglia una qualsiasi delle impostazioni e la run sembrerà "riuscita" ma farà la cosa sbagliata.

Guided walkthrough1 of 6
  1. Corto, umano. È quello che vedrai nella lista dei task pianificati e nelle notifiche mobile. 'Prep cliente lunedì' batte 'briefing-v2'.
  2. Scrivilo come se parlassi a un collega che entra da zero a ogni run — perché ogni run È una sessione fresca. Dichiara l'obiettivo, le fonti (quali connettori, quali skill, quali cartelle), la forma di output che vuoi, e ogni invariante (es. 'non inviare mai email, lascia sempre come bozza').
  3. Scegli tra orario / giornaliero / feriali / settimanale / manuale. Non c'è sintassi cron e non ci sono opzioni sotto l'ora — se ti serve 'ogni 5 min', sei sul tool sbagliato (usa l'API + il tuo scheduler).
  4. L'impostazione critica. Le opzioni sono auto-approve (Claude procede senza chiedere, buono per task read-only), ask-on-mobile (Claude si ferma a un punto di decisione e pinga il telefono — default sicuro per qualsiasi cosa scriva), o hold-for-review (il task finisce sempre con una bozza che rivedi dopo).
  5. Default sul Cowork default del tuo piano. Scegli un modello più piccolo/economico per loop pesanti di lettura-riassunto; scegli top-tier solo quando la qualità del ragionamento sposta davvero il risultato.
  6. Limita le scritture su file della sessione a uno specifico progetto/cartella nel tuo account Claude. Salta questa impostazione e gli output finiscono in una posizione di default — che va bene per un task, un casino quando ne hai dodici.

Template di prompt per task pianificato: briefing cliente lunedì 06:00

You are preparing my Monday morning brief for the Acme account.

Every Monday at 06:00 local:

1. Read the last 7 days of email in the "Acme" Gmail label. Group by
 thread; note anything that expects a reply from me.
2. Pull calendar events with "Acme" in the title or attendees from
 the coming week. Note prep needed for each.
3. Search the web for news about Acme (company name + "acquisition",
 "layoffs", "product launch") in the last 7 days. Cite sources.
4. Read the Google Doc "Acme - Running Notes" for open questions.

Produce a single briefing doc titled "Acme brief — <this-monday-date>"
in the "Client briefings" project folder. Structure:

- 3-bullet TL;DR at the top
- "Needs a reply from me" list (with links)
- "This week" list (calendar + prep)
- "News since last brief" (with sources)
- "Open questions" (from the running-notes doc)

DO NOT send any email. Leave a follow-up email as a DRAFT in Gmail
titled "Acme weekly check-in" pre-filled with the TL;DR — I'll edit
and send.

Due cose da notare su questo prompt:

  • L'invariante ("DO NOT send any email... leave as DRAFT") è scritta esplicitamente. In una run pianificata non puoi chiedere un follow-up "sei sicuro?" — gli invarianti devono stare nel prompt.
  • La posizione di output + naming è precisa. Quando queste run girano settimanalmente per mesi, li vuoi trovare, non sparsi sotto titoli di default.

Flusso di approvazione mobile — progettare per "sto dormendo"​

ask-on-mobile sembra amichevole finché non scatta alle 03:00 e la run si blocca in silenzio in attesa di te. Due regole rendono questo affidabile:

Guided walkthrough1 of 2
  1. Azioni read-only o solo-bozza → auto-approve. Qualsiasi cosa invii, pubblichi, cancelli o spenda soldi → ask-on-mobile con un fallback nel prompt: 'se non ho risposto entro 30 minuti, salva come bozza e termina il task'. Il fallback a livello prompt conta perché la piattaforma non farà il timeout per te.
  2. Nel prompt, incapsula i punti di decisione in una richiesta specifica: 'Prima di inviare qualsiasi cosa, richiedi approvazione con l'esatto subject e i primi 200 caratteri del body.' Le notifiche push tagliano — metti in testa le parti importanti così puoi approvare/negare dalla lockscreen senza aprire l'app.
Watch out
  • Le approvazioni push bloccano il task finché non rispondi. Se non rispondi mai, la run resta lì — non ricade automaticamente su un default sicuro. Metti un timeout 'se nessuna risposta, fai X' dentro il prompt stesso, o usa hold-for-review invece.

I quattro imprevisti che rompono le run Cowork pianificate​

Guided walkthrough1 of 4
  1. Se il prompt chiede al task di 'apri la mia cartella downloads', 'automatizza il mio browser', o 'fai uno screenshot del mio schermo', la sessione remota non ha modo di farlo. La run non crasha — salterà o improvviserà. Fix: fai un audit dei tuoi prompt pianificati e sostituisci le azioni sulla macchina locale con equivalenti tool-connessi (Google Drive invece di file locali, web fetch invece del browser locale, ecc).
  2. Al lancio di luglio 2026, eseguire il modello Fable 5 dentro una sessione Cowork richiede l'ultima app Claude Desktop. Se pianifichi un task che fissa Fable 5 e conti su di lui in remoto, verifica il supporto attuale — questo vincolo dovrebbe allentarsi ma controlla prima di fissarlo.
  3. Il lavoro Dispatch messo in background da una sessione desktop attiva muore quando chiudi l'app. Se ti serve davvero 'lancia questo settimanalmente, comunque', non usare Dispatch — crea un task pianificato.
  4. I token OAuth per Gmail, Slack, Google Drive possono scadere, essere revocati, o incappare in cambi di permesso. Un task pianificato sotto un connettore scaduto produce output vuoto e nessun errore evidente. Fix: per qualsiasi cosa giri settimanalmente o meno spesso, aggiungi come primo passo un self-check nel prompt ('conferma di poter leggere la label Gmail Acme; se no, produci un errore di una riga in cima al doc e fermati').

Quando prendere l'API invece​

I task Cowork pianificati sono una feature di prodotto — ottimi per lavoro ricorrente personale / small-team che vuoi visibile nel tuo account Claude, con approvazione umana nel loop. Sono il tool sbagliato quando ti serve:

  • Cadenza sotto l'ora — l'intervallo minimo dei task pianificati è orario.
  • Orchestrazione programmatica — decine di run parallele, scheduling dinamico, o integrazione stretta con la tua infra. Prendi i Managed Agents, o fai da te con l'Agent SDK + un cron/queue che già giri.
  • Memoria server-side tra run — i task Cowork passano stato via file nel tuo account, il che va bene per doc ma è grossolano per stato strutturato. Per memoria strutturata cross-run, usa i Managed Agents Memory Stores.
  • Coordinamento profondo multi-agente — per molti-agenti-che-collaborano, vedi Cowork & Agent Teams e Native Multi-Agent APIs.
