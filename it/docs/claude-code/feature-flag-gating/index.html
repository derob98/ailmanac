Feature flag: perché il tuo Claude Code non è il mio

Avanzato
Ultima verifica: 2026-09-24.

Quali funzionalità stiano dietro a un flag scaricato cambia quasi a ogni release di Claude Code — le funzionalità escono dal gating quando il rollout è completo. Considera l'elenco qui sotto come la forma del problema, e controlla la documentazione ufficiale per l'appartenenza esatta di oggi.

Conferma confrontando con la fonte ufficiale.

Due sviluppatori installano la stessa versione di Claude Code, sullo stesso OS, nello stesso repo. Uno dei due ha una funzionalità che l'altro non ha, e nessuno dei due riceve un messaggio d'errore. Non è folklore — è il design documentato. Claude Code attiva alcune funzionalità usando feature flag che scarica da Anthropic all'avvio, e diverse configurazioni normali e in buona fede disattivano completamente quel fetch.

La conseguenza che sorprende: un'operazione puramente locale può dipendere da una chiamata di rete. A settembre 2026 è diventata un thread da 437 punti su Hacker News, perché leggere un file Markdown dal proprio disco si è rivelato averne bisogno.

What you'll learn
  • Come i feature flag remoti di Claude Code vengono scaricati, messi in cache e valutati
  • Le quattro configurazioni che disattivano silenziosamente il fetch dei flag
  • Perché DISABLE_TELEMETRY=0 ti esclude comunque — e perché DO_NOT_TRACK=0 no
  • Le quindici funzionalità che perdi con il fetch disattivato
  • Come rilevare il gating in due minuti e fissare il comportamento perché non ti morda

Il meccanismo​

Claude Code include un valore di default nel codice per ogni flag e poi prova a scaricare i valori reali. Il provider è GrowthBook — esiste una variabile d'ambiente dedicata DISABLE_GROWTHBOOK, e il changelog contiene voci come la correzione di un crash "quando una funzionalità GrowthBook viene valutata a null" (v2.1.214).

Quattro proprietà di quel sistema spiegano quasi ogni caso strano che incontrerai:

Guided walkthrough1 of 4
  1. Il binario conosce i nomi dei flag e un valore di fallback per ciascuno. I valori che decidono cosa può fare la tua sessione arrivano da Anthropic via rete. Nessun fetch significa che ogni flag ricade sul suo default nel codice — che per una funzionalità in pieno rollout è di solito off.
  2. I valori scaricati persistono tra le sessioni, ed è per questo che una funzionalità può comparire una sessione dopo quella in cui te l'aspettavi. Il changelog registra quando questo è andato storto: la v2.1.70 ha corretto i flag letti nelle prime fasi di avvio che non aggiornavano mai la loro cache su disco, per cui valori obsoleti sopravvivevano tra le sessioni.
  3. La valutazione tiene conto della tua versione di Claude Code e del tuo piano di abbonamento. La v2.1.227 ha corretto i flag valutati senza il piano dell'utente quando una sessione partiva con un token di login scaduto — cosa che chiedeva erroneamente agli utenti del piano Max di attivare i crediti d'uso. La v2.1.261 ha corretto i flag riservati a una versione più recente che occasionalmente venivano applicati a un Claude Code più vecchio sulla stessa macchina.
  4. La v2.1.214 ha corretto i feature flag che diventavano obsoleti nelle sessioni di lunga durata dopo la rotazione del token OAuth. Una sessione che gira per ore non ha la garanzia di mantenere lo stesso set di funzionalità con cui è partita.

I quattro modi in cui il fetch si spegne​

La documentazione è esplicita su questo. Claude Code salta il fetch dei flag in queste sessioni:

  • Hai impostato una di quattro variabili d'ambiente: DISABLE_GROWTHBOOK, DISABLE_TELEMETRY, DO_NOT_TRACK o CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC.
  • Sei su un provider terzo: Amazon Bedrock, Claude Platform su AWS, Agent Platform di Google Cloud o Microsoft Foundry — a meno che una piattaforma host che incorpora Claude Code imposti CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST.
  • Sei in una sessione gateway delle app Claude.
  • È la tua prima sessione dopo un'installazione pulita o un aggiornamento — i flag non sono ancora arrivati. Più avanti i dettagli.

Nota cosa hanno in comune i primi due: sono le configurazioni che sceglie un'azienda attenta alla sicurezza. Esattamente la popolazione che più probabilmente disabilita la telemetria e passa da Bedrock è la popolazione che riceve silenziosamente il set di funzionalità più piccolo.

Watch out
  • Disabilitare la telemetria non è solo una scelta di privacy — è anche un interruttore per le funzionalità. La documentazione dice che DISABLE_TELEMETRY 'disabilita anche il fetch dei feature flag con lo stesso effetto di DISABLE_GROWTHBOOK'.
  • Se vuoi privacy senza perdere funzionalità, non esiste combinazione che dia entrambe: ogni modo documentato di fermare la telemetria ferma anche il fetch dei flag.
  • I runner CI con una HOME effimera sono un'installazione pulita a ogni esecuzione, quindi ricadono nel caso senza flag ogni singola volta.

La trappola dei valori: tre variabili, tre regole di parsing​

Questa è la parte che costa un pomeriggio. Queste variabili appartengono alla stessa famiglia, si leggono come se facessero la stessa cosa, e interpretano i loro valori secondo tre regole diverse.

VariabileCome legge il valoreQuindi =0 significa
DISABLE_TELEMETRYQualsiasi valore non vuoto la attivaTi esclude comunque. Rimuovila per riattivare
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFICQualsiasi valore non vuoto la attivaDisabilita comunque il traffico. Rimuovila per riattivare
DISABLE_ERROR_REPORTINGQualsiasi valore non vuoto la attivaTi esclude comunque. Rimuovila per riattivare
DISABLE_GROWTHBOOKBooleano standard — imposta 1 o trueLascia il fetch attivo
DO_NOT_TRACKBooleano standard — imposta 1Lascia la telemetria attiva

Leggi quella tabella due volte. DISABLE_TELEMETRY=0 disabilita la telemetria. DO_NOT_TRACK=0 no. Entrambi i comportamenti sono documentati, deliberati e opposti.

What you'll learn
  • La documentazione enuncia la regola direttamente: alcune variabili 'leggono solo se le hai impostate o no, quindi qualsiasi valore non vuoto compreso 0 attiva il comportamento'.
  • Per annullarne una devi rimuovere la variabile o impostarla a un valore vuoto — assegnare 0 o false non è un interruttore di spegnimento.
  • Questo morde più forte in un Dockerfile o in una configurazione CI dove qualcuno l'ha 'disattivata' cambiando 1 in 0.

Cosa perdi davvero​

Con il fetch dei flag disattivato, quindici capacità documentate scompaiono. Raggruppate per quello che ti costano:

Permessi e avvio

  • Le sessioni non possono partire in modalità auto per default sui piani Pro, Max e Team
  • L'estensione VS Code non può leggere i file di settings per la modalità di permessi iniziale
  • /auto-mode-setup non può redigere le voci autoMode.environment

Tutto ciò che va oltre la sessione locale

  • Remote Control
  • Messaggi verso sessioni su altre macchine (i messaggi sulla stessa macchina continuano a funzionare)
  • La sincronizzazione delle skill e dei plugin abilitati sul tuo account claude.ai nelle sessioni da terminale
  • Leggere o rispondere ai commenti su un artifact
  • Il tool advisor

Comandi e diagnostica

  • claude import e il comando /import
  • /skill-doctor e il suo report nella tab Stats di /plugin

Cambi di comportamento silenziosi — il gruppo pericoloso

  • MCP: Claude Code smette di escludere i tool MCP il cui schema di input verrebbe rifiutato dall'API. Invia lo schema comunque, e la richiesta fallisce con un 400 che nomina il tool per posizione
  • MCP: nessun probing dei server connector di claude.ai per la revisione di protocollo 2026-07-28, a meno che non imposti MCP_PROTOCOL_NEGOTIATION=auto
  • I paste di grandi dimensioni non vengono più trattati come testo incollato anziché digitato — il contenuto dietro un placeholder [Pasted text #N] arriva a Claude non marcato
  • Su Windows con Git Bash installato, gli account claude.ai e Console non ottengono il tool PowerShell per default; imposta CLAUDE_CODE_USE_POWERSHELL_TOOL=1
  • Il feedback redatto da Claude è disattivato

L'ultimo gruppo è quello da interiorizzare. Un comando slash mancante si annuncia da sé. Un errore 400 che nomina un tool per la sua posizione nell'array non somiglia a un'impostazione di telemetria, e passerai un'ora a fare debug del tuo server MCP prima di pensare a controllare una variabile d'ambiente.

Il raggio d'azione ha dei precedenti​

Le impostazioni di flag e telemetria sono filtrate in posti che nessuno prevederebbe. Due esempi dal changelog, corretti ma istruttivi:

  • La v2.1.108 ha corretto gli abbonati che impostavano DISABLE_TELEMETRY e ricadevano su un TTL della cache dei prompt di 5 minuti invece di 1 ora. Una variabile di privacy costava silenziosamente soldi a ogni sessione lunga — una finestra di cache 12× più corta.
  • La v2.1.105 ha corretto CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC impostata nei settings di un solo progetto che disabilitava permanentemente le metriche d'uso per tutti i progetti sulla macchina.

Entrambi sono corretti. Entrambi mostrano la forma del rischio: questi interruttori tagliano trasversalmente sottosistemi che sembrano non correlati.

La prima sessione dopo un'installazione o un aggiornamento​

Questa merita un suo titolo perché produce il classico bug report irriproducibile.

Alla tua prima sessione dopo l'installazione di Claude Code — o dopo un aggiornamento a una versione che aggiunge una funzionalità — una funzionalità sotto gating può semplicemente non esserci, e la sessione può partire in modalità Manual su un piano che altrimenti parte in modalità auto. Claude Code scarica i flag durante quella sessione, quindi entrambe le cose sono presenti la volta successiva.

Due corollari:

  • Si risolve da sé, che è esattamente il motivo per cui è difficile da segnalare. Quando qualcuno va a guardare, la seconda sessione ha già i flag.
  • Non si risolve mai da sé negli ambienti effimeri. Un runner CI, un container appena creato, o qualsiasi setup con una home directory usa-e-getta è alla prima sessione ogni volta.

La documentazione segnala una mitigazione: dopo un'installazione pulita, una sessione non interattiva come claude -p, l'Agent SDK o l'estensione VS Code può comunque recuperare i flag prima di scegliere la modalità di permessi iniziale.

Caso di studio: AGENTS.md, un file locale dietro un interruttore remoto​

L'esempio più chiaro dell'intero pattern, e quello che è arrivato in prima pagina.

Guided walkthrough1 of 5
  1. La voce del changelog: in un progetto senza CLAUDE.md, Claude Code legge AGENTS.md; lo cambi sotto 'Project instructions' in /config. La voce stessa segnala che non è ancora attivo su Bedrock, Vertex o Foundry.
  2. Poiché il rollout era sotto gating, le sessioni che saltano il fetch ricadevano sul default nel codice — off. Leggere un file Markdown dalla directory corrente, un'operazione senza alcuna componente di rete, è diventato condizionato a una chiamata di rete.
  3. Nessun warning, nessuna riga di log, nessun errore. Le istruzioni semplicemente non arrivano mai al modello, quindi il sintomo si legge come 'Claude sta ignorando il mio AGENTS.md' — cosa che ti manda a riscrivere il file invece che a controllare una variabile d'ambiente.
  4. Aperta come 'Claude Code's AGENTS.md Support: A Local Feature Locked Behind a Remote Switch'. Chi ha segnalato l'ha riprodotta su 2.1.278 e 2.1.280, e ha confermato che DISABLE_TELEMETRY, DISABLE_GROWTHBOOK e il traffico non essenziale disattivato la bloccano tutti, oltre alla primissima sessione dopo un'installazione pulita.
  5. La documentazione sulla memoria ora lo dice chiaramente: 'Prima della v2.1.281, alcune sessioni, come quelle su Amazon Bedrock o con la telemetria disabilitata, leggevano solo i file CLAUDE.md. Su quelle versioni, aggiorna Claude Code.' Se sei fermo sotto la 2.1.281, hai ancora questo problema.

La lezione si generalizza oltre questo singolo bug. Chiediti, per qualsiasi nuova funzionalità di Claude Code: è sotto gating? Se lo è, allora la tua postura sulla telemetria, il tuo provider e quanto di recente hai installato diventano tutti input per stabilire se funziona.

Diagnosticalo in due minuti​

Non serve tirare a indovinare. Tre controlli, dal più economico.

1. Chiediti se l'impostazione esiste del tutto. Quando il supporto ad AGENTS.md non è disponibile, la riga Project instructions non appare affatto nel pannello /config. Un'impostazione mancante è già la diagnosi — la funzionalità non è disattivata, è assente.

2. Guarda cosa ti dice una sessione interattiva. Quando funziona, Claude Code stampa nella conversazione una riga tipo no CLAUDE.md found; AGENTS.md loaded: /home/you/repo/AGENTS.md. Nessuna riga, nessun caricamento.

3. Usa un canarino. La tecnica che ha risolto la segnalazione originale: metti nel file una parola che non compare da nessun'altra parte, poi chiedila in una sessione pulita e non interattiva. Se la parola torna, il file è arrivato al modello. Funziona per qualsiasi file di istruzioni, su qualsiasi versione.

Test del canarino — il file di istruzioni è stato davvero caricato?

mkdir -p /tmp/canary && cd /tmp/canary
echo 'The project codeword is PERIWINKLE.' > AGENTS.md
claude -p 'What is the project codeword? Answer with one word.'

Eseguilo una volta con il tuo ambiente normale, poi una volta con le variabili di privacy azzerate, e confronta. Nota l'assegnazione a stringa vuota — ricorda che DISABLE_TELEMETRY=0 non la rimuoverebbe.

Lo stesso test con il fetch dei flag consentito — nota i valori vuoti, non gli zeri

cd /tmp/canary
env DISABLE_TELEMETRY= CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC= DISABLE_GROWTHBOOK=false \
claude -p 'What is the project codeword? Answer with one word.'

4. Se ti serve il dettaglio, attiva il logging di debug. Lancia con --debug o /debug, e i log finiscono in ~/.claude/debug/<session-id>.txt. Un'insidia: la variabile d'ambiente DEBUG accetta solo i valori veri 1, true, yes e on — un pattern di namespace come DEBUG=express:* rimasto da un altro strumento non la attiverà.

Fissa il comportamento invece di affidarti a un flag​

La soluzione durevole è smettere di dipendere dal gating. Due pattern.

Fissa l'impostazione esplicitamente. Per i file di istruzioni, il valore Project instructions può stare in un file di settings sotto l'ID del plugin integrato, invece di essere lasciato al default. Un limite importante: Claude Code ignora questa chiave nei file di settings di progetto e locali — la legge solo da ~/.claude/settings.json, da un file --settings o dai managed settings. Metterla nel .claude/settings.json del tuo repo non farà nulla.

Carica CLAUDE.md e AGENTS.md insieme — solo settings utente o managed

{
"pluginConfigs": {
  "agents-md@builtin": {
    "options": { "instructionFiles": "claude-md-and-agents-md" }
  }
}
}

Usa un percorso che non è mai stato sotto gating. Un CLAUDE.md che importa AGENTS.md ha funzionato su ogni versione, ogni provider e con la telemetria disattivata — perché è la normale espansione degli import @path, non un percorso di codice sotto flag. È la raccomandazione che la documentazione stessa dà per le sessioni su Bedrock, Vertex e Foundry.

Il CLAUDE.md di una riga che non ha mai avuto bisogno di un flag

@AGENTS.md

Una sottigliezza se prendi questa strada: un AGENTS.md letto attraverso l'impostazione si comporta in modo leggermente diverso da uno tirato dentro da un import. Gli hook InstructionsLoaded non scattano per il percorso basato sull'impostazione, ma scattano normalmente per un AGENTS.md che un CLAUDE.md importa o a cui punta con un symlink. Se hai hook sul caricamento delle istruzioni, l'import è la strada più sicura.

Key takeaways
  • Claude Code scarica i feature flag da Anthropic (GrowthBook), li mette in cache su disco e li valuta in base alla tua versione e al tuo piano di abbonamento — quindi due installazioni identiche possono legittimamente comportarsi in modo diverso.
  • Quattro variabili d'ambiente, tre provider terzi, le sessioni gateway delle app e la prima sessione dopo un'installazione saltano tutti quel fetch, costandoti quindici funzionalità documentate.
  • DISABLE_TELEMETRY, CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC e DISABLE_ERROR_REPORTING trattano qualsiasi valore non vuoto come attivo — compreso 0. DO_NOT_TRACK e DISABLE_GROWTHBOOK sono booleani veri. Rimuovi, non azzerare.
  • Le perdite peggiori sono silenziose: schemi MCP non filtrati che causano 400 posizionali, e testo incollato non marcato.
  • AGENTS.md è stato il caso di studio — nativo dalla v2.1.277, sotto gating, corretto nella v2.1.281. Un CLAUDE.md che contiene @AGENTS.md non ha mai avuto bisogno del flag.

Avanti​

  • AGENTS.md e interoperabilità tra strumenti — la funzionalità che questa pagina ha usato come caso di studio, e i pattern di sincronizzazione che non dipendono da un flag
  • Settings e configurazione — dove vivono pluginConfigs e la chiave env, e quali file di settings vengono letti
  • Ambienti self-hosted ed enterprise — setup Bedrock, Vertex e gateway, le stesse sessioni che saltano il fetch

Fonti e approfondimenti​

  • Variabili d'ambiente di Claude Code — funzionalità che richiedono il fetch dei feature flag — l'elenco autorevole, più la semantica dei valori variabile per variabile
  • Documentazione sulla memoria di Claude Code — AGENTS.md — tabella di precedenza, l'impostazione Project instructions, e quando il supporto non è disponibile
  • CHANGELOG di Claude Code — v2.1.277 (supporto ad AGENTS.md), v2.1.281, e le correzioni al sistema dei flag in v2.1.70, v2.1.108, v2.1.214, v2.1.227 e v2.1.261
  • anthropics/claude-code issue #95690 — la segnalazione originale, con riproduzioni della community su 2.1.278 e 2.1.280
  • Claude Code legge AGENTS.md solo con la telemetria attiva — l'articolo che l'ha portata a galla, e il metodo della parola canarino
