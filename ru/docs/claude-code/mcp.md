# MCP-серверы в Claude Code

> Source: https://derob98.github.io/ailmanac/ru/docs/claude-code/mcp · AILmanac (CC BY 4.0) · last verified 2026-11-10

Подключайте базы данных, GitHub, браузеры и многое другое через Model Context Protocol.

<LevelBadge level="advanced" />

<VerifyNote lastVerified="2026-11-10" source="https://code.claude.com/docs/en/mcp">
Команды `claude mcp`, области конфигурации и транспорты со временем меняются — сверяйтесь с официальной документацией Claude Code по MCP и с modelcontextprotocol.io. Четыре транспорта, пути хранения для областей, отказ от SSE и поведение при утверждении проекта ниже — всё это взято с той страницы.
</VerifyNote>

**Model Context Protocol (MCP)** — это открытый стандарт для подключения ИИ к внешним инструментам и данным. **MCP-сервер** предоставляет возможности (запрос к базе данных, открытие PR на GitHub, управление браузером); Claude Code подключается к нему и во время сессии может **вызывать эти инструменты**. Так вы расширяете Claude за пределы вашей файловой системы и оболочки.

## Общая схема

```mermaid
flowchart LR
  CC[Claude Code] -- calls tool --> S[MCP server]
  S -- result --> CC
  S --- D[(DB / API / Browser / SaaS)]
```

Вы объявляете серверы, которыми Claude может пользоваться; каждый сервер публикует набор инструментов со схемами; Claude выбирает и вызывает их, как любой другой инструмент.

## Транспорты

Есть четыре способа, которыми Claude обращается к серверу. Выбирайте в зависимости от того, где работает сервер и как он общается.

- **stdio** — локальный процесс, который запускает Claude (отлично для локальных инструментов и CLI). Именно это означает JSON-запись без `type`.
- **HTTP** — размещённый сервер, часто с OAuth. Выбор по умолчанию для всего удалённого.
- **SSE** — **устарел**; используйте HTTP, где это возможно. Некоторые сервисы по-прежнему предоставляют только конечную точку SSE, а начиная с Claude Code v2.1.265 `--transport http` сначала пробует HTTP и сам переключается на SSE, поэтому явно указывать `--transport sse` приходится редко.
- **WebSocket** (`ws` / `wss`) — постоянное двунаправленное соединение для сервера, который сам отправляет события. `--transport` *не* принимает `ws`: добавьте его через `claude mcp add-json '{"type":"ws","url":"wss://…"}'` или запишите в `.mcp.json`. OAuth нет — аутентификация только через заголовки.

<Callout type="warning" items={["JSON-запись с url, но без type — это ошибка конфигурации, а не разумное значение по умолчанию: Claude Code читает запись без type как stdio-сервер, пропускает её и сообщает, что у неё есть «url», но нет «type». Всегда задавайте \"type\": \"http\" (или \"sse\" / \"ws\") для удалённого сервера, который вы пишете вручную."]} />

## Настройка серверов

Самый быстрый путь — команда `claude mcp add`: она сама записывает конфигурацию. Пройдите эту последовательность, чтобы с нуля дойти до подключённого сервера.

<Steps items={[{title: "Добавьте локальный stdio-сервер", body: "Выполните claude mcp add — всё, что идёт после --, это команда запуска, которую Claude выполнит за вас."}, {title: "Или добавьте удалённый HTTP-сервер", body: "Передайте --transport http и область, затем URL сервера. Удалённые серверы часто размещены у провайдера и используют OAuth."}, {title: "Посмотрите, что подключено", body: "Выполните claude mcp list, чтобы увидеть настроенные серверы и состояние их подключения."}, {title: "Изучите и аутентифицируйтесь", body: "Используйте /mcp внутри сессии, чтобы изучить инструменты сервера и аутентифицировать удалённые серверы."}]} />

<PromptCard title="Добавить локальный stdio-сервер">{`# A local stdio server (everything after -- is the launch command)
claude mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem ~/code/myproject`}</PromptCard>

<PromptCard title="Добавить удалённый HTTP-сервер (общий для проекта)">{`# A remote HTTP server, shared with everyone on the project
claude mcp add --transport http --scope project github https://api.githubcopilot.com/mcp/`}</PromptCard>

Под капотом это просто JSON. Сервер с областью **project** попадает в файл `.mcp.json` в корне репозитория — закоммитьте его, и ваши коллеги получат те же инструменты, как только доверятся рабочему пространству:

```json
{
  "mcpServers": {
    "github": { "type": "http", "url": "https://api.githubcopilot.com/mcp/" }
  }
}
```

<Callout type="warning" items={["Не берите пакеты @modelcontextprotocol/server-github, -postgres, -slack и -puppeteer, которые встречаются в старых руководствах. Они заархивированы и снабжены уведомлением об устаревании в npm: «Archived and unmaintained; no security guarantees». Используйте сервер самого вендора, где он есть — у GitHub это HTTP-конечная точка выше, а управление браузером переехало в @playwright/mcp. Из референсных серверов на TypeScript по-прежнему поддерживаются только filesystem, memory, everything и sequential-thinking."]} />

### Область определяет, кто видит сервер

| Область | Где хранится | Где загружается | Для чего использовать |
|---|---|---|---|
| `local` (по умолчанию) | `~/.claude.json`, под путём этого проекта | только в этом проекте | личные эксперименты, секреты |
| `project` | `.mcp.json` в репозитории (коммитится) | только в этом проекте, общий для команды | инструменты, которые должна делить вся команда |
| `user` | `~/.claude.json` | во всех ваших проектах | серверы, которые нужны вам везде |

<Callout type="warning" items={["«Область local» в MCP — это не то же самое, что локальные настройки. MCP-сервер с областью local живёт в ~/.claude.json в вашей домашней папке, а НЕ в .claude/settings.local.json проекта. Искать его в папке проекта бесполезно."]} />

Выполните `claude mcp list`, чтобы увидеть, что подключено, и `/mcp` внутри сессии, чтобы изучить инструменты и аутентифицировать удалённые серверы. Готовые заготовки для копирования см. в разделе [Конфигурация MCP и заготовки серверов](/docs/templates/mcp-config).

## Разбор на примере: дайте Claude вашу базу данных

Допустим, вы хотите, чтобы Claude отвечал на вопросы по локальному Postgres, а не вставляли вы сами результаты запросов. Добавьте сервер с областью project, чтобы он был и у коллег.

Именно на базах данных проблема заархивированных серверов бьёт сильнее всего: прежний `@modelcontextprotocol/server-postgres` больше не поддерживается, а официальной замены нет, так что название пакета — единственное решение, которое вам придётся принять самому. Выберите поддерживаемый серверный пакет от сообщества, [изучите его](/docs/security/reviewing-third-party-code), затем подключите — форма одна и та же, что бы вы ни выбрали:

<PromptCard title="Добавить сервер Postgres с областью project">{`# Replace the package with a maintained Postgres MCP server you have reviewed.
# The connection string is read-only on purpose — see below.
claude mcp add --scope project db -- npx -y <postgres-mcp-server> "postgresql://readonly@localhost/app"`}</PromptCard>

Теперь в сессии можно задать вопрос простым языком и позволить Claude самому выполнить цикл запросов:

<PromptCard title="Задать вопрос базе данных">{`How many users signed up last week? Check the DB.`}</PromptCard>

Claude вызывает инструмент запросов, который публикует сервер, получает строки и отвечает — без копирования туда-обратно. Держите строку подключения только для чтения, если Claude действительно не нужно писать. А если вам нужен был всего один запрос, учтите, что `psql -c '…'` через Bash стоит лишь малую долю токенов; в [Налоге на токены MCP](/docs/claude-code/mcp-token-cost) разобрано, когда выигрывает каждый вариант.

Поскольку область project, коллега, который подтянет репозиторий, получит ту же возможность — но **не молча и не сразу**. Сервер из закоммиченного `.mcp.json` остаётся в состоянии `⏸ Pending approval`, пока коллега не запустит `claude` в этой папке и не примет диалог доверия рабочему пространству. Клонированный репозиторий не может заранее одобрить собственные серверы: `enableAllProjectMcpServers` или `enabledMcpjsonServers`, закоммиченные в `.claude/settings.json` проекта, в недоверенной папке *игнорируются*. А вот одобрения из пользовательского `~/.claude/settings.json`, из управляемых настроек или переданные через `--settings` там действуют. Это обычный ответ на вопрос «почему мой коллега не видит сервер?»

## Доверие и безопасность

<Callout type="warning" items={["MCP-сервер выполняет код, может читать данные и совершать действия — подключайте только серверы, которым доверяете.", "Давайте каждому серверу минимально необходимые привилегии.", "Любой внешний контент, который возвращает сервер, может содержать prompt injection.", "Проверяйте сторонние серверы, прежде чем подключать их."]} />

:::warning[Относитесь к MCP-серверам как к установке программ]
MCP-сервер выполняет код, может читать данные и совершать действия. Подключайте только серверы, которым доверяете, давайте им **минимально необходимые привилегии** и помните, что любой внешний контент, который они возвращают, может содержать [prompt injection](/docs/security/prompt-injection). Сначала проверяйте сторонние серверы — см. [Проверка стороннего кода](/docs/security/reviewing-third-party-code).
:::

MCP также лежит в основе **коннекторов** в приложениях Claude — тот же стандарт, другая поверхность. См. [Коннекторы (MCP) в приложениях](/docs/claude-app/connectors) и, для API, [MCP и подключение к инструментам](/docs/api/mcp).

## Частые ошибки

- **Не та область.** Сервер, добавленный с областью `local`, не появится у коллег; сервер, который вам нужен только для себя, не стоит коммитить с областью `project`. Выбирайте осознанно.
- **Слишком много серверов, слишком много инструментов.** Поиск инструментов включён по умолчанию, поэтому подключённый сервер обычно обходится вам каждый ход в *названия* его инструментов и инструкции сервера, а не в полные схемы — но это всё равно налог на каждый ход, а схемы попадают в контекст в тот момент, когда Claude их ищет. Подключайте то, что нужно для задачи, а не весь каталог. Реальные цифры, режимы `ENABLE_TOOL_SEARCH` и то, как выполнение кода сокращает вторую статью расходов, см. в [Налоге на токены MCP](/docs/claude-code/mcp-token-cost).
- **Избыточные привилегии подключения.** Дайте серверу базы данных роль только для чтения, если Claude действительно не нужно писать. MCP делает возможности реальными — сужайте их.
- **Забыть про риск инъекций.** Всё, что возвращает сервер (веб-страница, текст задачи, строка из базы), — это недоверенный текст, который может содержать [prompt injection](/docs/security/prompt-injection). Не подключайте мощный сервер с правом записи рядом с недоверенным сервером с правом чтения, не продумав это как следует.
