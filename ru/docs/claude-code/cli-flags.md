# CLI claude: флаги, которые меняют результат

> Source: https://derob98.github.io/ailmanac/ru/docs/claude-code/cli-flags · AILmanac (CC BY 4.0) · last verified 2026-10-07

Авторский обзор командной строки Claude Code — контракт из пяти флагов для запусков без присмотра, ловушка записанного системного промпта и чем различаются --bare, --safe-mode и --restricted.

<LevelBadge level="intermediate" />

<VerifyNote lastVerified="2026-10-07" source="https://code.claude.com/docs/en/cli-reference">
Каждая команда, флаг, значение по умолчанию и минимальная версия ниже взяты из официального [справочника по CLI](https://code.claude.com/docs/en/cli-reference), прочитанного 2026-10-07. Флаги появляются и меняются от релиза к релизу, а в справочнике прямо сказано, что `claude --help` **перечисляет не все флаги** — поэтому флаг, которого нет в `--help`, не обязательно отсутствует в вашей сборке. Сверяйтесь со справочником, а не с текстом справки, и проверяйте свою версию командой `claude -v`.
</VerifyNote>

Большинство людей узнают о командной строке Claude Code три вещи — `claude`, `claude -c` и `claude -p` — и на этом останавливаются. Это разумная остановка, если вы всегда работаете сидя перед экраном. Но как только вы ставите Claude Code в скрипт, задачу CI, фоновую очередь или отдаёте его в руки коллеги, флаги перестают быть удобством и становятся разницей между запуском за доллар и запуском, который висит час.

Эта страница — не вторая копия таблицы из справочника. Это **порядок, в котором стоит изучать поверхность**, флаги, которые реально меняют происходящее, и четыре ловушки, стоящие людям реального времени.

## Начните с вопроса: что это за сессия?

Все остальные решения вытекают из этого. Claude Code может запустить шесть существенно разных вещей, и флаг, выбирающий одну из них, обычно набирается первым.

| Вам нужно | Флаг | Вы получаете |
| --- | --- | --- |
| Разговор, за которым вы следите | *(нет)* | Интерактивную сессию в этом терминале |
| Один ответ и выход | `-p` / `--print` | Неинтерактивный запуск, вывод в stdout |
| Работу, которая переживёт этот терминал | `--bg` / `--background` | Фоновую сессию; она печатает свой ID и способ управления |
| Изолированную ветку для экспериментов | `-w` / `--worktree` | Git worktree в `<repo>/.claude/worktrees/<name>` |
| Работу на машинах Anthropic | `--cloud` | Облачную сессию или продолжение, поставленное в очередь в существующую |
| Управлять этой сессией с телефона | `--rc` / `--remote-control` | Интерактивную сессию, которой можно также управлять из claude.ai или приложения Claude |

Две из них несовместимы: `--bg` и `-p` взаимоисключающие, потому что одна возвращается сразу, а другая ждёт ответа. Если вам нужна в фоне shell-команда, а не сессия Claude, сочетайте `--bg` с `--exec`:

<PromptCard title="Запустить набор тестов как фоновое задание, а не как сессию Claude">
{`claude --bg --exec 'pytest -x'`}
</PromptCard>

А `--bg` перед стартом проверяет доверие к рабочему пространству для этого каталога — поэтому фоновая сессия в недоверенном репозитории падает сразу, а не на полпути.

## Контракт из пяти флагов для запусков без присмотра

Это самое ценное на этой странице. У запуска `claude -p` без присмотра есть три способа пойти не так, которых у интерактивной сессии просто нет: он может **застрять** на запросах разрешений, на которые некому ответить, может **зациклиться** гораздо дольше, чем вы ожидали, и может **выдать прозу**, когда вашему скрипту нужны были данные. Пять флагов закрывают все три риска.

  {title: "Решить, кто отвечает на запросы разрешений — --permission-prompts", body: "По умолчанию `host`: запросы уходят хосту Agent SDK или в `--permission-prompt-tool`. ## Семейство системного промпта и ловушка в нём

Пять флагов формируют системный промпт. Четыре задают его текст; пятый решает, сохранит ли разговор тот текст, с которого начал.

| Флаг | Что делает |
| --- | --- |
| `--system-prompt` | Заменяет весь промпт по умолчанию вашим текстом |
| `--system-prompt-file` | Заменяет его содержимым файла |
| `--append-system-prompt` | Дописывает ваш текст к промпту по умолчанию |
| `--append-system-prompt-file` | Дописывает содержимое файла к промпту по умолчанию |
| `--system-prompt-snapshot` | `off` пересобирает промпт при каждом запросе; `on` (по умолчанию) использует записанный |

Выбор между *дописать* и *заменить* — это выбор об идентичности. Дописывание сохраняет стандартные указания Claude Code по инструментам, инструкции безопасности и соглашения по написанию кода и накладывает ваши правила сверху — подходит для инструкций на конкретный запуск, форматирования вывода или контекста проекта. Замена отбрасывает **всё это**, включая указания по инструментам, и потому правильна лишь тогда, когда поверхность действительно не ассистент для кода: некодовый агент в конвейере, за которым никто не следит. Если вы заменяете, всё, что ещё нужно задаче, — на вас.

Их можно сочетать. Флаг дописывания вместе с флагом замены заменяет промпт по умолчанию, а затем дописывает ваш текст. Начиная с v2.1.283 можно также передать флаг вместе с его файловой формой — `--append-system-prompt` *и* `--append-system-prompt-file` — и Claude Code использует оба, причём содержимое файла идёт первым независимо от порядка, в котором вы их набрали.

<Callout type="warning" title="Ловушка: возобновлённый разговор использует промпт, с которым он родился" items={["Claude Code строит системный промпт один раз, при первом запросе разговора, и записывает его в сессию.","Пока разговор не сжат, каждый следующий запрос использует этот записанный промпт — в том числе после --resume или --continue.","Так что вы правите текст --append-system-prompt, снова запускаете claude --continue, и ничего не меняется. Флаг не сломан; разговор всё ещё использует запись.","Новый текст вступает в силу после сжатия разговора или в совершенно новом разговоре.","Чтобы подбирать формулировку между запусками --continue, передайте --system-prompt-snapshot off, и промпт будет пересобираться при каждом запросе. Требует v2.1.257 или новее."]} />

Есть ещё один приём, полезный в заменяющем промпте, где смешаны стабильные инструкции и контекст конкретного запуска. Поставьте между ними строку, содержащую только `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__`: Claude Code делит промпт по первой такой строке и удаляет её, так что часть выше остаётся в кэше, а часть ниже меняется. Требует v2.1.275 или новее. Почему это важно для вашего счёта, рассказано в [Prompt Caching](/docs/api/prompt-caching).

А для скриптовых нагрузок с несколькими пользователями `--exclude-dynamic-system-prompt-sections` переносит контекст конкретного пользователя, например расположение автопамяти, из системного промпта в первое пользовательское сообщение — так одна и та же задача на разных машинах делит один кэшируемый префикс. Он применяется только к промпту по умолчанию и игнорируется, если вы задали `--system-prompt` или `--system-prompt-file`.

## Три флага, которые что-то отключают, и это не одно и то же

Их часто берут взаимозаменяемо, а потом удивляются, что симптом не сдвинулся. Они решают три разные проблемы.

| | `--bare` | `--safe-mode` | `--restricted` |
| --- | --- | --- | --- |
| Проблема, которую решает | Запуск слишком медленный для скриптового вызова | Моя конфигурация сломана, и я не знаю, какая часть | Оценочный стенд не должен трогать эту общую машину |
| CLAUDE.md, навыки, команды, субагенты, плагины, MCP, автопамять | Не обнаруживаются | Не загружаются | Загружаются только управляемые настройки и `--settings` |
| Встроенные инструменты | Bash, чтение файла, правка файла | Работают как обычно | Инструменты запуска команд/кода и WebFetch **удалены**, если не названы по отдельности в `--tools` |
| Доступ к файлам | Обычный | Обычный | Ограничен рабочими каталогами |
| `bypassPermissions` | Разрешён | Разрешён | **Отклоняется** |
| Управляемая политика | Применяется | Продолжает применяться, включая хуки политик и строку состояния | Применяется |
| Побочный эффект | Устанавливает `CLAUDE_CODE_SIMPLE` | Устанавливает `CLAUDE_CODE_SAFE_MODE` | Отказывается создавать облачные сессии |

Читайте таблицу как последовательность намерений: `--bare` — про **скорость**, `--safe-mode` — про **диагностику**, `--restricted` — про **изоляцию**. Полезная деталь: навыки из каталога, переданного через `--add-dir`, загружаются и под `--bare`, так вы сохраняете ровно одну возможность в остальном урезанном запуске.

`--safe-mode` — то, за что стоит браться первым, когда что-то работает не так и вы не можете понять, виноват Claude Code или ваша собственная конфигурация, — в том числе когда вы выясняете, не вызывает ли автоматический откат модели какая-то из ваших настроек. Сочетайте его с `claude doctor`, который выводит диагностику установки и настроек только для чтения, вообще не запуская сессию. (Команда `/doctor` внутри сессии — другое: она может и применять исправления.) Больше отладки по симптомам — в [Устранение неполадок Claude Code](/docs/claude-code/troubleshooting). `--restricted` требует v2.1.248 или новее.
