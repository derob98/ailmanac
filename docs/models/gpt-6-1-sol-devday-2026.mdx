<LevelBadge level="intermediate" />

At **DevDay on September 29, 2026** OpenAI shipped **GPT-6.1 Sol** (`gpt-6.1-sol`)
one week after GPT-6 Sol, with the pitch **"near-Astra intelligence for a fifth of
the price."** It went straight to the top of Hacker News.

For a Claude user the interesting fact is not the pitch. It is that GPT-6.1 Sol lands
on **exactly Claude Sonnet 5.5's rate card** — $2 in, $10 out per MTok — while
charging **half** of Sonnet 5.5's cached-input rate. Two models, same headline price,
different bills, different shapes of work. This page is the specs, the pricing
mechanics most write-ups skip, an honest read of the benchmark table, and the rest of
what DevDay shipped for developers.

## Specs

| | `gpt-6.1-sol` |
|---|---|
| Context window | **1,050,000** tokens |
| Max **input** tokens | **922,000** |
| Max output tokens | 128,000 |
| Knowledge cutoff | April 30, 2026 |
| Reasoning efforts | low, **medium (default)**, high, xhigh, max |
| Input / cached input / output | **$2.00 / $0.10 / $10.00** per MTok |
| Cache write | $2.50 per MTok |
| Long context (>272K) | 2× input and cache rates, 1.5× output |
| Fast Mode | 2× standard pricing |
| Batch / Flex | 50% below standard |
| Rate limits | Tier 1: 500 RPM / 500K TPM → Tier 5: 15K RPM / 40M TPM |

### The two ceilings that are not the context window

**1,050,000 is the window. 922,000 is the input ceiling.** The gap is not slack you
can spend on a bigger document — it is the room reasoning and output need. If you
size a retrieval step against "1M context" you will hit a limit ~12% earlier than the
marketing number, and you will hit it at the worst moment, after you have already paid
to assemble the prompt.

**Then there is the price cliff at 272K.** Cross it and input and cached input double,
output goes up by half. This is the same cliff GPT-6 Astra has, and it changes the
economics of long-context work sharply: a 300K-token prompt does not cost 10% more
than a 272K one, it costs roughly twice as much on the input side. If you are near the
boundary, compressing to stay under it is worth real engineering effort. Claude prices
its 1M window differently — see [what AI costs across
providers](/docs/models/what-ai-costs-across-providers) and [prompt caching across
providers](/docs/models/prompt-caching-across-providers).

## The trap: tool calling is not on both APIs

The model page lists **Chat Completions (without tool calling)** and **Responses API
(tool calling)**. Read that twice if you are porting an existing integration.

If your code posts to Chat Completions — the endpoint most third-party libraries,
gateways and "OpenAI-compatible" wrappers default to — **you do not get function
calling on this model.** The fix is not a parameter, it is a different endpoint and a
different request shape.

Also unsupported: Live, Realtime, Assistants, fine-tuning, embeddings, image
generation, video, speech and transcription, moderation, and legacy Completions. The
supported tool list is broad — web search, file search, image generation, code
interpreter, hosted shell, apply patch, skills, computer use, MCP, tool search — but
it is a **Responses API** list.

<Callout type="warning" items={[
  "Check your AI gateway before you switch a model string. A router that normalises everything to Chat Completions will silently drop tool calling on gpt-6.1-sol — the request succeeds, the tools just never fire."
]} />

## Price it against Claude properly

Same headline numbers, different mechanics.

| | **GPT-6.1 Sol** | **Claude Sonnet 5.5** | **Claude Opus 5.5** |
|---|---|---|---|
| Input / output per MTok | $2 / $10 | $2 / $10 | $4 / $20 |
| Cached read per MTok | **$0.10** | $0.20 | $0.20 |
| Context | 1.05M (922K input) | 1M | 1M |
| Max output | 128K | 128K | 128K |
| Long-context surcharge | **Yes, above 272K** | No published cliff | No published cliff |

Two consequences that matter more than the headline parity:

**On a long agent loop, GPT-6.1 Sol's cache read is the cheaper line.** $0.10 against
$0.20 is a 2× gap on the item an agentic loop re-pays on every single turn. If your
prompt is a large stable prefix plus a small delta — which is what an agent is — that
is where the bill actually lives.

**Above 272K the direction flips hard.** Anthropic publishes no equivalent cliff on
the Claude 5.5 models, so a workload that genuinely needs 400K of context is priced on
very different curves. Know which side of 272K you live on before you compare
anything.

## The benchmarks, read honestly

OpenAI's launch numbers, as compiled at launch. These are vendor-run; nobody has
reproduced them independently yet.

| Benchmark | GPT-6.1 Sol | GPT-6 Astra | Claude | Cost per task |
|---|---|---|---|---|
| **DeepSWE v1.1** (software engineering) | **75.2%** (high) | 74.8% (high) | Sonnet 5.5: 71.0% | ~$1.50 vs Astra ~$7.70 |
| **OSWorld 2.0** (computer use) | 71.4% (max) | **73.5%** (max) | Opus 5: 60.3% (medium) | $1.30 vs Astra $9.30 |
| **GDP.pdf** (document analysis) | 32.0% | **32.2%** | Opus 5.5: 28.8% | — |
| **AutomationBench 1.0.6** (business workflows) | 36.0% | — | **Sonnet 5.5: 44.7%** | $0.30 vs Sonnet ~$1.14 |
| Low-effort factual error rate | **7.7%** | — | — | (GPT-6 Sol: 11.4%) |

Three things to take from this table:

**1. The cost claim is the strong claim.** Beating Astra on DeepSWE by 0.4 points is
noise. Doing it at roughly a fifth of the cost per task is not. The interesting
comparison in this release is never Sol against Astra on quality — it is Sol against
Astra on price for the same quality.

**2. AutomationBench is the row OpenAI did not lead with.** Claude Sonnet 5.5 scores
**44.7%** against GPT-6.1 Sol's **36.0%** — 8.7 points, on business-workflow
automation, at ~4× the cost per task. That is a genuine trade, not a rout in either
direction: if a failed workflow costs you more than $0.84, the expensive model is the
cheap one. Decide with your own failure cost, not with the leaderboard.

**3. Even the best computer-use number is 71.4%.** Roughly three in ten tasks fail on
the benchmark designed for the capability. Everything in [computer-use agents
compared](/docs/models/computer-use-agents) about confirmation gates still applies.

The factual-error figure is the quietest interesting number: **7.7% at low effort**,
down from 11.4% on GPT-6 Sol. Error rate improving specifically *at the cheap setting*
is what makes a workhorse model usable as a default rather than as a fallback.
