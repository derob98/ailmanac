Claude Code isn't only interactive. You can run it **headless** (non-interactive, scriptable) and you can build your **own agents** on the same underlying harness with the **Agent SDK**.

<Callout type="objectives" items={["How to run a single prompt non-interactively and capture its output","Why an unattended run needs a deliberate permission posture, not the interactive default","When you have outgrown a one-shot call and should reach for the Agent SDK instead","The three modes side by side, so you pick deliberately rather than by habit"]} />

## Headless mode

Run a single prompt non-interactively and capture the output — perfect for scripts, pre-commit hooks, and CI:

<PromptCard title="Review the staged diff from a script">
{`claude -p "Review the staged diff and list any bugs as a Markdown checklist"`}
</PromptCard>

Pipe input in, get a result out. Combine with [permissions](/docs/claude-code/permissions) set to a safe, non-interactive posture so it never hangs waiting for approval — and **lock it down** so an automated run can't touch secrets (see [Hardening Autonomous Runs](/docs/security/hardening-autonomous-runs)).

<Steps items={[
  {title: "Start with -p and a narrow prompt", body: "One prompt, one answer, exit. Everything a headless run needs is a flag, because there is no UI to ask you anything."},
  {title: "Decide the permission posture up front", body: "An interactive session asks you; a CI job has nobody to ask. Set explicit allow rules for the tools the task genuinely needs, and make sure an unanswerable prompt ends the run instead of stalling it."},
  {title: "Bound the run", body: "Cap the turns and the spend so a loop that goes wrong costs minutes and cents rather than hours and dollars."},
  {title: "Ask for structured output", body: "A script that parses prose is a script that breaks. Request JSON — or a schema — so the result is machine-readable by construction."},
  {title: "Harden what it can reach", body: "Secrets, network, and write access are the three things an unattended run should have least of. See Hardening Autonomous Runs."}
]} />

The exact flags for each step — and the traps in them — are in [The claude CLI: Flags That Change Outcomes](/docs/claude-code/cli-flags). A classic use of all of it together: a CI job that has Claude review every pull request — see the [PR-review walkthrough](/docs/walkthroughs/pr-review-action).

## The Agent SDK

The **Claude Agent SDK** (Python and TypeScript) lets you build production agents on the same loop that powers Claude Code — tool use, file/shell access, permissions, context management — but wired into *your* application.

```mermaid
flowchart LR
  A[Your app / CI] --> H[Agent harness]
  H --> T[Tools: files, shell, MCP, custom]
  H --> L[Claude model]
  L --> H --> A
```

Reach for it when you've outgrown a single API call or a hand-rolled loop and want a batteries-included agent runtime. For the spectrum of options — single call → workflow → custom agent → managed — see [Building Agents on the API](/docs/api/building-agents).

## Headless/SDK vs interactive

| Mode | For |
|---|---|
| Interactive Claude Code | Day-to-day dev with a human in the loop |
| Headless (`claude -p`) | Scripts, pre-commit, CI one-offs |
| Agent SDK | Production agents embedded in your software |
