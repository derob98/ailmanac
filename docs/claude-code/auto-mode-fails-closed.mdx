[Auto mode](/docs/claude-code/permissions) is the mode most people now run in: instead of prompting you for every action, a **safety classifier** screens each one. In **v2.1.319** (November 6, 2026) Anthropic changed what happens when that classifier can't be reached — and the change is not in anyone's "new features" list, because it isn't a feature. It's an enforcement decision that turns a previously-silent degradation into a hard stop.

If you run Claude Code unattended — cron, CI, a scheduled task, a self-hosted runner — read the next two sections before your next pipeline run.

## What changed

Auto mode's check runs **server-side**. Before v2.1.319, a session that couldn't reach it fell back to a **built-in local classifier** and carried on. Now it doesn't: calls the server can't check are **asked about, or denied**, with no fallback.

| | Before v2.1.319 | From v2.1.319 |
|---|---|---|
| Server check reachable | Server classifier screens the call | Unchanged |
| Server check unreachable | Falls back to the built-in local classifier | **Asks you, or denies** |
| Unattended session (`-p`, cron, CI) | Kept running on the local classifier | **Turn stops** |
| `claude -p` exit code in that case | `0` | **`1`** |

That last row is the one that reaches production. The exit-code change is filed as a *fix* — `claude -p` was exiting `0` when its actions had been refused because no safety check was available, and text and JSON output now exit `1`. It is a fix: a pipeline that reported success while doing nothing was lying to you. But the symptom you'll see is a green job turning red after an upgrade, with the real cause sitting one layer away from the error message.

:::warning[Three environments trigger this, and two look nothing like each other]
- **Telemetry disabled** — the server check travels the same path.
- **Feature flags not fetched** — same.
- **Behind an LLM gateway** — the gateway drops the check.

**Bedrock, Vertex and Foundry are explicitly unchanged.** So an org on Bedrock sees nothing while the team next door, behind a gateway, loses every unattended run on the same version.
:::

Two related repairs landed in the same release, and both tell you that this failure mode had been hiding:

- `/status` used to show **"Auto mode server: Enabled"** when the server-side review wasn't actually reaching the session — for example behind a gateway that drops it. So the diagnostic you'd reach for first was, until v2.1.319, confirming the opposite of the truth.
- Auto mode used to **fail every turn** when a gateway answered `403` or `422` to the safety check. (A `403` with an `apiKeyHelper` is unchanged.)

## Fixing a run that just started failing

  },
  {

  },
  {

The wrong fix is reaching for `bypassPermissions` because the pipeline went red. That trades a stopped turn for no screen at all — see [Hardening Autonomous Runs](/docs/security/hardening-autonomous-runs) for what unattended actually requires.

## Five other changes that alter behavior quietly

Twenty-five releases shipped between **October 7 and November 10, 2026** (v2.1.293 → v2.1.322). These are the ones that change what your existing setup does, without announcing themselves as breaking.

### 1. Opus 4.8 fast mode is removed on November 30, 2026

Deprecated as of **October 30, 2026** (shipped in v2.1.316). After removal, fast mode requests on Opus 4.8 **return an error and do not fall back** to standard Opus 4.8. Migrating to Opus 5.5 keeps the speedup. A hard date with no graceful degradation is the rarest kind of change in this changelog — see [Models & Pricing](/docs/whats-new/models-and-pricing).

### 2. Skill loading narrowed twice, in two different ways

- **v2.1.319:** with the Bash sandbox on, skills in `.claude/skills` folders *below* your starting folder load only if you start Claude Code there or `/cd` there.
- **v2.1.321** (November 9): `.claude/skills` folders inside `~/.claude/plugins` **no longer load** when Claude works on files there.

If a [skill](/docs/claude-code/skills) silently stopped being available, this is the first thing to check — the symptom is absence, which produces no error.

### 3. MCP tool calls now background themselves

**v2.1.319** added support for MCP tasks in the terminal: when an MCP server runs a tool call as a task, Claude Code moves it to the background **right away** and tells Claude the result when it finishes. Set `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND` to make it wait inside the tool call instead.

MCP tasks also now work **without feature-flag fetching** (Bedrock, Vertex, Foundry, LLM gateways, `DISABLE_TELEMETRY`); `CLAUDE_CODE_DISABLE_MCP_TASKS=1` turns them off entirely. See [MCP Servers](/docs/claude-code/mcp) and [Background Tasks](/docs/claude-code/background-tasks).

### 4. Re-reading an unchanged file returns its content again

**v2.1.317** (November 3) removed the Read tool's `"file unchanged since your last Read"` stub. Reading the same file twice now returns the file, not a placeholder. Better for correctness — Claude can no longer act on a stale assumption — and a real change to how fast a long session fills its [context budget](/docs/claude-code/context-budget-audit).

### 5. `sed -i` is a real Bash command now

**v2.1.309** (October 22) changed `sed -i` to get the standard Bash prompt and run as written, rather than as a simulated file-edit preview. Like other Bash edits, **it is no longer restored by `/rewind`**. If your workflow leaned on `/rewind` to undo in-place stream edits, that safety net is gone — see [Checkpoints & Rewind](/docs/claude-code/checkpoints-and-rewind).

A sixth, smaller one worth knowing if you automate: self-paced `/loop` now **ends** when a turn finishes instead of scheduling a fallback wakeup (v2.1.319). `CLAUDE_CODE_LOOP_KEEPALIVE=1` restores the old behavior.
