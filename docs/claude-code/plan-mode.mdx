## The big idea

Imagine handing a contractor your house keys versus first asking them to walk through and write up *what* they'd change. Plan Mode is the walkthrough.

**Plan Mode** tells Claude to **research and propose changes without making them**: it reads files, runs shell commands to explore, and writes a plan — but it does **not edit your source**. Edits stay blocked until you approve the plan.

<Callout type="tip" items={["Plan Mode means Claude INVESTIGATES but does not CHANGE your source — it produces a plan and waits for your go."]} />

### It is not strictly read-only

Exploring sometimes needs a command, so Plan Mode is about *not editing*, not about *not executing*. What happens to a shell command during planning depends on the session — the first case that matches wins:

## Why it's the safest way to start

For anything big, risky, or unfamiliar, you want to see *what* Claude intends before it touches your repo. Plan Mode separates **thinking** from **doing**:

```mermaid
flowchart LR
  A[Goal] --> B[Claude investigates<br/>no source edits]
  B --> C[Presents a plan]
  C --> D{You approve?}
  D -->|edit/refine| C
  D -->|approve| E[Claude executes the plan]
```

The payoff: you catch wrong assumptions *before* they become wrong code.

## When to use it

<Callout type="tip" items={["ALWAYS for large or multi-file changes, migrations, or refactors", "When working in a codebase you don't fully know yet", "When you want a reviewable plan to share with a teammate"]} />

For tiny, obvious edits you can skip it — but when in doubt, plan first.

## How it works in practice

Follow the loop. Each step earns the next — Claude only switches to editing *after* you approve.

<Steps items={[{title: "Enter Plan Mode and state your goal", body: "Press Shift+Tab to cycle permission modes until the status bar reads 'plan mode on', or prefix a single prompt with /plan. To start there, launch with claude --permission-mode plan. Then describe what you want to achieve."}, {title: "Claude investigates", body: "It reads the relevant files, runs exploratory commands, and asks clarifying questions."}, {title: "Claude returns a step-by-step plan", body: "Files to change, the approach, and how to verify the result. Approving exits Plan Mode into the permission mode that option describes, and Claude starts editing."}]} />

To leave Plan Mode without approving a plan, press `Shift+Tab` again. To make it the default for a project's terminal sessions, set `defaultMode` to `plan` in `.claude/settings.json` — see [Settings](/docs/claude-code/settings).

## Plan Mode vs Permissions

A classic mix-up. They solve different problems and work together:

- **Plan Mode** = "investigate and propose, don't edit yet." (This page.)
- **[Permissions](/docs/claude-code/permissions)** = once acting, *which* actions are allowed without asking.

Think of it as **whether to act now** (Plan Mode) versus **which actions are allowed once acting** (Permissions).
