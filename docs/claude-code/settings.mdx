`settings.json` is where Claude Code's configuration lives — [permissions](/docs/claude-code/permissions), [hooks](/docs/claude-code/hooks), environment variables, model defaults, and more. Understanding the **tiers** is the key.

## The tiers (highest precedence first)

When the same key is set in more than one place, Claude Code uses the value from the highest level that sets it:

<Steps items={[
  {title: "Managed / enterprise", body: "managed-settings.json, an MDM policy, or server-managed settings from the claude.ai console. Nothing you set overrides them (bar a few security-sensitive exceptions)."},
  {title: "Command line", body: "claude --settings '<json-or-path>', for one session only. Sits above every file except managed, and writes to no file — so it is the right tool for an experiment you do not want to remember."},
  {title: "Project (personal)", body: ".claude/settings.local.json, git-ignored. Your overrides for this repo: machine-specific paths, a model you prefer here, a hook only you want."},
  {title: "Project (shared)", body: ".claude/settings.json, committed to the repo. Team-wide conventions — the file a new teammate inherits by cloning."},
  {title: "User", body: "~/.claude/settings.json. Your defaults across all projects. Lowest precedence, so a repo can always override you."}
]} />

```mermaid
flowchart TB
  M[Managed / enterprise] -->|overrides| C[Command line --settings]
  C -->|overrides| L[Project local]
  L -->|overrides| P[Project shared]
  P -->|overrides| U[User]
```

:::note Environment variables are not a tier
They sit outside this stack and are resolved per key. For example `ANTHROPIC_MODEL` applies over the `model` key from any file, while `ANTHROPIC_DEFAULT_MODEL` applies only when no file sets `model`.
:::

:::tip Commit the shared file, ignore the local one
Put team conventions in `.claude/settings.json` (committed). Put personal tweaks and machine-specific paths in `.claude/settings.local.json` (git-ignored). This keeps the team consistent without forcing your preferences on others.
:::

## What you'll commonly set

- **`permissions`** — allow/ask/deny rules. See [Permissions](/docs/claude-code/permissions).
- **`hooks`** — commands that run at lifecycle events. See [Hooks](/docs/claude-code/hooks).
- **`env`** — environment variables for the session.
- **Model / behaviour defaults** — e.g. preferred model.

## Editing safely

- Keep it valid JSON (a trailing comma will break it).
- Prefer **narrow** permission rules over broad ones.
- Never put secrets in a committed file — use `env` references or a secrets manager.

<PromptCard title="Try a setting for one session without writing it to any file">
{`claude --settings '{"permissions":{"allow":["Bash(git log *)"]}}'`}
</PromptCard>

Ready-to-copy starting files live in [Hooks & settings.json Recipes](/docs/templates/hooks-settings). When a file is malformed or a key isn't doing what you expect, `claude doctor` prints settings-file validation errors without starting a session — see [the CLI page](/docs/claude-code/cli-flags) for that and `--safe-mode`.
