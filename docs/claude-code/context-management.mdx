## The big idea

Every session has a finite [context window](/docs/foundations/tokens-and-context). As it fills, older content gets squeezed and Claude can start to "drift." Managing context deliberately is what keeps long sessions sharp.

## The two essential commands

Two commands cover almost every situation. The trick is matching the command to your intent.

<Flashcards cards={[{front: "/clear", back: "Wipe the conversation and start fresh. Use it when you switch to an UNRELATED task. The cheapest way to regain a clean, focused context. Aliases: /reset and /new."}, {front: "/compact", back: "Summarize the conversation so far into a compact form — keeps the gist while freeing space. Use it when you want to CONTINUE the same task but the window is getting full. Takes optional focus instructions."}]} />

Decide with one question: is this a new task or the same one?

```mermaid
flowchart TD
  A{New task or same task?} -->|New / unrelated| B[/clear]
  A -->|Same task, context full| C[/compact]
```

Two details that are easy to miss:

- **`/compact` takes instructions.** `/compact focus on the auth bug fix` keeps what *you* choose instead of what the automatic pass guesses matters. Run it deliberately before starting a long new task rather than waiting for the window to force it.
- **`/clear` is not a point of no return.** Pass a name (`/clear auth refactor`) to label the outgoing conversation in the `/resume` picker, and within the same Claude Code process the rewind menu still offers a `/resume <session-id> (previous session)` entry — see [Checkpoints & Rewind](/docs/claude-code/checkpoints-and-rewind).

## Auto-compaction — and how to move it

When context approaches the limit, Claude Code **auto-compacts** so work continues without a hard stop. On models with the 1M context window that happens at about 967K tokens by default; earlier models compact at their context-window boundary. Claude Code can also compact a conversation you leave idle.

The threshold is yours to move. `/autocompact 500k` compacts earlier — useful when you'd rather summarize on your own terms than at 96% full — and `/autocompact auto` returns to the window tuned for your model.

## What survives compaction

Compaction summarizes the *conversation*. Everything your setup loads from disk is handled separately — which is why a compacted session still knows your project conventions.

<Steps items={[{title: "Re-injected from disk", body: "The system prompt and output style still apply; project-root CLAUDE.md, unscoped rules, auto memory and the plan Claude wrote in plan mode come back. Skill descriptions are rebuilt from your current skills (Claude Code v2.1.304 or later). If the session started with a git status snapshot, Claude Code reads a fresh one."}, {title: "Reloaded on demand", body: "Rules with paths: frontmatter and nested CLAUDE.md files in subdirectories are summarized away and reload only when Claude next touches a matching file. If a rule must persist across compaction, drop the paths: frontmatter or move it into the project-root CLAUDE.md."}, {title: "Partially restored", body: "Claude Code re-reads up to five of the files Claude read or edited, most recently modified first — but a file over 5,000 tokens comes back as a path reference ('Referenced file') without its content. Invoked skill bodies are re-injected capped at 5,000 tokens per skill and 25,000 total, oldest dropped first, keeping the start of the file: put what matters near the top of SKILL.md."}, {title: "Summarized away", body: "The conversation itself, including context that hooks added earlier. SessionStart hooks matching the 'compact' source run again and their output joins the compacted context — that's the hook to use for anything that must come back."}, {title: "Untouched", body: "Background commands and background subagents keep running, and Claude Code reminds Claude which ones are still live so it doesn't start a duplicate."}]} />

## Techniques to stay effective

Beyond the two commands, four habits keep your context lean from the start.

These map to live docs: [subagents](/docs/claude-code/subagents), [CLAUDE.md](/docs/claude-code/claude-md), and [statusline](/docs/claude-code/statusline).

:::tip[Symptom → fix]
If Claude starts forgetting an earlier instruction or repeating itself, the window is likely full. `/compact` (same task) or `/clear` (new task) usually fixes it instantly. Run `/context` to confirm — when the conversation has actually exceeded the window, its output names how far over you are and which command frees space. More in [Why Did Claude Do That?](/docs/contribute/troubleshooting).

If you instead hit `Autocompact is thrashing`, compaction is working and something oversized keeps refilling the window — see [Troubleshooting Claude Code](/docs/claude-code/troubleshooting).
:::
