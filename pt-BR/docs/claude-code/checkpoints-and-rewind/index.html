Checkpoints e Rewind

Intermediário
What you'll learn
  • Entender o que um checkpoint captura — e o que ele silenciosamente não captura
  • Abrir o menu de rewind de duas formas e escolher a ação de restauração certa todas as vezes
  • Distinguir 'restaurar' (desfazer o estado) de 'resumir' (comprimir o contexto)
  • Saber exatamente por que os checkpoints complementam o Git, mas nunca o substituem
Última verificação: 2026-10-20.

O comportamento dos checkpoints, as ações do menu de rewind, o limite de snapshots e a retenção mudam entre versões — confirme na documentação oficial.

Confirme na fonte oficial.

A grande ideia​

Quando você solta o Claude em uma mudança ambiciosa e de grande escala, a pergunta mais assustadora é "e se der errado três edições adiante?" O checkpointing é a resposta: o Claude Code tira automaticamente um snapshot do seu código antes de cada edição, para que você possa voltar a qualquer estado anterior em vez de desembaraçar à mão uma refatoração pela metade.

Pense nele como um desfazer local para a sessão inteira — uma rede de segurança que permite dizer "sim, tente a abordagem ousada" sem medo.

Como os checkpoints são criados​

Você não cria checkpoints — eles acontecem automaticamente.

Guided walkthrough1 of 4
  1. Cada prompt que inicia um turno captura o estado do seu código antes de as ferramentas de edição de arquivos do Claude rodarem. Sem comando, sem configuração, sem cerimônia.
  2. O Claude Code mantém snapshots de arquivos para os 100 checkpoints mais recentes de uma sessão. Os mais antigos são descartados, então uma sessão muito longa não pode ser revertida até o começo.
  3. Os checkpoints são salvos junto com a conversa, então você ainda pode executar /rewind depois de retomar uma sessão, não apenas na sessão ativa.
  4. Os snapshots de arquivos de uma sessão são apagados na varredura de retenção, por padrão cerca de 30 dias depois que a sessão salvou um snapshot pela última vez. Voltar a um checkpoint cujos snapshots já se foram falha com 'No files were restored' — aumente cleanupPeriodDays para mantê-los por mais tempo.

Abrindo o menu de rewind​

Há duas formas de entrar:

Guided walkthrough1 of 2
  1. Digite o comando de barra no prompt. Sempre funciona. /checkpoint e /undo são aliases do mesmo comando, então use o nome que lhe vier à cabeça.
  2. Esc duplo abre o menu de rewind quando a caixa de prompt está vazia. Se houver texto nela, o Esc duplo apaga esse texto (o texto apagado vai para o histórico de entrada, então pressione Seta para cima para recuperá-lo depois).

Abrir o menu de rewind

/rewind
Watch out
  • Os nomes dos aliases são mais amigáveis do que literais: /checkpoint não tira um snapshot sob demanda (os snapshots são automáticos), e /undo não desfaz sozinho a última edição. Os três nomes abrem o mesmo menu, no qual você ainda escolhe o ponto e a ação.

O menu lista todos os prompts que você enviou nesta sessão. Escolha o ponto em que quer agir e depois uma ação.

Restaurar vs. resumir: a distinção-chave​

É aqui que as pessoas se confundem. O menu oferece dois tipos de ação:

  • As ações de restaurar alteram o estado em disco e/ou na conversa — elas desfazem.
  • As ações de resumir nunca tocam nos seus arquivos — elas comprimem a conversa para liberar espaço na janela de contexto.
Watch out
  • Restaurar = desfazer (reverte o código, a conversa ou ambos). Resumir = comprimir o contexto (os arquivos em disco ficam intactos).
  • Recorra a restaurar quando uma edição quebrou algo. Recorra a resumir quando a sessão está inchada mas o código está bom.

As ações de restaurar​

Guided walkthrough1 of 3
  1. Reverte tanto os arquivos quanto o histórico do chat até o ponto selecionado — um 'voltar no tempo' limpo até aquele momento.
  2. Volta o chat até aquela mensagem, mas mantém o código atual. Útil para refazer uma pergunta sem perder edições que você quer manter.
  3. Reverte as mudanças nos arquivos, mas mantém a conversa. Desfaz as edições e preserva a discussão sobre elas.

As duas opções de restaurar código só aparecem quando o checkpoint selecionado realmente tem mudanças de arquivo rastreadas para reverter. Se nenhuma edição de arquivo foi capturada depois desse ponto, o menu oferece apenas Restaurar conversa, as duas opções de resumir e Never mind (que volta à lista de mensagens sem mudar nada).

Depois de restaurar a conversa (ou de escolher "Summarize from here"), o prompt original da mensagem selecionada volta para o campo de entrada, para você reenviá-lo ou editá-lo.

As ações de resumir​

Ambas comprimem parte da conversa em um resumo gerado por IA — como um /compact direcionado, em que você escolhe qual lado da mensagem selecionada comprimir.

Guided walkthrough1 of 2
  1. As mensagens ANTES da mensagem selecionada permanecem intactas. A mensagem selecionada e tudo o que vem depois viram um resumo. Use para descartar uma discussão paralela mantendo o contexto inicial em todos os detalhes.
  2. As mensagens ANTES da mensagem selecionada viram um resumo; a mensagem selecionada e tudo o que vem depois permanecem intactos. Você continua no fim da conversa. Use para comprimir a conversa inicial de preparação mantendo o trabalho recente literal.

As mensagens originais continuam na transcrição da sessão de qualquer forma, então o Claude ainda pode consultar os detalhes, e um marcador Summarized conversation aparece onde ficavam as mensagens comprimidas. Para orientar o foco do resumo, destaque uma opção Summarize com as setas e digite instruções onde a linha diz add context (optional), depois pressione Enter — escolher a opção pela tecla numérica resume imediatamente, sem instruções.

Para o fluxo completo, veja Gerenciamento de contexto — as ações de resumir do /rewind são um bisturi, enquanto o /compact é um pincel largo.

What you'll learn
  • Resumir mantém você na mesma sessão. Para criar uma ramificação e tentar outra abordagem deixando a sessão original intacta, use /branch ou claude --continue --fork-session.

Voltando além de um /clear​

Se você executou /clear antes, no mesmo processo do Claude Code, o menu de rewind mostra uma entrada extra no topo: /resume <session-id> (previous session). Selecione-a para voltar à conversa que estava ativa antes do /clear.

Última verificação: 2026-10-20.

Essa entrada só fica disponível até você sair do Claude Code ou retomar outra sessão. Depois que ela some, execute /resume e escolha a sessão anterior na lista.

Confirme na fonte oficial.

Onde os checkpoints terminam — os limites que machucam​

Os checkpoints parecem mágicos até deixarem de ser. Estas lacunas importam:

Guided walkthrough1 of 6
  1. Arquivos tocados por comandos de shell que o Claude executa — rm, mv, cp, geradores de código, formatadores — NÃO são rastreados. Só as edições diretas feitas pelas ferramentas de edição de arquivos do Claude têm checkpoint. Um arquivo apagado com rm está perdido no que diz respeito ao rewind.
  2. Um subagente edita com as mesmas ferramentas de arquivo, mas sua sessão normalmente não captura essas edições. A exceção é uma skill bifurcada em primeiro plano (context: fork com background: false), que edita durante o seu próprio turno e é revertida normalmente. Qualquer outro subagente — inclusive uma skill bifurcada em segundo plano, que é o padrão — precisa do Git para desfazer. Veja /docs/claude-code/subagents.
  3. Edições manuais feitas fora do Claude Code e edições de outras sessões concorrentes normalmente não são capturadas — a menos que toquem os mesmos arquivos que a sessão atual editou.
  4. Uma mensagem que você enfileira enquanto o Claude trabalha e que o alcança dentro do turno em andamento entra nesse turno em vez de iniciar um novo, então não recebe um checkpoint próprio — o menu de rewind a marca como 'No code restore'. Para desfazer o que veio depois dela, volte ao prompt que iniciou o turno, o que reverte o turno inteiro, inclusive o trabalho feito antes de a sua mensagem chegar. Selecionar a própria mensagem marcada ainda oferece Restaurar conversa, deixando os arquivos como estão.
  5. A restauração ignora qualquer caminho rastreado que seja um symlink ou hard link e avisa 'Restored the code, but skipped N files'; esses arquivos mantêm o conteúdo atual. Symlinks de gerenciadores de dotfiles e hard links do pnpm caem nesse caso. Execute /debug antes de restaurar para que os caminhos ignorados sejam nomeados no log de debug.
  6. Os checkpoints são uma recuperação local e rápida. Não são commits, não são branches e não podem ser compartilhados com a sua equipe.

Checkpoints vs. Git: use os dois​

Eles resolvem problemas diferentes, então combine-os.

Checkpoints (/rewind)Git
EscopoUma sessãoHistórico inteiro do projeto
GranularidadePor prompt que inicia um turno, automáticaPor commit, deliberada
Rastreia mudanças feitas via bash?NãoSim (depois de staged/commitadas)
DuraçãoÚltimos 100 checkpoints, varridos ~30 dias após a sessãoPermanente
Compartilhável / colaborativoNãoSim
Modelo mental"Desfazer local""Histórico permanente"
Pro tip
  • Faça commit dos estados que funcionam com o Git antes de uma execução arriscada e de grande escala — esse é o seu piso durável.
  • Use /rewind para uma recuperação rápida dentro da sessão entre commits, sem poluir o histórico do Git.
  • Se o Claude for rodar bash destrutivo (rm/mv), geradores ou subagentes em segundo plano, apoie-se no Git — o rewind não salvará esses arquivos.

Quando recorrer a ele​

Guided walkthrough1 of 4
  1. Tente uma implementação ousada e, se não gostar, restaure código e conversa até o ponto de bifurcação e tente outra.
  2. Uma edição introduziu um bug três prompts atrás? Restaure o código para logo antes dela em vez de depurar os destroços.
  3. Experimente variações sabendo sempre que um estado funcional conhecido está a um /rewind de distância.
  4. Um desvio verboso de depuração consumiu sua janela de contexto? Resuma do ponto intermediário em diante e mantenha suas instruções originais em todos os detalhes.

Key takeaways
  • Os checkpoints são snapshots automáticos tirados antes de cada prompt que inicia um turno — um desfazer local para a sessão. Os últimos 100 são mantidos e depois varridos ~30 dias após a sessão.
  • Abra o menu de rewind com /rewind (aliases: /checkpoint, /undo) ou Esc duplo em uma entrada vazia; ele lista todos os prompts que você enviou.
  • As ações de restaurar desfazem o estado (código, conversa ou ambos); as ações de resumir comprimem o contexto e nunca tocam nos arquivos.
  • Mudanças feitas via bash, externas, concorrentes e a maioria das de subagentes NÃO são rastreadas — e caminhos com symlink ou hard link são ignorados na restauração.
  • Os checkpoints complementam o Git, não o substituem: pense em 'desfazer local' vs. 'histórico permanente e compartilhável'.
