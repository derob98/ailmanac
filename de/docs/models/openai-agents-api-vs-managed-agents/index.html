OpenAI Agents API vs. Claude Managed Agents: Die gehostete Agentenschleife im Vergleich

Experte
What you'll learn
  • Die beiden Stacks auf dieselben vier Primitive abbilden — Agent, Environment, Session, Events — und wissen, wo jeder Anbieter die Regler platziert hat
  • Den minimalen Create-Session-Aufruf auf beiden Seiten schreiben und wissen, welche Felder auf den Agenten und welche auf die Session gehören
  • Die Dinge vergleichen, die sich in der Praxis unterscheiden: Berechtigungsmodi, wo Secrets liegen, harte Budgets, Netzwerkrichtlinie, Datenresidenz, die Sandbox-Rechnung
  • Verstehen, was 'automatische Kompaktierung' und 'Tool-Suche' tatsächlich mit deinem Kontext und deinem Cache machen, und warum der SSE-Stream auf beiden Seiten eine Reconnect-Strategie braucht
  • Eine Laufzeit pro Workload wählen: Agents API, Managed Agents, deine eigene Schleife auf der Responses-/Messages-API oder das Agents SDK / Claude Agent SDK

Zwei Jahre lang war die „Agentenschleife“ — Modell aufrufen, Tool ausführen, Ergebnis anhängen, wiederholen, kompaktieren, wenn voll — etwas, das jedes Team neu baute. Anthropic hat sie am 8. April 2026 mit Managed Agents serverseitig verlagert. Am 10. September 2026 tat OpenAI dasselbe mit der öffentlichen Beta der Agents API, die nach eigenen Worten der Codex-Harness hinter einem API-Aufruf ist. Wenn du die Responses-Multi-Agent-Beta vom Juli genutzt hast, ist das die nächste Ebene darüber: nicht „das Modell fächert Subagenten innerhalb einer Anfrage auf“, sondern „OpenAI hält den gesamten Agenten stundenlang am Leben, mit einem Dateisystem“.

Die beiden Produkte sehen sich inzwischen verblüffend ähnlich. Diese Seite stellt sie nebeneinander, mit den echten Request-Formen, und verbringt den Großteil ihrer Länge an den Stellen, wo sie sich unterscheiden — denn das sind die Stellen, die entscheiden, ob man deinem Agenten Produktions-Zugangsdaten anvertrauen kann.

Zuletzt verifiziert: 2026-09-14. Diese Seite zitiert Fakten, die sich im Laufe der Zeit ändern — betrachte das obige Datum als ihren Aktualitätsstand. Bestätige anhand der offiziellen Quelle.

Dieselben vier Primitive, zwei Vokabulare​

KonzeptOpenAI Agents APIClaude Managed Agents
Die Definitionagent (model, instructions, tools, MCP-Server, multi_agent) — inline auf jeder SessionAgent-Objekt, persistiert und versioniert über POST /v1/agents; Sessions referenzieren es per id
Wo Tools laufenenvironment — openai_hosted oder self_hostedEnvironment-Objekt — cloud oder self_hosted
Das laufende Dingsession — dauerhaft, fortsetzbar, Stunden oder TageSession — dauerhaft, streamt Events, an eine Agent-Version gepinnt
Die LeitungEvents + Items; Stream oder WebhooksEvents; SSE-Stream unter /v1/sessions/{id}/events/stream
Beta-GateHeader OpenAI-Beta: agents=v1Header managed-agents-2026-04-01
Selbst gehosteter Workercodex exec-server wählt sich per WebSocket mit einem eingeschränkten Executor-Key nach außen einEnvironmentWorker.run() oder ant beta:worker poll mit einem Environment-Key

★ Der eine strukturelle Unterschied, der alles andere prägt: OpenAI legt die Agentendefinition inline auf die Session; Anthropic macht sie zu einem erstklassigen, versionierten Objekt. Wenn du dich auf der Anthropic-Seite dabei ertappst, model, system oder tools an sessions.create() zu übergeben, hast du es verkehrt herum — die gehören auf agents.create(), und laufende Sessions bleiben an die Version gepinnt, mit der sie gestartet sind. Auf der OpenAI-Seite gibt es keine Agenten-Registry, die man aufgeräumt halten muss, aber auch nichts, das dir sagt, welche deiner 400 laufenden Sessions auf den Anweisungen von letzter Woche laufen.

Der minimale Aufruf auf jeder Seite​

OpenAI, Python, gehostete Sandbox, Streaming:

from openai import OpenAI

with OpenAI() as client:
    with client.beta.agents.sessions.create(
        agent={
            "model": "gpt-6-astra",
            "instructions": "Write clean code, run it, and report the actual output.",
            "tools": [{"type": "web_search"}],
            "multi_agent": {"enabled": True, "max_concurrent_subagents": 3},
        },
        environment={
            "type": "openai_hosted",
            "packages": {"python": ["pandas==2.2.3"]},
            "network_policy": {"access": "restricted", "allowed_domains": ["pypi.org", "files.pythonhosted.org"]},
        },
        input="Create tree.py that prints a readable tree of /workspace, run it, paste the output.",
        stream=True,
    ) as events:
        for event in events:
            print(event.to_json(indent=None), flush=True)

Anthropic, zwei Aufrufe, weil der Agent ein eigenes Objekt ist:

import anthropic

client = anthropic.Anthropic()

agent = client.beta.agents.create(
    model="claude-fable-5-1",
    system="Write clean code, run it, and report the actual output.",
    tools=[{
        "type": "agent_toolset_20260401",
        "configs": [{"name": "web_fetch", "allowed_domains": ["pypi.org"]}],
    }],
    permission_policy={"mode": "auto"},
)

session = client.beta.sessions.create(
    agent=agent.id,
    environment_id="env_...",
    budget={"type": "limit", "max_list_cost": {"amount": "500", "currency": "USD"}},
)
# then stream GET /v1/sessions/{id}/events/stream and send user events

Beide ersparen dir die Schleife, die Kompaktierung, die Retry-Logik und die Sandbox-Bereitstellung. Beide berechnen dir Tokens plus die Kosten der Sandbox. Nun die Unterschiede.

Wo sie sich unterscheiden​

1. Berechtigungen: OpenAI hat auf API-Ebene (noch) keine; Anthropic hat drei Modi​

Managed Agents liefert eine Permission Policy pro Agent und pro MCP-Toolset mit drei Modi: always_allow (Standard für die eigenen Tools des Agenten), always_ask (Standard für MCP-Toolsets — die Session pausiert bei jedem Aufruf, bis ein Client eine user.tool_confirmation sendet) und seit dem 10. September 2026 auto. In auto klassifiziert der Server jeden einzelnen Aufruf — das Tool, die Eingabe dieses Aufrufs und die bisherige Session — als ausführen, ablehnen oder pending_approval. Zwei Aufrufe desselben Tools können unterschiedlich beurteilt werden, jedes Event trägt ein Feld evaluated_permission, und ein Client kann eine Ablehnung nicht überstimmen (eine Bestätigung für einen abgelehnten Aufruf liefert 400).

Die Agents API hat noch kein Äquivalent. Deine Hebel sind die Tool-Liste, die Netzwerkrichtlinie und die Authentifizierung der MCP-Server. Wenn ein Aufruf von einem Menschen freigegeben werden muss, baust du das in deine eigene Event-Schleife — oder nutzt stattdessen das Agents SDK, wohin OpenAIs Docs für „Approvals“ verweisen.

2. Secrets: Vaults vs. Umgebungsvariablen​

Anthropics Antwort auf „wie ruft der Agent einen authentifizierten MCP-Server auf“ sind Vaults: Die mcp_servers-Einträge des Agenten deklarieren nur {type, name, url}; Zugangsdaten (mcp_oauth mit Auto-Refresh, static_bearer oder environment_variable) liegen in einem Vault, der bei der Session-Erstellung angehängt wird, und werden beim Egress eingesetzt, sodass das Modell sie nie sieht.

OpenAIs gehostete Sandbox nimmt eine env-Map aus String-Variablen entgegen und lehnt ein paar reservierte Namen ab (PATH, CODEX_*, OPENAI_API_KEY). Alles andere, was du dort ablegst, ist für den Code lesbar, den der Agent ausführt. Das ist in Ordnung für ein Build-Token, das du stündlich rotierst; für den OAuth-Refresh-Token eines Kunden ist es der falsche Ort. Bei selbst gehosteten Environments kann der eingeschränkte Key des Executors nur Environments verbinden — er kann selbst bei einem Leak nicht den Rest der API aufrufen —, was das richtige Design ist und es wert, kopiert zu werden.

3. Harte Budgets vs. dein eigener Zähler​

Managed Agents akzeptiert ein Dollar-Budget auf der Session; wird es erreicht, pausiert die Session mit budget_reached und akzeptiert nur noch Settle-Events, bis du die Obergrenze erhöhst oder entfernst. Deployments (geplante Sessions) nehmen ebenfalls Budgets entgegen. Siehe Session-Budgets.

Die Agents API hat in den Launch-Docs keine Ausgabenobergrenze pro Session. Du bekommst Streaming-Events mit Usage, du bekommst Container-Zeit, und die Obergrenze setzt du selbst. Bei einer außer Kontrolle geratenen Schleife ist der Unterschied der zwischen „bei 5 $ pausiert“ und „auf der Rechnung bemerkt“.

4. Netzwerkrichtlinie: beide haben sie, auf verschiedenen Ebenen​

OpenAIs gehostete Sandbox hat eine network_policy mit drei Zuständen — enabled (Standard, sofern du kein Template erbst), disabled und restricted mit einer allowed_domains-Liste von 1–100 exakten Hostnamen: keine Wildcards, keine Ports, keine Pfade, und Redirect-Ziele wie Subdomains brauchen jeweils einen eigenen Eintrag. Zwei Fallstricke aus den Docs: stdio-MCP-Server erfordern derzeit enabled, und eine gespeicherte environment_template_id kippt den Standard auf kein Netzwerk.

Anthropic beschränkt stattdessen auf Tool-Ebene — allowed_domains / blocked_domains / max_content_tokens in den Tool-Konfigurationen von web_search und web_fetch, nicht im Environment — und der Egress des Bash-Tools folgt dem Networking des Environments. Siehe Domain-Einschränkungen für die vollständige Matrix. Wenn die Lehre aus GemStuffer lautet „Egress im Netzwerk durchsetzen, nicht im Prompt“, ist OpenAIs restricted-Richtlinie die wörtlichere Umsetzung; Anthropics ist pro Tool leichter nachzuvollziehen.

5. Datenresidenz und Aufbewahrung​

Die Agents-API-Beta ist bei der Datenresidenz nur USA und unterstützt keine Zero Data Retention — und, ausdrücklich, eine selbst gehostete Sandbox macht eine Session nicht ZDR-fähig. Managed Agents lässt dich über model.inference_geo auf dem Agenten oder pro Session festlegen, wo die Inferenz läuft. Für einen regulierten Workload ist das heute entscheidend, keine Nuance.

6. Was die Sandbox kostet​

OpenAIs gehostete Sandbox wird zu Standard-Container-Tarifen abgerechnet, getrennt von den Tokens — minutengenau mit fünf Minuten Minimum, von etwa 0,03 $ pro 20 Minuten für einen 1-GB-Container bis 1,92 $ für 64 GB (grob 0,09 $ bis 5,76 $ pro Stunde), laut Berichten vom Launch-Tag. Inaktive Sandboxes werden nach einer Stunde ohne Aktivität oder Keep-Alives gelöscht; dieses Timeout ist nicht konfigurierbar. Dateien unter /workspace/outputs werden beim Abschluss einer Runde als unveränderliche Artefakte veröffentlicht und überleben die Sandbox. Anthropics Cloud-Environment ist ein Container pro Session, als Compute zusätzlich zu den Tokens abgerechnet; prüfe die aktuelle Preisseite statt diesem Absatz.

Das Erste, was ein Entwickler unter OpenAIs Ankündigungs-Thread schrieb, war eine Warnung, die Container-Kosten zu berechnen, bevor man Sandboxes in einer Schleife hochfährt. Nimm das wörtlich: Ein Subagenten-Fan-out von sechs auf einem 16-GB-Image sind sechs Container.

Die zwei Features, nach denen alle fragen​

Automatische Kompaktierung. Beide Laufzeiten fassen früheren Kontext zusammen, wenn sich die Session ihrem Limit nähert, sodass eine Session stundenlang laufen kann, ohne dass du den Zusammenfasser schreibst. Was keine der beiden für dich tut, ist, die richtigen Dinge zu behalten: Wenn ein Fakt über die Kompaktierung hinweg zählt, schreibe ihn in eine Datei im Workspace (OpenAI) oder in einen Memory-Store (Anthropic), statt der Zusammenfassung zu vertrauen. Die Harness-Muster in Harnesses für langlaufende Agenten gelten unverändert.

Tool-Suche und programmatisches Tool-Calling (OpenAI). Die Tool-Suche lädt Tool-Definitionen bei Bedarf, statt jedes Schema in den Prompt zu stopfen — was das gecachte Präfix stabil hält, wenn du Dutzende MCP-Tools hast. Programmatisches Tool-Calling, aktiviert mit {"type": "programmatic_tool_calling"}, lässt das Modell Code schreiben, der mehrere Tools aufruft, Schleifen dreht und Ergebnisse filtert, bevor irgendetwas zurück in den Kontext kommt. Anthropics Äquivalent ist das Bash-plus-Dateien-Toolset: Das Modell schreibt einfach das Skript. Gleicher Effekt, weniger Zeremonie, weniger Struktur.

Subagenten. OpenAI: multi_agent.enabled mit max_concurrent_subagents, Standard 6, ohne den Koordinator; Subagenten bekommen einen eigenen Kontext, erben MCP-Tools, Zugangsdaten und Dateien, können aber keine Function-Tools verwenden, und Koordinations-Events können Nachrichteninhalte auslassen — du wirst im Stream keine vollständigen Subagenten-Transkripte sehen. Anthropic: Managed Agents stellt keinen symmetrischen Regler bereit; du komponierst Sessions oder nutzt die Subagenten des Claude Agent SDK clientseitig. Die Seite zu nativen Multi-Agent-APIs hat die Kostenrechnung, die weiterhin gilt.

Sechs Fallstricke aus den Docs, beide Seiten​

Guided walkthrough1 of 6
  1. OpenAI: Wenn der Stream abbricht, rufe die Session und ihre gespeicherten Items ab, bevor du es erneut versuchst — eine abgeschlossene Runde bedeutet nicht, dass jedes Tool erfolgreich war; achte auf agent.session.turn.completed. Anthropic: Der SSE-Stream hat kein Replay; bei einem Abbruch GET /v1/sessions/{id}/events, per Event-ID deduplizieren, dann neu verbinden.
  2. model, system, tools, mcp_servers und skills gehören auf agents.create(). Erstelle den Agenten einmal, speichere seine id und Version und referenziere ihn. Ein Agent pro Lauf hinterlässt verwaiste Konfigurationen und erhöht die Latenz.
  3. setup_commands laufen der Reihe nach, bevor der Agent startet; ein Exit-Code ungleich null blockiert die Session. Pinne Paketversionen in den Listen python / npm / system, damit ein transitives Upgrade nicht alle Sessions auf einmal lahmlegt.
  4. 1–100 Hostnamen, keine Wildcards. api.github.com und github.com sind zwei Einträge; ein Redirect zu objects.githubusercontent.com ist ein dritter. Teste die Allowlist mit einer Trockenlauf-Session, bevor du dich darauf verlässt.
  5. Das Archivieren eines Agenten, Environments, einer Session, eines Vaults oder Memory-Stores macht ihn schreibgeschützt, ohne Unarchive. Laufende Sessions laufen weiter, neue können ihn nicht referenzieren. Bestätige, bevor du irgendetwas aus der Produktion archivierst.
  6. Auf beiden Seiten setzt sich ein HTTP-Client-Timeout bei jedem gestreamten Chunk zurück, es ist also keine Wanduhr-Obergrenze. Nutze das Plattform-Budget (Anthropic) oder deine eigene Deadline plus Session-Delete (OpenAI) für den harten Stopp.

Welche Laufzeit für welche Aufgabe​

OpenAIs eigene Docs teilen die Wahl jetzt dreifach — Agents API, wenn OpenAI den Agenten verwalten und seinen Fortschritt speichern soll, Agents SDK, wenn du Kontrolle über Deployment, Speicherung und Freigaben in deiner App brauchst, Responses API für direkte Modellinteraktion — und Anthropics Aufteilung ist Managed Agents vs. Claude Agent SDK vs. die rohe Messages API.
