GPT-6.1 Sol: The Field Guide for Claude Users

Intermedio

At DevDay on September 29, 2026 OpenAI shipped GPT-6.1 Sol (gpt-6.1-sol) one week after GPT-6 Sol, with the pitch "near-Astra intelligence for a fifth of the price." It went straight to the top of Hacker News.

For a Claude user the interesting fact is not the pitch. It is that GPT-6.1 Sol lands on exactly Claude Sonnet 5.5's rate card — $2 in, $10 out per MTok — while charging half of Sonnet 5.5's cached-input rate. Two models, same headline price, different bills, different shapes of work. This page is the specs, the pricing mechanics most write-ups skip, an honest read of the benchmark table, and the rest of what DevDay shipped for developers.

What you'll learn
  • Know the exact specs — and the two ceilings that are not the context window
  • Price a workload correctly, including the 272K cliff and the cached-input gap with Sonnet 5.5
  • Avoid the API-surface trap: tool calling is not available on both endpoints
  • Read the launch benchmarks including the row where Claude still wins
  • Know what else landed at DevDay for developers: Ultrafast, the Decisions API, Codex Security Cloud, Private Intelligence
Última verificación: 2026-09-29.

Specs, pricing, endpoint support and rate limits from OpenAI's gpt-6.1-sol model page, read the day of launch. Benchmarks are OpenAI's launch figures as compiled by third parties and are not independently reproduced. Three conflicts to know: (1) availability — OpenAI's DevDay resource index lists GPT-6.1 Sol as "coming soon", while launch-day reporting describes it as live in the API, ChatGPT Work and Codex and not yet in general ChatGPT chat; check the model page for your account. (2) One widely shared comparison table lists Claude Opus 5.5 at $5/$25 per MTok; Anthropic's own price is $4/$20 — use Anthropic's. (3) Ultrafast: OpenAI's guide lists broad availability for GPT-6 Astra with preview access for GPT-5.6 Sol, while the DevDay index says Astra now, Sol soon. Prices and limits move; read the source before quoting.

The two ceilings that are not the context window​

1,050,000 is the window. 922,000 is the input ceiling. The gap is not slack you can spend on a bigger document — it is the room reasoning and output need. If you size a retrieval step against "1M context" you will hit a limit ~12% earlier than the marketing number, and you will hit it at the worst moment, after you have already paid to assemble the prompt.

Then there is the price cliff at 272K. Cross it and input and cached input double, output goes up by half. This is the same cliff GPT-6 Astra has, and it changes the economics of long-context work sharply: a 300K-token prompt does not cost 10% more than a 272K one, it costs roughly twice as much on the input side. If you are near the boundary, compressing to stay under it is worth real engineering effort. Claude prices its 1M window differently — see what AI costs across providers and prompt caching across providers.

The trap: tool calling is not on both APIs​

The model page lists Chat Completions (without tool calling) and Responses API (tool calling). Read that twice if you are porting an existing integration.

If your code posts to Chat Completions — the endpoint most third-party libraries, gateways and "OpenAI-compatible" wrappers default to — you do not get function calling on this model. The fix is not a parameter, it is a different endpoint and a different request shape.

Also unsupported: Live, Realtime, Assistants, fine-tuning, embeddings, image generation, video, speech and transcription, moderation, and legacy Completions. The supported tool list is broad — web search, file search, image generation, code interpreter, hosted shell, apply patch, skills, computer use, MCP, tool search — but it is a Responses API list.

Watch out
  • Check your AI gateway before you switch a model string. A router that normalises everything to Chat Completions will silently drop tool calling on gpt-6.1-sol — the request succeeds, the tools just never fire.

Price it against Claude properly​

Same headline numbers, different mechanics.

Context1.05M (922K input)1M1M

Two consequences that matter more than the headline parity:

On a long agent loop, GPT-6.1 Sol's cache read is the cheaper line. $0.10 against $0.20 is a 2× gap on the item an agentic loop re-pays on every single turn. If your prompt is a large stable prefix plus a small delta — which is what an agent is — that is where the bill actually lives.

Above 272K the direction flips hard. Anthropic publishes no equivalent cliff on the Claude 5.5 models, so a workload that genuinely needs 400K of context is priced on very different curves. Know which side of 272K you live on before you compare anything.

Three things to take from this table:

1. The cost claim is the strong claim. Beating Astra on DeepSWE by 0.4 points is noise. Doing it at roughly a fifth of the cost per task is not. The interesting comparison in this release is never Sol against Astra on quality — it is Sol against Astra on price for the same quality.

2. AutomationBench is the row OpenAI did not lead with. Claude Sonnet 5.5 scores 44.7% against GPT-6.1 Sol's 36.0% — 8.7 points, on business-workflow automation, at ~4× the cost per task. That is a genuine trade, not a rout in either direction: if a failed workflow costs you more than $0.84, the expensive model is the cheap one. Decide with your own failure cost, not with the leaderboard.

3. Even the best computer-use number is 71.4%. Roughly three in ten tasks fail on the benchmark designed for the capability. Everything in computer-use agents compared about confirmation gates still applies.

The factual-error figure is the quietest interesting number: 7.7% at low effort, down from 11.4% on GPT-6 Sol. Error rate improving specifically at the cheap setting is what makes a workhorse model usable as a default rather than as a fallback.

What else DevDay shipped for developers​

Short version, because several of these deserve their own pages.

Guided walkthrough1 of 5
  1. A paid speed tier: OpenAI describes up to 8x faster token generation in Codex and 6x in the API. The guide notes it is US data residency and global processing only — no EU or other regional processing endpoints — and strongly recommends WebSockets over HTTP, because per-request network overhead eats the latency win on tool-heavy agent loops. On the consumer side it is exclusive to the new $500/month Pro 500 plan.
  2. The Agents API (public beta since September 10) can now operate software through its UI, alongside Codex's multi-agent capabilities, tool search and context compaction. The side-by-side with Anthropic's hosted loop is already written up on this site.
  3. Sub-second classification and routing over predefined options, running on the Luna model. This is a direct answer to the decision-model category — the same shape as Jev and Kev: return a choice with calibrated confidence instead of prose.
  4. Scans whole GitHub repositories, reviews new commits continuously, deduplicates findings and prepares fixes for review while your laptop is closed. The CLI is open source at github.com/openai/codex-security, with a TypeScript SDK.
  5. Zero Data Retention with Private Safety Processing — automated safety checks that run without OpenAI personnel accessing the content. Private Inference, combining confidential computing with verifiable controls, is previewed for later in the fall.

The Decisions API is the one to watch if you have been following the decision-model thread on this site: it takes a research direction that was open-weight and DIY and turns it into a hosted endpoint from the largest vendor. See System One decision models: Jev, Kev and the open clones and train your own decision model for what the category actually guarantees — and what "cannot hallucinate" does not mean.

Should you switch?​

Guided walkthrough1 of 4
  1. The models trade rows. GPT-6.1 Sol wins software engineering and raw cost per task; Sonnet 5.5 wins business-workflow automation by 8.7 points. A default-model change should follow a measurement on your own work, not a launch table.
  2. DeepSWE at 75.2% for ~$1.50 a task, with cached reads at $0.10, is the combination that makes a long agent loop cheap. If your bill is dominated by cache reads on a big stable prefix, that line alone can move it.
  3. If your integration or gateway speaks Chat Completions, tool calling does not come with the model switch. Verify you can move to the Responses API first; that is a bigger change than the model string.
  4. Below the cliff, this is a cheap 1M-context model. Above it, input and cache double. Instrument your actual prompt sizes before assuming the window is flat-priced.
