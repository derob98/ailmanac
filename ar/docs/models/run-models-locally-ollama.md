# تشغيل نماذج الذكاء الاصطناعي محليًا مع Ollama

> Source: https://derob98.github.io/ailmanac/ar/docs/models/run-models-locally-ollama · AILmanac (CC BY 4.0) · last verified 2026-10-21

شغّل النماذج مفتوحة الأوزان (Llama وMistral وQwen…) على جهازك — بخصوصية كاملة، دون إنترنت، وبلا تكلفة تشغيل — باستخدام Ollama. الإعداد وسطر الأوامر والاستدعاء من الكود.

<LevelBadge level="intermediate" />

تعيش النماذج الرائدة في السحابة، لكن فئة كاملة من النماذج **مفتوحة الأوزان** — Llama وMistral وQwen وDeepSeek وGemma — يمكنك تنزيلها وتشغيلها على حاسوبك المحمول أو خادمك. يُعدّ [Ollama](https://ollama.com/) أبسط طريقة لفعل ذلك: تثبيت واحد، وأمر واحد، فيعمل النموذج محليًا. تأخذك هذه الصفحة من الصفر إلى نموذج يعمل، ثم إلى استدعائه من الكود، وتعرّفك بالمفاضلات حتى لا تتوقع من نموذج محلي بحجم 7B أن يتصرف كنموذج رائد.

## لماذا تشغّل نموذجًا محليًا (ومتى لا تفعل)

تشغيل نموذج على عتادك الخاص يمنحك أربعة أشياء:

- **الخصوصية** — لا تغادر مطالباتك (prompts) وبياناتك جهازك أبدًا. وهذا هو السبب الذي يدفع الفرق العاملة في المجالات المنظَّمة أو الحساسة إلى النماذج المحلية. (انظر مفترق الخصوصية/الاستضافة الذاتية في [اختيار نموذج](/docs/models/choosing-a-model).)
- **دون اتصال** — لا إنترنت ولا واجهة API ولا اعتماد على انقطاع الخدمة. النموذج ملف على قرصك.
- **التكلفة** — لا فاتورة لكل رمز (token). بعد التنزيل يصبح تشغيله «مجانيًا» (تدفع كهرباءً وعتادًا، لا نفقات API). وإذا كان [إنفاق الرموز](/docs/power-user/token-economy) هو قيدك على نطاق واسع، فقد يتفوق الحل المحلي.
- **التحكم** — ثبّت إصدارًا بعينه، وخصّص السلوك، وادمج دون حدود معدّل الطلبات ودون مفاجآت في شروط الخدمة.

المفاضلات الصريحة:

- **فجوة القدرات.** النموذج الذي يمكنك تشغيله على حاسوب محمول (من 1B إلى 14B معامل) **ليس** في مستوى النموذج الرائد السحابي في الاستدلال الصعب أو السياق الطويل أو المهام الوكيلية. في كثير من المهام اليومية تكون الفجوة صغيرة، أما في أصعبها فهي كبيرة.
- **العتاد.** تحتاج النماذج الأكبر والأقدر إلى ذاكرة RAM/VRAM أكثر مما في الجهاز المعتاد. وكثيرًا ما تختار *أكبر نموذج يستطيع عتادك تشغيله*، لا أفضل نموذج موجود.
- **أنت من يشغّله.** لا توسيع نطاق مُدار ولا ترقيات تلقائية — هذا ثمن التحكم.

نمط شائع ودائم: **ابنِ نموذجًا أوليًا واختر** عبر تقييم صغير (الطريقة نفسها المتبعة مع النماذج السحابية — انظر [اختيار نموذج](/docs/models/choosing-a-model))، واستخدم النموذج المحلي للأعمال الخاصة/دون اتصال/الرخيصة على نطاق واسع، وارجع إلى واجهة API رائدة حين تحتاج المهمة فعلًا إلى القدرة الإضافية.

## واجهة سطر الأوامر الأساسية

حفنة من الأوامر تغطي تقريبًا كل شيء. شغّل `ollama --help` للقائمة الكاملة.

```bash
# Download a model without starting a chat
ollama pull qwen3

# Start an interactive chat (downloads first if needed)
ollama run qwen3

# One-shot: pass the prompt inline, get the answer, exit
ollama run qwen3 "Summarize the CAP theorem in two sentences."

# List models you've downloaded
ollama list

# Show models currently loaded in memory
ollama ps

# Stop a running/loaded model (frees memory)
ollama stop qwen3

# Delete a downloaded model to reclaim disk
ollama rm qwen3
```

داخل جلسة `ollama run` التفاعلية، اكتب `/bye` للخروج و`/?` لعرض أوامر الجلسة. أما الخدمة الخلفية التي تقدّم النماذج فعليًا فتبدأ بالأمر `ollama serve` (يشغّلها تطبيق سطح المكتب تلقائيًا نيابةً عنك).

## استدعِه من الكود (واجهة API متوافقة مع OpenAI)

هذا هو الجزء الذي يجعل النماذج المحلية مفيدة حقًا في التطبيقات. تكشف خدمة Ollama الخلفية واجهة HTTP محلية على العنوان **`http://localhost:11434`**، على المنفذ الافتراضي **11434**. لها نقاط نهاية أصلية خاصة بها (`/api/generate` و`/api/chat`) **و**طبقة **متوافقة مع OpenAI** على `/v1` — لذا فإن معظم الكود المكتوب لحزمة OpenAI SDK يعمل مع نموذجك المحلي بتغيير سطرين فقط.

HTTP خام باستخدام `curl` (نقطة النهاية الأصلية):

```bash
curl http://localhost:11434/api/chat -d '{
  "model": "gemma4:e2b",
  "messages": [
    { "role": "user", "content": "Why is the sky blue?" }
  ],
  "stream": false
}'
```

من Python باستخدام حزمة OpenAI SDK الرسمية — وجّه `base_url` إلى Ollama ومرّر أي `api_key` غير فارغ (يشترط Ollama وجود الحقل لكنه يتجاهل قيمته):

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama",  # required by the SDK, ignored by Ollama
)

response = client.chat.completions.create(
    model="gemma4:e2b",
    messages=[
        {"role": "system", "content": "You are a concise assistant."},
        {"role": "user", "content": "Explain gradient descent in two sentences."},
    ],
)

print(response.choices[0].message.content)
```

ولأنها متوافقة مع OpenAI، فإن الأنماط نفسها التي تستخدمها مع واجهة API مستضافة تنتقل كما هي — بما في ذلك البث المتدفق (streaming) و[استخدام الأدوات / استدعاء الدوال](/docs/api/tool-use)، وهي تعمل محليًا كما تعمل في السحابة (شرط أن يكون النموذج جيدًا فيها فعلًا). تغطي طبقة `/v1` في Ollama المسارات `/v1/chat/completions` و`/v1/completions` و`/v1/responses` و`/v1/models` (و`/v1/models/{model}`) و`/v1/embeddings`.

## العتاد وأحجام النماذج والتكميم

الرقم الذي تراه مرفقًا باسم النموذج — **1B أو 7B أو 8B أو 70B** — هو **عدد معاملاته** (بالمليارات). المزيد من المعاملات يعني عمومًا نموذجًا أقدر *وأشد* استهلاكًا للذاكرة. والحد العملي لما يمكنك تشغيله هو **الذاكرة RAM** (وعلى وحدة معالجة الرسوم GPU هو **VRAM**).

**التكميم (Quantization)** هو الحيلة الأساسية التي تجعل ذلك ممكنًا على أجهزة عادية. تُخزَّن أوزان النموذج في الأصل بدقة عالية (مثل 16 بت)، لكن يمكن ضغطها إلى نحو 4 بت بكلفة جودة صغيرة وغالبًا لا تكاد تُلحظ. يوزّع Ollama معظم النماذج مكمَّمة افتراضيًا — ولهذا يتسع نموذج بمليارات المعاملات في بضعة غيغابايت. قاعدة تقريبية (تحقق منها في صفحة النموذج المعني):

- نماذج **~1B–3B**: تعمل براحة على معظم الحواسيب المحمولة الحديثة (بضعة غيغابايت من RAM).
- نماذج **~7B–8B**: النقطة المثلى بين القدرة وإمكان التشغيل؛ خصّص عدة غيغابايت من الذاكرة الحرة.
- نماذج **~13B–14B**: تحتاج إلى جهاز ذي مواصفات جيدة نسبيًا.
- نماذج **~70B+**: تحتاج إلى محطة عمل/خادم بذاكرة كبيرة أو وحدة GPU قوية — وليست من نطاق الحاسوب المحمول المعتاد.

وصفة عملية: ابدأ بنموذج صغير (`gemma4:e2b`)، وتأكد من سير العمل من البداية إلى النهاية، ثم *اصعد* إلى أكبر نموذج لا يزال يعمل بسلاسة على عتادك — لا إلى أكبر نموذج موجود.

## LM Studio: بديل برسومات

إن لم يكن سطر الأوامر مناسبًا لك، فإن **[LM Studio](https://lmstudio.ai/)** تطبيق لسطح المكتب (macOS وWindows وLinux) يؤدي العمل نفسه عبر واجهة رسومية: تصفّح النماذج المفتوحة وتنزيلها، والدردشة معها في واجهة مدمجة، وكما يفعل Ollama، تشغيل **خادم محلي متوافق مع OpenAI** ليتمكن الكود من التخاطب معه. وهو نقطة الدخول الأسهل لغير المطورين أو لمن يفضّل الإشارة والنقر على الطرفية؛ أما Ollama فيميل إلى التفوق حين تريد واجهة أوامر قابلة للبرمجة النصية وخدمة خلفية خفيفة. كلاهما يشغّل أنواع النماذج مفتوحة الأوزان نفسها، فتنتقل مفاهيم هذه الصفحة مباشرة.

- قبل أن تمنح نموذجًا مسحوبًا صلاحية استخدام الأدوات → [أوزان مفتوحة ملغَّمة بباب خلفي: سلسلة توريد النماذج «abliterated»](/docs/security/backdoored-open-weights) — ملف GGUF الذي تسحبه هو عادةً الحلقة الثالثة في سلسلة ثقة من ثلاثة أطراف
- هل تنقل مطالبة نظام كبيرة من Claude إلى نموذج محلي؟ → [لماذا تنهار مطالبة نظام بحجم 35 KB على نموذج محلي](/docs/models/large-system-prompts-on-local-models)
- إلى أي حد يمكن للتكميم أن ينزل دون 4 بت؟ → [التكميم الثلاثي عمليًا: Bonsai 2 27B في 5.95 GB](/docs/models/ternary-quantization-bonsai-2-27b) — 1.75 بت لكل وزن، ولماذا لا يستطيع Ollama تحميله
- قرّر بين المحلي والسحابي لمهمة ما → [اختيار نموذج](/docs/models/choosing-a-model)
- اجعل الأدوات تعمل محليًا أيضًا → [استخدام الأدوات](/docs/api/tool-use)
- راقب كلفة تشغيل النماذج فعليًا → [اقتصاد الرموز](/docs/power-user/token-economy)
