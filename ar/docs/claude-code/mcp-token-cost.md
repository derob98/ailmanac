# ضريبة رموز MCP

أرقام الرموز وأسماء الميزات (`defer_loading` وTool Search Tool وProgrammatic Tool Calling) مصدرها منشورات Anthropic الهندسية. أما سلوك البحث عن الأدوات في Claude Code نفسه — أنه مفعّل افتراضيًا، وقيم `ENABLE_TOOL_SEARCH`، والحد الأدنى للنموذج، وحدود طول الأوصاف — فمصدره [توثيق MCP في Claude Code](https://code.claude.com/docs/en/mcp#scale-with-mcp-tool-search)، وهو المكان الذي يتغيّر فيه هذا الجزء. تحقق من المصدرين قبل اقتباس أرقام دقيقة.

هناك جدال يتكرر على Hacker News وX: *لماذا نحرق عشرات الآلاف من الرموز في عملية MCP واحدة بينما يكلّف الأمر نفسه عبر سطر الأوامر بضع مئات؟* يبدو هذا هجومًا على MCP. وليس كذلك. أعلى الأصوات في هذا الجدال هم من يحبّون الوكلاء — لكنهم اصطدموا للتو بالفاتورة. هذه الصفحة هي الدليل العملي لتلك الفاتورة: أين تذهب الرموز فعلًا، والتكلفتان اللتان لا يفصل بينهما أحد تقريبًا، والحلول الثلاثة التي تحوّل سير عمل من 150,000 رمز إلى سير عمل من 2,000 رمز.

## تكلفتان لا تكلفة واحدة

عند ربط خادم MCP، يطلب العميل منه `tools/list` ويستلم **كل أداة مع مخطط JSON الكامل الخاص بها**. تُحقن تلك الكتلة بأكملها في سياق النموذج. يتوقف معظم الناس في حساباتهم الذهنية عند هذا الحد. لكن هناك ضريبتين منفصلتين، والثانية عادةً أكبر.

**التكلفة 1 — تعريفات الأدوات.** اسم كل أداة متصلة ووصفها ومخطط معاملاتها كلها تقيم في السياق. وصف Anthropic نفسها: *«عندما تكون الوكلاء متصلة بآلاف الأدوات، سيتعيّن عليها معالجة مئات الآلاف من الرموز قبل قراءة الطلب.»* يمكن لخادم مؤسسي واحد أن ينشر عشرات إلى مئات الأدوات؛ وتقدّر تحليلات الأطراف الثالثة خادمًا من 400 أداة بنحو 400,000 رمز للمخطط وحده — ضعف نافذة 200k، وما زال 40% من نافذة 1M، تُنفق قبل الطلب الأول. (أحجام النوافذ لكل نموذج: [النماذج والأسعار](/docs/whats-new/models-and-pricing).)

**التكلفة 2 — النتائج الوسيطة.** عندما يستدعي النموذج أداةً مباشرةً، **تمرّ كل نتيجة مجددًا عبر سياق النموذج**، حتى الأجزاء التي لم تكن تريده أن يقرأها. مثال Anthropic: تسحب نص اجتماع مدته ساعتان من أداة وتمرّره إلى أخرى، فيمرّ النص الكامل عبر النموذج *مرتين* — ربما نحو 50,000 رمز — فقط لإنتاج ملخص من سطر واحد.

<Callout type="warning" items={["التكلفة 1 تُدفع في كل دورة حتى يبدأ التخزين المؤقت للمطالبات (prompt caching) — فالمخططات تُعاد إرسالها مع كل طلب في المحادثة، ولا تُحمَّل مرة واحدة. كتالوج الأدوات الكبير ضريبة على الجلسة كلها، لا رسم لمرة واحدة. هذه هي تكلفة أداة تعريفها محمَّل؛ وتأجيله (أدناه) هو ما يُخرجه من فاتورة كل دورة.", "التكلفة 2 تتناسب مع بياناتك، لا مع عدد أدواتك. قد تكون عشر أدوات صغيرة أرخص من أداة واحدة تعيد كتلة ضخمة."]} />

### الأرقام من المصادر الأولية

| الحل | المهمة | قبل | بعد | الانخفاض |
| --- | --- | --- | --- | --- |
| تنفيذ الشيفرة مع MCP | سير عمل Google Drive → Salesforce | 150,000 | 2,000 | **98.7%** |
| Tool Search Tool | تحميل التعريفات قبل بدء العمل | ~77,000 | ~8,700 | **85%** |
| Programmatic Tool Calling | مهمة بحثية معقدة | 43,588 | 27,297 | **37%** |

الصفوف الثلاثة كلها أرقام نشرتها Anthropic. والمفاجئ ليس التكلفة بل **الدقة**: فمع Tool Search Tool *ارتفعت* دقة اختيار الأداة (انتقل Opus 4.5 من 79.5% إلى 88.1%؛ وانتقل Opus 4 من 49% إلى 74%). أدوات أقل تزدحم في السياق تعني أن النموذج يختار الصحيحة أكثر. هنا تتحرك التكلفة والجودة في الاتجاه نفسه، وهذا نادر.

## الحل 1 — حمّل مخططات الأدوات عند الطلب

بدلًا من حقن كل المخططات منذ البداية، علّمها بـ `defer_loading: true`. عندها لا يرى Claude سوى فهرس خفيف؛ وعندما يحتاج GitHub يستدعي **Tool Search Tool** الذي يعيد *فقط* مخططات GitHub المطابقة — لا أكثر من 50 أداة من كل خادم آخر. تفيد Anthropic بأن هذا يحفظ نحو 191,300 رمز من السياق مقابل نحو 122,800 عند تحميل كل شيء مسبقًا.

### في Claude Code هو مفعّل بالفعل

أنت ترى هذا النمط الآن إن كنت تستخدم Claude Code مع خوادم MCP. **البحث عن الأدوات مفعّل افتراضيًا**: عند بدء الجلسة تُحمَّل فقط *أسماء* الأدوات وتعليمات الخادم، ويجلب Claude المخطط الكامل عبر استدعاء `ToolSearch` عندما تحتاجه مهمة ما. فإضافة خادم آخر تكلّفك أسماء أدواته، لا مخططاتها — ولا يضع Claude Code سقفًا لعدد الأدوات لكل خادم، ويقول إن الحد العملي هو ميزانية نافذة السياق لديك.

هناك ادعاء كثير التكرار يستحق التصحيح لأنه صحيح جزئيًا. عتبة «~10% من نافذة السياق» حقيقية، لكنها **ليست** المُشغّل الافتراضي — إنها وضع اختياري واحد من متغير البيئة `ENABLE_TOOL_SEARCH`:

| `ENABLE_TOOL_SEARCH` | السلوك |
| --- | --- |
| *(غير مضبوط)* — الافتراضي | كل أداة MCP مؤجَّلة وتُحمَّل عند الطلب |
| `true` | مثل غير المضبوط |
| `auto` | وضع العتبة. تُحمَّل الأدوات القابلة للتأجيل **مسبقًا** ما دام مجموع تعريفاتها أقل من 10% من نافذة السياق؛ وعند 10% أو أكثر يُفعَّل البحث عن الأدوات |
| `auto:N` | وضع العتبة بنسبتك الخاصة (`N` من 0 إلى 100)، مثل `auto:5` |
| `false` | كل أداة MCP تُحمَّل مسبقًا، بلا تأجيل |

لذا إن كنت تعوّل على تحميل الأدوات مسبقًا تحت 10%، فقد فهمت الافتراضي بالعكس — لا شيء يُحمَّل مسبقًا ما لم تطلب `auto`. و`auto` **لاصق**: فبمجرد أن يتجاوز المجموع العتبة ويُفعَّل البحث عن الأدوات، قد تبقى تلك الأدوات مؤجَّلة حتى بعد أن يعود المجموع إلى ما دونها.

<Callout type="warning" items={["ثلاثة أشياء توقف البحث عن الأدوات وتتجاهل ENABLE_TOOL_SEARCH كليًا: CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS (ابتداءً من Claude Code v2.1.227 يمكن للمؤسسة إبقاؤه مفعّلًا عبر الإعدادات المُدارة)، وجلسة تحصل على إعداد HIPAA (بلا أي تجاوز)، ونُشُر Microsoft Foundry المستضافة على Azure التي ترفضه من جهة الخادم. كما أن رفض أداة ToolSearch في الأذونات يحمّل كل شيء مسبقًا.", "هناك حد أدنى للنموذج: يستخدم Claude Code البحث عن الأدوات مع Claude Opus 4 وSonnet 4 وHaiku 4.5 وما بعدها. وفي النماذج الأقدم يُحمَّل كل شيء مسبقًا ولا يتجاوز ENABLE_TOOL_SEARCH=true ذلك. وعلى Agent Platform من Google Cloud يكون الحد الأدنى أعلى — Opus 4.5 وSonnet 4.5 وHaiku 4.5 وما بعدها."]} />

إذا كنت تكتب خوادم MCP فإن التأجيل يغيّر أيضًا ميزانية الأوصاف، وبشكل غير متماثل: الأداة المحمَّلة **مسبقًا** تُقتطع عند 4,096 حرفًا (السقف نفسه لتعليمات الخادم)، والمحمَّلة **عبر البحث عن الأدوات** عند 16,384. لكن البحث نفسه يطابق مقابل الحد الأقصر فقط، لذا يجب أن تكون الكلمات التي سيبحث عنها Claude قرب البداية في الحالتين.

## الحل 2 — أبقِ النتائج خارج السياق بتنفيذ الشيفرة

الحل الأعمق يستهدف التكلفة 2. فبدلًا من أن يستدعي النموذج الأدوات واحدة تلو الأخرى وتمرّ كل نتيجة عبره، **يكتب النموذج شيفرة** تستدعي الأدوات، وتبقى البيانات الوسيطة في بيئة التنفيذ. تعرض Anthropic خوادم MCP على شكل **شجرة ملفات من الأدوات** يستكشفها الوكيل كما يستكشف نظام ملفات، فيحمّل التعريفات التي يحتاجها فقط — و*«النتائج الوسيطة تبقى في بيئة التنفيذ افتراضيًا… الوكيل لا يرى إلا ما تسجّله أو تعيده صراحةً.»*

هذا التغيير التصميمي الواحد هو ما يختصر سير عمل Drive→Salesforce من 150,000 إلى 2,000 رمز: السجلات تتحرك عبر الشيفرة، ولا يعود إلى النموذج إلا العدد النهائي. وعلى Developer Platform تأتي الفكرة نفسها باسم **Programmatic Tool Calling** — يكتب Claude شيفرة Python تنسّق عدة أدوات وتصفّي المخرجات قبل أن تصل إلى سياقه.

<Callout type="tip" items={["قاعدة عامة: إذا كانت الأداة تُرجع شيئًا كبيرًا (نصًا مفرَّغًا أو تفريغ استعلام أو ملفًا) فأنت تريد تنفيذ الشيفرة كي تُعالَج الكتلة خارج السياق. وإذا كانت الأداة تنفّذ شيئًا صغيرًا فحسب (إنشاء بلاغ، إرسال صف واحد) فالاستدعاء المباشر مناسب."]} />

## الحل 3 — اعرف متى يكسب استدعاء سطر الأوامر ببساطة

أحيانًا لا يكون الجواب الصحيح إعداد MCP أفضل، بل عدم استخدام MCP أصلًا. للجدال على HN/X وجاهة حقيقية: أمر shell مثل `gh pr list` أو `psql -c '…'` يكلّف بضع مئات من الرموز ذهابًا وإيابًا، بينما يدفع المسار المكافئ عبر MCP ثمن المخططات إضافةً إلى نتيجة مهيكلة. إن كان لدى الوكيل طرفية بالفعل وكان سطر الأوامر موجودًا، فغالبًا ما يكون هذا أخف مسار.

<PromptCard title="فضّل سطر الأوامر عندما تكون الأداة أصلًا أداة سطر أوامر">
{`# Instead of connecting a GitHub MCP server for read-only work,
# let the agent use the gh CLI it already has:
gh pr list --state open --json number,title,author

# ~200 tokens of command + compact output, no schema tax,
# no server to keep connected across the session.`}
</PromptCard>

يستحق MCP عبأه حين تحتاج قدرة **مُنمَّطة ومحكومة بالأذونات وعابرة للواجهات** — قاعدة بيانات بدور للقراءة فقط، أو متصفح يستطيع تشغيله، أو واجهة SaaS تستخدم OAuth — أو حين تُعاد الأدوات نفسها عبر دورات كثيرة فيوزّع التخزين المؤقت تكلفة المخططات. اختر سطر الأوامر حين تكون القدرة لمرة واحدة، وقابلة للبرمجة أصلًا، وتعيد شيئًا صغيرًا. ليس أيٌّ منهما «أفضل»؛ إنهما نقطتان مختلفتان على منحنى التكلفة.

## ذو صلة على AILmanac

- [خوادم MCP في Claude Code](/docs/claude-code/mcp) — كيف تضيف الخوادم وتحدد نطاقها وتؤمّنها.
- [اقتصاد الرموز](/docs/power-user/token-economy) — ضغط مخرجات الأوامر قبل وصولها إلى النموذج.
- [Dynamic Workflows](/docs/claude-code/dynamic-workflows) — أين تظهر تكلفة التنسيق، وكيف تجزّئ لقياس الإنفاق.
- [استخدام الأدوات في الـ API](/docs/api/tool-use) — شكل الطلب/الاستجابة الكامن خلف كل هذا.
- [Playwright MCP: الدليل العملي المعمّق](/docs/api/playwright-mcp-deep-guide) — مثال تطبيقي على أثقل خادم منفرد يربطه الناس (ضريبة مخططات ~3,500 رمز)، ومتى يكسب مسار Skill/CLI بدلًا منه.
- [Tool Search والتحميل المؤجَّل](/docs/api/tool-search-and-deferred-loading) — الغوص المعمّق على مستوى الـ API: regex مقابل BM25، وأخطاء 400 الخمسة، ولماذا لا يصغر جسم الطلب.

## المصادر ولمزيد من القراءة

- [Code execution with MCP: building more efficient AI agents](https://www.anthropic.com/engineering/code-execution-with-mcp) — Anthropic Engineering. مصدر رقم 150,000 ← 2,000 رمز (98.7%) ونمط «النتائج الوسيطة تبقى في بيئة التنفيذ».
- [Introducing advanced tool use on the Claude Developer Platform](https://www.anthropic.com/engineering/advanced-tool-use) — Anthropic Engineering. Tool Search Tool (`defer_loading`، خفض ~85%، تحسّن الدقة) وProgrammatic Tool Calling (43,588 ← 27,297 رمزًا).
- [توثيق MCP في Claude Code](https://code.claude.com/docs/en/mcp) — المرجع الرسمي لربط الخوادم وتحديد نطاقها. قسمه [Scale with MCP tool search](https://code.claude.com/docs/en/mcp#scale-with-mcp-tool-search) هو مصدر كون البحث عن الأدوات الافتراضي، وجدول `ENABLE_TOOL_SEARCH`، والحد الأدنى للنموذج، وسقفي الأوصاف 4,096 / 16,384 حرفًا.
- [modelcontextprotocol — Progressive Tool Discovery discussion](https://github.com/modelcontextprotocol/modelcontextprotocol/discussions/1923) — نقاش تصميمي مجتمعي حول تحميل الأدوات عند الطلب.
- [MCP Progressive Disclosure](https://www.solo.io/blog/mcp-progressive-disclosure) (Solo.io) — شرح من طرف ثالث لنمط الفهرس الخفيف / جلب المخطط عند الطلب.
