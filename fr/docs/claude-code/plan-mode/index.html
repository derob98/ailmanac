Plan Mode

Débutant
What you'll learn
  • Expliquer ce que Plan Mode bloque — et ce qu'il laisse quand même exécuter à Claude
  • Entrer et sortir de Plan Mode de trois façons différentes
  • Parcourir la boucle enquêter-proposer-approuver-exécuter
  • Distinguer Plan Mode des Permissions et les utiliser ensemble
Dernière vérification : 2026-10-09.

La façon d'entrer en Plan Mode (raccourci/option), et les commandes shell qu'il laisse exactement exécuter à Claude pendant la planification, changent d'une version à l'autre — vérifiez dans la documentation officielle de Claude Code.

Vérifiez auprès de la source officielle.

L'idée principale​

Imaginez confier vos clés de maison à un artisan versus lui demander d'abord de faire le tour et de noter ce qu'il changerait. Plan Mode est le tour de repérage.

Plan Mode demande à Claude de rechercher et proposer des changements sans les faire : il lit des fichiers, exécute des commandes shell pour explorer et rédige un plan — mais il n'édite pas vos sources. Les éditions restent bloquées jusqu'à ce que vous approuviez le plan.

Pro tip
  • Plan Mode signifie que Claude ENQUÊTE mais ne MODIFIE pas vos sources — il produit un plan et attend votre feu vert.

Il n'est pas strictement en lecture seule​

Explorer nécessite parfois une commande : Plan Mode consiste donc à ne pas éditer, non à ne pas exécuter. Ce qui arrive à une commande shell pendant la planification dépend de la session — le premier cas qui correspond l'emporte :

Guided walkthrough1 of 3
  1. Les blocages de Plan Mode ne sont PAS appliqués. Claude reçoit toujours la consigne de planifier sans éditer, mais une édition ou une commande qu'il tente pendant la planification s'exécute sans demande de confirmation. Plan Mode conserve ses blocages partout ailleurs — les exécutions headless -p, l'Agent SDK et le panneau de chat de l'extension VS Code.
  2. Le classifieur examine les commandes shell au lieu de vous solliciter, sauf pour les suppressions sur des chemins critiques. Les commandes approuvées s'exécutent ; celles qui sont rejetées sont bloquées.
  3. Les commandes qui sortent de l'ensemble intégré en lecture seule vous demandent une approbation.
Watch out
  • Si vous avez lancé avec --allow-dangerously-skip-permissions, Plan Mode est une instruction forte plutôt qu'un garde-fou strict. Traitez-le comme une convention de planification, pas comme un bac à sable.

Pourquoi c'est la façon la plus sûre de commencer​

Pour tout ce qui est grand, risqué ou inconnu, vous voulez voir ce que Claude compte faire avant qu'il ne touche votre dépôt. Plan Mode sépare la réflexion de l'action :

Le gain : vous attrapez les mauvaises hypothèses avant qu'elles ne deviennent du mauvais code.

Quand l'utiliser​

Pro tip
  • TOUJOURS pour les changements grands ou multi-fichiers, les migrations ou les refactorisations
  • Quand vous travaillez dans une base de code que vous ne connaissez pas encore entièrement
  • Quand vous voulez un plan révisable à partager avec un coéquipier

Pour de minuscules éditions évidentes, vous pouvez sauter cette étape — mais en cas de doute, planifiez d'abord.

Comment ça marche en pratique​

Suivez la boucle. Chaque étape mérite la suivante — Claude ne passe à l'édition qu'après votre approbation.

Guided walkthrough1 of 4
  1. Appuyez sur Shift+Tab pour faire défiler les modes de permission jusqu'à ce que la barre d'état affiche 'plan mode on', ou préfixez un seul prompt avec /plan. Pour démarrer directement dedans, lancez claude --permission-mode plan. Décrivez ensuite ce que vous voulez accomplir.
  2. Il lit les fichiers pertinents, exécute des commandes exploratoires et pose des questions de clarification.
  3. Les fichiers à changer, l'approche, et comment vérifier le résultat. Appuyez sur Ctrl+G pour ouvrir le plan proposé dans votre éditeur et le modifier directement.
  4. Choisissez 'Yes, and use auto mode', 'Yes, manually approve edits', ou 'No, keep planning'. L'approbation fait sortir de Plan Mode vers le mode de permission décrit par l'option choisie, et Claude commence à éditer.

Pour quitter Plan Mode sans approuver de plan, appuyez à nouveau sur Shift+Tab. Pour en faire le mode par défaut des sessions de terminal d'un projet, définissez defaultMode sur plan dans .claude/settings.json — voir Réglages.

Plan Mode vs Permissions​

Une confusion classique. Ils résolvent des problèmes différents et fonctionnent ensemble :

  • Plan Mode = « enquêter et proposer, ne pas encore éditer ». (Cette page.)
  • Permissions = une fois en action, quelles actions sont autorisées sans demander.

Voyez-le comme agir maintenant ou non (Plan Mode) versus quelles actions sont autorisées une fois en action (Permissions).

Key takeaways
  • Plan Mode, c'est rechercher et proposer : Claude lit et exécute des commandes exploratoires mais n'édite pas vos sources tant que vous n'avez pas approuvé le plan
  • Il n'est pas strictement en lecture seule — pendant la planification, les commandes sont examinées par le classifieur, soumises à votre approbation, ou (avec bypass permissions disponible dans un terminal interactif) entièrement débloquées
  • Entrez avec Shift+Tab, un préfixe /plan, ou --permission-mode plan ; l'approbation fait basculer la session dans le mode nommé par l'option d'approbation choisie
  • Utilisez-le par défaut pour le travail grand, risqué ou inconnu ; ne sautez que les minuscules éditions évidentes
  • Plan Mode régit S'IL FAUT agir maintenant ; les Permissions régissent QUELLES actions sont autorisées une fois en action
